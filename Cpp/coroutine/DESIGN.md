# coroutine 设计说明

## 设计目标

用最小示例解释 C++20 协程的编译器协作机制，并逐步连接到 Reactor、调度器、超时和取消。

## 组织决策

- 先讲 Promise、handle 和 Awaitable，再讲网络等待和调度策略。
- 将概念演示与工程实现区分，`08`-`10` 当前保留为学习材料。
- 所有协程对象必须明确协程帧、handle 和返回对象的所有权关系。

## 关键边界

- `final_suspend` 后的销毁责任必须明确。
- 异常不能静默丢失，取消和超时必须有结果语义。
- Reactor 恢复协程前必须确认 fd 和等待状态仍然有效。
- 同一 handle 不得被重复 resume，关闭流程必须清理挂起任务。

## 已知限制

- 当前没有统一 C++20 构建矩阵。
- 协程池、超时和取消示例缺少真实生命周期测试。
- 性能数字暂无平台、编译器和基准依据，不应作为通用结论。

## 验证计划

1. 建立最小 C++20 构建工程。
2. 增加 handle 生命周期和异常传播测试。
3. 增加取消、超时、重复 resume 和关闭场景测试。
4. 再评估协程池和工作窃取实现。
