### 任务2：协程超时控制（预计60分钟）
**文件**：`coroutine/09_coroutine_timeout.cpp`

**学习内容**：
1. **超时控制的必要性**
   - 防止协程永久挂起（网络请求超时、数据库查询超时）
   - 资源泄漏预防
   - 用户体验保障（不让用户无限等待）

2. **三种超时检测方法**
   - **轮询检测**：协程内部定期检查时间
   - **定时器触发**：外部定时器超时后取消协程
   - **时间轮算法**：高效批量超时管理（推荐）

3. **超时处理策略**
   - 返回错误码（推荐）
   - 抛出异常（需要异常安全保证）
   - 回调通知

4. **推荐超时配置**
   - HTTP 请求：3-10秒
   - 数据库查询：5-30秒
   - 文件 I/O：1-5秒
   - RPC 调用：1-3秒

5. **实战示例**
   - 实现 `TimeoutAwaitable`（带超时的 Awaitable）
   - 模拟网络请求超时场景
   - 超时后的清理工作

### 任务3：协程取消与资源管理（预计30分钟）
**文件**：`coroutine/10_coroutine_cancel.cpp`

**学习内容**：
1. **协程取消机制**
   - 协作式取消（推荐）：协程主动检查取消标志
   - 强制式取消（危险）：直接销毁协程（可能泄漏资源）

2. **取消标志设计**
   - `std::atomic<bool>` 线程安全标志
   - 协程内部定期检查 `if (cancelled) return;`

3. **资源管理与 RAII**
   - 协程中的资源泄漏风险（文件句柄、网络连接、内存）
   - RAII 模式保证资源释放
   - `unique_ptr` / `shared_ptr` 自动管理

4. **优雅关闭流程**
   - 停止接收新任务
   - 等待当前任务完成
   - 取消等待中的任务
   - 清理资源
   - 确认关闭

5. **实战示例**
   - 实现可取消的协程
   - 模拟文件下载取消场景
   - 优雅关闭协程池

## 📌 注意事项

⚠️ **协程取消陷阱**：
- 不要直接 `destroy()` 协程句柄（可能泄漏资源）
- 协程必须定期检查取消标志（协作式）
- 资源释放依赖 RAII，不要手动 `delete`

⚠️ **超时检测陷阱**：
- 轮询检测影响性能（频繁调用时间函数）
- 定时器触发需要多线程支持
- 时间轮算法最高效但实现复杂

⚠️ **资源管理陷阱**：
- 协程中的局部变量在暂停期间仍存在
- 暂停期间引用的外部对象可能失效
- 使用 `shared_ptr` 延长生命周期
