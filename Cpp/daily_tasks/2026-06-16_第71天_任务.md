### 任务1：LT vs ET 理论学习（预计60分钟）

**学习内容**：

#### 1.1 水平触发（Level Triggered, LT）

**触发条件**：
- 只要 fd 处于"就绪"状态，epoll_wait 就会返回
- 即使你没有读完数据，下次 epoll_wait 还会通知你

**特点**：
- 默认模式（不设置 EPOLLET 就是 LT）
- 类似 select 的行为
- 更安全，不容易漏掉数据

**举例**：
```
客户端发送 1000 字节
你只读了 500 字节
→ 下次 epoll_wait 还会通知你（因为还有 500 字节未读）
```

---

#### 1.2 边缘触发（Edge Triggered, ET）

**触发条件**：
- 只在状态从"未就绪"变为"就绪"时通知一次
- 如果你没有读完数据，不会再次通知

**特点**：
- 需要设置 EPOLLET 标志
- 更高效，减少系统调用
- 更危险，容易漏掉数据

**举例**：
```
客户端发送 1000 字节
你只读了 500 字节
→ 下次 epoll_wait 不会通知（状态没有变化）
→ 剩余 500 字节会丢失！
```

---

#### 1.3 LT vs ET 对比

| 特性 | LT（水平触发） | ET（边缘触发） |
|------|---------------|---------------|
| **触发条件** | 只要就绪就通知 | 状态变化时通知一次 |
| **安全性** | 更安全 | 容易漏数据 |
| **性能** | 较低（通知次数多） | 更高（通知次数少） |
| **编程难度** | 简单 | 复杂 |
| **是否需要非阻塞** | 可选 | 必须 |
| **是否需要循环读** | 可选 | 必须 |

---

#### 1.4 为什么 ET 更快？

**LT 模式的问题**：
```
1. fd 就绪
2. epoll_wait 返回（通知你）
3. 你读了一部分数据
4. epoll_wait 再次返回（又通知你）← 额外的系统调用
5. 你读完数据
```

**ET 模式的优势**：
```
1. fd 就绪
2. epoll_wait 返回（通知你一次）
3. 你一次性读完所有数据 ← 减少系统调用
```

**结论**：
- LT：每次 epoll_wait 都可能返回同一个 fd（只要还有数据）
- ET：epoll_wait 只返回一次，必须一次性处理完

---

#### 1.5 ET 模式的要求

**必须配合非阻塞 I/O**：
- 为什么？因为要循环读取直到读完
- 如果是阻塞 I/O，读到最后一次会一直阻塞（等待更多数据）
- 非阻塞 I/O 会返回 EAGAIN（表示数据读完了）

**必须循环读取**：
```cpp
while (true) {
    int n = recv(fd, buf, sizeof(buf), 0);
    if (n > 0) {
        // 处理数据
    } else if (n == 0) {
        // 连接关闭
        break;
    } else {
        if (errno == EAGAIN || errno == EWOULDBLOCK) {
            // 数据读完了，正常退出
            break;
        } else {
            // 真正的错误
            perror("recv");
            break;
        }
    }
}
```

### 任务2：非阻塞 I/O 实战（预计60分钟）

**项目目标**：实现 ET 模式的 epoll 回显服务器

**文件**：`high_performance/02_epoll_et.cpp`

**实现步骤**：

#### Step 1：设置 fd 为非阻塞模式

```cpp
void setNonBlocking(int fd) {
    int flags = fcntl(fd, F_GETFL, 0);
    if (flags == -1) {
        perror("fcntl F_GETFL");
        return;
    }
    if (fcntl(fd, F_SETFL, flags | O_NONBLOCK) == -1) {
        perror("fcntl F_SETFL");
    }
}
```

#### Step 2：监听时设置 EPOLLET 标志

```cpp
struct epoll_event ev;
ev.events = EPOLLIN | EPOLLET;  // 添加 EPOLLET 标志
ev.data.fd = client_fd;
epoll_ctl(epfd, EPOLL_CTL_ADD, client_fd, &ev);
```

#### Step 3：循环读取直到 EAGAIN

```cpp
// ET 模式必须循环读取直到 EAGAIN
while (true) {
    char buf[1024];
    int n = recv(fd, buf, sizeof(buf) - 1, 0);
    
    if (n > 0) {
        // 收到数据，回显
        buf[n] = '\0';
        send(fd, buf, n, 0);
    } 
    else if (n == 0) {
        // 客户端关闭连接
        cout << "[关闭] fd=" << fd << endl;
        epoll_ctl(epfd, EPOLL_CTL_DEL, fd, NULL);
        close(fd);
        break;
    } 
    else {
        // n < 0
        if (errno == EAGAIN || errno == EWOULDBLOCK) {
            // 数据读完了，正常
            break;
        } else {
            // 真正的错误
            perror("recv");
            epoll_ctl(epfd, EPOLL_CTL_DEL, fd, NULL);
            close(fd);
            break;
        }
    }
}
```

**关键点**：
1. 所有 fd（包括 listen_fd 和 client_fd）都要设置为非阻塞
2. 必须循环读取，直到 recv 返回 EAGAIN
3. EAGAIN 不是错误，是"数据读完了"的信号

## 🎓 学习重点

1. **核心理解**：LT 是"持续通知"，ET 是"通知一次"
2. **为什么 ET 快**：减少 epoll_wait 的返回次数（减少系统调用）
3. **ET 的代价**：必须非阻塞 + 循环读取（编程更复杂）
4. **EAGAIN 的含义**：不是错误，是"暂时没有数据"的信号

## ⚠️ 常见陷阱

1. **ET 模式忘记循环读取** → 数据丢失
2. **ET 模式使用阻塞 I/O** → 最后一次 recv 会永久阻塞
3. **把 EAGAIN 当作错误** → 错误地关闭连接
4. **只设置 client_fd 为非阻塞，忘记设置 listen_fd** → accept 可能阻塞
