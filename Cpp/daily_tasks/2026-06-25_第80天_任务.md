### 任务1：协程 + Reactor 理论（预计60分钟）

#### 1.1 为什么要协程化 Reactor？

**传统 Reactor（回调）的问题**：
```cpp
class ReadHandler {
    void handleEvent() {
        recv(fd, buf, ...);
        // 业务逻辑
        process(buf, [this](result1) {
            send(fd, result1, [this](n) {
                recv(fd, buf2, [this](data2) {
                    // 回调地狱
                });
            });
        });
    }
};
```

**协程化的目标**：
```cpp
Task<void> handleClient(int fd) {
    while (true) {
        auto data = co_await asyncRead(fd);   // 同步写法
        auto result = process(data);
        co_await asyncWrite(fd, result);       // 同步写法
    }
}
```

**好处**：
- 代码线性（易读）
- 逻辑集中
- 错误处理简单

---

#### 1.2 核心思想：把 I/O 操作变成 Awaitable

**关键**：实现一个 Awaitable，让 co_await 可以等待 I/O 完成

**ReadAwaitable 设计**：
```cpp
struct ReadAwaitable {
    int fd;
    Reactor* reactor;
    char* buffer;
    int result;
    
    // 1. 是否需要暂停？
    bool await_ready() {
        // 尝试立即读取
        result = recv(fd, buffer, size, MSG_DONTWAIT);
        if (result >= 0 || errno != EAGAIN) {
            return true;  // 立即完成，不暂停
        }
        return false;  // 数据未就绪，暂停
    }
    
    // 2. 暂停时：注册到 epoll
    void await_suspend(std::coroutine_handle<> handle) {
        // 注册 fd 到 epoll，保存协程 handle
        reactor->registerRead(fd, handle);
    }
    
    // 3. 恢复时：返回读取结果
    int await_resume() {
        return result;
    }
};
```

---

#### 1.3 完整流程

```
协程执行 co_await asyncRead(fd)
  ↓
创建 ReadAwaitable
  ↓
调用 await_ready()
  ├─ 数据就绪 → 返回 true → 立即继续
  └─ 数据未就绪 → 返回 false → 暂停
       ↓
     调用 await_suspend(handle)
       ↓
     注册 fd 到 epoll，保存 handle
       ↓
     协程暂停，返回控制权给 Reactor
       ↓
     Reactor 事件循环继续（处理其他协程）
       ↓
     epoll 检测到 fd 可读
       ↓
     Reactor 找到对应的 handle
       ↓
     调用 handle.resume() 恢复协程
       ↓
     调用 await_resume()，返回读取结果
       ↓
     协程从 co_await 处继续执行
```

#### 1.4 Reactor 的改造

**传统 Reactor**：
```cpp
class Reactor {
    map<int, Handler*> handlers;  // fd → Handler
    
    void run() {
        while (true) {
            epoll_wait(...);
            handler->handleEvent();  // 调用回调
        }
    }
};
```

**协程版 Reactor**：
```cpp
class Reactor {
    map<int, coroutine_handle<>> handles;  // fd → 协程 handle
    
    void run() {
        while (true) {
            epoll_wait(...);
            // 恢复对应的协程
            auto handle = handles[fd];
            handle.resume();
        }
    }
    
    // 注册读事件
    void registerRead(int fd, coroutine_handle<> handle) {
        handles[fd] = handle;
        // 添加 fd 到 epoll
        epoll_ctl(epfd, EPOLL_CTL_ADD, fd, ...);
    }
};
```

### 任务3：回调 vs 协程对比（预计30分钟）

#### 3.1 代码对比

**回调版**：
```cpp
void handleClient(int fd) {
    asyncRead(fd, [fd](data) {
        auto result = process(data);
        asyncWrite(fd, result, [fd](n) {
            handleClient(fd);  // 递归
        });
    });
}
```

**协程版**：
```cpp
Task<void> handleClient(int fd) {
    while (true) {
        auto data = co_await asyncRead(fd);
        auto result = process(data);
        co_await asyncWrite(fd, result);
    }
}
```

---

#### 3.2 对比维度

| 维度 | 回调 | 协程 |
|------|------|------|
| 代码可读性 | 差（嵌套） | 好（线性） |
| 逻辑组织 | 分散 | 集中 |
| 错误处理 | 困难 | 简单（try-catch） |
| 调试 | 困难 | 容易 |
| 性能 | 高 | 高（相当） |
| 学习曲线 | 中 | 中（但代码易懂） |
