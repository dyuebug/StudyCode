### 任务1：Reactor 模式理论学习（预计60分钟）

#### 1.1 什么是 Reactor 模式？

**定义**：
- Reactor（反应器）是一种事件驱动架构模式
- 用于处理并发 I/O 事件
- 核心思想：事件分离与分发

**为什么需要 Reactor？**

**问题场景**：原始 epoll 代码的问题
```cpp
// 原始 epoll 代码（第1周写的）
while (true) {
    int n = epoll_wait(epfd, events, MAX_EVENTS, -1);
    
    for (int i = 0; i < n; i++) {
        int fd = events[i].data.fd;
        
        if (fd == listen_fd) {
            // 新连接处理代码（混在一起）
            int client_fd = accept(listen_fd, ...);
            // ...
        } else {
            // 数据处理代码（混在一起）
            char buf[1024];
            int n = recv(fd, buf, sizeof(buf), 0);
            // ...
        }
    }
}
```

**问题**：
- 所有逻辑混在事件循环中
- 难以扩展和维护
- 不同类型的事件处理逻辑耦合在一起

**Reactor 的解决方案**：
```cpp
// Reactor 模式
class Reactor {
    void run() {
        while (true) {
            int n = epoll_wait(epfd, events, MAX_EVENTS, -1);
            
            for (int i = 0; i < n; i++) {
                Handler* handler = getHandler(events[i].data.fd);
                handler->handleEvent();  // 分发给具体的 Handler
            }
        }
    }
};

class AcceptHandler {  // 专门处理新连接
    void handleEvent() { /* accept 逻辑 */ }
};

class ReadHandler {    // 专门处理读事件
    void handleEvent() { /* recv 逻辑 */ }
};
```

**优势**：
- 事件循环和事件处理分离
- 每种事件有独立的 Handler
- 易于扩展和维护

---

#### 1.2 Reactor 的核心组件

```
┌─────────────────────────────────────────┐
│            Reactor（反应器）              │
│  职责：事件循环 + 事件分发                │
│                                         │
│  run() {                                │
│    while (true) {                       │
│      events = demultiplexer.select()    │
│      for (event in events) {            │
│        handler = getHandler(event)      │
│        handler.handleEvent()            │
│      }                                  │
│    }                                    │
│  }                                      │
└─────────────────────────────────────────┘
              ↓ 使用
┌─────────────────────────────────────────┐
│     Demultiplexer（事件分离器）          │
│  职责：I/O 多路复用                      │
│                                         │
│  实现：epoll_wait / select / poll       │
│  作用：监听多个 fd，返回就绪的事件       │
└─────────────────────────────────────────┘
              ↓ 返回事件
┌─────────────────────────────────────────┐
│        Handler（事件处理器）             │
│  职责：处理具体的事件                    │
│                                         │
│  AcceptHandler：处理新连接               │
│  ReadHandler：处理读事件                 │
│  WriteHandler：处理写事件                │
└─────────────────────────────────────────┘
```

**三大组件**：

**1. Reactor（反应器）**
- 职责：事件循环 + 事件分发
- 核心方法：`run()` - 运行事件循环
- 包含：Demultiplexer + Handler 映射表

**2. Demultiplexer（事件分离器）**
- 职责：I/O 多路复用
- 实现：epoll_wait / select / poll
- 作用：监听多个 fd，返回就绪的事件

**3. Handler（事件处理器）**
- 职责：处理具体的事件
- 类型：AcceptHandler、ReadHandler、WriteHandler
- 接口：`handleEvent()` - 处理事件的抽象方法

---

#### 1.3 Reactor 工作流程

```
1. 应用启动
   ↓
2. 创建 Reactor
   ↓
3. 注册 Handler
   - AcceptHandler（listen_fd）
   - ReadHandler（client_fd）
   ↓
4. Reactor.run() 启动事件循环
   ↓
5. Demultiplexer.select()（epoll_wait）
   ↓ 返回就绪事件
6. Reactor 分发事件
   - 查找对应的 Handler
   - 调用 Handler.handleEvent()
   ↓
7. Handler 处理事件
   - AcceptHandler：accept + 注册新 ReadHandler
   - ReadHandler：recv + send
   ↓
8. 返回步骤 5（循环）
```

---

#### 1.4 Reactor 单线程模型

**架构图**：
```
┌────────────────────────────────────────┐
│          单线程 Reactor                 │
│                                        │
│  ┌──────────────────────────────────┐ │
│  │      Reactor（事件循环）          │ │
│  │                                  │ │
│  │  while (true) {                  │ │
│  │    events = epoll_wait()         │ │
│  │    dispatch(events)              │ │
│  │  }                               │ │
│  └──────────────────────────────────┘ │
│                                        │
│  ┌──────────┐  ┌──────────┐          │
│  │ Accept   │  │  Read    │          │
│  │ Handler  │  │ Handler  │  ...     │
│  └──────────┘  └──────────┘          │
│                                        │
└────────────────────────────────────────┘
      ↑                    ↑
      │ 新连接              │ 数据到达
    客户端              客户端
```

**特点**：
- 所有逻辑在单线程中执行
- Reactor + 所有 Handler 都在同一个线程
- 优点：简单，无竞态问题
- 缺点：业务逻辑慢会阻塞整个 Reactor

### 任务3：Reactor 设计模式分析（预计30分钟）

#### 3.1 Reactor vs 原始 epoll

| 维度 | 原始 epoll | Reactor |
|------|-----------|---------|
| **代码组织** | 所有逻辑混在一起 | 事件循环 + Handler 分离 |
| **扩展性** | 难以扩展 | 易于扩展（添加新 Handler） |
| **可维护性** | 低（逻辑耦合） | 高（职责分离） |
| **复杂度** | 简单 | 稍复杂 |

---

#### 3.2 Reactor 的优缺点

**优点**：
- ✅ 代码结构清晰（职责分离）
- ✅ 易于扩展（添加新 Handler）
- ✅ 易于测试（Handler 可单独测试）
- ✅ 符合开闭原则

**缺点**：
- ❌ 复杂度增加（需要设计 Handler 接口）
- ❌ 性能略有损失（函数调用开销）
- ❌ 单线程模型业务逻辑慢会阻塞

---

#### 3.3 适用场景

**Reactor 单线程适合**：
- I/O 密集型应用
- 业务逻辑简单且快
- 需要清晰的代码结构

**不适合**：
- CPU 密集型应用
- 业务逻辑复杂且慢
- 需要充分利用多核（需要多线程 Reactor）
