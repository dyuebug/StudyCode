### 任务1：Reactor 多线程理论学习（预计60分钟）

#### 1.1 单线程 Reactor 的瓶颈

**问题场景**：
```cpp
class ReadHandler {
    void handleEvent() {
        recv(fd, buf, sizeof(buf), 0);
        
        // 业务逻辑（假设需要 100ms）
        processBusinessLogic();  // ← 阻塞整个 Reactor
        
        send(fd, buf, len, 0);
    }
};
```

**问题**：
- 业务逻辑慢（数据库查询、文件操作、复杂计算）
- 阻塞整个 Reactor 事件循环
- 其他就绪的 fd 无法及时处理
- 无法充分利用多核 CPU

**影响**：
- 场景：1000 个连接，业务逻辑 100ms
- 单线程 Reactor：1000 × 100ms = 100 秒
- QPS = 10（非常低）

---

#### 1.2 Reactor + 线程池架构

**解决方案**：职责再分离

```
单线程 Reactor：
  Reactor：事件循环 + 事件分发 + 业务处理（全在一个线程）

多线程 Reactor：
  Reactor（主线程）：事件循环 + 事件分发（快）
  线程池：业务处理（可以慢）
```

**架构图**：
```
┌────────────────────────────────────────┐
│     主线程（Reactor）                   │
│                                        │
│  ┌──────────────────────────────────┐ │
│  │   Reactor 事件循环                │ │
│  │                                  │ │
│  │  while (true) {                  │ │
│  │    events = epoll_wait()         │ │
│  │    for (event in events) {       │ │
│  │      handler->handleEvent()      │ │
│  │    }                             │ │
│  │  }                               │ │
│  └──────────────────────────────────┘ │
│                                        │
│  Handler::handleEvent() {              │
│    // ⭐ 只负责接收数据                 │
│    recv(fd, buf, sizeof(buf), 0);     │
│                                        │
│    // ⭐ 交给线程池处理                 │
│    threadPool.enqueue([buf, fd]() {   │
│      processBusinessLogic();          │
│      send(fd, result, len, 0);        │
│    });                                │
│  }                                    │
└────────────────────────────────────────┘
              ↓ 任务队列
┌────────────────────────────────────────┐
│     工作线程池（4 个线程）              │
│                                        │
│  线程1：处理业务逻辑 1                  │
│  线程2：处理业务逻辑 2                  │
│  线程3：处理业务逻辑 3                  │
│  线程4：空闲，等待任务                  │
└────────────────────────────────────────┘
```

**优势**：
- Reactor 主线程不阻塞（只负责 I/O）
- 工作线程并发处理业务逻辑
- 充分利用多核 CPU

**性能提升**：
- 场景：1000 个连接，业务逻辑 100ms，4 个工作线程
- 多线程 Reactor：1000 × 100ms / 4 = 25 秒
- QPS = 40
- **性能提升 4 倍**

#### 1.3 Reactor + 线程池 vs 第1周 epoll + 线程池

**第1周的 epoll + 线程池**（第72天）：
```cpp
// 原始 epoll + 线程池
while (true) {
    int n = epoll_wait(epfd, events, MAX_EVENTS, -1);
    
    for (int i = 0; i < n; i++) {
        int fd = events[i].data.fd;
        
        if (fd == listen_fd) {
            // 主线程处理 accept
        } else {
            // ⭐ 整个事件处理交给线程池
            pool.enqueue([fd, epfd]() {
                handleClient(fd, epfd);  // recv + 业务 + send
            });
        }
    }
}
```

**今天的 Reactor + 线程池**：
```cpp
// Reactor + 线程池
class ReadHandler {
    void handleEvent() {
        // ⭐ 主线程只负责 recv
        recv(fd, buf, sizeof(buf), 0);
        
        // ⭐ 只把业务逻辑交给线程池
        pool.enqueue([buf]() {
            processBusinessLogic();
        });
    }
};
```

**核心区别**：

| 维度 | epoll + 线程池 | Reactor + 线程池 |
|------|---------------|-----------------|
| **架构** | 原始 epoll | Reactor 框架 |
| **主线程** | epoll_wait + 分发 | Reactor 事件循环 |
| **线程池** | recv + 业务 + send | 只处理业务逻辑 |
| **recv** | 工作线程 | 主线程 |
| **send** | 工作线程 | 工作线程或主线程 |
| **代码组织** | 混在一起 | Handler 分离 |
| **扩展性** | 低 | 高 |

**关键理解**：
- 第1周：整个事件处理交给线程池（粗粒度）
- 今天：只把业务逻辑交给线程池（细粒度）
- Reactor 提供了更清晰的架构

#### 1.4 Reactor 多线程模型的设计

**设计要点**：

**1. Handler 的职责划分**
```cpp
class ReadHandler {
    void handleEvent() {
        // ⭐ 主线程：I/O 操作（recv）
        recv(fd, buf, sizeof(buf), 0);
        
        // ⭐ 线程池：业务逻辑
        pool.enqueue([buf]() {
            processBusinessLogic();
        });
    }
};
```

**2. 线程安全问题**
- 主线程和工作线程可能同时访问 fd
- 需要考虑同步机制
- 或者设计为：主线程只读，工作线程只写

**3. 结果返回机制**
- 工作线程处理完成后如何返回结果？
- 方案1：工作线程直接 send
- 方案2：工作线程通知主线程，主线程 send

### 任务2：Reactor 多线程实战（预计60分钟）

**项目目标**：实现 Reactor + 线程池服务器

**文件**：`reactor/02_reactor_threadpool.cpp`

**设计方案**：

**方案1：工作线程直接 send（简单）**
```cpp
class ReadHandler {
    void handleEvent() {
        recv(fd, buf, sizeof(buf), 0);
        
        // 捕获 fd
        int fd_copy = fd;
        pool.enqueue([fd_copy, buf]() {
            // 业务逻辑
            processBusinessLogic(buf);
            
            // 直接 send
            send(fd_copy, result, len, 0);
        });
    }
};
```

优点：简单  
缺点：工作线程和主线程可能同时访问 fd

**方案2：事件驱动（复杂但正确）**
```cpp
class ReadHandler {
    void handleEvent() {
        recv(fd, buf, sizeof(buf), 0);
        
        pool.enqueue([this, buf]() {
            // 业务逻辑
            result = processBusinessLogic(buf);
            
            // ⭐ 通知主线程发送结果
            reactor->postTask([this, result]() {
                send(fd, result, len, 0);
            });
        });
    }
};
```

优点：正确，线程安全  
缺点：复杂，需要任务队列机制

**今天采用方案1**（简单，易于理解）
