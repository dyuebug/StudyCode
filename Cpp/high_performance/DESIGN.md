# high_performance 设计说明

## 设计目标

从 select 过渡到 epoll，学习 LT/ET、非阻塞 I/O、EPOLLONESHOT 和线程池协作，为 Reactor 和 HTTP 服务器打基础。

## 组织决策

- 采用 `01` 基础、`02` ET、`03` 线程池的渐进顺序。
- 理论分析与服务器示例并存，但理论性能数字必须明确标注假设或实测来源。
- 该目录是高性能 I/O 学习材料，不直接宣称生产级服务器。

## 已知限制

- 缺少统一构建、自动化客户端测试和真实压测记录。
- 现有 QPS/倍数结论需要改为理论估算或补充基准数据。
- fd 生命周期、部分写、优雅关闭和错误路径仍需工程化审查。

## 验证计划

1. 建立 Linux/WSL CMake 构建和 CTest 入口。
2. 增加固定回显客户端和并发测试。
3. 记录硬件、内核、编译器、优化级别和压测结果。
4. 在建立基线后再比较 LT、ET 和线程池版本。

## 变更历史

- 变更内容：补充学习边界、验证计划和性能限制。

- 影响范围：epoll 示例、性能文档和后续 Reactor 学习。
- 验证方式：人工核对目录文件和 README。
- 未解决问题：尚未执行压测。
