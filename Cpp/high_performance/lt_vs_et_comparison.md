# LT vs ET 模式对比实验

> **实验日期**：2026-06-16（第71天）  
> **实验目的**：理解 LT（水平触发）和 ET（边缘触发）的本质区别

---

## 📊 理论对比

| 特性 | LT（水平触发） | ET（边缘触发） |
|------|---------------|---------------|
| **触发条件** | 只要就绪就通知 | 状态变化时通知一次 |
| **通知次数** | 多次（持续通知） | 一次（只通知一次） |
| **系统调用** | 多 | 少 |
| **性能** | 较低 | 更高 |
| **编程难度** | 简单 | 复杂 |
| **是否需要非阻塞** | 可选 | 必须 |
| **是否需要循环读** | 可选 | 必须 |
| **数据安全性** | 高（不容易丢） | 低（容易丢） |

---

## 🔬 实验1：概念理解

### LT 模式的行为（水龙头）

```
客户端发送 1000 字节
↓
第1次 epoll_wait 返回 ← 通知你
你读了 300 字节
↓
第2次 epoll_wait 返回 ← 又通知你（还有 700 字节）
你读了 300 字节
↓
第3次 epoll_wait 返回 ← 又通知你（还有 400 字节）
你读完剩余 400 字节
```

**结论**：只要有数据，就持续通知（像水龙头一直流水）

---

### ET 模式的行为（门铃）

```
客户端发送 1000 字节
↓
第1次 epoll_wait 返回 ← 通知你一次
你必须循环读取：
  - 读 300 字节
  - 读 300 字节
  - 读 300 字节
  - 读 100 字节
  - recv 返回 EAGAIN（数据读完）
↓
后续 epoll_wait 不会再返回（除非有新数据到达）
```

**结论**：只在状态变化时通知一次（像门铃，按一次响一次）

## 📈 性能分析

### 理论计算

**场景**：1000 个连接，每个连接 10KB 数据，缓冲区 1KB

**LT 模式**：
- 每个连接需要读取 10 次（10KB / 1KB）
- 每次读取后，epoll_wait 会再次返回
- 总 epoll_wait 调用：1000 × 10 = **10000 次**

**ET 模式**：
- 每个连接触发 1 次 epoll_wait
- 在一次触发中循环读取 10 次
- 总 epoll_wait 调用：1000 × 1 = **1000 次**

**性能提升**：**10 倍**（系统调用减少 90%）

---

### 实际性能对比

| 指标 | LT 模式 | ET 模式 | 提升 |
|------|---------|---------|------|
| epoll_wait 调用次数 | 多 | 少 | 10倍+ |
| 系统调用开销 | 高 | 低 | 20-30% |
| 吞吐量（QPS） | 较低 | 较高 | 20-30% |
| CPU 使用率 | 较高 | 较低 | - |

**注意**：在低并发场景（<100 连接），差异不明显

## 🎓 关键理解

### 为什么 ET 更快？

**本质**：减少 epoll_wait 的返回次数

```
LT：epoll_wait 返回 → 读一部分 → epoll_wait 又返回 → 读一部分 → ...
ET：epoll_wait 返回一次 → 循环读完所有数据
```

**系统调用是昂贵的**：
- 用户态 → 内核态切换
- 上下文保存和恢复
- 缓存失效

ET 模式通过减少系统调用次数来提升性能。

---

### 为什么 ET 必须非阻塞？

**问题场景**：如果 ET 使用阻塞 I/O

```cpp
// ET 模式 + 阻塞 I/O（错误示范）
while (true) {
    int n = recv(fd, buf, 1024, 0);  // 阻塞模式
    if (n > 0) {
        // 处理数据
    }
}
// 当读完所有数据后，recv 会阻塞等待
// → 整个事件循环卡住
// → 其他连接无法处理 ← 灾难！
```

**正确方式**：ET + 非阻塞 I/O

```cpp
// ET 模式 + 非阻塞 I/O（正确）
while (true) {
    int n = recv(fd, buf, 1024, 0);  // 非阻塞模式
    if (n > 0) {
        // 处理数据
    } else if (n < 0 && errno == EAGAIN) {
        break;  // 数据读完，正常退出
    }
}
```

---

### EAGAIN 的真正含义

**常见误解**：
- ❌ EAGAIN 是错误，应该关闭连接
- ❌ EAGAIN 表示连接有问题

**正确理解**：
- ✅ EAGAIN = "暂时没有数据可读"
- ✅ 在 ET 模式下，EAGAIN 是"数据读完了"的信号
- ✅ 这是正常的，不是错误

**代码处理**：
```cpp
if (errno == EAGAIN || errno == EWOULDBLOCK) {
    break;  // 数据读完，正常退出循环
}
```

## ⚠️ ET 模式的常见陷阱

### 陷阱1：忘记循环读取

```cpp
// ❌ 错误：只读一次
char buf[1024];
int n = recv(fd, buf, sizeof(buf), 0);
send(fd, buf, n, 0);
// 问题：如果数据 > 1024 字节，剩余部分丢失
```

```cpp
// ✅ 正确：循环读取
while (true) {
    char buf[1024];
    int n = recv(fd, buf, sizeof(buf), 0);
    if (n > 0) {
        send(fd, buf, n, 0);
    } else if (errno == EAGAIN) {
        break;
    }
}
```

---

### 陷阱2：使用阻塞 I/O

```cpp
// ❌ 错误：ET + 阻塞 I/O
// 最后一次 recv 会永久阻塞
```

```cpp
// ✅ 正确：ET + 非阻塞 I/O
setNonBlocking(fd);
```

---

### 陷阱3：把 EAGAIN 当错误

```cpp
// ❌ 错误：把 EAGAIN 当错误
if (n < 0) {
    close(fd);  // 错误地关闭连接
}
```

```cpp
// ✅ 正确：区分 EAGAIN 和真正的错误
if (n < 0) {
    if (errno == EAGAIN) {
        break;  // 正常
    } else {
        // 真正的错误
        close(fd);
    }
}
```
