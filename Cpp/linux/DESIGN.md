# linux 设计说明

## 设计目标

使用 Linux/POSIX API 学习进程、IPC、文件、线程、Socket 和 I/O 多路复用，并通过小型服务器形成综合实践。

## 组织决策

- 按进程/文件、IPC、多线程、网络和综合项目顺序编号。
- 明确标记 Linux/WSL-only，避免误用 Windows 原生编译器。
- 示例优先保持单文件可读性，工程化构建和自动行为测试后续集中补充。

## 已知限制

- 当前缺少统一构建入口和测试目录。
- 网络示例缺少自动化客户端、短读短写和优雅关闭测试。
- System V IPC、线程和文件描述符资源的清理验证不完整。
- Sanitizer 命令需要按平台和示例类型分别确认适用性。

## 验证计划

1. 建立 Linux/WSL CMake 工程并区分可移植与 POSIX-only 示例。
2. 增加 TCP/UDP、线程池和 IPC 的最小行为测试。
3. 记录发行版、内核、编译器和依赖版本。
