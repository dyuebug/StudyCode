## 📖 学到的知识点

### 1. Linux 系统编程知识体系
- **进程管理**：fork 创建子进程、exec 替换进程映像、wait 回收子进程
- **IPC 进程间通信**：管道（单向）、共享内存（最快）、消息队列（结构化）
- **多线程编程**：pthread_create 创建线程、mutex 互斥锁、condition 条件变量
- **网络编程**：TCP 五步/UDP 无连接/select 多路复用

### 2. 多线程服务器设计模式
- **accept + pthread_create**：主线程循环 accept，每个新连接创建独立线程
- **线程分离**：pthread_detach() 自动回收资源，无需 join
- **共享数据保护**：在线客户端列表用 vector 存储，mutex 保护增删操作
- **资源管理**：线程结束时 close(fd)、从列表移除、释放内存

### 3. 关键设计技巧
- **动态分配参数**：`new int(client_fd)` 避免栈变量被覆盖
- **SO_REUSEADDR**：允许服务器重启后立即绑定端口
- **互斥锁粒度**：只锁住访问共享数据的代码段，减少锁持有时间
- **错误处理**：recv 返回 0（对方关闭）、-1（出错）需区别处理

### 4. 编译调试技巧
- 基础编译：`g++ -o prog prog.cpp -pthread`
- 数据竞争检测：`g++ -g -fsanitize=thread -o prog prog.cpp -pthread`
- 内存泄漏检测：`g++ -g -fsanitize=address -o prog prog.cpp`

## ❓ 遇到的问题与解决

**问题1**：如何避免多线程访问 vector 时数据竞争？

**解决**：
- 定义全局互斥锁 `pthread_mutex_t clients_mutex`
- 所有访问 `online_clients` 的操作都用 lock/unlock 包围
- 封装 `add_client()` 和 `remove_client()` 函数统一管理

**问题2**：为什么要动态分配 `int* fd_ptr = new int(client_fd)`？

**解决**：
- 如果直接传 `&client_fd`，下次循环会覆盖该变量
- 线程函数读到的可能是错误的 fd
- 动态分配保证每个线程有独立的参数副本

**问题3**：服务器重启时 bind 报错 "Address already in use"？

**解决**：
- 设置 SO_REUSEADDR 选项：
  ```cpp
  int opt = 1;
  setsockopt(listen_fd, SOL_SOCKET, SO_REUSEADDR, &opt, sizeof(opt));
  ```
- 允许立即重用处于 TIME_WAIT 状态的端口
