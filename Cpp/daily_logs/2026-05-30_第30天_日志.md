## 💡 今日学习要点

### 1. RAII 原理

**核心思想**：
- 资源获取即初始化（Resource Acquisition Is Initialization）
- 利用对象的生命周期管理资源
- 构造函数获取资源，析构函数释放资源

**优势**：
```cpp
// 传统方式：容易忘记释放
void func() {
    int* data = new int[1000];
    // ... 处理数据
    delete[] data;  // 可能忘记或执行不到
}

// RAII 方式：自动管理
void func() {
    vector<int> data(1000);
    // ... 处理数据
    // 自动释放，异常安全
}
```

### 2. unique_ptr - 独占所有权

**核心特性**：
- 同一时刻只能有一个 unique_ptr 指向对象
- 不能复制，只能移动（std::move）
- 对象销毁时自动释放内存

**使用场景**：
```cpp
// 创建（推荐 make_unique）
auto ptr = make_unique<Resource>("资源", 1);

// 移动所有权
auto ptr2 = move(ptr);  // ptr 变为空

// 函数返回（自动移动）
unique_ptr<Resource> createResource() {
    return make_unique<Resource>("资源", 2);
}

// 容器中使用
vector<unique_ptr<Resource>> resources;
resources.push_back(make_unique<Resource>("资源", 3));
```

**关键操作**：
- `get()` - 获取原始指针（不转移所有权）
- `release()` - 释放所有权，返回原始指针
- `reset()` - 释放当前对象，可选指向新对象
- `swap()` - 交换两个 unique_ptr

### 3. shared_ptr - 共享所有权

**核心特性**：
- 多个 shared_ptr 可以指向同一个对象
- 使用引用计数管理对象生命周期
- 最后一个 shared_ptr 销毁时，对象才被释放

**引用计数机制**：
```cpp
auto ptr1 = make_shared<Node>(100);
cout << ptr1.use_count() << endl;  // 1

auto ptr2 = ptr1;  // 复制
cout << ptr1.use_count() << endl;  // 2

ptr2.reset();  // 释放引用
cout << ptr1.use_count() << endl;  // 1
```

**使用场景**：
```cpp
// 共享资源
auto node = make_shared<Node>(200);
SharedResource res1(node);
SharedResource res2(node);
SharedResource res3(node);
// 所有对象共享同一个 node

// 容器中使用
vector<shared_ptr<Node>> vec;
vec.push_back(node);  // 引用计数增加
vec.push_back(node);  // 再次增加
```

**关键操作**：
- `use_count()` - 获取引用计数
- `unique()` - 检查是否唯一（引用计数为1）
- `reset()` - 释放当前引用
- `get()` - 获取原始指针

### 4. weak_ptr - 打破循环引用

**循环引用问题**：
```cpp
class A {
public:
    shared_ptr<B> ptrB;
};

class B {
public:
    shared_ptr<A> ptrA;  // 循环引用！
};

auto a = make_shared<A>();
auto b = make_shared<B>();
a->ptrB = b;
b->ptrA = a;  // 引用计数都为2，永远不会销毁
```

**weak_ptr 解决方案**：
```cpp
class B {
public:
    weak_ptr<A> ptrA;  // 使用 weak_ptr
};

// 不增加引用计数，打破循环引用
```

**使用方法**：
```cpp
shared_ptr<int> sp = make_shared<int>(100);
weak_ptr<int> wp = sp;  // 不增加引用计数

// 使用前需要转换为 shared_ptr
if (auto sp2 = wp.lock()) {
    cout << *sp2 << endl;  // 成功访问
} else {
    cout << "对象已被销毁" << endl;
}

// 检查对象是否存在
if (wp.expired()) {
    cout << "对象已被销毁" << endl;
}
```

**实际应用**：
- 公司与员工关系（避免循环引用）
- 观察者模式（观察者可能被销毁）
- 缓存系统（缓存项可能被清理）

## 🎯 重要知识点

### 1. 智能指针选择原则

**选择 unique_ptr**：
- 独占所有权
- 明确的资源拥有者
- 需要高效的移动语义
- 例如：工厂函数返回值、容器元素

**选择 shared_ptr**：
- 共享所有权
- 多个对象需要访问同一资源
- 不确定谁最后释放资源
- 例如：共享配置、缓存、观察者模式

**选择 weak_ptr**：
- 打破 shared_ptr 的循环引用
- 需要观察对象但不拥有它
- 缓存系统（不阻止对象销毁）
- 例如：父子关系、观察者模式

### 2. 智能指针最佳实践

**推荐做法**：
```cpp
// ✅ 使用 make_unique 和 make_shared
auto ptr1 = make_unique<Resource>("资源1", 1);
auto ptr2 = make_shared<Resource>("资源2", 2);

// ✅ 优先使用智能指针，避免原始指针
vector<unique_ptr<Resource>> resources;

// ✅ 函数参数传递智能指针引用（不转移所有权）
void inspect(const unique_ptr<Resource>& res);

// ✅ 函数返回智能指针（自动移动）
unique_ptr<Resource> create();
```

**避免做法**：
```cpp
// ❌ 不要使用 new（除非必要）
unique_ptr<Resource> ptr(new Resource("资源", 1));

// ❌ 不要 delete 智能指针管理的对象
auto ptr = make_unique<int>(100);
delete ptr.get();  // 错误！会导致 double free

// ❌ 不要混用智能指针和原始指针
auto ptr = make_shared<int>(100);
int* raw = ptr.get();
delete raw;  // 错误！

// ❌ 注意循环引用
class A { shared_ptr<B> ptrB; };
class B { shared_ptr<A> ptrA; };  // 应该用 weak_ptr
```

### 3. 性能考虑

**unique_ptr**：
- 零开销（与原始指针相同）
- 编译期优化
- 推荐作为默认选择

**shared_ptr**：
- 引用计数有一定开销
- 线程安全的引用计数（原子操作）
- 需要额外的控制块内存
- 通常开销可以忽略

**weak_ptr**：
- 不增加引用计数
- 需要 lock() 转换为 shared_ptr
- 适合观察者模式

## ❓ 遇到的问题与解决

**问题1**：为什么循环引用会导致内存泄漏？

**解答**：
```cpp
// 循环引用示例
auto a = make_shared<A>();  // a 引用计数 = 1
auto b = make_shared<B>();  // b 引用计数 = 1

a->ptrB = b;  // b 引用计数 = 2
b->ptrA = a;  // a 引用计数 = 2

// 离开作用域时：
// a 的引用计数减1，变为1（b->ptrA 还持有）
// b 的引用计数减1，变为1（a->ptrB 还持有）
// 两者都不为0，都不会被销毁
// 导致内存泄漏
```

**解决方案**：使用 weak_ptr 打破循环
```cpp
class B {
    weak_ptr<A> ptrA;  // 不增加引用计数
};
```

**问题2**：什么时候使用 unique_ptr，什么时候使用 shared_ptr？

**解答**：
- **默认使用 unique_ptr**：大多数情况下，资源有明确的拥有者
- **需要共享时使用 shared_ptr**：多个对象需要访问同一资源
- **原则**：能用 unique_ptr 就不用 shared_ptr（性能更好）

**问题3**：weak_ptr 的 lock() 为什么返回 shared_ptr？

**解答**：
- weak_ptr 不拥有对象，不能直接访问
- lock() 尝试创建一个临时的 shared_ptr
- 如果对象还存在，返回有效的 shared_ptr
- 如果对象已销毁，返回空的 shared_ptr
- 这样保证了访问的安全性
