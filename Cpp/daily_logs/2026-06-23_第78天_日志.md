## 📖 学到的知识点

### 1. 协程核心概念

**定义**：
```
协程（Coroutine）= 可暂停和恢复的函数
```

**核心特性**：
- **暂停（Suspend）**：co_await、co_yield
- **恢复（Resume）**：继续执行
- **状态保存**：局部变量、执行位置

**与普通函数的区别**：

| 维度 | 普通函数 | 协程 |
|------|---------|------|
| 执行次数 | 一次性 | 多次 |
| 暂停 | 不可以 | 可以 |
| 恢复 | 不可以 | 可以 |
| 状态保存 | 无 | 有 |

**示例**：
```cpp
// 普通函数
int add(int a, int b) {
    return a + b;  // 执行完就返回
}

// 协程
Generator<int> count() {
    int i = 0;
    while (true) {
        co_yield i++;  // 暂停并返回，保存状态
    }
}
```

### 2. 协程 vs 线程

**详细对比表**：

| 维度 | 线程（Thread） | 协程（Coroutine） |
|------|---------------|------------------|
| **调度方式** | 抢占式（内核） | 协作式（用户） |
| **调度器** | 操作系统内核 | 用户程序 |
| **创建开销** | 大（~1MB 栈） | 小（几百字节） |
| **切换开销** | 慢（1-10μs） | 快（10-100ns） |
| **并发数量** | 受限（~1000） | 很大（~100万） |
| **内存占用** | 大（每个 1MB） | 小（几百字节） |
| **同步机制** | 锁（复杂） | 无需（单线程） |
| **适用场景** | CPU 密集 | I/O 密集 |

**性能对比**：
```
线程：
- 创建：1ms
- 切换：1-10μs
- 内存：1MB
- 并发极限：~1000

协程：
- 创建：0.1μs（快 10000 倍）
- 切换：10-100ns（快 100 倍）
- 内存：0.5KB（小 2000 倍）
- 并发极限：~100万（大 1000 倍）
```

**资源占用对比**：
```
场景：10000 个并发连接

线程方式：
- 10000 个线程
- 内存：10000 × 1MB = 10GB
- 极限：受内存和调度限制

协程方式：
- 10000 个协程
- 内存：10000 × 0.5KB = 5MB
- 极限：可支持 100 万个
```

### 3. 协程 vs 回调

**回调方式（回调地狱）**：
```cpp
void handleClient(int fd) {
    asyncRead(fd, [fd](char* data1) {
        auto result1 = process(data1);
        asyncWrite(fd, result1, [fd](int n1) {
            asyncRead(fd, [fd](char* data2) {
                auto result2 = process(data2);
                asyncWrite(fd, result2, [](int n2) {
                    // 嵌套4层
                });
            });
        });
    });
}
```

**问题**：
- 嵌套深（回调地狱）
- 逻辑分散
- 错误处理困难
- 难以理解和维护

**协程方式（线性逻辑）**：
```cpp
Task<void> handleClient(int fd) {
    auto data1 = co_await asyncRead(fd);
    auto result1 = process(data1);
    co_await asyncWrite(fd, result1);
    
    auto data2 = co_await asyncRead(fd);
    auto result2 = process(data2);
    co_await asyncWrite(fd, result2);
    // 线性逻辑，清晰易懂
}
```

**优势**：
- 代码线性（从上到下）
- 逻辑集中（在同一函数）
- 易于理解（同步写法）
- 错误处理简单（try-catch）

### 4. 协程的优势

**1. 高并发**：
```
线程：10000 个连接 = 10000 个线程 = 10GB 内存
协程：10000 个连接 = 10000 个协程 = 5MB 内存
提升：2000 倍

极限：
线程：~1000 个（受内存和调度限制）
协程：~100 万个（只受内存限制）
提升：1000 倍
```

**2. 低延迟**：
```
线程切换：
- 保存寄存器、栈
- 切换页表
- 内核调度
- 耗时：1-10 微秒

协程切换：
- 保存少量状态
- 用户态调度
- 无内核参与
- 耗时：10-100 纳秒

提升：100 倍
```

**3. 简化异步编程**：
```
同步写法，异步执行：
auto result1 = co_await asyncOp1();
auto result2 = co_await asyncOp2(result1);
auto result3 = co_await asyncOp3(result2);

避免回调地狱：
asyncOp1([](r1) {
    asyncOp2(r1, [](r2) {
        asyncOp3(r2, [](r3) {
            // 嵌套3层
        });
    });
});
```

**4. 无锁编程**：
```
线程：需要锁（复杂）
std::mutex mtx;
{
    std::lock_guard<std::mutex> lock(mtx);
    shared_data++;
}

协程：无需锁（简单）
shared_data++;  // 单线程内执行，无竞态
co_await something();
shared_data++;  // 无需锁
```

### 5. C++20 Coroutines 基础

**三个关键字**：

**co_await - 等待异步操作**：
```cpp
// 作用：暂停协程，等待异步操作完成
result = co_await awaitable_object;

// 示例
Task<string> fetchUrl(string url) {
    auto data = co_await httpGet(url);  // 暂停，等待 HTTP 请求
    co_return data;  // 请求完成后恢复
}
```

**co_yield - 生成值并暂停**：
```cpp
// 作用：暂停协程，返回一个值给调用者
co_yield value;

// 示例
Generator<int> fibonacci() {
    int a = 0, b = 1;
    while (true) {
        co_yield a;  // 返回 a，然后暂停
        int next = a + b;
        a = b;
        b = next;
    }
}

// 使用
auto gen = fibonacci();
cout << gen.next();  // 0
cout << gen.next();  // 1
cout << gen.next();  // 1
cout << gen.next();  // 2
```

**co_return - 协程返回**：
```cpp
// 作用：协程返回结果，协程结束
co_return value;

// 示例
Task<int> calculate() {
    int result = 0;
    for (int i = 0; i < 10; i++) {
        result += i;
        co_await yield();
    }
    co_return result;  // 返回 45
}
```

**协程的生命周期**：
```
1. 创建（Create）
   ↓ 调用协程函数
2. 执行（Execute）
   ↓ 开始执行协程体
3. 暂停（Suspend）
   ↓ 遇到 co_await 或 co_yield
   ↓ 保存状态
4. 恢复（Resume）
   ↓ 从暂停处继续
   ↓ （可能多次暂停和恢复）
5. 完成（Complete）
   ↓ co_return 或执行到末尾
6. 销毁（Destroy）
   ↓ 释放协程帧
```

### 6. 协程应用场景

**场景1：异步 I/O**

**问题**：
- I/O 操作慢（等待时间长）
- 阻塞会降低性能
- 多线程开销大

**协程解决**：
```cpp
Task<void> handleClient(int fd) {
    while (true) {
        auto data = co_await asyncRead(fd);  // 暂停，不阻塞
        auto result = process(data);
        co_await asyncWrite(fd, result);     // 暂停，不阻塞
    }
}

// 10000 个客户端
for (int fd : clients) {
    handleClient(fd);  // 创建 10000 个协程，只需 5MB
}
```

**好处**：
- 等待 I/O 时暂停，让出 CPU
- 其他协程继续执行
- 充分利用 CPU
- 高并发（10000 个协程，5MB 内存）

---

**场景2：生成器（Generator）**

**问题**：
- 生成大量数据占用内存
- 需要惰性求值

**协程解决**：
```cpp
Generator<int> range(int start, int end) {
    for (int i = start; i < end; i++) {
        co_yield i;  // 按需生成
    }
}

// 使用
for (int i : range(0, 1000000)) {
    cout << i << endl;
    if (i > 10) break;
    // 只生成了 11 个数，不是 100 万
}
```

**好处**：
- 惰性求值（按需生成）
- 节省内存（不预先生成）
- 无限序列（可以生成无限个数）

---

**场景3：协程 + Reactor**

**传统 Reactor**（回调）：
```cpp
class ReadHandler {
    void handleEvent() {
        recv(fd, buf, ...);
        pool->enqueue([buf, fd]() {
            auto result = process(buf);
            send(fd, result, ...);
        });
    }
};
```

**协程 + Reactor**（同步写法）：
```cpp
Task<void> handleClient(int fd, Reactor* reactor) {
    while (true) {
        auto data = co_await reactor->asyncRead(fd);  // 同步写法
        auto result = process(data);
        co_await reactor->asyncWrite(fd, result);
    }
}
```

**好处**：
- 代码更清晰（线性逻辑）
- 逻辑更集中（在同一函数）
- 易于理解和维护
- 避免回调地狱

## ❓ 遇到的问题与解决

**问题1**：协程和线程的本质区别是什么？

**解决**：
- **调度方式**：
  - 线程：抢占式（内核强制切换）
  - 协程：协作式（主动让出 CPU）
- **调度器**：
  - 线程：操作系统内核
  - 协程：用户程序
- **开销**：
  - 线程：大（内核态切换）
  - 协程：小（用户态切换）

**问题2**：协程如何避免回调地狱？

**解决**：
- 回调：异步操作完成时调用回调函数（嵌套）
- 协程：用 co_await 等待异步操作（线性）
- 本质：协程把异步代码写成同步形式

**问题3**：协程适用于什么场景？

**解决**：
- ✅ I/O 密集型（网络、文件）
- ✅ 高并发（>10000 连接）
- ✅ 需要清晰代码
- ❌ CPU 密集型（用线程池）

### 2. 协程的"魔法"本质

**初看协程**：
```cpp
auto data = co_await asyncRead(fd);  // 看起来是同步的
```

**感觉像魔法**：
- 明明是异步操作
- 为什么可以写成同步形式？
- 如何做到暂停和恢复？

**理解本质**：
- co_await 暂停协程
- 保存当前状态（局部变量、执行位置）
- 返回给调用者（不阻塞）
- 异步操作完成后恢复协程
- 从暂停处继续执行

**这不是魔法**：
- 是编译器的支持
- 是语言级的特性
- 是状态机的语法糖

**状态机视角**：
```cpp
// 协程代码
Task<void> func() {
    auto data1 = co_await op1();  // 状态1 → 状态2
    auto data2 = co_await op2();  // 状态2 → 状态3
}

// 等价状态机
class FuncStateMachine {
    int state = 0;
    Data data1, data2;
    
    void resume() {
        switch (state) {
            case 0:
                op1();
                state = 1;
                return;  // 暂停
            case 1:
                data1 = get_op1_result();
                op2();
                state = 2;
                return;  // 暂停
            case 2:
                data2 = get_op2_result();
                state = 3;
                return;  // 完成
        }
    }
};
```

**协程 = 状态机的语法糖**：
- 编译器自动生成状态机
- 程序员写同步代码
- 既简单又高效
