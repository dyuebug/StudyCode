## 第1周：epoll

**学习天数**：第70-73天（4天）
**学习时长**：10小时
**学习主题**：epoll与I/O多路复用

### 学习内容

#### 第70天：epoll基础与原理

**核心内容**：
- select的三大缺陷（O(n)轮询、1024限制、重复设置）
- epoll的三大改进（事件通知、无限制、状态维护）
- epoll内部原理（红黑树 + 就绪列表）
- epoll三大API（create/ctl/wait）
- epoll回显服务器实战

**关键收获**：
```
epoll = 红黑树（管理fd）+ 就绪列表（高效通知）
性能提升：O(n) → O(1)
```

---

#### 第71天：边缘触发与水平触发

**核心内容**：
- LT持续通知 vs ET通知一次
- ET性能提升10倍原理（减少系统调用）
- ET两大要求（非阻塞I/O + 循环读取）
- EAGAIN不是错误，是信号
- ET模式epoll服务器实战

**关键收获**：
```
LT（水平触发）：数据未读完会持续通知（安全）
ET（边缘触发）：数据来时只通知一次（高效）
ET要求：fcntl设置O_NONBLOCK + 循环读取直到EAGAIN
```

---

#### 第72天：epoll实战与陷阱

**核心内容**：
- 单线程epoll瓶颈（业务逻辑慢阻塞主线程）
- epoll + 线程池架构（职责分离，性能提升4倍）
- 竞态问题（同一fd被多线程同时处理）
- EPOLLONESHOT解决方案（触发后自动下线）
- 10+常见陷阱和最佳实践

**关键收获**：
```
单线程epoll + 线程池 = 高性能
EPOLLONESHOT = 一次性事件（防止竞态）
```

---

#### 第73天：epoll第1周总结

**核心内容**：
- 知识体系梳理（基础 → 进阶 → 高级）
- 核心概念对比（select vs epoll、LT vs ET）
- epoll速查表（API参考、代码模板、陷阱清单）

## 第2周：Reactor

**学习天数**：第74-77天（4天）
**学习时长**：10小时
**学习主题**：Reactor事件驱动架构

### 学习内容

#### 第74天：Reactor单线程模型

**核心内容**：
- Reactor模式核心概念（事件分离与分发）
- 三大组件（Reactor/Demultiplexer/Handler）
- 工作流程（注册 → 循环 → 分离 → 分发 → 处理）
- Reactor单线程服务器实战
- Reactor vs 原始epoll对比

**关键收获**：
```
Reactor = epoll + 设计模式
职责分离：I/O检测 vs 事件处理
符合开闭原则：易扩展
```

---

#### 第75天：Reactor多线程模型

**核心内容**：
- 单线程瓶颈（业务逻辑慢阻塞Reactor）
- Reactor + 线程池架构（职责再分离）
- 性能提升（4线程QPS提升4倍）
- 与epoll + 线程池区别（细粒度 vs 粗粒度）

**关键收获**：
```
Reactor + 线程池 = I/O线程 + 业务线程
主线程recv，工作线程处理
最优线程数 = CPU核数 × 2（I/O密集型）
```

---

#### 第76天：主从Reactor模式

**核心内容**：
- 单Reactor + 线程池瓶颈（主线程I/O瓶颈）
- 主从Reactor架构（主accept，从recv）
- 性能提升（4从Reactor + 4线程池，QPS提升40倍）
- 连接分配策略（轮询/最少连接/哈希）
- Nginx架构（多进程 + 主从Reactor）

**关键收获**：
```
主从Reactor = 1个主Reactor（accept）+ N个从Reactor（I/O）+ M个线程（业务）
架构演进：单线程 → 线程池 → 主从
```

---
