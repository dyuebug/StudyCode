## 📖 学到的知识点

### 1. 优先级调度（Priority Scheduling）

**核心概念**：
- 每个任务有优先级值（数字越大优先级越高）
- 高优先级任务优先执行
- 使用 `std::priority_queue` 实现

**核心实现**：
```cpp
// 优先级队列
std::priority_queue<Task, std::vector<Task>, TaskComparator> task_queue;

// 自定义比较器
struct TaskComparator {
    bool operator()(const Task& a, const Task& b) const {
        return a.priority() < b.priority();  // 高优先级在堆顶
    }
};
```

**特点**：
- ✅ 重要任务快速响应
- ✅ 符合业务需求
- ❌ 可能导致低优先级任务"饥饿"

**适用场景**：
- Web服务器：用户请求（高优先级）vs 日志清理（低优先级）
- 游戏引擎：渲染（高优先级）vs 资源加载（低优先级）

---

### 2. 轮询调度（Round-Robin）

**核心概念**：
- 每个任务轮流执行一次
- 从队列头取出，执行后放到队列尾
- 完全公平，无优先级

**核心实现**：
```cpp
// 使用 deque 支持头尾操作
std::deque<Task> task_queue;

// 从头取出
Task task = task_queue.front();
task_queue.pop_front();

// 执行一次
task.handle.resume();

// 放到尾部
if (!task.handle.done()) {
    task_queue.push_back(task);
}
```

**特点**：
- ✅ 完全公平
- ✅ 无饥饿问题
- ✅ 响应时间可预测
- ❌ 无法区分优先级

**适用场景**：
- 多用户系统：每个用户平等对待
- 所有任务同等重要的场景

---

### 3. 时间片调度（Time Slicing）

**核心概念**：
- 每个任务分配固定的执行时间（时间片）
- 时间片用完后强制切换到下一个任务
- 平衡响应性和开销

**核心实现**：
```cpp
// 每个任务连续执行 time_slice 次
for (int i = 0; i < time_slice && !handle.done(); ++i) {
    handle.resume();
}
```

**时间片大小的影响**：
- 时间片=2：上下文切换6次，响应快，切换开销大
- 时间片=5：上下文切换3次，响应慢，效率高

**特点**：
- ✅ 平衡响应性和效率
- ✅ 短任务快速完成
- ⚠️ 需要调优时间片大小

**适用场景**：
- 交互式系统
- 混合长短任务的场景

---

### 4. 工作窃取（Work Stealing）

**核心概念**：
- 每个线程维护自己的任务队列
- 线程优先执行自己队列的任务
- 队列为空时，从其他线程"偷"任务

**特点**：
- ✅ 减少锁竞争（大部分时间无锁）
- ✅ 自动负载均衡
- ✅ 缓存友好

**工业界应用**：
- Go的goroutine调度器：M-P-G模型
- Java的ForkJoinPool
- Tokio异步运行时

---

### 5. 多队列调度

**核心概念**：
- 每个线程一个队列
- 新任务根据策略分配到队列
- 线程只处理自己队列的任务

**分配策略**：
1. 轮询分配（Round-Robin）
2. 最少任务分配（Least Load）
3. 哈希分配（Hash）
4. 随机分配（Random）

---

### 6. 亲和性调度（Affinity Scheduling）

**核心概念**：
- 任务绑定到特定线程或CPU
- 相关任务在同一线程执行
- 利用CPU缓存提高性能

**类型**：
1. 线程亲和性：任务绑定到特定线程
2. CPU亲和性：线程绑定到特定CPU核心
3. NUMA亲和性：任务绑定到特定NUMA节点

## ❓ 遇到的问题与解决

### 问题1：优先级比较器的逻辑容易搞反

**问题**：
```cpp
// 错误：这样会导致低优先级先执行
return a.priority() > b.priority();
```

**原因**：
- `priority_queue` 的比较器定义"谁的优先级更低"
- 返回 true 表示第一个参数优先级更低（应该排后面）

**正确做法**：
```cpp
// 正确：高优先级先执行
return a.priority() < b.priority();
```

**记忆技巧**：
- 比较器返回 true = 第一个参数优先级更低
- a < b 返回 true → a优先级更低 → b优先级更高 → b在堆顶

---

### 问题2：时间片设置不当

**问题**：
- 时间片太小（1）：切换频繁，开销大
- 时间片太大（100）：响应慢，退化为FIFO

**解决**：
- 根据任务特点选择合适的时间片
- 经验值：2-10
- 交互式系统：2-5
- 批处理系统：5-10

---

### 问题3：队列选择错误

**问题**：
```cpp
// 错误：queue 不支持从头部添加
std::queue<Task> task_queue;
```

**解决**：
```cpp
// 正确：deque 支持头尾操作
std::deque<Task> task_queue;
```

**对比**：
- `std::queue`：只能从尾部添加，从头部删除
- `std::deque`：头尾都支持添加和删除
- 轮询调度需要"头取尾放"，必须用 deque
