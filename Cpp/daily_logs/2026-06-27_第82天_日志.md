## 📖 学到的知识点

### 1. 为什么需要调度器

**手动管理协程的问题**：

**方案1：逐个手动调用（串行）**
```cpp
task1.resume();
while (!task1.done()) { task1.resume(); }
task2.resume();
while (!task2.done()) { task2.resume(); }
```
- ❌ 串行执行，无法并发
- ❌ 代码重复
- ❌ 不灵活

**方案2：手动轮询（并发）**
```cpp
while (true) {
    bool all_done = true;
    for (auto& task : tasks) {
        if (!task.done()) {
            task.resume();
            all_done = false;
        }
    }
    if (all_done) break;
}
```
- ❌ 代码复杂
- ❌ 容易出错
- ❌ 难以扩展
- ❌ 性能不佳（空轮询）

**调度器解决方案**：
```cpp
Scheduler scheduler;
scheduler.schedule(task1);
scheduler.schedule(task2);
scheduler.schedule(task3);
scheduler.run();  // 自动管理
```
- ✅ 代码简洁
- ✅ 自动管理
- ✅ 易于扩展
- ✅ 性能优化

**调度器的价值对比**：

| 维度 | 手动管理 | 调度器管理 |
|------|---------|-----------|
| 代码量 | 多 | 少 |
| 复杂度 | 高 | 低 |
| 并发性 | 难实现 | 内置支持 |
| 优先级 | 难实现 | 易于添加 |
| 超时控制 | 难实现 | 易于添加 |
| 可维护性 | 差 | 好 |

### 2. 调度器的核心作用

**作用1：协程生命周期管理**

```
schedule() → 创建
  ↓
run() → 开始执行
  ↓
co_await → 暂停（自动）
  ↓
resume() → 恢复（调度器决定）
  ↓
co_return → 完成
  ↓
destroy() → 销毁
```

**作用2：任务调度**

调度决策包括：
- 选择哪个协程执行（selectNextTask）
- 何时切换协程（shouldSwitch）
- 如何分配资源（allocateResources）

调度策略：
- **FIFO**：先进先出（最简单）
- **优先级**：高优先级优先（常用）
- **公平调度**：每个协程平等机会（公平）
- **抢占式**：时间片轮转（类似线程）

**作用3：状态追踪**

```cpp
enum class TaskState {
    READY,      // 就绪（在队列中）
    RUNNING,    // 运行中
    SUSPENDED,  // 暂停（等待事件）
    COMPLETED   // 已完成
};
```

状态转换：
```
READY → RUNNING → SUSPENDED → READY → COMPLETED
```

### 4. 调度器与协程的交互

**完整交互流程**：

```
1. 用户代码：scheduler.schedule(coro)
2. Scheduler：接收协程，添加到任务队列
3. Event Loop：scheduler.run()，事件循环开始
4. Scheduler：从队列取出协程
5. Coroutine：handle.resume()，开始执行
6. Coroutine：co_await，暂停
7. Scheduler：保存状态，切换到下一个协程
8. Scheduler：事件就绪，恢复协程
9. Coroutine：handle.resume()，继续执行
10. Coroutine：co_return，完成
11. Scheduler：handle.destroy()，销毁协程
```

**关键点**：

**协程的暂停和恢复**：
- 暂停：co_await → 状态保存 → 控制权返回调度器
- 恢复：handle.resume() → 从暂停点继续 → 局部变量保持

**调度器的职责**：
- 管理所有协程
- 决定执行顺序
- 在合适的时机切换
- 销毁完成的协程

### 5. 任务队列设计

**FIFO队列实现（最简单）**：

```cpp
class FIFOQueue {
private:
    std::queue<std::coroutine_handle<>> tasks;
    
public:
    void enqueue(std::coroutine_handle<> handle) {
        if (handle) tasks.push(handle);
    }
    
    std::coroutine_handle<> dequeue() {
        if (tasks.empty()) return nullptr;
        auto handle = tasks.front();
        tasks.pop();
        return handle;
    }
    
    bool empty() const { return tasks.empty(); }
    size_t size() const { return tasks.size(); }
};
```

**特点**：
- ✅ 简单易懂
- ✅ 公平（先进先出）
- ✅ 性能好（O(1)）
- ❌ 没有优先级

---

**线程安全的队列**：

```cpp
class ThreadSafeQueue {
private:
    std::queue<std::coroutine_handle<>> tasks;
    mutable std::mutex mtx;
    
public:
    void enqueue(std::coroutine_handle<> handle) {
        std::lock_guard<std::mutex> lock(mtx);
        if (handle) tasks.push(handle);
    }
    
    std::coroutine_handle<> dequeue() {
        std::lock_guard<std::mutex> lock(mtx);
        if (tasks.empty()) return nullptr;
        auto handle = tasks.front();
        tasks.pop();
        return handle;
    }
    
    bool empty() const {
        std::lock_guard<std::mutex> lock(mtx);
        return tasks.empty();
    }
};
```

**特点**：
- ✅ 线程安全
- ✅ 支持多线程调度
- ❌ 有锁开销

---

**队列选择指南**：

| 场景 | 推荐队列 | 理由 |
|------|---------|------|
| 单线程调度 | FIFO队列 | 简单高效 |
| 多线程调度 | 线程安全队列 | 避免竞态 |
| 需要优先级 | 优先级队列 | 支持调度策略 |
| 高性能要求 | 无锁队列 | 减少锁开销 |

### 6. 简单调度器实现

**Scheduler类设计**：

```cpp
class Scheduler {
private:
    std::queue<std::coroutine_handle<>> task_queue;
    bool running = false;
    
public:
    void schedule(std::coroutine_handle<> handle);  // 调度协程
    void run();                                      // 运行调度器
    void stop();                                     // 停止调度器
    size_t size() const;                            // 队列大小
};
```

---

**完整实现**：

```cpp
class Scheduler {
private:
    std::queue<std::coroutine_handle<>> task_queue;
    bool running = false;
    
public:
    // 调度协程（添加到队列）
    void schedule(std::coroutine_handle<> handle) {
        if (handle) {
            task_queue.push(handle);
        }
    }
    
    // 运行调度器（事件循环）
    void run() {
        running = true;
        
        while (running && !task_queue.empty()) {
            // 1. 从队列取出协程
            auto handle = task_queue.front();
            task_queue.pop();
            
            // 2. 检查协程是否完成
            if (handle.done()) {
                handle.destroy();
                continue;
            }
            
            // 3. 恢复协程
            handle.resume();
            
            // 4. 检查状态
            if (!handle.done()) {
                // 未完成：重新入队
                task_queue.push(handle);
            } else {
                // 已完成：销毁
                handle.destroy();
            }
        }
        
        running = false;
    }
    
    // 停止调度器
    void stop() {
        running = false;
    }
    
    // 获取队列大小
    size_t size() const {
        return task_queue.size();
    }
};
```

---

**核心逻辑**：

**schedule方法**：
- 接收协程handle
- 添加到任务队列
- 简单直接

**run方法（事件循环）**：
- while循环：事件循环
- dequeue：取出协程
- resume：恢复协程
- 根据状态：重新入队 or 销毁

### 7. 使用示例

**示例：管理多个协程**

```cpp
// 协程函数
Task<int> calculate(int n) {
    std::cout << "Task " << n << " start" << std::endl;
    co_await std::suspend_always{};
    
    std::cout << "Task " << n << " continue" << std::endl;
    co_await std::suspend_always{};
    
    std::cout << "Task " << n << " result: " << n * 2 << std::endl;
    co_return n * 2;
}

// 使用调度器
int main() {
    Scheduler scheduler;
    
    // 调度多个协程
    scheduler.schedule(calculate(1));
    scheduler.schedule(calculate(2));
    scheduler.schedule(calculate(3));
    
    // 运行调度器
    scheduler.run();
    
    return 0;
}
```

**输出特点**：
- 三个协程交替执行（并发）
- 每个协程在暂停点让出控制权
- 调度器自动管理所有协程
- 完成的协程自动销毁

## ❓ 遇到的问题与解决

**问题1**：为什么协程未完成要重新入队？

**解决**：
- 协程有多个暂停点
- 第1次resume：执行到暂停点1，暂停
- 第2次resume：从暂停点1继续，执行到暂停点2
- 第3次resume：完成
- **重新入队**：确保协程能被再次调度

---

**问题2**：如何避免协程无限循环？

**问题代码**：
```cpp
Task<void> infiniteLoop() {
    while (true) {
        doWork();
        // 没有暂停点！
    }
}
```

**解决方案**：
```cpp
Task<void> goodLoop() {
    while (true) {
        doWork();
        co_await std::suspend_always{};  // 定期让出控制权
    }
}
```

**建议**：
- 循环中必须有暂停点
- 定期让出控制权
- 避免长时间占用CPU

---

**问题3**：调度器和Reactor有什么区别？

**解决**：

**Reactor**：
- 事件驱动（I/O事件）
- 调度Handler（事件处理器）
- 基于epoll等I/O多路复用

**调度器**：
- 协程驱动（协程暂停/恢复）
- 调度协程（coroutine）
- 基于协程的暂停点

**关系**：
- Reactor可以与调度器结合
- 调度器管理协程
- Reactor管理I/O事件
