## 🎯 核心知识点总结

### 1. 进程管理（Process Management）
```
fork() → 创建子进程（Copy-On-Write）
exec() → 替换进程映像
wait() → 回收子进程，防止僵尸进程
```

**关键概念**：
- 进程 ID（PID）和父进程 ID（PPID）
- 进程状态：运行、就绪、阻塞、僵尸
- 孤儿进程和僵尸进程

---

### 2. IPC 进程间通信（Inter-Process Communication）

| 方式 | 速度 | 使用场景 | 优点 | 缺点 |
|------|------|---------|------|------|
| 管道 | 中 | 父子进程简单通信 | 简单易用 | 单向、容量有限 |
| 共享内存 | 快 | 大量数据传输 | 速度最快 | 需要同步机制 |
| 消息队列 | 慢 | 结构化消息 | 异步、解耦 | 性能较低 |

---

### 3. 多线程编程（Multi-threading）

**创建线程**：
```cpp
pthread_t tid;
pthread_create(&tid, NULL, thread_func, arg);
pthread_join(tid, NULL);  // 等待线程结束
// 或
pthread_detach(tid);      // 线程自动回收
```

**互斥锁（Mutex）**：
```cpp
pthread_mutex_t lock = PTHREAD_MUTEX_INITIALIZER;
pthread_mutex_lock(&lock);
// 临界区代码
pthread_mutex_unlock(&lock);
```

**条件变量（Condition Variable）**：
```cpp
pthread_cond_t cond = PTHREAD_COND_INITIALIZER;
pthread_cond_wait(&cond, &mutex);    // 等待
pthread_cond_signal(&cond);          // 唤醒一个
pthread_cond_broadcast(&cond);       // 唤醒全部
```

**线程池模式**：
- 任务队列 + 工作线程组
- 避免频繁创建/销毁线程
- 控制并发数量

---

### 4. 网络编程（Network Programming）

**TCP 服务端流程**：
```
socket() → bind() → listen() → accept() → recv/send() → close()
```

**TCP 客户端流程**：
```
socket() → connect() → send/recv() → close()
```

**UDP 通信**：
```
socket() → bind() → recvfrom/sendto() → close()
```

**select 多路复用**：
```cpp
fd_set readfds;
FD_ZERO(&readfds);
FD_SET(sockfd, &readfds);
select(maxfd + 1, &readfds, NULL, NULL, &timeout);
if (FD_ISSET(sockfd, &readfds)) {
    // 有数据可读
}
```

**字节序转换**：
- 主机字节序 → 网络字节序：`htons()`、`htonl()`
- 网络字节序 → 主机字节序：`ntohs()`、`ntohl()`

## 💡 重要设计模式和技巧

### 1. 生产者-消费者模式
**核心思想**：任务队列 + 条件变量同步

**应用场景**：
- 线程池
- 消息队列
- 异步任务处理

**关键点**：
- 队列为空时消费者等待
- 队列满时生产者等待
- 用 while 检查条件（防虚假唤醒）

---

### 2. 多线程服务器模式

**模式1：每连接一线程**（本阶段实现）
```
主线程 accept → 创建线程处理 → 线程结束自动回收
```
- 优点：简单、易理解
- 缺点：大量连接时线程开销大

**模式2：线程池（更优）**
```
主线程 accept → 任务加入队列 → 工作线程取出处理
```
- 优点：线程数可控、复用线程
- 缺点：需要任务队列和同步机制

**模式3：I/O 多路复用（高性能）**
```
select/epoll 监听 → 事件触发 → 处理数据
```
- 优点：单线程处理海量连接
- 缺点：编程复杂度高

---

### 3. RAII 资源管理
**原则**：资源获取即初始化（Resource Acquisition Is Initialization）

**应用**：
- 文件描述符自动关闭
- 互斥锁自动解锁
- 内存自动释放

**示例**：
```cpp
class LockGuard {
    pthread_mutex_t* mutex;
public:
    LockGuard(pthread_mutex_t* m) : mutex(m) {
        pthread_mutex_lock(mutex);
    }
    ~LockGuard() {
        pthread_mutex_unlock(mutex);
    }
};
```

## 🔧 编译与调试技巧


### 数据竞争检测（ThreadSanitizer）
```bash
g++ -g -fsanitize=thread -o prog prog.cpp -pthread
./prog  # 运行时会报告数据竞争
```

### 内存泄漏检测（AddressSanitizer）
```bash
g++ -g -fsanitize=address -o prog prog.cpp

```

## 🎯 最困难的部分

### 1. 多线程数据竞争
**难点**：
- counter++ 看起来是一条语句，实际是三步（读-改-写）
- 不加锁会导致结果随机偏小
- 难以复现和调试

**解决**：
- 所有共享数据访问都要加锁
- 使用 ThreadSanitizer 检测
- 封装访问函数，统一加锁

---

### 2. 条件变量的正确使用
**难点**：
- 为什么 cond_wait 必须配合 mutex？
- 为什么用 while 而不是 if？
- 什么是虚假唤醒？

**解决**：
- 理解"检查条件"与"进入等待"之间的竞态窗口
- 理解 cond_wait 的三步原子操作
- 醒来后重新检查条件

---

### 3. 网络编程的错误处理
**难点**：
- recv 返回 0 和 -1 的区别
- EINTR（被信号中断）
- EAGAIN/EWOULDBLOCK（非阻塞 I/O）

**解决**：
- recv 返回 0：对方关闭连接，正常
- recv 返回 -1：检查 errno，可能需要重试
- 完善的错误处理逻辑
