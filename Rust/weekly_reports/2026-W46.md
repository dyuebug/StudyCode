## 二、本周核心认知（截至目前）

### 【实测】1. proc-macro crate 只能导出宏——这是硬错误，不是约定

把 trait 写进 `proc-macro = true` 的 crate，编译直接失败：

```
error: `proc-macro` crate types currently cannot export any items other than
       functions tagged with `#[proc_macro]`, `#[proc_macro_derive]`,
       or `#[proc_macro_attribute]`
 --> src\lib.rs:1:1
  |
1 | pub trait Validate { fn validate(&self) -> bool; }
  | ^^^^^^^^^^^^^^^^^^
```

以前我认为 workspace 是"多包管理方便"，属于便利性选择。
这条错误说明它有时是**硬约束**：派生宏要生成 `impl Trait for X`，
就得有人定义那个 `Trait`，而定义者不能是宏 crate。

### 【实测】2. 过程宏的报错质量由 span 决定

同一个"未知属性键"，`Error::new(call_site(), ...)` 会把错误指到整个 derive 调用点；
`Error::new_spanned(&meta.path, ...)` 则精确指向用户写错的那个词（实测 caret 停在 `min_lenn`）。
用 `unwrap()` 更糟——panic 的 span 在宏内部，使用者只会看到 `proc-macro panicked`。

结论：**写完宏不主动触发一次错误，等于只做了一半。** 能生成代码和能被调试是两件事。

### 【实测】3. `#[instrument]` 没有输出，是因为没开 span 生命周期事件

加了 `#[tracing::instrument]` 却只看到普通 INFO 行，第一反应是宏没生效。
真实原因：subscriber 默认不打印 span 的 open/close。加上：

```rust
.with_span_events(FmtSpan::CLOSE)
```

立刻出现 `startup{host=... port=...}: close time.busy=52.5µs time.idle=6.80µs`。
与第 43–44 天反复撞到的「静默失败」同族：**该说话的东西没说话，而我们默认没说话 = 没问题**。

### 【实测】4. anyhow 的 `{}` 与 `{:#}` 差的是整整一层因果

同一段错误：

```
{}  ：读取配置文件失败：不存在的配置文件.conf
{:#}：读取配置文件失败：不存在的配置文件.conf: 系统找不到指定的文件。 (os error 2)
```

日志里用 `{}` 等于把根因永久丢掉。规则：anyhow 进日志一律 `{:#}` 或 `{:?}`。

### 【实测】5. 内存序错误跑不出来——故意写错的锁 5/5 全「通过」

`BrokenLock` 用 `Ordering::Relaxed` 做互斥状态（语义上是错的），
在 x86_64 Windows 上连跑 5 次，每次都是 4000，每次「通过」。

原因：x86 是 TSO 强模型，硬件几乎不重排；但**编译器重排在任何平台都存在**。
所以「本机跑通」只能标【实测】，**不能**推出「内存序正确」。

这条认知直接决定了材料 32 的写法：必须明确写出「这一条你无法用测试证明」，
否则是在教错。

### 【实测】6. 环境限制会把"优雅跳过"变成"假绿"——而且假绿是可以修掉的

`file-manager` 的链接保护测试在 Windows 上创建 symlink 失败，代码选择
`eprintln!("跳过：..."); return;` —— 测试于是"通过"了。
这与第 43 天「`cargo test` 0 用例仍退出码 0」是同一个陷阱，只是伪装成了环境降级。

**修复方式不是"以后注意"，而是找第二条路**：`symlink_dir` 要特权，但目录 **junction**
（`mklink /J`）不需要，而 std 把 junction 也报成 `is_symlink == true`（实测）。
于是测试真的跑起来了（集成 8 → 9 条）。

然后做可证伪验证——把 `lib.rs` 的 `symlink_metadata` 换回 `metadata`：

```
test 符号链接被列出但不展开 ... FAILED
panicked at tests\file_manager.rs:78: assertion `left == right` failed
test result: FAILED. 8 passed; 1 failed
```

换回后恢复 9 passed。同时新增 `junction_被识别为符号链接` 单独锁定退路前提，
避免哪天 std 改了行为、主测试悄悄失去意义。

**三个状态必须分清**：代码写了 / 测试跑了 / 测试**会红**。只有第三层算"验证过"。
仍缺：Unix 真 `symlink()` 与 `a -> b -> a` 环（junction 构造不出环）。

### 【材料】7. thiserror 与 anyhow 的分界线只有一个问题

> 调用方是否需要按变体分支？

需要 → `enum AppError`（thiserror），因为要 `match` 后映射 400/500；
不需要 → `anyhow::Result`，只要能加 context 和打印。
选反的代价：enum 用在只有 `?` 的地方 → 一堆没人 match 的变体；
anyhow 用在服务边界 → handler 里只能 `downcast`，类型系统失效。
（本项目两种都有，可直接对照 `src/lib.rs` 的两个函数。）
