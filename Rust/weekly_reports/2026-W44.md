## 三、本周的核心认知（按可复现程度排序）

### 【实测】1. 顺序类结论不能靠文档印象
第 35 天写中间件时，把 `wrap` 顺序按直觉写成"先 wrap 的在外层"，
跑起来才发现是反的（**后注册的在外层**）。
源码依据：`App::wrap` 每次都执行 `apply(mw, self.endpoint)`，
后写的包住的是"已被包过的服务"。

→ 之后的处理方式：**把对照实验留在代码里**（`[INNER]` / `[OUTER]` / `[API]`
三个不同前缀的日志），让下次读到这一课的人自己看到证据。

### 【实测】2. 404 与 405 取决于注册方式，不取决于"有没有这个方法"
第 35 天记的是"两个 `web::resource("/todos")` 导致 405"，
第 36 天做对照实验才发现还有另一半：

```text
cfg.route 重复注册同一路径  → 方法不匹配返回 404
web::resource 合并两条 route → 方法不匹配返回 405
```

→ 结论：同一路径的多个方法**必须**写在同一个 `web::resource` 上。
这不只是"能工作"，还决定了排查时 404/405 是否可信。

### 【实测】3. 一条测试的价值 = 它在什么情况下会失败
把函数写成 `a + b + 1000`，测试体只有 `if ... { println! }`，
结果是 `test ... ok`。**假测试不会报错，它只是什么都不保护。**

→ 判断方法只有一句：**说得出它会怎么挂吗？** 说不出就是没测。

### 【修正】4. 三个被自己写错、后来靠实测纠正的说法
本周有三处"听起来很像真的"的断言，都在跑过之后回改了：

| 原说法 | 实测结果 | 处置 |
|---|---|---|
| `wrap` 先写的在外层 | 后注册的在外层 | 改写第 35 天材料三处 |
| `static mut` 引用在 Rust 2024 报 `mutable reference` | 实际是 `shared reference`；2021 只是 warning | 4.6 两版输出原文保留 |
| `sqlite::memory:` 池里每连接一个独立库 | 同一个池共享一个具名内存库 | 回改 `tests/api.rs` 与练习 7 |

第 3 条尤其值得记：它**不影响编译、不影响测试通过**，
只影响"你以为自己覆盖了什么"。这类错误只能靠"跑一次"发现。

### 【实测】5. 基础设施决定测试能不能被信任
第 36 天真正花时间的不是断言，而是三件外围工作：
- 拆 `lib.rs`：否则 `tests/`（独立 crate）什么都 import 不到
- 路由收敛到 `configure`：否则测试抄一份路由，慢慢**漂移**
- 清理挂在 `Drop` 上：否则测试一挂，磁盘就开始积垃圾

→ 共同点：**它们都不是被测代码，却决定了"绿灯"意味着什么。**

## 四、本周踩的坑（值得记住的）

| 坑 | 根因 | 教训 |
|---|---|---|
| `E0758: unterminated block comment` 两次 | Rust 块注释**会嵌套**，注释里写 `src/mw/*.rs`、`/api/*` 打开了新层 | 块注释里别写通配符路径 |
| 模块说明提前关闭 → 43 个编译错误 | 该说明是一个块注释含两小节，替换前半时多补了一个 `*/` | 改带 `*/` 的片段要整段复看 |
| `E0271` 鉴权短路后 body 类型不一致 | 两条出口一个 `B` 一个 `BoxBody` | 用 `EitherBody` |
| `E0277 Rc cannot be sent between threads` 报在 `main.rs` | `HttpServer::new` 的闭包要求 `Send` | 报错位置在上层时，往上找第一个自己写的类型 |
| `E0310` 关联类型生命周期不够 | `dyn Future` 默认要求 `'static` | 加 `S::Future: 'static` |
| 清理失败 `os error 32` | WAL 的 `-shm` 内存映射未及时解映射 | 重试，不要 `sleep` 猜时间 |
| Windows 下 curl 发中文 JSON 变非法 UTF-8 | 终端编码，不是服务端问题 | 手工验证先把"请求本身是否合法"排掉 |
