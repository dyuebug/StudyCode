## 📝 具体任务

1. [ ] 建项目骨架（预计 50 分钟）
   - 路径：`task-manager/`
   - 结构：`src/lib.rs`（对外装配）/ `src/main.rs`（入口）/ `db.rs` / `state.rs` /
     `models.rs` / `handlers.rs` / `mw.rs` / `migrations/` / `tests/`
   - 要求：复用 `todo-api` 的 **lib + `configure`** 模式，不重新发明
   - 关键：`app()` 把路由 + 中间件 + 状态**一起**收敛，main 与 tests 只调它

2. [ ] 设计并写迁移（预计 60 分钟）
   - 文件：`task-manager/migrations/0001_init.sql`
   - 五张表：`users` / `projects` / `tasks` / `tags` / `task_tags`
   - 重点：
     * `ON DELETE CASCADE`（用户→项目→任务）vs `ON DELETE SET NULL`（指派人）
     * `UNIQUE(owner_id, name)` 而不是 `UNIQUE(name)`——重名的作用域是"个人"
     * `status` 用 `TEXT + CHECK`，`priority` 用 `INTEGER + CHECK`
     * `idx_tasks_project`、`idx_task_tags_tag`（复合主键前缀用不上反查）

3. [ ] 打通一条最小链路（预计 70 分钟）
   - 只做「创建项目 + 列出项目」，但走完：迁移 → 模型 → handler → `configure` → 集成测试
   - 要求：`cargo test` **≥ 4 条**集成用例通过
   - 再加两条接口：`GET/POST /projects/{id}/tasks`（同一条链路的第二次验证）

4. [ ] 把中间件接进骨架（预计 40 分钟）
   - **动手 A（必做）**：把 `mw::auth()` 改成写死的"始终放行"，
     跑 `cargo test`，数一数有几条用例会红；然后**只**删掉
     `web::scope("/projects").wrap(mw::auth())` 这一行再跑一次，对比两者差异
   - **动手 B（必做）**：把 `wrap(mw::logging())` 从 App 级挪进
     `/projects` scope 内，`cargo run` 后访问 `/no-such-path`，
     观察日志里**还有没有这一条**，并解释原因
   - **动手 C（选做）**：把 `UNIQUE(owner_id, name)` 改成 `UNIQUE(name)`，
     看哪条用例变红（提示：`duplicate_project_name_is_409_per_owner` 的第二段）
