### 任务1：改造 translate-cli 为异步版本（核心任务）⭐⭐⭐⭐⭐

**预计时长**：1.5-2小时

**为什么选择 translate-cli**：
- 代码量适中（约240行）
- 涉及网络请求（最适合异步）
- 已经理解业务逻辑
- 容易对比性能差异

**改造步骤**：
1. 创建新项目 `translate-cli-async/`
2. 修改 Cargo.toml：
   - 添加 tokio = { version = "1", features = ["full"] }
   - 使用 reqwest 的异步版本（默认就是异步）
3. 改造 main 函数为异步：`#[tokio::main] async fn main()`
4. 改造所有API调用函数为 async fn
5. 在调用处添加 .await
6. 测试功能是否正常
7. 对比性能差异

**文件结构**：
```
translate-cli-async/
├── Cargo.toml
└── src/
    └── main.rs
```

**关键改造点**：
```rust
// 同步版本
fn translate_text(...) -> Result<...> {
    let response = client.get(url).send()?;
    // ...
}

// 异步版本
async fn translate_text(...) -> Result<...> {
    let response = client.get(url).send().await?;  // 添加 .await
    // ...
}
```

**成功标准**：
- ✅ 编译通过
- ✅ 功能正常（翻译、历史、清除）
- ✅ 能够对比性能差异

### 任务2：性能对比测试（验证任务）⭐⭐⭐

**预计时长**：20-30分钟

**测试方法**：
1. 同步版本：翻译3个句子，记录总时间
2. 异步版本：翻译3个句子，记录总时间

**测试命令**：
```bash

cargo run -- text "world" en zh
cargo run -- text "rust" en zh

# 异步版本

```

**预期结果**：
- 单个请求：差异不大（都是等待网络）
- 多个并发请求：异步版本显著更快

### 任务3：批量翻译功能（扩展任务）⭐⭐⭐⭐

**预计时长**：1-1.5小时

**目标**：体验异步并发的真正威力

**新增功能**：
- 一次翻译多个句子
- 使用 tokio::join! 并发执行
- 对比顺序执行 vs 并发执行

**实现思路**：
```rust
// 顺序翻译（慢）
for text in texts {
    translate_text(text).await;
}

// 并发翻译（快）
let futures = texts.iter().map(|text| translate_text(text));
let results = futures::future::join_all(futures).await;
```

**命令示例**：
```bash
cargo run -- batch "hello" "world" "rust" "async" "tokio"
```

**成功标准**：
- ✅ 能够批量翻译
- ✅ 并发执行
- ✅ 显示时间对比

## 💡 学习重点

### 核心概念
1. **异步改造模式**：
   - 同步函数 → async fn
   - 阻塞调用 → .await
   - main 函数 → #[tokio::main]

2. **性能对比思维**：
   - 单个请求：差异不大
   - 并发请求：异步显著更快
   - 量化性能提升

3. **实战应用**：
   - 不是为了异步而异步
   - 根据场景选择
   - I/O密集 → 异步优先

### 关键技能
- ✅ 将同步代码改造为异步代码
- ✅ 识别哪些操作需要 .await
- ✅ 使用 tokio::join! 实现并发
- ✅ 性能测试和对比分析
- ✅ 错误处理在异步中的应用
