## 📝 具体任务

1. [ ] 学习 `rust_basics/28_testing.rs`（预计 80 分钟）
   - 文件：`rust_basics/28_testing.rs`
   - 跑法：
     ```bash
     rustc --test --edition 2021 28_testing.rs -o 28_testing.exe
     ./28_testing.exe
     ./28_testing.exe --nocapture
     ./28_testing.exe --ignored
     ```
   - 重点读 1.5（假测试）、4.5（用 `if` 代替断言）、4.6（共享 `static mut`）
   - **动手 A**：把 `add` 改成 `a + b + 1000`，观察 4.5 那条测试**依然是 ok**
   - **动手 B**：给 `parse_port` 加 bug（`n > 65535` 改成 `n >= 65535`），
     看哪几条测试挂、哪条没挂，并解释为什么

2. [ ] 读 `todo-api/tests/api.rs`（预计 60 分钟）
   - 项目：`todo-api/`
   - 跑法：`cargo test`、`cargo test -- --nocapture`、`cargo test --test api`
   - 重点看三处：
     - `TempDirGuard`：为什么清理挂在 `Drop` 上（panic 路径）
     - `TestEnv::new`：为什么调用**生产代码**的 `db::init_db`
     - `macro_rules! app!`：为什么必须用 `todo_api::configure`
   - **动手 C**：把 `configure` 里的 `web::resource` 改回两次 `cfg.route`，
     跑 `cargo test --test api collection_rejects_put`，记录状态码如何从 405 变 404
   - **动手 D**：注释掉 `TempDirGuard` 的 `Drop` 实现，跑一遍测试，
     数一数 CPU 临时目录里多了几个 `todo-api-test-*`

3. [ ] 读 `todo-api/src/lib.rs`（预计 25 分钟）
   - 焦点：为什么一个"只会起服务"的项目也要 lib target
   - 焦点：`ServiceConfig` 与 `App` 的区别，为什么装配函数收 `ServiceConfig`
   - 焦点：`main.rs` 拆分后还剩什么（应当只剩"建池 → 迁移 → 起服务"）

4. [ ] 读 7 个常见错误（预计 30 分钟）
   - 必做：4.1（测试函数带参数 / async）、4.5（假测试）、4.6（共享 `static mut`）
   - 4.6 末尾有钱两个 edition 的差异，值得记住：
     `static mut` 引用在 edition 2021 是 warning，在 2024 是 **error**
   - 4.7 的实测补充是本日新写的：手工清理的两个坑

5. [ ] 完成练习题（预计 40 分钟）
   - 必做：练习 1（零拷贝验证）、练习 3（写一条真的会失败的测试）、
     练习 4（注入 bug 看谁抓得住）
   - 思考题 6（找出本文件里的"测了但没测到"）
   - 思考题 7（三种隔离方案的取舍，含"内存库跑不跑得到 WAL 分支"）
