1. [ ] 读 `src/main.rs` 第一部分「核心概念详解」（约 40 分钟）
   - 1.1 中间件解决的是"覆盖"问题，不是"重复"问题

   - 1.4 中间件 / 提取器 / guard 的边界
   - 1.5 什么时候**不该**用中间件

2. [ ] 读 `src/mw/logging.rs` 与 `src/mw/auth.rs`（约 50 分钟）
   - 两个文件都是"两个类型 + 三个关联类型"的同一套路，对比着读
   - `logging.rs`：`S::Future: 'static` 为什么必须写
   - `auth.rs`：`extensions_mut()` 来自 `HttpMessage`，`&self` 就能写
   - `auth.rs`：`FromRequest` 实现——中间件写、提取器读的闭环
   - **动手 A**：把 `auth.rs` 的 `Arc` 改成 `Rc`，记录报错位置
     （报在 `main.rs` 的 `HttpServer::new`，不是 `auth.rs`）
   - **动手 B**：删掉 `S::Future: 'static`，记录 `E0310` 的完整输出

3. [ ] 跑服务，做顺序实验（约 45 分钟）
   ```bash
   cargo run
   ```
   - 先按现在的代码跑一遍，确认三条日志的顺序是 `[API] → [INNER] → [OUTER]`
   - **动手 C**：把 `.wrap(Logging::with_prefix("[OUTER]"))` 挪到最前面，
     重新编译运行，记录 200 请求的新顺序
   - **动手 D**：在 `[API]` 与 `auth` 之间插入第三个日志中间件，
     预测 401 会不会经过它，再验证
   - 打开 `/debug/forgot-auth`，确认服务端打出"漏挂鉴权"警告

4. [ ] 给 `todo-api` 加两个中间件（约 50 分钟）
   - 项目：`todo-api/`
   - 内容：请求日志（方法/路径/状态码/耗时）、鉴权（除 `/health` 外都要 token）
   - 要求：中间件代码直接从 `web/middleware/src/mw/` 复制改造，
     **不要**从零写（今天的目标是会用，不是背模板）
   - 注意：加完后重跑第 33 天的 6 个接口测试，确认行为没变

5. [ ] 读第四部分 7 个常见错误（约 25 分钟）
   - **必做**：4.2（`Ready` 里想 await）、4.3（借用跨 move）、4.7（`RefMut` 跨 await）
   - 4.7 是运行时 panic，不是编译错误——**一定要真的跑一次**看 panic 输出
