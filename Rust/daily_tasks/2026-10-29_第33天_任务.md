## 📝 具体任务

1. [ ] 读《数据库设计速查表》第 1–4 节（约 40 分钟）
   - 文件：`knowledge_base/数据库设计速查表.md`
   - 1. 四步建模法（实体 → 关系 → 属性 → 约束）
   - 2. 范式判断：三个反例，判断它们各自违反了第几范式
   - 2.3 **划重点**：只有三类数据可以合法反范式（可重建的统计数据）
   - 3. 主键策略对比表——重点看 UUID v4 破坏 B 树局部性的那一段
   - 4. 类型表：金额用整数分、时间用 UTC、布尔用 INTEGER、枚举用 CHECK

2. [ ] 读第 5–8 节（约 40 分钟）
   - 5. 索引策略：三个判定标准 + 最左前缀表 + "每表不超过 5 个索引"
   - 6. 约束的三种坑（`UNIQUE` 允许多个 NULL、SQLite 外键默认关、`CHECK` 不跨表）
   - 7. **软删除与 UNIQUE 的冲突**——这是最值得记住的一个设计陷阱
     - 三种解法，哪种才是对的（部分索引）
   - 8. 任务管理系统的完整 ER 图 + DDL 草稿，逐个索引问"为什么需要"

3. [ ] 读第 9–11 节（约 25 分钟）
   - 9. SQLite 与 PostgreSQL 差异表（知道边界在哪，别把 SQLite 习惯带进 PG）
   - 10. 十条反模式清单——逐条对照自己写过的代码
   - 11. 十二项评审清单——保存下来，以后建表前过一遍

4. [ ] 迁移 todo-api（约 70 分钟）
   ```bash
   cd todo-api
   cargo run
   ```
   - 4.1 看启动日志的四行：
     `数据库已就绪` → `旧数据已导入并归档为 todos.json.imported` → `已从 todos.json 导入 1 条历史数据` → `应用状态初始化完成`
   - 4.2 `GET /health`：确认它真的查了库（不是只返回 200）
   - 4.3 `GET /todos`：**确认旧数据还在**——这是迁移的唯一及格线
   - 4.4 `POST` / `GET {id}` / `PUT` / `DELETE` 逐个打通
   - 4.5 **重点**：`PUT` 传 `{"completed":true}` 只改一个字段，
     标题保持不变——理解 `COALESCE(?, title)` 的含义
   - 4.6 对不存在的 id 发 `GET`/`PUT`/`DELETE`，确认三个都是 404 而不是 500
   - 4.7 **重启服务**，确认数据还在、且没有第二次导入
     （启动日志应变成 `📂 无需导入旧数据`）

5. [ ] 读源码并对照迁移前后（约 50 分钟）
   - `todo-api/src/db.rs`：池配置三开关（WAL / 外键 / busy_timeout）各自解决什么
   - `todo-api/src/state.rs`：两个 `Arc<Mutex<>>` 是怎么被砍掉的
   - `todo-api/src/handlers.rs`：`COALESCE` + `RETURNING` 各少了一次往返
   - `todo-api/src/persistence.rs`：**退役文件**，只看文件头横幅和 `save()` 的
     `tmp + rename` 原子写入——那是第 27 天的正确做法，现在被数据库取代了
   - 对照 `handlers.rs` 末尾的注释逐条回答："旧实现的第 N 个问题去哪了"

6. [ ] 动手实验（约 45 分钟）
   - 实验 1：删掉 `todos.db` 三件套，重启，确认导入流程重跑一遍
     （结果：`todos.json` 又一次被改名归档）
   - 实验 2：删掉某条记录，再新增一条，看新记录的 id 是多少
     （提示：`INTEGER PRIMARY KEY` 是 rowid 的别名，不是 `AUTOINCREMENT`）
   - 实验 3：用 `sqlite3 todos.db "SELECT * FROM todos"` 直接看库，
     再看 `todos.db-wal`、`todos.db-shm` 两个伴生文件——它们必须一起进 `.gitignore`
   - 实验 4（进阶）：给 `PUT` 加一个"完整性校验"——先 `SELECT` 读出当前行，
     判断 `completed` 能不能改，再 `UPDATE`。此时读到"丢失更新"了吗？
     如果想彻底解决，需要加什么列？（答案见第 32 天的乐观锁）
