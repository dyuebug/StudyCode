## 🚀 实战项目：HTTP 服务器

### 项目概述
从零开始构建的多线程 HTTP 服务器，零依赖，只使用 Rust 标准库。

### 技术架构
```
HTTP 服务器
├── TCP 层：TcpListener、TcpStream
├── HTTP 层：请求解析、响应构造、路由匹配
├── 并发层：线程池、任务队列（channel）
└── 文件层：静态文件服务
```

### 核心实现
**线程池**：
- 固定4个工作线程
- mpsc::channel 作为任务队列
- Arc<Mutex<Receiver>> 共享接收端
- 生产者-消费者模式

**HTTP 处理**：
- 解析请求行（GET /path HTTP/1.1）
- 路由匹配（/, /about, /sleep, 404）
- 读取 HTML 文件
- 构造完整响应（状态行 + 响应头 + 响应体）

**并发特性**：
- 4个请求可以并发处理
- 慢请求（5秒）不阻塞其他请求
- 性能提升4倍

### 项目统计
- 代码行数：约170行纯 Rust
- 文件数量：2个（main.rs + lib.rs）
- HTML 页面：3个（index, about, 404）
- 依赖：0个（零依赖）
- 性能：4倍并发提升

### 学到的经验
1. **架构设计**：分层设计，职责清晰
2. **并发模式**：线程池是生产环境的标准模式
3. **零依赖**：标准库功能强大
4. **性能优化**：多线程充分利用 CPU

## 💡 核心理念理解

### 1. 零成本抽象
**理念**：高级抽象不应该有性能损失

**实践**：
- 迭代器 = 手写循环性能
- 闭包 = 直接调用性能
- 泛型 = 编译期单态化
- 智能指针 = 原始指针性能

**证明**：HTTP 服务器使用了大量抽象，性能依然出色

### 2. 内存安全
**理念**：编译期保证内存安全，无需垃圾回收

**实践**：
- 所有权系统防止内存泄漏
- 借用检查器防止悬垂指针
- 生命周期保证引用有效性

**证明**：整个项目没有 unsafe 代码，完全内存安全

### 3. 并发安全
**理念**："Fearless Concurrency" - 无畏并发

**实践**：
- Send trait 保证所有权可转移
- Sync trait 保证引用可共享
- 编译器保证无数据竞争

**证明**：线程池实现完全类型安全，无需担心并发问题
