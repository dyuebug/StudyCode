## 🧪 实测记录（可直接复现）

### 1. 中间件顺序：**后注册的在外层**

装配代码的书写顺序（从内到外）：

```rust
App::new()
    .wrap(Logging::with_prefix("[INNER]"))   // 先写 → 里层
    .wrap(Logging::with_prefix("[OUTER]"))   // 后写 → 外层
```

一次 `GET /api/whoami`（带 token）的完整输出：

```text
[API]   GET /api/whoami → 200 OK (0 ms)      ← 最里层最先打印
[INNER] GET /api/whoami → 200 OK (0 ms)
[OUTER] GET /api/whoami → 200 OK (0 ms)
```

三条日志都在响应阶段打印（中间件先 `await` 内层，再打日志），
响应是"后进先出"，所以**先打印的在里层**。

> ⚠️ **这条结论改掉了我原本写进材料里的说法。**
> 我最初按直觉写成"先 wrap 的在最外层"，写完后做了对照实验才发现是反的，
> 于是把 `main.rs` 第 1.3 节、4.6 节、第五部分卡片全部改写。
> 依据在源码里：`App::wrap` 每次都立刻把 `self.endpoint` 包一层
> （`App { endpoint: apply(mw, self.endpoint) }`），
> 所以第二次 `wrap` 包住的是"已经被包过的服务"——它在更外面。

### 2. 短路：401 不经过内层中间件

`/api` scope 下先写 `[API]` 日志、后写 `auth`，于是 auth 在 `[API]` 外面：

```text
[AUTH] 拒绝 GET /api/todos
[INNER] GET /api/todos → 401 Unauthorized (0 ms)   ← 注意：没有 [API]
[OUTER] GET /api/todos → 401 Unauthorized (0 ms)
```

`[API]` 一行都没有 → **Auth 短路在它外面，它根本没机会执行**。
这就是 4.6「日志写在最前面导致 401 不进日志」的最小现场。

### 3. 404 也被记到了

```text
[INNER] GET /nope → 404 Not Found (0 ms)
[OUTER] GET /nope → 404 Not Found (0 ms)
```

App 级中间件包住了 `default_service`，所以路由匹配失败也在监控范围内。
——这条是中间件相对于"在 handler 里打日志"的核心优势。

### 4. 八个端点的行为

| 请求 | 结果 |
|---|---|
| `GET /health` | `200` `{"service":"middleware-demo","status":"ok"}` |
| `GET /api/todos`（无 token） | `401` + `www-authenticate: Bearer` + JSON 错误体 |
| `GET /api/todos`（`Bearer secret-token`） | `200`，3 条 todo |
| `GET /api/whoami`（`other-token`） | `200` `{"user":"bob", ...}` |
| `GET /api/slow/300` | `200`，日志耗时 **301 ms** |
| `POST /api/todos`（JSON body） | `201` `{"created_by":"alice", ...}` |
| `GET /debug/forgot-auth` | `401` + 服务端警告（见下） |
| `GET /nope` | `404` |

### 5. 漏挂鉴权会在第一次调用时报出来

```text
$ curl -i http://127.0.0.1:8082/debug/forgot-auth
HTTP/1.1 401 Unauthorized

服务端：
[AUTH] ⚠️ GET /debug/forgot-auth 没有 UserId —— 检查是否漏挂鉴权中间件
```

handler 签名写了 `user: UserId`，但路由没挂 `Auth`。
提取器找不到 → 401 + 警告。**不会静默放过**，
也不会"看起来能跑但实际没鉴权"——这是类型参与安全的实际价值。

### 6. 中间件没有吃掉请求体

```text
$ curl -X POST -H "Authorization: Bearer secret-token" \
       -H "Content-Type: application/json" --data-binary @todo.json .../api/todos

{"created_by":"alice","data":{"completed":false,"id":4,"title":"测试中间件不吃 body"},"success":true}
```

如果鉴权中间件读了 payload 却没放回，这里会变成
`Json deserialize error: EOF while parsing a value at line 1 column 0`。

## 📖 知识点摘要（来自材料，非学习心得）

### 1. 中间件解决的是"覆盖"，不只是"重复"
把日志写进 handler 会漏三类请求：
新增接口忘了加、404（没进 handler）、401（handler 没执行）。
中间件在 handler **外面**，所以天然覆盖全部。

### 2. 三个 trait 的调用时机
| trait | 调用时机 |
|---|---|
| `Transform::new_transform` | 应用启动，**每个 worker 一次** |
| `Service::call` | **每个请求一次** |
| `ServiceFactory` | 由 App 内部使用，几乎不用自己写 |

把"每个请求都要做"的逻辑写进 `new_transform`，症状是"日志只打印一次"。

### 3. `EitherBody` 存在的原因
鉴权有两条出口：通过 → 内层的 `ServiceResponse<B>`；拒绝 → 自己的 `ServiceResponse<BoxBody>`。
`Service::Response` 只能有一个类型，所以用 `EitherBody<B, BoxBody>` 把两者装进一个枚举。
不写它，编译报 `E0271: expected Result<ServiceResponse<B>, _>, found Result<ServiceResponse, BoxBody>`。

### 4. 身份传递：`extensions` vs `AppState`
- `extensions` 内部是 `Rc<RefCell<Extensions>>`，**随请求走**，天然隔离
- `AppState` 是全局唯一，**并发请求会互相覆盖** → 越权 bug

判断标准：这个值属于"这次请求"还是"整个进程"？
前者 → extensions；后者（配置、连接池）→ `web::Data`。

### 5. `RefMut` 跨 `await` = 运行时 panic
`extensions_mut()` 的内部是 `RefCell`，借用检查在**运行时**。
拿着 `RefMut` 跨 `await`，其他任务来 borrow 就 panic：
`already borrowed: BorrowMutError`。
**看到 `Ref`/`RefMut` 就跟看到 `MutexGuard` 一样——绝不跨 await。**

### 6. 两个"报错很远"的约束
- 泛型参数少了 `'static` → 报在 `HttpServer::new`（E0310）
- 中间件捕获了 `Rc` → 报在 `HttpServer::new`（E0277，`Send` 不满足）

后者尤其隐蔽：`Rc` 在中间件里完全合法（单 worker 内单线程），
但 `HttpServer::new` 的闭包要求 `Send`（每个 worker 各跑一份）。
**排查技巧**：报错在 `main.rs` 时，往上找第一个"自己写的类型"。

## ❓ 遇到的问题与解决

### 问题 1：一开始把 `wrap` 顺序写反了
**现象**：材料里写"先 wrap 的在最外层"，但实测 `[OUTER]` 后打印 → 它在外面。
**原因**：`App::wrap` 是"立刻包一层"（`apply(mw, self.endpoint)`），
所以后写的包住的是已经包过的服务。
**解决**：改写 `main.rs` 的 1.3 / 4.6 / 第五部分卡片，并把实验代码留在项目里当证据。

**教训**：这类"顺序/时序"结论，**不要靠文档印象写进教材**。
用一个最小改动（加两个不同前缀的日志中间件）跑一次，成本两分钟。

### 问题 2：`POST /api/todos` 返回 405
**现象**：GET 正常，POST 全部 405。
**原因**：写了两个 `web::resource("/todos")`，各自挂一个方法。
actix 匹配到第一个 resource 就结束了，第二个永远不生效。
**解决**：合并成一个 resource，挂两条 `.route()`。

**教训**：同一路径的多个方法必须写在**一个** `resource` 上。
405 而不是 404 这个细节本身就在提示"路径匹配到了，方法没匹配"。

### 问题 3：`Authorization: bearer secret-token` → 401
**现象**：token 完全正确，只因为把 `Bearer` 写成小写就被拒。
**原因**：`strip_prefix("Bearer ")` 是大小写敏感的。
**结论**：RFC 7235 规定 auth scheme 不区分大小写，严格实现该用
`eq_ignore_ascii_case`。这里保留简单写法并**在代码里标注**，
因为它是个真实的互操作坑：客户端换个库就"突然登不上"。

### 问题 4：块注释嵌套导致 `E0758: unterminated block comment`
**现象**：编译报第 7 行的 `/*` 未闭合，但注释明明有结尾。
**原因**：Rust 的块注释**会嵌套**。注释里写了路径 `src/mw/*.rs` 和 `/api/*`，
其中的 `/*` 被当成"再开一层注释"，后面的 `*/` 只关掉了内层。
**解决**：把注释里的 `/*` 改掉（写成 `/api 下的所有路由`）。
**教训**：块注释里写通配符路径要小心；`//` 行注释没有这个问题。

### 学习重点

- **`tests/` 目录下的集成测试是"黑盒"**：只能看到 `pub` API，
  适合测端点；`src` 内的 `#[cfg(test)]` 能测私有函数
- **`init_service` 需要 `await`**：它返回的是"建好的 App"，不是 Future 的包装
- **测试并行是默认行为**：共享一个 SQLite 文件时，
  要么串行（`--test-threads=1`），要么每个测试用一个独立库
- **断言要测行为，不要测实现**：断言"返回 401"而不是"中间件里调用了 X"
