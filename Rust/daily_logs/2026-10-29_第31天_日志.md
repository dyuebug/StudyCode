## 📖 知识点摘要（来自材料，非学习心得）

### 1. JSON 方案的六条边界 → 数据库的六个机制
| 文件方案的边界 | 数据库的对应机制 |
|---|---|
| 全量读写，改一条重写全部 | 行级 I/O |
| 无并发控制（后写覆盖） | 事务 + 隔离级别 |
| 无查询能力（全加载后过滤） | SQL + 执行计划 |
| 无事务（跨实体操作无法原子） | BEGIN / COMMIT / ROLLBACK |
| 无索引（条件查询 O(n)） | B 树索引 |
| 无约束（唯一/外键靠代码） | UNIQUE / FOREIGN KEY / CHECK |

**结论**：换数据库不是"更专业"，是因为文件方案的代价随数据量**线性增长**。

### 2. 三个执行入口的校验时机
| 入口 | 返回 | 校验时机 | 适用 |
|---|---|---|---|
| `query` | `Row` | 无（运行时按列名取） | 动态 SQL、DDL、聚合 |
| `query_as` | `T`（元组/FromRow） | 运行时解码 | 固定 SQL，不想设 DATABASE_URL |
| `query!` | 匿名结构体 | **编译期**（连库 prepare） | 固定 SQL，想要类型安全 |

`query!` 的代价：编译需数据库可达，CI 要提交 `.sqlx/` + `SQLX_OFFLINE=true`。

### 3. 三种 `fetch_*` 的语义
- `fetch_one`：**必须恰好有一行**，否则 `Err(RowNotFound)`
- `fetch_optional`：0 或 1 行 → `Option<T>`（"可能没有"的正确建模）
- `fetch_all`：任意行数 → `Vec<T>`

**判断**：查主键且业务上一定存在 → `fetch_one`；查可能不存在的 → `fetch_optional`。

### 4. 事务是 RAII 的
- `pool.begin()` 开启，`tx.commit()` 提交
- **忘记 commit → drop 时自动 rollback**（安全的默认值）
- 事务内所有语句必须 `.execute(&mut *tx)`；用 `&pool` 会**静默地不在事务里**

材料实测：事务内看到 6 条，回滚后回到 5 条 —— 这是隔离性的直接演示。

### 5. SQLite 的类型映射
| Rust | SQLite |
|---|---|
| `i64` | INTEGER |
| `f64` | REAL |
| `String` | TEXT |
| `Vec<u8>` | BLOB |
| `bool` | INTEGER (0/1) |
| `Option<T>` | NULL |
| `DateTime<Utc>` | TEXT（需 chrono feature） |

**SQLite 只有 5 种存储类别**：NULL / INTEGER / REAL / TEXT / BLOB。
没有 BOOLEAN、没有 DATETIME、没有 JSON 类型（`json` 是函数，不是类型）。

### 6. `rows_affected()` 是操作是否命中的唯一证据
- UPDATE 不存在的行 → **不报错**，`rows_affected() == 0`
- 这是 REST API 返回 404 的依据，不是可选项
- DELETE 同理

### 7. `:memory:` 是「每个连接一个库」
`SqlitePool::connect("sqlite::memory:")` + 多连接 → 概率性 `no such table`。
两种修法：`max_connections(1)` 或 `?cache=shared`。
**这是 SQLite 测试代码里人人踩一次的坑。**
