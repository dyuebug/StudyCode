```
[LOG] GET /health → 200 OK (0 ms)
[AUTH] 拒绝 GET /projects
[LOG] GET /projects → 401 Unauthorized (0 ms)
[LOG] GET /no-such-path → 404 Not Found (0 ms)
[LOG] GET /projects → 200 OK (0 ms)
```

两个结论同时被证实：

- **404 进了日志** → 日志中间件在 App 级，覆盖了 `default_service`。
  若挂在 `/projects` scope 上，`/no-such-path` 在路由匹配阶段就被拒，这行根本不会出现。
- **`[AUTH]` 在 `[LOG] ... 401` 之前** → 日志在外层、认证在内层。
  顺序相反的话，`[AUTH]` 会排在 `[LOG]` 之后。

### 4. `created_at` 是 UTC

种子数据 `created_at = 2026-10-29 17:14:26`，而本机时间是 `2026-10-30 01:14`（GMT+8），
相差正好 8 小时。原因：SQLite 的 `datetime('now')` 返回 **UTC**。
展示给用户前必须转换，否则会静默错 8 小时——这类错误不会报错，只会被用户发现。

### 5. `cargo build --offline` 失败

```

  version 0.9.8 is yanked

```

本机 registry 缓存里只有被 yank 的 `spin 0.9.8`，离线解析失败；
联网解析（`cargo build`）正常完成。**这不是代码问题，是缓存状态问题**——

## 📖 学到的知识点

### 1. 边界自检法："改一个东西要动几个文件"

`models` 不认识 HTTP，`handlers` 不认识 SQL 细节，`lib.rs` 管装配。
用一句话检验：换数据库只动 `db.rs`；加字段动 `migrations` + `models.rs`；
改路由只动 `configure`。**动到三个以上文件，说明边界画错了。**

### 2. 迁移即契约：先 SQL，后结构体

表结构是最晚能改的东西。先用 SQL 定，因为 SQL 是数据库**唯一真正接受的语法**；
先用 Rust 结构体描述再翻译，翻译中每个"应该差不多"都会在跑迁移时变成错误。

### 3. SQLite 三个必须显式设置的开关

| 开关 | 默认 | 不设置的后果 |
|---|---|---|
| `journal_mode` | DELETE | 读写互斥（WAL 才能读不阻塞写） |
| `foreign_keys` | **OFF** | 外键约束形同虚设，**静默失效** |
| `busy_timeout` | 0 | 撞上写锁立刻 `SQLITE_BUSY` |

第 2 个最危险：不报错、不警告，只是"约束不生效"。

### 4. `App` 的返回类型：两个编译器教的坑（**实测**）

**坑一：`App` 只有一个泛型参数。**

```
error[E0107]: struct takes 1 generic argument but 2 were supplied
  --> src\lib.rs:68:36
```

`App<T, B>` 是旧版本的形状；actix-web 4.18 里是 `App<T>`。

**坑二：约束里的请求类型是 `ServiceRequest`，不是 `Request`。**

```
error[E0277]: the trait bound `impl ServiceFactory<..., Config = (), Response = ...,
              Error = ..., InitError = ()>: ServiceFactory<...>` is not satisfied
```

照抄 `HttpServer` 的签名写 `ServiceFactory<Request>` 就会撞上它。
**源码依据**（actix-web 4.18.1 `src/app.rs:446`）：

```rust
impl<T, B> IntoServiceFactory<AppInit<T, B>, Request> for App<T>
where
    T: ServiceFactory<ServiceRequest, Config = (), Response = ServiceResponse<B>, ...> + 'static,
```

`App` 内层工厂处理的是**已经进了 App 的请求**（`ServiceRequest`，带 extensions 与 payload），
不是 TCP 层刚解出来的 `Request`。

### 5. 中间件顺序：`[AUTH]` 与 `[LOG]` 的相对位置就是证据

后注册的 `.wrap()` 在外层。App 级 `.wrap(logging)` + scope 级 `.wrap(auth)`
⇒ 日志在外、认证在内 ⇒ 拒绝请求时先看到 `[AUTH]`，再看到 `[LOG] ... 401`。
**这条日志顺序比任何文档都可靠**：改错了顺序，日志形状会立刻变化。

### 6. `CurrentUser` 提取器：用类型代替纪律

```rust
pub async fn list_projects(state: web::Data<AppState>, user: CurrentUser) -> ...
```

- 中间件写 `extensions.insert(CurrentUser(id))`，提取器读它
- handler 取不到 → 401；提取器是 newtype，裸 `i64` 无法冒充
- **漏写检查**这种 bug 变成**漏写参数**，编译期就报错

### 7. 越权返回 404，不是 403

403 等于承认"资源存在，只是不属于你"，而 id 自增 ⇒ 可以枚举。
测试 `foreign_project_is_404_not_403` 同时断言"别人的项目"和"不存在的项目"
都返回 404——两者**不可区分**，这正是设计目标。

### 8. `COALESCE(?, 2)`：让数据库当默认值的唯一来源

`priority` 省略时回落到 DB 默认值 2，而不是在 Rust 里 `unwrap_or(2)`。
后者会让默认值存在两份，改一处漏一处。
实测 `create_task_then_list_roundtrip` 断言了 `status == "todo"`、`priority == 2`。

### 9. 唯一约束的识别用 `is_unique_violation()`，不解析错误字符串

`e.to_string().contains("UNIQUE")` 依赖 SQLite 的文案，换库/换版本就失效。
`DatabaseError::is_unique_violation()` 是语义化判断。

### 10. 测试用真文件库，不用 `sqlite::memory:`

内存库确实全连接共享（第 36 天实测 `shared_cache`），能跑；
但**不支持 WAL**，而生产用 WAL——测试跑在另一条路径上。
真文件库还能顺带验证"迁移能在干净库上跑通"和"清理干不干净"。

## ❓ 遇到的问题与解决

### 问题 1：`cargo build --offline` 报 `spin 0.9.8 is yanked`

**现象**：依赖解析阶段直接失败，连编译都没开始。
**原因**：本机 registry 缓存里只有被 yank 的版本，离线模式不允许重新解析。
**解决**：联网 `cargo build`，生成 `Cargo.lock` 后即可离线。
**教训**：离线构建的前提是**依赖已经解析过一次**；`--offline` 不是"不用网络也能随便装包"。

### 问题 2：`error[E0107]` —— `App` 的泛型参数个数

**原因**：按记忆里的旧签名写 `App<T, B>`。
**解决**：改成 `App<T>`，只留内层工厂。
**教训**：泛型参数个数这类"看起来显然"的东西，**先看源码再写**，比试错快。

### 问题 3：`error[E0277]` —— `ServiceFactory<Request>` 不满足

**原因**：照抄 `HttpServer` 的签名，但 `App` 内层工厂处理的是 `ServiceRequest`。
**解决**：把约束改成 `ServiceFactory<ServiceRequest, ...> + 'static`。
**验证方式**：读 `app.rs:446` 的 `IntoServiceFactory` 实现，而不是继续猜。
**教训**：**报错说"trait 不满足"时，去读 trait 的实现约束**——
编译器只告诉你"不满足"，源码才告诉你"需要满足什么"。

### 问题 4：`actix-http` 白加了一个依赖

**现象**：一开始为在返回类型里写 `actix_http::Request` 而加了 `actix-http = "3"`。
**解决**：改用 `ServiceRequest` 后不再需要它，从 `Cargo.toml` 删除。
**教训**：**直接依赖只加"自己代码里真的写了名字"的 crate**——否则只是延长编译时间，
还会让下一个人误以为"我们在直接用 actix-http"。

### 问题 5：`warning: unused import: web`（测试文件）

**现象**：`tests/api.rs` 里 `use actix_web::{test, web};`，`web` 实际没用到
（因为 `app()` 已经封装了 `web::Data`）。
**解决**：删掉，恢复"零警告"。
**意义**：零警告不是洁癖——警告会积累，等到有 200 条时真问题就淹没了。

### 问题 6：端口与临时目录的收尾

**现象**：后台起了服务，`TaskStop` 之后 `taskkill` 报"找不到进程"。
**检查**：`curl -m 2` 返回 `000`（连接失败）⇒ 端口确实已释放，不是僵尸进程。
**解决**：按字面路径删除临时目录，确认 `$TEMP/tm-live-*` 为空。
**教训**：**停服务后要验证"端口真的关了"**，而不是"我发了停止命令"。

## 💭 今日心得

今天最大的收获不是"又写了一个 API"，而是发现**文档和记忆都可能过期**：

- `App<T, B>` → `App<T>`：旧签名还在很多教程里
- `ServiceFactory<Request>` → `ServiceFactory<ServiceRequest>`：`HttpServer` 用前者，
  `App` 用后者，两个签名长得很像但含义不同

两次都是**编译器先发现了问题，我再去读源码**。这说明"读懂错误信息 + 会读依赖源码"
这两件事，比"记住正确写法"更抗过时。

第二个收获是**验证比断言便宜**：今天的 `[AUTH]` / `[LOG]` 行序、
`.db` 是否被污染、临时目录是否删干净，都是**一眼就能看到**的检查项。
如果每次都靠"我应该写对了"，那 401 不打日志这种事能藏好几个礼拜。

第三，`task-manager` 才写了 4 个接口就已经有 9 条测试，
而 `todo-api` 写了 6 个接口才 8 条测试——**结构对了以后，测试是自然长出来的**，
不是"写完再补"的额外工作。

### 学习重点

- **事务的边界**：多张表一起变，就必须在一个事务里
- **非法状态是业务错误**，不是 400（形状对，语义错 → 409/422）
- **`Option` 的三态**：没给 / 给 null / 给值——这是 `PATCH` 最容易错的地方
- **索引不是写完就有用**：要 `EXPLAIN` 验证

### 学习方法

1. 每个接口先写测试，断言"非法输入"的那条**先写**
2. 事务相关的用例，要额外断言"失败后数据真的没变"
3. `EXPLAIN QUERY PLAN` 的输出直接贴进日志——不要用"应该会走索引"来结论
