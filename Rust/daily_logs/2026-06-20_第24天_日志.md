## 📖 学到的知识点

### Actix-web 核心概念

1. **HttpServer - HTTP 服务器**：
   ```rust
   HttpServer::new(|| {
       // 应用配置
   })
   .bind("127.0.0.1:8080")?
   .run()
   .await
   ```
   - 创建和管理 HTTP 服务器
   - 绑定地址和端口
   - 异步运行

2. **App - 应用实例**：
   ```rust
   App::new()
       .route("/", web::get().to(handler))
       .app_data(web::Data::new(state))
   ```
   - 配置路由
   - 管理共享状态
   - 添加中间件

3. **Route - 路由定义**：
   ```rust
   web::get().to(handler)      // GET 请求
   web::post().to(handler)     // POST 请求
   web::put().to(handler)      // PUT 请求
   web::delete().to(handler)   // DELETE 请求
   ```
   - 将 HTTP 请求映射到处理函数
   - 支持路径参数（:id）

4. **Handler - 请求处理函数**：
   ```rust
   async fn handler() -> impl Responder {
       "Hello, World!"
   }
   ```
   - 必须是 async fn
   - 返回实现 Responder trait 的类型
   - 可以接受多种 Extractor

5. **Extractor - 请求数据提取**：
   ```rust
   web::Path<u32>          // 路径参数
   web::Query<Params>      // 查询参数
   web::Json<Data>         // JSON 数据
   web::Data<AppState>     // 共享状态
   ```

6. **Responder - 响应生成**：
   ```rust
   "Hello"                     // 字符串
   web::Json(data)             // JSON
   HttpResponse::Ok().body()   // 自定义响应
   ```

### RESTful API 设计

7. **核心原则**：
   - 资源导向（URL 表示资源）
   - HTTP 方法（GET/POST/PUT/DELETE）
   - 标准状态码（200/201/404/400）
   - 无状态（每个请求独立）
   - 统一接口（一致的设计）

8. **Todo List API 接口设计**：
   - `GET /todos` - 获取所有任务
   - `POST /todos` - 创建任务
   - `GET /todos/:id` - 获取单个任务
   - `PUT /todos/:id` - 更新任务
   - `DELETE /todos/:id` - 删除任务

### 数据模型设计

9. **Todo 结构**：
   ```rust
   #[derive(Serialize, Deserialize, Clone)]
   struct Todo {
       id: u32,
       title: String,
       completed: bool,
   }
   ```

10. **请求数据结构**：
    ```rust
    #[derive(Deserialize)]
    struct CreateTodo {
        title: String,
    }
    
    #[derive(Deserialize)]
    struct UpdateTodo {
        title: Option<String>,
        completed: Option<bool>,
    }
    ```

### 状态管理

11. **共享状态设计**：
    ```rust
    type AppState = Arc<Mutex<Vec<Todo>>>;
    ```
    - `Vec<Todo>`：存储所有任务
    - `Mutex`：保证线程安全
    - `Arc`：允许多线程共享

12. **为什么需要这样？**
    - Web 服务器是多线程的
    - 多个请求可能同时到达
    - 需要保证数据安全
    - 回顾第16天的并发知识
