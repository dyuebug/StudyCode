## 📖 学到的知识点

### web::Path<T> 路径参数提取器

1. **基本用法**：
   ```rust
   pub async fn get_by_id(
       state: web::Data<AppState>,
       id: web::Path<u32>,  // 从 URL 自动提取
   ) -> impl Responder {
       let todo_id = id.into_inner();  // 获取内部值
   }
   ```
   - web::Path<T> 自动从 URL 提取参数
   - /todos/{id} → web::Path<u32>
   - into_inner() 获取内部值

2. **路径参数语法**：
   ```rust
   .route("/todos/{id}", web::get().to(handlers::get_by_id))
   ```
   - {id} 定义路径参数
   - 参数名与 handler 无关，类型由 web::Path<T> 决定
   - 支持多个参数：/users/{user_id}/posts/{post_id}

3. **类型安全**：
   - 如果 URL 中的 id 不是有效的 u32，自动返回 400
   - 编译时类型检查
   - 运行时自动验证

### 多个 Extractor 组合使用

4. **组合 web::Path 和 web::Json**：
   ```rust
   pub async fn update(
       state: web::Data<AppState>,
       id: web::Path<u32>,              // 路径参数
       update_data: web::Json<UpdateTodo>,  // JSON 请求体
   ) -> impl Responder {
       // 两个 Extractor 独立工作
   }
   ```

5. **Extractor 的灵活性**：
   - 参数顺序不重要
   - Actix-web 根据类型自动匹配
   - 每个 Extractor 独立工作
   - 可以组合任意数量的 Extractor

### 迭代器方法的选择

6. **iter() vs iter_mut()**：
   ```rust
   // 不可变迭代器 - 用于查找
   let todo = todos.iter().find(|t| t.id == id);  // Option<&Todo>
   
   // 可变迭代器 - 用于更新
   let todo = todos.iter_mut().find(|t| t.id == id);  // Option<&mut Todo>
   ```
   - iter(): 返回不可变引用 &T
   - iter_mut(): 返回可变引用 &mut T
   - 更新操作必须使用 iter_mut()

7. **find() vs position()**：
   ```rust
   // find() 返回元素引用
   let todo = todos.iter().find(|t| t.id == id);  // Option<&Todo>
   
   // position() 返回索引
   let index = todos.iter().position(|t| t.id == id);  // Option<usize>
   ```
   - find(): 用于获取元素（读取或更新）
   - position(): 用于删除（需要索引）

8. **为什么删除需要索引？**
   ```rust
   let removed = todos.remove(index);
   ```
   - Vec::remove(index) 需要索引参数
   - 不能直接通过引用删除
   - position() 是正确的选择

### 部分更新模式

9. **Option<T> 实现部分更新**：
   ```rust
   #[derive(Deserialize)]
   pub struct UpdateTodo {
       pub title: Option<String>,
       pub completed: Option<bool>,
   }
   ```
   - 所有字段都是 Option
   - None 表示不更新该字段
   - Some(value) 表示更新为新值

10. **if let Some 模式**：
    ```rust
    if let Some(new_title) = &update_data.title {
        found_todo.title = new_title.clone();
    }
    if let Some(new_completed) = update_data.completed {
        found_todo.completed = new_completed;
    }
    ```
    - 只有 Some 时才执行更新
    - 支持任意字段组合
    - 灵活的部分更新

### 错误处理

11. **404 Not Found 处理**：
    ```rust
    match todo {
        Some(found_todo) => {
            // 找到了，返回 200 OK
            HttpResponse::Ok().json(response)
        }
        None => {
            // 没找到，返回 404
            let error = ErrorResponse::error("Todo not found");
            HttpResponse::NotFound().json(error)
        }
    }
    ```

12. **ErrorResponse 结构**：
    ```rust
    #[derive(Serialize)]
    pub struct ErrorResponse {
        pub success: bool,
        pub error: String,
    }
    ```
    - 统一的错误响应格式
    - 与成功响应保持一致的结构

### Vec 操作

13. **Vec::remove()**：
    ```rust
    let removed_todo = todos.remove(index);
    ```
    - 移除指定位置的元素
    - 返回被移除的元素（获取所有权）
    - 后续元素自动向前移动
    - O(n) 时间复杂度

14. **为什么不用 retain()？**
    ```rust
    // retain() 不返回被删除的元素
    todos.retain(|t| t.id != todo_id);
    ```
    - retain() 用于批量过滤
    - 不返回被删除的元素
    - 我们需要返回被删除的任务

### RESTful 路由设计

15. **完整的 CRUD 路由**：
    ```rust
    .route("/todos", web::get().to(handlers::get_all))
    .route("/todos", web::post().to(handlers::create))
    .route("/todos/{id}", web::get().to(handlers::get_by_id))
    .route("/todos/{id}", web::put().to(handlers::update))
    .route("/todos/{id}", web::delete().to(handlers::delete))
    ```

16. **路由顺序的重要性**：
    - 精确路由（/todos）在前
    - 参数路由（/todos/{id}）在后
    - Actix-web 按顺序匹配
    - 避免路由冲突

17. **HTTP 方法语义**：
    - GET: 获取资源（幂等、安全）
    - POST: 创建资源（非幂等）
    - PUT: 更新资源（幂等）
    - DELETE: 删除资源（幂等）

### match 表达式高级用法

18. **match 与 Option**：
    ```rust
    match position {
        Some(index) => {
            // 找到了索引
            let removed = todos.remove(index);
            HttpResponse::Ok().json(response)
        }
        None => {
            // 没找到
            HttpResponse::NotFound().json(error)
        }
    }
    ```
    - 处理 Option 和 Result
    - 覆盖所有可能的情况
    - 返回不同的 HTTP 响应

### 克隆策略

19. **为什么要克隆？**
    ```rust
    let todo = todos.iter().find(|t| t.id == id);
    match todo {
        Some(found_todo) => {
            let response = ApiResponse::success(found_todo.clone());
            // 必须克隆，因为 found_todo 是引用
        }
    }
    ```
    - found_todo 是 &Todo（引用）
    - 需要 Todo（所有权）来构造响应
    - 克隆创建独立副本

20. **&update_data.title vs update_data.completed**：
    ```rust
    if let Some(new_title) = &update_data.title {
        // String 需要引用避免移动
    }
    if let Some(new_completed) = update_data.completed {
        // bool 是 Copy，可以直接值传递
    }
    ```
    - String 不是 Copy，需要引用
    - bool 是 Copy，可以直接使用值
