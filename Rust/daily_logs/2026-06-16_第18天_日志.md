## 📖 学到的知识点

### 命令行工具开发

1. **命令行参数处理**：
   - `std::env::args()` 获取参数
   - `args.collect()` 收集为 Vec
   - 参数验证和错误提示
   - `process::exit()` 退出程序

2. **环境变量**：
   - `env::var()` 读取环境变量
   - `is_ok()` 检查是否存在
   - 用于配置选项（如 IGNORE_CASE）

3. **标准输出和错误**：
   - `println!()` 输出到标准输出
   - `eprintln!()` 输出到标准错误
   - 错误信息应该用 stderr

### 文件 I/O

4. **文件读取**：
   - `fs::read_to_string()` 读取整个文件
   - 返回 `Result<String, Error>`
   - `?` 运算符传播错误

5. **文本处理**：
   - `lines()` 按行分割
   - `enumerate()` 添加索引
   - `contains()` 检查子串

### 迭代器和闭包（实战）

6. **迭代器链式调用**：
   ```rust
   contents.lines()
       .enumerate()
       .filter(|(_, line)| line.contains(query))
       .map(|(index, line)| (index + 1, line))
       .collect()
   ```
   - 函数式风格
   - 零成本抽象
   - 代码简洁清晰

7. **闭包在迭代器中的应用**：
   - `filter()` 的闭包：过滤条件
   - `map()` 的闭包：转换逻辑
   - 闭包捕获外部变量（query）

### 模块化设计

8. **lib.rs 和 main.rs 分离**：
   - `lib.rs`：核心逻辑，可复用，可测试
   - `main.rs`：CLI 接口，轻薄层
   - 职责分离原则

9. **公共 API 设计**：
   - `pub struct Config`
   - `pub fn run()`
   - `pub fn search()`
   - 清晰的接口

### 错误处理

10. **Result 类型的使用**：
    - `Config::build() -> Result<Config, &'static str>`
    - `run() -> Result<(), Box<dyn Error>>`
    - `?` 运算符简化错误传播

11. **unwrap_or_else 模式**：
    ```rust
    Config::build(&args).unwrap_or_else(|err| {
        eprintln!("错误: {}", err);
        process::exit(1);
    });
    ```
    - 错误时执行自定义逻辑
    - 提供友好的错误信息

### 生命周期

12. **生命周期注解的实际应用**：
    ```rust
    pub fn search<'a>(query: &str, contents: &'a str) -> Vec<(usize, &'a str)>
    ```
    - 返回值的生命周期与 `contents` 相同
    - 编译器保证返回的引用有效
    - 避免悬垂引用

### 测试驱动开发

    - `#[test]` 标记测试函数

14. **测试最佳实践**：

    - 测试覆盖正常和边界情况

## 💭 今日心得

### 关于 CLI 工具开发

minigrep 是一个经典的 Rust 入门项目，但麻雀虽小，五脏俱全。通过这个项目，我真正理解了：

**1. 命令行工具的标准结构**
- 参数解析 → 配置构建 → 核心逻辑 → 输出结果
- 错误用 stderr，正常输出用 stdout
- 环境变量作为配置选项

**2. Rust 的模块化设计**
- lib.rs 是核心，main.rs 是壳
- lib.rs 可以被测试、被复用
- main.rs 只负责 CLI 交互
- 这种设计非常优雅

**3. 迭代器的实用性**
手写循环版本：
```rust
let mut results = Vec::new();
for (index, line) in contents.lines().enumerate() {
    if line.contains(query) {
        results.push((index + 1, line));
    }
}
results
```

迭代器版本：
```rust
contents.lines()
    .enumerate()
    .filter(|(_, line)| line.contains(query))
    .map(|(index, line)| (index + 1, line))
    .collect()
```

迭代器版本更简洁、更声明式，而且性能一样！

**4. 测试驱动开发的价值**
- 写测试让我更清楚函数的输入输出
- 测试保证重构时不会破坏功能
- 测试通过给我信心

### 关于生命周期

在 `search` 函数中使用生命周期注解：
```rust
pub fn search<'a>(query: &str, contents: &'a str) -> Vec<(usize, &'a str)>
```

这让我真正理解了生命周期的作用：
- 返回的 `&str` 引用来自 `contents`
- 生命周期 `'a` 确保返回值不会比 `contents` 活得更久
- 编译器用这个信息保证内存安全

### 对比两个项目

**HTTP 服务器**：
- 重点：并发、网络
- 复杂度：高（线程池、Arc+Mutex）
- 挑战：理解并发模式

**minigrep**：
- 重点：迭代器、I/O、测试
- 复杂度：中（逻辑清晰）
- 挑战：模块化设计

两个项目互补，各有侧重。HTTP 服务器让我理解并发，minigrep 让我掌握迭代器和测试。
