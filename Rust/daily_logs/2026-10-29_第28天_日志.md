## 📖 知识点摘要（来自材料，非学习心得）

### 1. 判据：泛型优先，宏处理语法层
- 类型不同的重复 → 泛型单态化解决，**不该用宏**
- 必须用宏的四类场景：可变参数、语法要变形（`vec![0; 5]`）、编译期检查、需要拿到符号名文本

### 2. 词法树匹配，不是文本替换
```rust
macro_rules! square { ($x:expr) => { $x * $x }; }
square!(1 + 2)   // → (1+2)*(1+2) = 9，不是 5
```
C 的 `#define SQUARE(x) x*x` 会得到 `1+2*1+2 = 5`。差别在于 Rust 捕获的是 AST 片段。

### 3. 匹配器选错 = 编译失败
| 匹配器 | 能吃的内容 | 误用后果 |
|---|---|---|
| `expr` | 完整表达式 | — |
| `tt` | 单个词法树 | `square!(1 + 2)` → `no rules expected +` |
| `ident` | 单个标识符 | 传入 `a.b` 失败 |
| `ty` | 类型 | 传入表达式失败 |

### 4. 重复模式与递归
- `$( ... ),*` 里，分隔符是**契约的一部分**，定义与调用必须一致
- `$var` 的生命周期只到所在重复块结束，块外引用 → `attempted to repeat an expression containing no syntax variables`
- 递归宏**第一个分支必须是空输入**，否则 `recursion limit reached`

### 5. 卫生性只有一半
- ✅ 局部变量卫生：宏内 `let x` 不污染调用处的 `x`
- ❌ 路径不卫生：宏内的 `serde_json::to_string` 按**调用处**解析
- ❌ 宏内定义的 `fn`/`struct` 会泄露到调用处
- 跨 crate 导出宏 → 所有路径必须加 `$crate::`

### 6. 三种过程宏
| 类型 | 形态 | 典型例子 |
|---|---|---|
| derive | `#[derive(X)]` | serde 的 `#[derive(Serialize)]` |
| attribute | `#[route(GET, "/")]` | actix-web 的 `#[get("/")]` |
| function-like | `m!(...)` | sqlx 的 `query!`（编译期连库校验 SQL） |
