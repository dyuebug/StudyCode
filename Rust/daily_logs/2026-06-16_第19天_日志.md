## 📖 学到的知识点

### serde 核心知识

1. **序列化（Serialization）**：
   - 将 Rust 数据结构转换为 JSON 字符串
   - `serde_json::to_string(&data)`
   - `serde_json::to_string_pretty(&data)` 美化输出

2. **反序列化（Deserialization）**：
   - 将 JSON 字符串转换回 Rust 数据结构
   - `serde_json::from_str(&json_str)`
   - 类型安全，编译期检查

3. **derive 宏**：
   - `#[derive(Serialize, Deserialize)]`
   - 自动实现序列化和反序列化
   - 零样板代码

4. **数据类型支持**：
   - 基本类型：String, i32, u32, bool, f64
   - 复合类型：结构体、元组
   - 集合类型：Vec, HashMap
   - 可选类型：Option（对应 JSON null）

5. **属性定制**：
   - `#[serde(rename = "...")]` 字段重命名
   - `#[serde(skip)]` 跳过字段
   - `#[serde(default)]` 默认值
   - `#[serde(flatten)]` 扁平化

6. **嵌套结构**：
   - 结构体可以嵌套其他结构体
   - 自动递归序列化
   - 支持任意深度嵌套

7. **Vec 和 Option**：
   - Vec 对应 JSON 数组
   - Option::Some 对应值，Option::None 对应 null
   - 空数组 `[]` vs null 的区别

### 实战：配置文件管理

8. **配置结构设计**：
   ```rust
   #[derive(Serialize, Deserialize)]
   struct AppConfig {
       default_ignore_case: bool,
       recent_searches: Vec<String>,
       recent_files: Vec<String>,
       max_history: usize,
   }
   ```

9. **配置加载**：
   ```rust
   pub fn load<P: AsRef<Path>>(path: P) -> Result<Self, Box<dyn Error>> {
       let contents = fs::read_to_string(path)?;
       let config = serde_json::from_str(&contents)?;
       Ok(config)
   }
   ```

10. **配置保存**：
    ```rust
    pub fn save<P: AsRef<Path>>(&self, path: P) -> Result<(), Box<dyn Error>> {
        let json = serde_json::to_string_pretty(self)?;
        fs::write(path, json)?;
        Ok(())
    }
    ```

11. **Default trait**：
    ```rust
    impl Default for AppConfig {
        fn default() -> Self { /* ... */ }
    }
    ```
    - 提供默认配置
    - `unwrap_or_default()` 模式

12. **配置管理模式**：
    - 加载配置（如果存在）
    - 使用配置
    - 更新配置
    - 保存配置

### 文件 I/O 集成

13. **读取文件**：
    - `fs::read_to_string()` 读取整个文件
    - 与 serde 配合：`from_str(&contents)`

14. **写入文件**：
    - `fs::write()` 写入文件
    - 与 serde 配合：`to_string_pretty(&data)`

15. **错误处理**：
    - `Result<T, Box<dyn Error>>` 统一错误类型
    - `?` 运算符传播错误
    - `unwrap_or_default()` 优雅降级

### 模块化设计

16. **模块分离**：

17. **公共 API 设计**：

## 💭 今日心得

### 关于 serde

**serde 是 Rust 生态系统的基石！**

**为什么 serde 如此重要**：
1. **无处不在**：几乎所有涉及数据交换的项目都会用到
2. **零成本抽象**：性能极高，无运行时开销
3. **类型安全**：编译期保证正确性，不会出现运行时错误
4. **易于使用**：一行 `#[derive]` 就能实现序列化

**学习体会**：
- derive 宏的威力：一行代码实现复杂功能
- Option 和 JSON null 的完美对应
- 支持任意复杂的嵌套结构
- 错误处理友好，与 Result 完美配合

### 技术细节的理解

**1. serde 的 derive 宏**：
```rust
#[derive(Serialize, Deserialize)]
```
这一行代码背后：
- 编译期生成序列化代码
- 零运行时开销
- 类型安全保证

**2. Option 和 JSON null**：
```rust
email: Option<String>
```
- Some("...") → "email": "..."
- None → "email": null
- 完美对应，自然直观

**3. 错误处理的优雅**：
```rust
AppConfig::load(path).unwrap_or_default()
```
- 配置文件不存在？用默认配置
- 不会因为配置问题崩溃
- 用户体验友好

**4. 模块化的价值**：
```
config.rs    - 配置管理（独立、可测试、可复用）
lib.rs       - 核心逻辑（不变）
main.rs      - CLI 接口（集成配置）
```
- 职责清晰
- 易于维护
- 可以独立测试
