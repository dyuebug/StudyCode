## 📖 知识点摘要（来自材料，非学习心得）

### 1. 迁移是"一次且仅一次"，所以它必须幂等
- `migrate!` 宏在**编译期**把 SQL 读进二进制
- 运行时先建 `_sqlx_migrations` 表，按版本号顺序执行**未执行过**的
- 文件名格式 `{版本}_{描述}.sql`，版本号决定顺序
- 因此它可以挂在每次启动上，第二次全部跳过

**推论**：已提交的迁移文件视为**不可变**。改结构只能新增文件。

### 2. 能 bind 什么，不能 bind 什么
| 类别 | 处理方式 | 原因 |
|---|---|---|
| 所有**值**（字符串/数字/时间） | `bind` / `push_bind` | 走协议层，永远当数据 |
| 表名、列名 | 白名单拼接 | 标识符在解析期就要确定 |
| `ORDER BY` 字段与方向 | 白名单拼接 | 同上 |
| `LIMIT` / `OFFSET` | SQLite 可 bind，PG 部分实现可 bind | — |

**规则：值 bind，标识符白名单，没有第三种。**

### 3. QueryBuilder 的正确用法
```rust
let mut qb = QueryBuilder::new("SELECT ... FROM tasks WHERE 1=1");
if let Some(kw) = keyword { qb.push(" AND title LIKE ").push_bind(format!("%{}%", kw)); }
qb.push(" ORDER BY ").push(whitelisted_column);
qb.build_query_as::<TaskRow>().fetch_all(pool).await
```
`push` 是**原样拼接**（所以只能放自己写的字面量），`push_bind` 才安全。

### 4. OFFSET 分页 vs 键集分页
| | OFFSET | 键集（cursor） |
|---|---|---|
| 复杂度 | O(offset) | O(limit) |
| 深页性能 | 越来越慢 | 恒定 |
| 数据变动时 | 会漏行/重复 | 稳定 |
| 跳页 | 支持 | 不支持（只能下一页） |

```sql
-- OFFSET
SELECT ... ORDER BY id LIMIT ? OFFSET ?
-- 键集
SELECT ... WHERE id > ? ORDER BY id LIMIT ?
```

### 5. 乐观锁的完整语义
```sql
UPDATE tasks SET title = ?, version = version + 1
WHERE id = ? AND version = ?
```
- `rows_affected() == 1` → 成功
- `rows_affected() == 0` → **可能是"不存在"，也可能是"版本过期"**
- 要区分 404 / 409，必须再查一次存在性

这是"未命中 ≠ 错误类型"的典型例子。

### 6. EXPLAIN QUERY PLAN 的三个关键输出
| 输出 | 含义 |
|---|---|
| `SCAN tasks` | 全表扫描，没有可用索引 |
| `SEARCH tasks USING INDEX idx_x (col=?)` | 走了索引 |
| `USE TEMP B-TREE FOR ORDER BY` | 排序没利用索引，建了临时 B 树 |

**注意**：数据量小时优化器可能**主动不用**索引（算成本）。"有索引"≠"一定用"。

### 7. 批量插入：事务比多值更普适
材料实测（本机，50 条）：无事务循环 ≈ 32ms，事务包住循环 ≈ 1.8ms，差约 **18 倍**。
差距来自"每条一次隐式提交"。多值 INSERT 也能达到同等效果，但受变量数上限约束
（SQLite 32766）。

**结论：批量写永远包事务，这是基线要求，不是优化。**

### 8. 连接池耗尽的四种成因
1. 把 `PoolConnection` 存进 State 长期持有
2. 持有连接时 `await` 一个不会完成的 future
3. 事务死循环，`tx` 永不 drop
4. 用 `fetch` 流但没消费完就 return（流借用连接）

（实际学习后填写。建议回答：为什么"图省事"的写法在数据库上是危险的？

参考视角：这一课最反直觉的一点是——**多数数据库错误是静默的**。
ORDER BY 注入不会报错，只是返回了被操纵的数据；
`rows_affected() == 0` 不会报错，只是让 API 返回了假的 200；
用 `&pool` 代替 `&mut *tx` 不会报错，只是让事务形同虚设；
改已执行的迁移不会报错，只是让两台机器的表结构悄悄分叉。
**数据库里"没报错"不等于"对了"**，这是从 demo 走向生产必须跨过的一道认知门槛。）
