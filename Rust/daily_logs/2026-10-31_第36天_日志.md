### 5. 【实测】【修正】`cfg.route` 与 `web::resource` 的方法不匹配行为不同

同一天做的对照实验（actix-web 4.18.1，对 `/todos` 发 `PUT`）：

```text
COMPARE cfg.route=404 Not Found web::resource=405 Method Not Allowed
```

- `cfg.route("/todos", get)` + `cfg.route("/todos", post)` → **404**
- `web::resource("/todos").route(get).route(post)` → **405**

原因：`cfg.route()` 每次注册一个**独立** resource，各管一个方法；
方法不匹配 → 整条 resource 不匹配 → 落到 `default_service` → 404。
合并成一个 resource 后，"资源存在、方法不支持"才是 405（RFC 9110）。

**据此把 `configure()` 改成 resource 式**，并把这条写成了断言
（`collection_rejects_put`）。这也补全了第 35 天那条笔记——
当时只写了"两个 `web::resource` 导致 405"，没意识到 `cfg.route` 是另一种行为。

## 📖 知识点摘要（来自材料，非学习心得）

### 1. 测试的价值不是"证明对"，是"改坏时立刻响"
一条测试有没有用，只问一个问题：**它在什么情况下会失败？**
答不出来 → 它在保护 0 行代码，但占着"已覆盖"的心理位置。

### 2. `#[cfg(test)]` 与 `#[test]` 分工不同
- `#[cfg(test)]` 控制**编不编译**（决定测试代码进不进正式构建）
- `#[test]` 控制**跑不跑**
两个都要写。只写 `#[test]` 会把测试代码连同 `assert!` 一起编进发布二进制。

### 3. `tests/` 是独立 crate，这是能力边界也是设计约束
所以：
- 它只能看到 `pub`，**测不了 private**（想测私有函数就写回 `src` 里）
- 它 `use todo_api::...`，**包必须有 lib target**，否则 `unresolved import`

第二条是今天真正动手改代码的原因。

### 4. 测试漂移：测试里重写一遍装配 = 测了另一个东西
如果测试自己再写一遍 `.route(...)`，那"测试的路由"和"线上的路由"
就是两份代码。改了一处忘了另一处，测试持续通过而线上已经 404。
所以路由装配必须收敛成一个 `configure(cfg: &mut ServiceConfig)`，
`main.rs` 和 `tests/` 都调它。

### 5. 测试默认并行 → 共享资源 = 确定性冲突
不是"偶发 bug"，只是出现顺序随机。三种处理：
不共享（每测试一个库）> 串行（`--test-threads=1`）> 真共享但只读（`OnceLock`）。

判断依据：**单独过、一起挂** → 先查共享资源，别怀疑被测代码。

### 6. 清理要挂在 `Drop` 上，不能写在测试末尾
测试失败会 panic，panic 之后"最后那句 `remove_dir_all`"永远执行不到。
`Drop` 在 unwind 过程中一定执行，这是 RAII 的用处之一——
不止管内存，也管"测试跑完机器要干净"。

### 7. Windows 上删 SQLite 文件会撞"文件被占用"
`pool.close().await` 已返回，WAL 的 `-shm` 内存映射还没解完，
单次删除和它赛跑，输赢看调度。**重试**，不要 `sleep` 猜时间。

## ❓ 遇到的问题与解决

### 问题 1：默认 `rustc` 是 edition 2015，`async` 直接被当成标识符

**现象**：抓测试的报错时先看到 `error[E0670]: async fn is not allowed in Rust 2015`。
**解决**：所有示例统一加 `--edition 2021`。
**教训**：本目录的单文件材料一直靠 `rustc xxx.rs` 直接跑，
不带 edition 就用 2015——写 `async`、`dyn` 之外的现代语法时容易踩到。

### 问题 2：`tempfile` 依赖下载超时，被迫重新设计

**现象**：

```text
error: failed to download from `https://static.crates.io/crates/tempfile/3.27.0/download`
Caused by: [28] Timeout was reached
```

**解决**：撤销该 dev-dependency（`Cargo.lock` 里新增的 4 个包也一并清掉），
手写 25 行 `TempDirGuard`（`Drop` + 重试）。
**收获**：这反而逼出了本日最有价值的一段代码——
先写的是"关池后 `remove_dir_all` 一次"，实测才暴露两个坑（见下条）。
**教训**：`tempfile` 的真正价值就是"drop 时清理"，这一条自己写得起。
**顺带**：`cargo test` 会把不再被引用的包从 `Cargo.lock` 里自动剔除，
不需要手工编辑锁文件。

### 问题 3：8 个测试里 2 个清理失败（os error 32）

**现象**：

```text
CLEANUP_ERR 另一个程序正在使用此文件，进程无法访问。 (os error 32)
```

**原因**：单次 `remove_dir_all` 与 WAL 的 `-shm` 内存映射解映射赛跑。
**解决**：清理搬进 `Drop`（覆盖 panic 路径）+ 重试 10 次 × 50ms。
**结果**：再跑一轮，8/8 删除成功，残留 0 个。
**教训**：`pool.close().await` 返回 **不等于** 文件句柄已被 OS 释放。
涉及外部资源时，"调用返回"和"资源真的没了"是两件事。

### 问题 4：【修正】"内存库每连接一个独立库"是错的

**现象**：我给测试写注释、给练习写提示，都说 `sqlite::memory:`
在池里"每条连接是独立的库"。为了严谨去验证——
同时持有两条连接，连接 1 建表，连接 2 能查到：

```text
TWO_CONNS_SAME_DB=Ok("shared")
```

**原因**：`sqlx-sqlite-0.8.6/src/options/parse.rs` 把 `:memory:` 改写成

```rust
options.in_memory = true;
options.shared_cache = true;
options.filename = format!("file:sqlx-in-memory-{seqno}");
```

具名 + 共享缓存 → **同一个池的所有连接看到同一个库**。
**解决**：回改两处（`tests/api.rs` 的说明、`28_testing.rs` 练习 7 的提示）。
**同时**给出了"那为什么还用临时文件"的**正确**理由：
内存库用不上 WAL，而线上正是 `journal_mode(Wal)`——
用内存库测试等于**永远不测 WAL 那条路径**。

**教训**：这类"听起来很像真的"的结论最危险——它不影响代码编译，
只影响你**以为**自己测了什么。写进材料之前必须跑一次。

> 第一次实验其实设计错了：先 `drop(c1)` 再取连接，
> 池把**同一条**空闲连接还给了我，于是"能查到表"什么也证明不了。
> 改成**同时持有两条**才有效。

### 问题 5：块注释提前结束，43 个编译错误

**现象**：改 `tests/api.rs` 末尾那段说明时，`cargo test` 报

```text
error: expected item, found `[`
  --> tests\api.rs:520:1
```

**原因**：那段说明原本是**一个**块注释，里面包含两小节
（【为什么不用内存库】和【已知局限】）。
我只替换了前半部分，并在新内容末尾加了 `*/`——
于是注释提前关闭，后半部分变成了"代码"。
**教训**：跟第 35 天的 `E0758`（注释嵌套）是同源问题：
**块注释的边界比内容更容易出错**。改动带 `*/` 的片段后要整段复看。

### 问题 6：Windows 下用 curl 发中文 JSON 变成非法 UTF-8

**现象**：

```text
Json deserialize error: invalid unicode code point at line 1 column 15
```

**原因**：Git Bash 把命令行里的中文按 GBK 传给了 `curl`（或反之），
请求体不是合法 UTF-8。**不是服务端的问题**。
**解决**：冒烟测试改用 ASCII（`"smoke"`）；要发中文就写进文件再用
`--data-binary @body.json`。
**教训**：手工验证时"请求失败"要先把"请求本身是否合法"排掉，
否则会去改根本没坏的服务端代码。
