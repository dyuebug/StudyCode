## 📖 学到的知识点

### 迭代器（已学）

1. **Iterator trait**：核心方法 `next() -> Option<Self::Item>`
2. **三种迭代方法**：iter()、into_iter()、iter_mut()
3. **消费器**：collect、sum、fold、count、any、all
4. **适配器**：map、filter、take、skip、enumerate
5. **惰性求值**：适配器不立即执行，消费器触发
6. **链式调用**：组合多个操作，代码简洁
7. **零成本抽象**：性能和手写循环一样

### HTTP 服务器项目（实战）

8. **TCP 网络编程**：
   - TcpListener::bind() 监听端口
   - TcpStream 表示连接
   - Read/Write trait 读写数据

9. **HTTP 协议**：
   - 请求格式：请求行 + 请求头 + 空行 + 请求体
   - 响应格式：状态行 + 响应头 + 空行 + 响应体
   - 状态码：200 OK、404 NOT FOUND

10. **路由系统**：
    - 解析请求行（GET /path HTTP/1.1）
    - 路径匹配（/, /about, /sleep, 404）
    - 返回不同内容

11. **文件服务**：
    - fs::read_to_string 读取文件
    - Content-Type 设置响应类型
    - Content-Length 设置响应大小

### 并发编程（深入）

12. **线程基础**：
    - thread::spawn(闭包) 创建线程
    - move 关键字转移所有权
    - join() 等待线程完成
    - 获取线程返回值

13. **消息传递（Channel）**：
    - mpsc::channel() 创建通道
    - Sender::send() 发送消息
    - Receiver::recv() 接收消息
    - 多生产者：克隆 Sender
    - rx 是迭代器

14. **互斥锁（Mutex）**：
    - Mutex::new() 创建锁
    - lock() 获取锁，返回 MutexGuard
    - MutexGuard 自动释放锁
    - 保证同一时间只有一个线程访问

15. **原子引用计数（Arc）**：
    - Arc::new() 创建共享所有权
    - Arc::clone() 增加引用计数
    - 线程安全的引用计数（Rc 的多线程版本）

16. **Arc<Mutex<T>> 组合**：
    - 多线程共享可变数据的标准模式
    - Arc 提供共享所有权
    - Mutex 提供内部可变性

17. **读写锁（RwLock）**：
    - read() 获取读锁（多个读者）
    - write() 获取写锁（一个写者）
    - 读多写少场景更高效

18. **线程池模式**：
    - 固定数量的工作线程
    - 任务队列（通道）
    - 生产者-消费者模式
    - Worker 线程循环接收任务

19. **Send 和 Sync trait**：
    - Send：可以在线程间转移所有权
    - Sync：可以在线程间共享引用
    - 编译器自动实现
    - 保证线程安全

20. **并发模式**：
    - 消息传递：所有权转移，适合任务分发
    - 共享状态：Arc + Mutex，适合共享数据
    - 生产者-消费者：线程池的核心模式

### 关于并发编程

**并发编程是 Rust 的核心优势！**

"Fearless Concurrency"（无畏并发）不是口号，是现实：
- 编译器保证无数据竞争
- 所有权系统保证线程安全
- 不需要运行时开销

**并发模式选择**：
- 任务分发？→ 消息传递（channel）
- 共享数据？→ Arc + Mutex
- 读多写少？→ RwLock

**线程池模式的优雅**：
- 固定线程数：避免线程爆炸
- 任务队列：解耦生产和消费
- 通道通信：清晰的数据流

### 关键理解

**1. 所有权系统 + 并发 = 完美组合**
- 所有权保证内存安全
- Send/Sync trait 保证线程安全
- 编译期检查，零运行时开销

**2. Arc<Mutex<T>> 的必然性**
- Arc：多线程需要共享所有权
- Mutex：共享数据需要同步访问
- 两者缺一不可

**3. 消息传递 vs 共享状态**
- 消息传递：Go 风格，"不要通过共享内存通信，而要通过通信共享内存"
- 共享状态：传统风格，直接访问共享数据
- Rust 两者都支持，根据场景选择

**4. 零成本抽象的现实意义**
- 迭代器 = 手写循环性能
- 线程池 = 原始线程性能
- 高级抽象 ≠ 性能损失
