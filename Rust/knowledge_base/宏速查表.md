# 宏速查表（Rust Macros）

> 对应学习材料：`rust_basics/20_macros.rs`（第 28 天）
> 本表只放"要用的时候能立刻查到"的东西；为什么这么设计的推导在材料里。

---

## 1. 一句话

宏是**在编译期展开的代码模板**。它操作的是**词法树（token tree）**，不是文本。
所以没有 C 的 `#define SQUARE(x) x*x` → `SQUARE(1+2)` 得到 `1+2*1+2` 这种灾难。

## 2. 声明宏 `macro_rules!`

### 骨架

```rust
macro_rules! 名字 {
    // 一条规则：左边是模式，右边是展开结果
    ($x:expr) => { $x + 1 };
}

// 多条规则：从上到下匹配，第一条匹配成功就用它
macro_rules! 多规则 {
    ($x:expr) => { $x + 1 };
    ($a:expr, $b:expr) => { $a + $b };
}

// 重复：$( ... ) 分隔符 重复算子
macro_rules! 求和 {
    ($($x:expr),*) => { 0 $(+ $x)* };
    ($($x:expr),+ ,) => { 求和!($($x),+) };   // 容忍尾逗号
}
```

### 片段说明符（最常查的一张表）

| 说明符 | 匹配什么 | 典型用途 |
|---|---|---|
| `expr` | 表达式 | `println!` 的参数 |
| `ty` | 类型 | `vec![T; n]` |
| `ident` | 标识符 | 生成函数名/变量名 |
| `path` | 路径（`a::b::C`） | 引用外部类型 |
| `pat` | 模式 | `matches!` |
| `stmt` | 语句 | 语句级宏 |
| `tt` | **单个词法树** | 万能兜底，过程宏转发 |
| `item` | 项（fn/struct/impl） | 生成批量函数 |
| `block` | 块 `{...}` | 生成作用域 |
| `literal` | 字面量 | 编译期常量检查 |
| `meta` | 属性内容 | `#[cfg(...)]` 转发 |
| `vis` | 可见性 `pub` | 生成批量 API |
| `lifetime` | `'a` | 生命周期生成 |

### 重复算子

| 算子 | 含义 |
|---|---|
| `*` | 0 次或多次 |
| `+` | 1 次或多次 |
| `?` | 0 次或 1 次 |

### 两个必记的细节

- **卫生性（hygiene）**：宏内部 `let x = 1;` 不会污染调用处的 `x`。
- **`$crate`**：宏里引用自己 crate 的项必须写 `$crate::foo()`，
  否则调用方一 `use` 到同名项就炸。

## 3. 三种过程宏

| 类型 | 写法 | 例子 |
|---|---|---|
| derive | `#[proc_macro_derive(Name)]` | `#[derive(Debug, Clone)]` |
| attribute | `#[proc_macro_attribute]` | `#[actix_web::main]`、`#[tokio::test]` |
| function-like | `#[proc_macro]` | `sqlx::query!`、`serde_json::json!` |

**硬约束**：过程宏只能定义在 `proc-macro = true` 的 crate 里，
且该 crate **不能再导出其他东西**。所以生态里全都是 `xxx-derive` 独立包
（`serde` / `serde_derive`）。

## 4. 本项目里真实用到的宏

| 宏 | 类型 | 出现位置 | 为什么必须用宏 |
|---|---|---|---|
| `include_str!("../static/chat.html")` | 内建 function-like | `realtime-chat/src/lib.rs` | 把文件**编译期**塞进二进制；函数做不到（参数必须是编译期常量） |
| `format!` / `println!` / `write!` | 内建 | 全项目 | 可变参数 + 格式串校验，函数不支持变参 |
| `serde_json::json!` | 过程宏 | `realtime-chat/tests/ws.rs`、`task-manager/tests/api.rs` | 用字面量语法构造 `Value`，比手写 `Value::Object` 树短一个数量级 |
| `#[tokio::test]` / `#[actix_web::test]` | attribute 过程宏 | `tests/ws.rs`、`tests/api.rs` | 把 `async fn` 包成同步测试入口 |
| `#[derive(Debug, Clone)]` | derive | 全项目 | 手写 `impl` 纯样板 |
| `vec![]` / `assert_eq!` | 内建 | 全项目 | — |

> `include_str!` 有一个真实代价：**改了 HTML，回滚/缓存的判断只看二进制**。
> 第 42 天 Docker 那次的 stub 二进制事故与之同族——
> 构建系统认的是"文件有没有变"，不是"你以为有没有变"。

## 5. 踩过的坑

### 5.1 宏展开后报错指向调用处，不指向宏体

```
error[E0308]: mismatched types
 --> src/main.rs:12:5
  |
12|     my_macro!(1, "a");     ← 错误在这里被指出，但问题在宏定义里
```

定位手段：`cargo expand`（需 `cargo install cargo-expand`，本项目**未实测**）。
退而求其次：把宏体拆成普通函数，先让函数编过，再包回宏。

### 5.2 块注释里写 `**/` 会提前结束注释

第 43 天实测：在 `/* ... */` 里写 GitHub 的递归 glob `**/Cargo.lock`，
其中的 `*/` 被当成注释结束标记，后面的 YAML 全被当 Rust 解析：

```
error: prefix `lock` is unknown
error[E0762]: unterminated character literal
```

Rust 块注释**支持嵌套**，所以这个错特别难找。写文档时把 `**/` 拆开。

### 5.3 宏里用了外部项却没写 `$crate`

调用方 `use` 了同名项 → 宏展开后指向调用方的那个 → 报"类型不匹配"，
而错误信息完全不提宏。规则：宏体内引用本 crate 的项**一律** `$crate::`。

## 6. 什么时候该用宏（判断清单）

- [ ] 需要**可变参数**？→ 宏（函数不行）
- [ ] 需要在**编译期**报错（如"这个常量必须是 2 的幂"）？→ 宏
- [ ] 需要**生成一批**结构相同的代码（N 个类型的 impl）？→ 宏
- [ ] 需要**扩展语法**（`json!` 那种字面量写法）？→ 宏
- [ ] 以上都不是？→ **写函数**。宏的调试成本、错误信息质量都明显更差

原则：**能用函数就别用宏**。宏是最后手段，不是"高级"的代名词。
