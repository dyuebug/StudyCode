# 「静默失败」检查清单

> 这个仓库里反复出现同一族问题：**失败不吭声，成功也是假的**。
> 本清单把它整理成"症状 → 检查动作"，全部条目都有实测来源。
> 生成日期：2026-11-08（第 44 天）

---

## 0. 为什么单独成文

一周之内撞了 10 次同一族问题（第 39–43 天）。
它们的表面形态完全不同——Docker、YAML、Shell、测试框架——
但内核只有一个：

> **一个应该说话的东西没说话，而我们默认"没说话 = 没问题"。**

比"报了错"危险得多：报错会让你去查，沉默会让你继续往前走。

| # | 案例 | 表面现象 | 真相 | 来源 |
|---|---|---|---|---|
| 1 | Docker `COPY` 保留构建上下文的旧 mtime | 构建成功；容器 `Exited (0)`；`docker logs` **完全空白** | 镜像里是 `fn main() {}` 的 stub 二进制。构建日志里 `#15 DONE 0.4s` —— 编一个 actix-web 应用不可能这么快 | 第 42 天实测 |

| 5 | workflow 放在子项目目录 | 文件在、YAML 格式对 | GitHub 只读**仓库根** `.github/workflows/`；子目录里的永不运行，且不报错 | 第 43 天查证 |
| 6 | "本地零警告" | 一直显示零警告 | `cargo build` **不编译** `tests/`、`examples/`。`clippy --all-targets` 一开就报 3 个 `useless_conversion`，退出码 101 | 第 43 天实测 |
| 7 | 并发 `>>` 追加写同一文件 | 压测"全成功" | 200 个请求只记到 105 行——**测量工具本身在丢数据，而且丢得很像真的** | 第 39 天实测 |
| 8 | 只加 `Lagged` 处理就算"防僵尸连接" | 代码里有 `Err(Lagged)` 分支 | 它拦的是"读得慢"，**拦不住"根本不读"**（那些客户端卡在 `Session` 内部 32 槽 mpsc，走不到 `rx.recv()`）。实测僵尸连接一直挂着 | 第 40 天实测 |
| 9 | `docker run -w /probe` | 命令执行了 | Git Bash 把 `/probe` 转成 `C:/Program Files/Git/probe`。命令跑了，跑的不是你以为的那个路径 | 第 42 天实测 |
| 10 | Windows 上 `Drop` 里删临时目录 | 测试通过 | 文件占用导致删除失败，而 `Drop` **不能返回错误**。9 个残留目录（已清理） | 第 36–39 天实测 |
| 11 | 测试里 `eprintln!("跳过：…"); return;` | 计入当次 `N passed` | 那条测试什么都没验证，只是没失败。它和真通过**在计数上完全一致**（当时 file-manager 报 15 passed，其中 1 条是跳过的）。改法：让跳过变成 `#[ignore]`（会被单独计数），或换一条能真正跑的路 | 第 45 天实测 |
| 12 | `rustup target add …` 无网络 | 前 25 s **完全无输出**；约 60 s 才吐出 `source: TimedOut`，随后**自动重试且无次数上限** | 它既不是"快速失败"也不是"一直沉默"：先沉默一分钟，再无限重试。只等 25 s 会误判为挂死，只看到 `TimedOut` 一行就以为结束了——其实进程还在跑。**必须用 `timeout` 设硬界**（实测 60 s 被杀于 124） | 第 45–46 天实测 |

## 2. 症状 → 检查动作

### 2.1 命令"成功"了

| 症状 | 可能是什么 | 立刻查 |
|---|---|---|
| 退出码 0，但没有任何输出 | 命令没真正执行 / 输出被吞 / 脚本最后一条是 `echo` | 在命令前后各打一行标记，确认它被执行过 |
| 退出码 0，但耗时不正常地短 | 缓存误命中 / 目标根本没编译 / 目录不对 | 对比历史耗时；把"应该几十秒"的步骤单独计时 |
| 退出码 0，但你没看过真实退出码 | `cmd; ...` / `cmd \| tee` / `cmd &` | `set -e` + `set -o pipefail`，让退出码来自**你关心的那条命令** |
| 长时间**完全无输出**，也不返回 | 挂起：等网络、等锁、等交互输入（案例 12） | 用 `timeout 25 <cmd>` 强制设界；"没有输出"不等于"正常运行"。**注意**：有输出也不等于会结束——失败后自动重试同样会永久挂住 |

### 2.2 检查"通过"了

| 症状 | 可能是什么 | 立刻查 |
|---|---|---|
| `0 passed` 也算通过 | 测试根本没被收集（文件名、目录、feature） | 断言**汇总数量 ≥ N**，不是"存在通过行" |
| 满屏 `warning:` 但任务绿 | 没加 `-D warnings` | 警告不改变退出码，门禁必须把它变成错误 |
| "零警告"持续很久了 | 那些目标从来没被编译 | 加 `--all-targets`；或先改坏一个，确认检查会红 |
| 覆盖了某个场景，但只测了理想路径 | 闸门拦的是另一条路径（案例 8） | 问"这条闸门在哪一层？它上游还堵着什么？" |
| 测试数对得上，但有一条其实"跳过"了 | `return` 走的是**通过**分支（案例 11） | `--nocapture` 看有没有「跳过」字样；跳过请用 `#[ignore]`，它会被单独计数 |
| 计数里少了一条，不是多了一条 | 环境不支持，代码悄悄降级 | 数一遍"总共该有多少条"，对不上就逐条查 |

### 2.3 配置写了但不生效

| 症状 | 可能是什么 | 立刻查 |
|---|---|---|
| 文件在、格式对、没效果 | 位置不对（案例 5） / 被上层覆盖 / 键名写错 | 找**权威的发现规则**（读文档），不要靠"我觉得应该在这" |
| 环境变量改了但行为没变 | 读的是另一个键 / 有默认值兜底 / 进程没重启 | 让程序启动时把**读到的值**打出来 |
| 中间件/拦截器挂上了但没拦住 | 挂在 `Scope` 而非 `App`；或短路顺序不对 | 用**不带凭证的请求**逐个打接口，别读代码猜 |

## 3. 六条通用防御

### 3.1 退出码只有一个来源

```bash
set -e            # 任何一步失败就整体失败
set -o pipefail   # 管道取最左侧失败命令的退出码
```

禁止写法：`cmd; echo ok`、`cmd | tee log`（无 pipefail）、`cmd &`。

### 3.2 断言"数量"和"内容"，不只断言"有没有"

```bash
# 弱：有通过行就行
grep -q "test result: ok" log

# 强：汇总数量 ≥ N（本项目 N=10）
total=$(grep -Eo 'test result: ok\. [0-9]+ passed' log \
        | grep -Eo '[0-9]+' | awk '{s += $1} END {print s + 0}')
[ "$total" -ge 10 ] || exit 1
```

构建产物同理：

```bash
grep -aq "聊天服务" target/release/realtime-chat \
  || { echo "产物是 stub 二进制"; exit 1; }
```

### 3.3 标注来源：这个数字是谁产生的

写下来的每个数字都要能回答"怎么测的"。
不能回答的，标【推定】或删掉。
**没有来源的"实测"，比没有数据更糟。**

### 3.4 警惕"太快"，也警惕"太顺"

不该快的快了 → 没执行。
一路顺利没有任何意外 → 很可能是没真正跑到。

### 3.5 让检查能被证伪

每加一条断言，先**故意把它该拦的东西造出来**，确认它会红。
不会红的检查等于没有检查。

### 3.6 权威规则去读文档，不靠直觉

"文件放这里应该会生效吧" —— 这一句制造了本清单第 5 条。
发现机制（workflow 在哪读、配置从哪加载、钩子在哪个阶段跑）
必须查文档或实测，不能靠命名猜。

## 4. 交付前自查（可直接抄）

- [ ] 每条关键命令都确认过**真实退出码**（不是 `echo` 的、不是 `tee` 的）
- [ ] 测试有**数量断言**，且阈值写明了"加测试时要改"
- [ ] 构建有**产物断言**（产物里有一句只有真源码才有的字符串）
- [ ] 写进文档的每个数字都有来源标注，估算值标【推定】
- [ ] 至少一条断言被**反向验证**过（改坏 → 变红）
- [ ] 配置类文件的位置按**文档规则**确认过，不是按目录结构猜
- [ ] 耗时异常短的步骤都解释清楚了，解释不了的当作没执行
- [ ] 报告里区分了"本地跑通"与"目标环境跑通"
