## 📖 学到的知识点

### 1. 多态的概念

**什么是多态**：
- 多态（Polymorphism）的字面意思是"多种形态"
- 同一接口，可以有不同的实现方式
- 面向对象编程的三大特性之一（封装、继承、多态）

**多态的分类**：

**1. 编译时多态（静态多态）**
- 函数重载：同名函数，不同参数
- 运算符重载：重定义运算符行为
- 模板：类型参数化
- 特点：编译期确定调用哪个函数（静态绑定）

**2. 运行时多态（动态多态）**
- 虚函数 + 继承 + 基类指针/引用
- 特点：运行期确定调用哪个函数（动态绑定）
- 本节重点：运行时多态

**为什么需要多态**：
- 提高代码的灵活性和可扩展性
- 实现接口和实现分离
- 便于维护和扩展（开闭原则：对扩展开放，对修改关闭）

---

### 2. 虚函数（Virtual Function）⭐⭐⭐⭐⭐

**虚函数的定义**：

语法：在基类中用 `virtual` 关键字声明函数
```cpp
class Base {
public:
    virtual void func() {  // 虚函数
        cout << "Base::func()" << endl;
    }
};
```

**虚函数的重写（Override）**：
```cpp
class Derived : public Base {
public:
    void func() override {  // C++11推荐使用override关键字
        cout << "Derived::func()" << endl;
    }
};
```

**重写规则**：
- 函数名必须相同
- 参数列表必须相同（类型、个数、顺序）
- 返回类型必须相同（协变返回类型除外）
- const 修饰必须相同
- 访问权限可以不同（但不推荐）

**C++11 新特性**：
- `override`：明确标记重写虚函数，编译器会检查是否正确重写
- `final`：禁止派生类重写虚函数

---

### 3. 虚函数表（Virtual Table, vtable）⭐⭐⭐⭐⭐（面试高频考点！）

**虚函数表原理**：

**1. 虚函数指针（vptr）**
- 每个含有虚函数的对象都有一个 vptr
- vptr 存储在对象的起始位置（通常）
- vptr 指向该对象所属类的 vtable

**2. 虚函数表（vtable）**
- 每个含有虚函数的类都有一个 vtable
- vtable 存储该类所有虚函数的地址
- vtable 在编译期生成，存储在只读数据段

**3. 动态绑定过程**
- 通过基类指针/引用调用虚函数
- 通过对象的 vptr 找到 vtable
- 在 vtable 中找到对应虚函数的地址
- 调用该地址的函数

**对象内存布局**：
```
Shape 对象：
┌─────────────┐
│   vptr      │ ← 虚函数指针（8字节，64位系统）
└─────────────┘

Circle 对象：
┌─────────────┐
│   vptr      │ ← 8字节（指向Circle::vtable）
├─────────────┤
│  _radius    │ ← 8字节（double）
└─────────────┘

虚函数表（Circle::vtable）：
┌─────────────────┐
│ Circle::draw    │ ← 重写的虚函数
├─────────────────┤
│ Circle::area    │ ← 重写的虚函数
├─────────────────┤
│ Circle::~Circle │ ← 虚析构函数
└─────────────────┘
```

**实践验证**：
```
没有虚函数的类，对象大小：4 字节（只有数据成员）
有虚函数的类，对象大小：16 字节（数据成员 + vptr + 内存对齐）

Shape 对象大小：8 字节（包含 vptr）
Circle 对象大小：16 字节（包含 vptr + _radius）
Rectangle 对象大小：24 字节（包含 vptr + _width + _height）
```

**结论**：
- ✅ 含有虚函数的对象包含 vptr
- ✅ vptr 占用额外的内存空间（8字节）
- ✅ 不同类型的对象有各自的 vtable

### 4. 动态绑定和静态绑定

**静态绑定（编译时绑定）**：
- 编译期确定调用哪个函数
- 通过对象调用（即使是虚函数）
- 效率更高

```cpp
Circle c(5.0);
c.draw();  // 静态绑定，编译期确定调用 Circle::draw()
```

**动态绑定（运行时绑定）**：
- 运行期通过 vptr 和 vtable 确定调用哪个函数
- 必须通过基类指针或引用调用虚函数
- 实现多态

```cpp
Shape* p = new Circle(5.0);
p->draw();  // 动态绑定，运行期调用 Circle::draw()
```

**动态绑定的条件**（必须同时满足）⭐⭐⭐⭐⭐：
1. 必须是虚函数
2. 必须通过基类指针或引用调用

**实践验证**：
```
【静态绑定：通过对象调用】
绘制圆形，半径 = 5    ← 静态绑定
绘制图形              ← 静态绑定

【动态绑定：通过基类指针调用】
绘制圆形，半径 = 5    ← 动态绑定（Circle::draw）
绘制矩形，宽 = 4, 高 = 6  ← 动态绑定（Rectangle::draw）
```

### 5. 纯虚函数和抽象类

**纯虚函数**：

语法：在虚函数声明后加 `= 0`
```cpp
class Animal {
public:
    virtual void makeSound() const = 0;  // 纯虚函数
    virtual void move() const = 0;       // 纯虚函数
};
```

特点：
- 没有函数体（不需要实现）
- 必须由派生类实现
- 用于定义接口

**抽象类**：

定义：包含纯虚函数的类称为抽象类

特点：
- 不能实例化（不能创建对象）
- 可以有构造函数和析构函数
- 可以有普通成员函数和数据成员
- 派生类必须实现所有纯虚函数，否则也是抽象类

作用：
- 定义接口（类似Java的interface）
- 强制派生类实现特定功能
- 实现接口和实现分离

**实践验证**：
```cpp
// Animal a;  // ❌ 错误：抽象类不能实例化

class Dog : public Animal {
public:
    void makeSound() const override {  // 必须实现
        cout << "汪汪汪！" << endl;
    }
    void move() const override {       // 必须实现
        cout << "狗在跑" << endl;
    }
};

Dog dog;  // ✅ 正确：派生类实现了所有纯虚函数
```

### 6. 虚析构函数 ⭐⭐⭐⭐⭐（超级重要！）

**规则：基类的析构函数必须是虚函数！**

**为什么？**
- 防止内存泄漏
- 确保派生类的析构函数被正确调用

**错误示例（没有虚析构函数）**：
```cpp
class Base {
public:
    ~Base() { }  // ❌ 非虚析构函数
};

class Derived : public Base {
public:
    ~Derived() { delete[] data; }  // 释放资源
private:
    int* data;
};

Base* p = new Derived();
delete p;  // ❌ 问题：只调用~Base()，不调用~Derived()
           // 结果：内存泄漏！data没有被释放
```

**实践验证**：
```
【错误示例：没有虚析构函数】
BaseWithoutVirtualDestructor构造
DerivedWithResource构造，分配了资源
BaseWithoutVirtualDestructor析构    ← ❌ 只调用基类析构
（注意：派生类析构没有被调用，资源没有释放！）
```

**正确做法（有虚析构函数）**：
```cpp
class Base {
public:
    virtual ~Base() { }  // ✅ 虚析构函数
};

delete p;  // ✅ 正确：先调用~Derived()，再调用~Base()
```

**实践验证**：
```
【正确示例：有虚析构函数】
BaseWithVirtualDestructor构造
DerivedWithResourceCorrect构造，分配了资源
DerivedWithResourceCorrect析构，释放了资源  ← ✅ 先调用派生类析构
BaseWithVirtualDestructor析构              ← ✅ 再调用基类析构
```

**记忆技巧**：
- 只要类会被继承，析构函数就应该是虚函数
- 如果类中有虚函数，析构函数也应该是虚函数
- 这是C++最重要的规则之一！

## ❓ 遇到的问题与解决

### 问题1：为什么通过对象调用虚函数不是动态绑定？

**解答**：
这是很多人容易混淆的地方。

**原理**：
- 通过对象调用时，编译期就知道对象的确切类型
- 编译器直接生成调用该类型函数的代码
- 不需要通过 vptr 查找 vtable
- 效率更高

**示例**：
```cpp
Circle c(5.0);
c.draw();  // 编译期知道 c 是 Circle 类型，直接调用 Circle::draw()
```

**动态绑定的条件**：
1. 必须是虚函数
2. 必须通过基类指针或引用调用

**结论**：
- 对象调用：静态绑定（编译期确定）
- 指针/引用调用：动态绑定（运行期确定）

---

### 问题2：虚函数表是如何工作的？

**解答**：
虚函数表是实现动态绑定的关键机制。

**原理**：

**编译期**：
1. 每个含有虚函数的类生成一个 vtable
2. vtable 存储该类所有虚函数的地址
3. 如果派生类重写了虚函数，vtable 中存储重写后的函数地址

**运行期**：
1. 每个对象包含一个 vptr，指向类的 vtable
2. 通过基类指针调用虚函数时，通过 vptr 找到 vtable
3. 在 vtable 中找到对应虚函数的地址
4. 调用该地址的函数

**实践验证**：
```
Shape 对象大小：8 字节（包含 vptr）
Circle 对象大小：16 字节（包含 vptr + _radius）

没有虚函数的类，对象大小：4 字节
有虚函数的类，对象大小：16 字节（多了 vptr）
```

**结论**：
- vptr 占用额外的内存空间（8字节，64位系统）
- 动态绑定需要额外的间接调用开销
- 但换来了灵活性和可扩展性

---

### 问题3：为什么基类析构函数必须是虚函数？

**解答**：
这是C++最重要的规则之一！

**问题场景**：
```cpp
class Base {
public:
    ~Base() { }  // 非虚析构函数
};

class Derived : public Base {
public:
    ~Derived() { delete[] data; }  // 释放资源
private:
    int* data;
};

Base* p = new Derived();
delete p;  // 问题：只调用~Base()，不调用~Derived()
```

**实践验证**：
```
【错误示例：没有虚析构函数】
BaseWithoutVirtualDestructor构造
DerivedWithResource构造，分配了资源
BaseWithoutVirtualDestructor析构    ← 只调用基类析构

结果：派生类的析构函数没有被调用，资源没有释放（内存泄漏）
```

**正确做法**：
```cpp
class Base {
public:
    virtual ~Base() { }  // 虚析构函数
};

delete p;  // 先调用~Derived()，再调用~Base()
```

**实践验证**：
```
【正确示例：有虚析构函数】
BaseWithVirtualDestructor构造
DerivedWithResourceCorrect构造，分配了资源
DerivedWithResourceCorrect析构，释放了资源  ← 先调用派生类析构
BaseWithVirtualDestructor析构              ← 再调用基类析构
```

**结论**：
- 基类析构函数必须是虚函数
- 否则 delete 基类指针时，只调用基类析构，导致内存泄漏
- 这是C++多态编程的基本要求

## 💭 今日心得

### 1. 多态是面向对象的精华

今天学习了多态和虚函数机制，最大的感受是：
- **多态让程序设计更加灵活**
- 同一接口，不同实现
- 易于扩展和维护

**理解了多态的价值**：
- 开闭原则：对扩展开放，对修改关闭
- 新增派生类不需要修改现有代码
- 通过基类指针/引用统一处理不同类型的对象

### 2. 虚函数表机制很巧妙

**vptr + vtable 的设计非常优雅**：
- 每个对象只包含一个 vptr（8字节）
- 相同类型的对象共享同一个 vtable（节省内存）
- 运行期通过 vptr 找到 vtable，实现动态绑定

**理解了动态绑定的原理**：
- 编译期生成 vtable
- 运行期通过 vptr 查找 vtable
- 多态的开销：vptr 占用内存 + 间接调用

### 3. 虚析构函数极其重要

**这是C++最重要的规则之一**：
- 基类析构函数必须是虚函数
- 否则会导致内存泄漏

**实践验证了问题**：
- 没有虚析构函数：只调用基类析构，派生类资源没有释放
- 有虚析构函数：先调用派生类析构，再调用基类析构

**记住了规则**：
- 只要类会被继承，析构函数就应该是虚函数
- 如果类中有虚函数，析构函数也应该是虚函数

### 4. 动态绑定的条件要牢记

**动态绑定的条件**（必须同时满足）：
1. 必须是虚函数
2. 必须通过基类指针或引用调用

**常见误区**：
- 以为只要是虚函数就会动态绑定
- 其实通过对象调用是静态绑定

**记住了规则**：
- 对象调用：静态绑定（编译期确定）
- 指针/引用调用：动态绑定（运行期确定）
