## 📖 学到的知识点

### 1. 友元（Friend）

**什么是友元**：
- 友元可以访问类的私有成员
- 用 `friend` 关键字声明
- 打破了封装，但提供了灵活性

**三种形式**：
1. **普通函数友元**
2. **成员函数友元**
3. **友元类**

**普通函数友元示例**：
```cpp
class Point {
private:
    int _x, _y;
public:
    friend float distance(const Point& a, const Point& b);
};

float distance(const Point& a, const Point& b) {
    // 可以访问 a._x, a._y, b._x, b._y
    return sqrt((a._x - b._x)*(a._x - b._x) + 
                (a._y - b._y)*(a._y - b._y));
}
```

**关键理解**：
- 友元打破了封装，要谨慎使用
- 友元不是成员函数，不能用 this
- 友元声明在类内，定义在类外

### 2. 运算符重载的概念

**什么是运算符重载**：
- 让自定义类型可以使用运算符
- 指导思想：**让自定义类型与内置类型保持一致**

**运算符重载的本质** ⭐⭐⭐⭐⭐：
- **运算符重载本质上是函数**
- `a + b` 等价于 `a.operator+(b)` 或 `operator+(a, b)`
- 只是语法糖，编译器会转换为函数调用

**示例**：
```cpp
Complex c1(1, 2), c2(3, 4);
Complex c3 = c1 + c2;  // 语法糖
// 等价于：
Complex c3 = operator+(c1, c2);  // 友元函数
// 或：
Complex c3 = c1.operator+(c2);   // 成员函数
```

---

### 3. 可重载/不可重载的运算符

**可重载的运算符**（42个）：
- 算术：`+`、`-`、`*`、`/`、`%`
- 关系：`==`、`!=`、`<`、`>`、`<=`、`>=`
- 逻辑：`&&`、`||`、`!`
- 位运算：`&`、`|`、`^`、`~`、`<<`、`>>`
- 赋值：`=`、`+=`、`-=`、`*=`、`/=`、`%=`
- 自增自减：`++`、`--`
- 其他：`[]`、`()`、`->`、`,`、`new`、`delete`

**不能重载的运算符**（记忆口诀：**带点的运算符 + sizeof**）：
- `::`（作用域解析）
- `.`（成员访问）
- `.*`（成员指针访问）
- `?:`（三目运算符）
- `sizeof`

---

### 4. 运算符重载的规则 ⭐⭐⭐⭐⭐（重点）

**6条规则**：
1. **至少有一个操作数是自定义类型**（不能全是内置类型）
2. **优先级和结合性不变**
3. **操作数个数保持不变**
4. **不能设置默认参数**
5. **不能臆造新运算符**
6. **保持运算符的原有语义**

**最重要的规则**：保持运算符的原有语义
- `+` 应该表示加法
- `==` 应该表示相等比较
- 不要滥用运算符重载（如用 `+` 表示减法）

---

### 5. 运算符重载的三种形式

#### **形式1：友元函数**（推荐用于不修改操作数的运算符）

```cpp
class Complex {
private:
    double _real, _imag;
public:
    friend Complex operator+(const Complex& lhs, const Complex& rhs);
};

Complex operator+(const Complex& lhs, const Complex& rhs) {
    return Complex(lhs._real + rhs._real, lhs._imag + rhs._imag);
}

// 使用
Complex c3 = c1 + c2;  // 等价于 operator+(c1, c2)
```

**特点**：
- 两个操作数都是参数
- 对称性好
- 需要友元访问私有成员

---

#### **形式2：成员函数**（推荐用于修改操作数的运算符）

```cpp
class Complex {
private:
    double _real, _imag;
public:
    Complex operator+(const Complex& rhs) const {
        return Complex(_real + rhs._real, _imag + rhs._imag);
    }
};

// 使用
Complex c3 = c1 + c2;  // 等价于 c1.operator+(c2)
```

**特点**：
- 左操作数是 this 指针
- 参数列表只有右操作数
- 可以直接访问私有成员

---

#### **形式3：普通函数**（不推荐）

```cpp
class Complex {
public:
    double getReal() const { return _real; }
    double getImag() const { return _imag; }
private:
    double _real, _imag;
};

Complex operator+(const Complex& lhs, const Complex& rhs) {
    return Complex(lhs.getReal() + rhs.getReal(), 
                   lhs.getImag() + rhs.getImag());
}
```

**缺点**：
- 需要提供 getter 函数
- 几乎完全失去了对私有成员的保护
- **不推荐使用**

---

### 6. 重载形式的选择 ⭐⭐⭐⭐⭐（重点）

**选择原则**：

| 运算符类型 | 推荐形式 | 原因 |
|-----------|---------|------|
| 不修改操作数（+、-、*、/） | 友元函数 | 对称性，不修改 this |
| 修改操作数（+=、-=、++、--） | 成员函数 | 需要修改 this |
| =、[]、()、->、->* | **必须**成员函数 | C++ 语法规定 |
| <<、>> | **必须**友元函数 | 左操作数是流对象 |

**记忆方法**：
- 修改左操作数 → 成员函数
- 不修改操作数 → 友元函数
- 流操作符 → 必须友元函数（cout 是左操作数）

---

### 7. 常用运算符重载详解

#### **+ 运算符**（友元函数）

```cpp
friend Complex operator+(const Complex& lhs, const Complex& rhs) {
    return Complex(lhs._real + rhs._real, lhs._imag + rhs._imag);
}
```

**要点**：
- 不修改操作数，使用 const 引用
- 返回新对象（值）
- 友元函数形式

---

#### **+= 运算符**（成员函数）

```cpp
Complex& operator+=(const Complex& rhs) {
    _real += rhs._real;
    _imag += rhs._imag;
    return *this;  // 返回自身引用
}
```

**要点**：
- 修改左操作数（this）
- 返回自身引用（支持链式调用）
- 成员函数形式

---

#### **++ 运算符**（前置 vs 后置）⭐⭐⭐⭐⭐

```cpp
// 前置++：先自增，返回自身引用
Counter& operator++() {
    ++_count;
    return *this;
}

// 后置++：先返回副本，再自增
// int 是哑元参数，仅用于区分前置和后置
Counter operator++(int) {
    Counter tmp(*this);  // 保存当前值
    ++_count;            // 自增
    return tmp;          // 返回旧值
}
```

**关键区别**：

| 特性 | 前置++ | 后置++ |
|------|--------|--------|
| 返回值 | 引用 | 副本 |
| 效率 | 高（无需创建临时对象） | 低（需要创建临时对象） |
| 语义 | 先自增，返回自增后的值 | 先返回旧值，再自增 |
| 参数 | 无参数 | int 哑元参数 |

**实践验证**：
```
Counter c3(10);
Counter c4 = ++c3;  // 前置：c3先自增，c4得到11
// 结果：c3=11, c4=11

Counter c5(10);
Counter c6 = c5++;  // 后置：c6得到旧值10，c5再自增
// 结果：c5=11, c6=10
```

**推荐**：优先使用前置++，效率更高

---

#### **[] 运算符**（成员函数）

```cpp
char& operator[](size_t idx) {
    if (idx < _size) {
        return _data[idx];
    } else {
        cout << "下标越界！" << endl;
        static char nullchar = '\0';
        return nullchar;
    }
}
```

**要点**：
- 返回引用（可以修改元素）
- 检查边界
- 必须是成员函数

---

#### **<< 运算符**（友元函数）⭐⭐⭐⭐⭐

```cpp
friend ostream& operator<<(ostream& os, const Complex& c) {
    os << c._real << "+" << c._imag << "i";
    return os;  // 返回流引用，支持链式调用
}

// 使用
cout << c1 << endl;  // 等价于 operator<<(cout, c1)
```

**要点**：
- 必须是友元函数（左操作数是 ostream）
- 返回流引用（支持链式调用）
- 不能是成员函数（否则 `c1 << cout`）

**链式调用**：
```cpp
cout << c1 << ", " << c2 << endl;
// 等价于：
operator<<(operator<<(operator<<(cout, c1), ", "), c2) << endl;
```

---

#### **= 运算符**（赋值运算符）

```cpp
MyString& operator=(const MyString& rhs) {
    if (this != &rhs) {  // 防止自赋值
        // 释放旧资源
        delete[] _data;

        // 分配新资源
        _size = rhs._size;
        _data = new char[_size + 1];
        strcpy(_data, rhs._data);
    }
    return *this;
}
```

**要点**：
- 必须是成员函数
- 防止自赋值（`a = a`）
- 释放旧资源，分配新资源
- 返回自身引用

## ❓ 遇到的问题与解决

**问题1**：为什么流操作符必须是友元函数？

**解决**：
- `cout << obj` 的左操作数是 cout（ostream对象）
- 如果是成员函数，调用形式是 `obj.operator<<(cout)`
- 这样就变成了 `obj << cout`，不符合习惯

**示例**：
```cpp
// 成员函数（错误）
class Complex {
    ostream& operator<<(ostream& os) {
        // 调用形式：c1.operator<<(cout) → c1 << cout ❌
    }
};

// 友元函数（正确）
friend ostream& operator<<(ostream& os, const Complex& c) {
    // 调用形式：operator<<(cout, c1) → cout << c1 ✅
}
```

**结论**：流操作符必须是友元函数

---

**问题2**：前置++和后置++有什么区别？

**解决**：
通过实践验证，发现关键区别：

| 特性 | 前置++ | 后置++ |
|------|--------|--------|
| 返回值 | 引用 | 副本 |
| 效率 | 高 | 低 |
| 使用 | `++c` | `c++` |

**验证结果**：
```
前置++：c3 = 11, c4 = 11  （c4得到自增后的值）
后置++：c5 = 11, c6 = 10  （c6得到自增前的值）
```

**结论**：优先使用前置++，效率更高

---

**问题3**：为什么赋值运算符要防止自赋值？

**解决**：
如果不防止自赋值：
```cpp
MyString& operator=(const MyString& rhs) {
    delete[] _data;  // 如果 this == &rhs，释放了自己的数据
    _data = new char[rhs._size + 1];
    strcpy(_data, rhs._data);  // rhs._data 已经被释放，错误！
    return *this;
}
```

**正确做法**：
```cpp
if (this != &rhs) {  // 防止自赋值
    // 释放和分配
}
```

**结论**：赋值运算符必须防止自赋值

理解了运算符重载的本质：
- `a + b` 只是语法糖

### 3. 选择友元函数还是成员函数

通过实践，总结了选择原则：
- **修改左操作数 → 成员函数**（如 +=、++）
- **不修改操作数 → 友元函数**（如 +、-）
- **流操作符 → 必须友元函数**（左操作数是流对象）

特别是理解了为什么流操作符必须是友元函数，这是因为左操作数是 cout，不是自定义对象。

实践验证了前置++和后置++的区别：
- 前置++：返回引用，效率高
- 后置++：返回副本，需要创建临时对象

**记忆方法**：
- 前置：`++i`，先自增，返回自己
- 后置：`i++`，先复制，再自增，返回副本

**推荐**：优先使用前置++

### 5. 保持运算符的原有语义

最重要的一点：**保持运算符的原有语义**
- `+` 应该表示加法
- `==` 应该表示相等
- 不要滥用运算符重载

虽然可以用 `+` 实现减法，但这违反了直觉，会造成混乱。
