# 从航空飞管 C 语言软件转向嵌入式开发

> 适用对象：目前在航空领域从事飞管系统开发，主要负责 C 语言软件，但尚未系统接触 MCU、RTOS、外设驱动和板级调试，希望转入实时嵌入式方向。
>
> 核心原则：**真实表达已有经验，用独立可复现的嵌入式项目补齐硬件证据，不虚构经历，不泄露工作信息。**

## 1. 转型定位

你不是从零开始学习嵌入式，而是从“航空安全关键 C 软件”向“板级实时嵌入式软件”迁移。

### 已有优势

- C 语言工程开发经验
- 实时处理和周期任务思维
- 状态机、接口约束和数据链路设计经验
- 安全关键软件意识
- 需求、设计、编码、测试和问题闭环经验
- 对确定性、可追溯性和可靠性的理解

### 需要补齐的能力

- ARM 和 MCU 基础
- 内存映射、寄存器和启动流程
- GPIO、UART、SPI、I2C、CAN、定时器、ADC、PWM
- 中断和 DMA
- FreeRTOS 或其他实时操作系统
- 看原理图和使用示波器、逻辑分析仪
- 开发板上的真实调试
- 后续扩展到交叉编译、设备树和 Linux 驱动

推荐定位为：

> 有安全关键和实时软件经验，正在补齐板级、RTOS 和外设开发能力的嵌入式软件工程师。

不建议将自己定位为“完全没有嵌入式经验的初学者”，也不建议把尚未实际完成的驱动、RTOS 或硬件调试经历写进简历。

## 2. 目标岗位优先级

### 第一优先级：实时嵌入式软件

适合投递：

- 航空电子软件工程师
- 飞控或任务计算机软件工程师
- 实时系统软件工程师
- 航电设备嵌入式软件工程师
- 安全关键软件工程师
- 嵌入式控制软件工程师

这些岗位最容易认可你在 C 语言、实时性、状态管理、安全关键软件和验证流程方面的积累。

### 第二优先级：工业控制和汽车电子

适合投递：

- 工业控制嵌入式软件工程师
- 汽车电子软件工程师
- ECU 软件工程师
- 机器人控制软件工程师
- 电机控制软件工程师
- 底层控制软件工程师

这些岗位通常重视 C、RTOS、CAN、状态机、故障保护、实时任务和通信协议，你的航空背景具有较好的迁移性。

### 第三优先级：嵌入式 Linux 和驱动

适合投递：

- Linux 驱动工程师
- Embedded Linux 软件工程师
- BSP 工程师
- 设备驱动工程师
- Linux 系统软件工程师

这条路线可以作为第二阶段目标。当前主要差距是 Linux 内核模块、设备树、U-Boot、交叉编译、字符设备和 BSP。建议先完成 MCU、RTOS、通信和板级调试，再深入 Linux 驱动。

## 3. 能力迁移关系

| 现有经验 | 可以迁移为 | 面试时的表达 |
|---|---|---|
| 飞管系统 C 语言开发 | 嵌入式 C、状态机、接口设计、资源约束意识 | 我擅长在资源和实时性约束下编写可预测、可验证的 C 代码。 |
| 飞控或飞管实时处理 | 周期任务、确定性、时延预算、数据链路 | 我熟悉周期性处理、时序约束和数据链路设计，并通过开发板项目补齐 MCU 调度实践。 |
| 安全关键软件流程 | 需求分解、验证确认、审查、配置管理、缺陷闭环 | 我能建立需求、设计、实现和测试之间的追踪关系。具体标准和项目内容以可披露范围为准。 |

| 尚无 Linux 驱动经验 | 第二阶段学习目标 | 我不把 Linux 应用经验包装成内核驱动，相关能力会按实际项目边界描述。 |

### 不应直接包装的经历

除非确实做过并且能够现场解释，否则不要直接声称具备：

- 底层驱动经验
- Linux 内核经验
- BSP 经验
- 硬件调试经验
- RTOS 项目经验
- CAN 驱动开发经验
- 设备树和 U-Boot 经验

更可信的策略是：

```text
工作经验：讲真实、讲深度
个人项目：讲实现、讲证据
能力缺口：主动承认、说明补齐计划
```

## 4. 推荐主项目

### 项目名称

**航空主题实时飞控计算机地面仿真节点**

### 项目定位

这是一个个人学习和面试展示项目，应明确声明：

- 仅用于学习和地面仿真
- 不用于真实飞行
- 不等同于真实飞控系统
- 不使用工作项目的代码、数据、接口或参数
- 控制算法采用教学级简化模型

### 推荐技术栈

- ARM MCU 开发板，例如 STM32 或同类平台
- C 语言
- FreeRTOS
- UART
- CAN；如果硬件暂时不具备，可先用第二路 UART 模拟协议链路
- Python 上位机
- 示波器或逻辑分析仪
- Git
- CMake 或平台对应的构建工具

### 系统数据链路

```text
PC 端传感器模拟器
        ↓
UART/CAN 通信
        ↓
MCU 数据接收任务
        ↓
数据有效性检查
        ↓
模式管理任务
        ↓
控制与状态计算任务
        ↓
健康监控和故障处理
        ↓
状态回传与日志记录
```

### 输入层功能

- 空速、姿态、位置等教学模拟数据
- 帧头和长度检查
- CRC 校验
- 序列号
- 时间戳
- 超时检测
- 数据范围检查
- 数据变化率检查

### 实时处理层功能

- 周期性采集任务
- 数据处理任务
- 状态管理任务
- 通信任务
- 健康监控任务
- 看门狗管理
- 简化控制输出
- 输出边界保护

### 故障管理功能

至少实现以下故障场景：

- 传感器超时
- 通信丢帧
- CRC 错误
- 数据越界
- 数据突变
- 任务阻塞
- 看门狗复位
- 降级模式
- 故障记录

项目的重点不是模拟真实飞控算法，而是证明以下能力：

- 能写实时任务
- 能设计数据链路
- 能处理异常
- 能让程序运行在真实硬件上
- 能使用仪器进行验证
- 能建立可复现的测试证据
