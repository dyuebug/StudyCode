## 核心概念

### 1. 逻辑分析仪和示波器不是一回事

教材的定义只有一句：逻辑分析仪"采集引脚高低电平，按协议分析多引脚信息"（`hal.txt:225` 附近）。

这句话里有两个限制，都不显眼但决定了整个设计：

- **只记 0/1，不记电压**。所以它查不了"这个 3.3 V 实际只有 1.8 V"这类问题——那是示波器的活。
- **多引脚、同一时刻**。示波器一般是 2–4 通道且关心波形形状；逻辑分析仪是 8/16 通道，
  关心的是**哪根线在第几个时钟沿变化**，也就是协议。

这两个限制反过来决定了它的核心指标不是"带宽"，而是**采样深度 × 采样率**，以及**时间轴准不准**。

### 2. 两种方案：buffer 与 stream

教材给了两张对照（`hal.txt:228-235`）：

| 方案 | 做法 | 优势 | 被什么卡住 |
| --- | --- | --- | --- |
| buffer 模式 | FPGA 高速采集 → 写入 DRAM → 事后由单片机上传 | 采样率高 | **时长受 DRAM 容量限制** |
| stream 模式 | 边采边传，不存 | 时长可以很长 | **采样率受上传接口限制** |

教材随后说明本教程不用 FPGA，用 STM32F103 做 demo（`hal.txt:239` 附近）。
这意味着两种方案的上限都要重新算——因为 F103 既没有 FPGA 的高速采集，也没有 DRAM，
更没有 USB FS 之外的高速接口。**第 5 章那两组算术就是在算这个**。

### 3. 采集 = 电平 + 时间，时间从哪来

教材的原话是"在中断函数里把引脚状态、时间记录在内存里"（`hal.txt:243-247` 附近）。
这句话藏着两个必须自己回答的问题：

- **时间怎么记？** 两条路：
  - **定时器节拍**：定时器每 N µs 触发一次中断，中断里读 `IDR`。优点是时间轴天然均匀；
    缺点是采样率被中断开销卡死，且**其它中断会插队，造成时间轴不均匀**。
  - **事件时间戳**：`EXTI` 只在边沿触发，中断里读 `DWT->CYCCNT` 记下周期数。
    优点是边沿时刻精度极高（72 MHz → 13.89 ns）；缺点是**只在边沿才有数据**，不能定速采样。
- **记录在哪？** 环形缓冲。它的容量决定 buffer 模式的窗口，它的满时策略决定"故障来晚了怎么办"。

本工程选的是第一条路（定时器节拍），因为要的是"连续波形"。时间戳方案在 §7 作为对照说明。

### 4. 采样定理之外，还有一个更实用的判据

严格地说，奈奎斯特要求 fs ≥ 2 × 信号最高频率。但调试时序问题时用不上这条——
因为你要回答的不是"这个方波能不能还原"，而是"这个脉冲到底是 8 µs 还是 12 µs"。

于是判据变成**量化误差**：采样周期 Ts，被测宽度 W，误差 ±Ts，相对误差 = Ts/W。
要求相对误差 ≤ 10 % 时：

```text
Ts ≤ W/10  ⇒  fs ≥ 10/W
```

代入数字（`host/lab_la_arith` 第 4 节的实测输出）：

| 脉冲宽 W | 需要 fs | 1 MSa/s 下误差 | 够不够 |
| --- | --- | --- | --- |
| 1 µs | 10 MHz | 100.0 % | 不够 |
| 10 µs | 1 MHz | 10.0 % | 够（刚好踩线） |
| 100 µs | 100 kHz | 1.0 % | 够 |
| 1000 µs | 10 kHz | 0.1 % | 够 |

**这是本篇最有行动价值的一条**：它解释了为什么调 I2C/SPI 时序时，
成熟工具都让你看**边沿位置**而不是脉冲宽度——边沿可以打时间戳，精度不取决于采样率。

### 5. 采样深度只是"SRAM 除以每样本字节数"

朴素得不像个知识点，但两个选项差 4 倍：

| 存法 | 每样本 | 16 384 B 缓冲能放 | 1 MSa/s 窗口 |
| --- | --- | --- | --- |
| 打包 8 通道 → 1 字节 | 1 B | 16 384 样本 | 16.4 ms |
| 直接存 `uint32_t` 的 `IDR` | 4 B | 4 096 样本 | 4.1 ms |

"反正 `IDR` 一次就读到，直接存下来最省事"——省 5 行代码，丢 3/4 采样深度。
而且打包顺手统一了通道顺序，解码器不必再知道引脚号。

### 6. 环形缓冲满了：丢新的还是丢旧的

两条都能自圆其说，必须显式选一个并**计数**：

| 策略 | 保住什么 | 丢掉什么 | 适合什么 |
| --- | --- | --- | --- |
| 覆盖旧的 | 最近 N 个样本 | 最早那段 | "故障刚发生，往前看" |
| 丢弃新的 | 最早 N 个样本 | 之后的所有 | "从触发点开始往后看" |

本工程选**丢弃新的并计 `dropped`**。理由：逻辑分析仪的价值在"触发之后那一段"，
覆盖旧的会让首段消失；丢新的只是少了尾部，且 `dropped` 会明说少了多少。

**真正的要点不是选哪个，而是必须能区分"没采到"与"采到全 0"。**
`F103_17`（ADC）踩过这个坑：未建模的外设恒读 0，让"等待清零"类判据秒过并打印"校准完成"。
所以 `dropped` 计数、启动探针、"寄存器回读值"三样都不是装饰。

### 7. SUMP 协议与本工程的 ASCII 流

教材说 PC 端用开源的 PulseView，通信走 SUMP 协议（`hal.txt:258-262` 附近）。
SUMP 的关键设计是**位打包**：一次采样的多个通道压进 1 个字节，多字节样本再按小端拼。

本工程只实现了 SUMP 的**深度字段**（`'1'..'4'` ↔ 2^(8N) 个样本），
样本流用的是 ASCII：`s=<序号>,<两位十六进制>`。

| | SUMP 二进制 | 本工程 ASCII |
| --- | --- | --- |
| 一个 8 通道样本 | 1 字节 | 约 11 字节（`s=1234,AB`） |
| 能在串口助手里直接看 | 不能 | 能 |
| 对接 PulseView | 能 | 不能 |

**选 ASCII 的代价是可以量化的**：11 倍体积，直接落进 §8 的带宽账里。
所以这是个有意识的交换，不是"没做完"。

### 8. 在中断里采样的两笔账

**第一笔是平均开销。** 一次采样中断约 32–40 周期，72 MHz 下 444–556 ns：
100 % CPU 时上限 1.8–2.25 MSa/s；留 50 % 给主循环只剩 0.90 MSa/s。

**第二笔是抖动，比第一笔难缠。** 若 UART RX 中断优先级高于采样中断，
每个字节（115200 下每 87 µs 一个）就会插队一次。后果不是"少采几个点"，
而是**时间轴不均匀**——FFT 与协议解码都会因此判错，而波形看上去完全正常。

对策只有两条，都有代价：采样期间关全局中断（会丢串口字节），
或把采样交给硬件触发（F1 没有 DMA-on-GPIO，做不到）。

## 系统调用/接口卡片

> 本节全部是**本工程自定义接口**（`la_core.h`），不是教材内容，也不是标准库。
> 教材这一章没有代码，所以接口设计本身也是需要论证的部分。

### `uint8_t la_pack(uint32_t idr, uint32_t mask)`

作用：把端口输入寄存器的若干位"压实"成 8 通道的一字节。

原型：`uint8_t la_pack(uint32_t idr, uint32_t mask);`

参数：`idr` = `GPIOx->IDR`；`mask` = 关心的位（如 `0x00FF` 取 PA0..PA7）。

返回值和错误：按**引脚号升序**依次填入结果 bit0..bit7；mask 中置 1 的位超过 8 个时只取前 8 个。

资源所有权：无。

线程/进程安全：纯函数。

最小示例：

```c
uint8_t v = la_pack(GPIOA->IDR, 0x00FFUL);   /* PA0..PA7 → bit0..bit7 */
```

常见误用：以为位序跟着 mask 的**写法的顺序**走。实际是跟着**位号**走，
`mask = 0x0F00` 时 bit8 → 结果 bit0、bit11 → 结果 bit3。

### `int la_ring_push(la_ring *r, uint8_t v)` / `int la_ring_pop(la_ring *r, uint8_t *out)`

作用：定长的环形缓冲；满时丢弃新样本并累加 `dropped`。

原型：`int la_ring_push(la_ring *r, uint8_t v);`、`int la_ring_pop(la_ring *r, uint8_t *out);`

参数：`r` 由 `la_ring_init(r, buf, cap)` 初始化。

返回值和错误：`push` 返回 1 = 写入成功、0 = 满（已计数）；`pop` 返回 1 = 取到、0 = 空（不写 `out`）。

资源所有权：`buf` 由调用者提供，`la_ring` 不释放。

线程/进程安全：**不是**。中断里 `push`、主循环里 `pop` 时必须保证单生产者单消费者，
或关中断保护。

最小示例：

```c
static uint8_t buf[512];
static la_ring r;
la_ring_init(&r, buf, 512);
while (la_ring_pop(&r, &v)) { ...; }
```

常见误用：把尾指针也存成一个成员变量。它由 `head` 与 `count` 唯一确定，
多存一个就多一处可以不同步的状态。

### `int la_uart_decode(const uint8_t *samples, uint16_t n, uint8_t ch, uint16_t spp, uint8_t *out, uint16_t outcap)`

作用：从采样流里还原 UART 8N1 字节序列。

参数：`spp` = 每 bit 的采样点数（≥ 2）；采样点在每个 bit 的**中点**。

返回值和错误：成功解码的字节数；参数非法返回 -1。
帧错误（停止位不是高）的帧被**整帧丢弃**，不写入也不计数。

资源所有权：无（`out` 由调用者提供）。

线程/进程安全：纯函数。

最小示例：

```c
int n = la_uart_decode(flat, got, 0u, 8u, bytes, 8u);
```

常见误用：① 漏算起始位本身占的 `spp`，整帧偏 1 bit（本工程首版就这样错了）；
② 解完一帧后跳到下一帧起始位，边沿检测再也找不到下降沿（第二个 bug）。
两条都写在 `la_core.c` 的注释里。

### `uint32_t la_capture_us(uint32_t nsamples, uint32_t fs_hz)`

作用：算 N 个样本在 fs 下覆盖多长时间（微秒）。

返回值和错误：`fs_hz == 0` 返回 0；结果超出 `uint32_t` 时**饱和到 `UINT32_MAX`**，不回绕。

常见误用：写成 `(nsamples * 1000000) / fs` 的 32 位版本。
16 384 × 10⁶ = 1.6×10¹⁰，早就溢出了，算出来会是一个"看起来正常"的小数。

## 结果观察

### 主机端（实测）

```text
---- 合计 54 项：通过 54，失败 0 ----
PASS
```

算术程序六节全部 `assert` 通过。关键读数：

```text
  1000000  Sa/s → 窗口 16.4 ms（16384 µs）
  打包（1 B/样本）：16384 样本 / 存 IDR（4 B/样本）：4096 样本 / 比值 4.00×
  115200 bps ÷ 10 bit/B = 11520 B/s → 上限 11520 Sa/s
  填满 16384 样本需 16384 µs，上传需 1422222 µs（1422 ms）→ 上传/采集 = 86.8 倍
  W=10 µs → 需要 1000000 Hz，1 MSa/s 下误差 10.0% → 够
  乐观 32 周期 = 444 ns → 上限 2.25 MSa/s（100% CPU）
```

### 固件在 QEMU 里（实测，`logs/exp20_logicanalyzer.log`，42 行）

```text
[la] src=synthetic (LA_SYNTHETIC=1)
[probe] TIM2 PSC=0 ARR=0 CR1=0x0000 DIER=0x0000
[probe] CNT|stuck|a=0 b=0|定时器未推进
[la] mode=sw need=256 got=256 dropped=0 isr=0
[la] decode n=3 bytes=4C 41 21
[la] verdict=PASS
[la] s=0,2B ... s=15,2B        ← 空闲高：0x2A | 1 = 0x2B
[la] s=16,2A ... s=31,2A       ← 起始位：0x2A | 0 = 0x2A
```

三件事值得注意：

1. **`TIM2` 的寄存器一个都没读回来**（`PSC/ARR/CR1/DIER` 全 0）。这不是"计数器不跑"，
   而是"这段没有模型"。两者对判据的影响完全不同：前者可以等，后者永远等不到。
   所以探针必须先打印寄存器回读，再打印 `CNT` 变化。
2. **降级路径有效**：`mode=sw` 用主循环 1 ms 节拍采满 256 个样本，`dropped=0`，
   整条链路照样跑通。
3. **端到端解码正确**：`4C 41 21` = `'L','A','!'`。

### 判据自证（负向验证）

把解码器的 `spp` 从 8 改成 7（波形仍是 8 采样/bit），其余不动：

```text
[la] decode n=1 bytes=0D
[la] verdict=FAIL
```

改回 8 后恢复 `n=3 / PASS`。**`verdict` 不是常量。**

## 常见错误和陷阱

| 陷阱 | 症状 | 根因 | 处理 |
| --- | --- | --- | --- |
| 采样点漏算起始位 | 部分字节能解、部分不能；像信号质量问题 | 数据位 b 应取 `s + spp + spp/2 + b*spp`，漏掉 `+spp` 整帧偏 1 bit | 用已知字节做端到端断言，别只看"解出了一个" |
| 帧间重入位置错 | 每段波形只解出第一帧 | 跳到下一帧起始位（低电平）上，边沿检测要求"前一点为高" | 停在**停止位**（高）上，`i = s + 9*spp` |
| 32 位算时间 | 转换结果是一个"看起来正常"的小数 | `nsamples * 1000000` 溢出 | 用 `uint64_t` 中间量，并显式饱和 |
| 未建模外设让"等清零"假通过 | 打印"校准完成"，实际什么都没发生 | 读未建模寄存器恒为 0 | 判据要能区分"没响应"与"做完了"：先看写入是否置位，再看是否清零 |
| 环形缓冲静默丢样本 | 波形少了尾巴但没人知道 | 满时直接 return，不计数 | `dropped` 必须计数并打印 |
| 存整个 `IDR` | 采样深度只有 1/4 | 4 B/样本 vs 1 B/样本 | 打包；顺手统一通道顺序 |
| 采样期间被高优先级中断插队 | 波形"看着对"但解码错乱 | 时间轴不均匀 | 轮询时基（本工程 `f103_tick_init`）、降低抢占、或关中断 |
| 用 ASCII 流却想对接 PulseView | PulseView 解析不出 | SUMP 是二进制位打包协议 | 二选一，别混用 |

## 故障排查方法

按"从能判定的开始"的顺序查，不要一上来就怀疑硬件：

1. **先跑主机端。** `./host/lab_la_proto` 失败 ⇒ 不用碰板，问题在 `la_core.c`。
2. **看启动探针。** `[probe]` 打印寄存器回读值 + `CNT` 两次读数。
   - 寄存器回读全 0 ⇒ 这段没模型（QEMU）或时钟没开（真板）。
   - 回读正确但 `CNT` 不动 ⇒ 时钟或 `CEN` 的问题。
3. **看 `dropped`。** 非 0 ⇒ 缓冲不够或采样率太高，不要靠"覆盖旧样本"绕过去。
4. **看样本行本身。** 通道 1..7 的固定图案（`0x2A`）是否保持？破坏了 ⇒ 打包写错位。
5. **看解码结果与 `spp` 的关系。** 解出的字节数明显偏少 ⇒ 先做一次 `spp±1` 的负向验证，
   确认判据有灵敏度，再查波形。
6. **真板上最后才查抖动。** 需要参考信号 + 逻辑分析仪/示波器，且要区分
   "平均开销"（降采样率就好）与"抖动"（要改中断优先级）。

**本次实测抓到的两个真实缺陷**（详见实验 README §9）：

1. 采样点漏算起始位，整帧偏移 1 bit ⇒ 任何含 0 数据位的帧都被误判为帧错误。
2. 帧间重入位置落在下一帧起始位上 ⇒ 每段波形只解出第一帧。

两条都是"没有板也能抓、有板很难定位"的类型，也是本篇把核心逻辑拆出来的直接理由。
