## 核心概念

### 1. SR501 的电气行为

```text
检测到人体移动 -> OUT 输出高电平（持续数十毫秒到数秒）
无移动         -> OUT 输出低电平
```

它是**数字量**传感器，不需要 ADC。驱动只需读电平或等边沿。

### 2. 数据流

```text
人体移动
  -> SR501 内部电路判决
  -> OUT 引脚电平变化
  -> GPIO 控制器产生中断
  -> 驱动硬中断：返回 IRQ_WAKE_THREAD
  -> 驱动线程：读电平、记录事件、wake_up
  -> 应用 read() / poll() 返回
```

### 4. 有中断 vs 没有中断

| 方案 | 优点 | 缺点 | 适用 |
| --- | --- | --- | --- |
| 中断（推荐） | 响应快、CPU 占用低 | 需要 GPIO 支持中断 | 绝大多数 SoC |
| 定时轮询 | 实现简单 | 延迟取决于轮询周期，CPU 有开销 | GPIO 无中断 |
| 内核线程轮询 | 可用 `msleep` 降低占用 | 仍有延迟与唤醒开销 | 需要复杂去抖逻辑 |
| 定时器轮询 | 无需线程 | 软中断上下文限制 | 轻量周期任务 |

### 5. 设备树

课程 `sr501.dts`：

```dts
sr501 {
	compatible = "100ask,sr501";
	gpios = <&gpio4 19 GPIO_ACTIVE_HIGH>;
};
```

注意属性名是 `gpios`（无前缀），驱动侧 `devm_gpiod_get(dev, NULL, ...)` 或 `of_get_named_gpio(np, "gpios", 0)`。

若用中断，节点还需要：

```dts
interrupt-parent = <&gpio4>;
interrupts = <19 IRQ_TYPE_EDGE_RISING>;
```

或直接用 `gpiod_to_irq()` 从 GPIO 描述符得到中断号。

### 6. 实战中最容易踩的坑

1. **电平类型判断错**：`GPIO_ACTIVE_HIGH` 与模块实际输出不一致，导致"有人却读不到"。
2. **中断类型选错**：只注册上升沿，离开时没有事件；通常需要双边沿。
3. **去抖缺失**：SR501 输出有抖动，短时间内可能多次触发。
4. **未处理"无人时也触发"**：电源干扰或灵敏度旋钮设置过高。
5. **read 无数据时不阻塞**：应用忙等，CPU 占满。

## 系统调用/接口卡片

### `struct gpio_desc *devm_gpiod_get(struct device *dev, const char *con_id, enum gpiod_flags flags)`

作用：取得设备树中的 GPIO。

参数：`con_id` 为 `NULL` 时匹配 `gpios` 属性。

最小示例：`gpiod = devm_gpiod_get(&pdev->dev, NULL, GPIOD_IN);`

常见误用：`con_id` 写成 `"gpio"` 却对应 `gpios` 属性。

### `int gpiod_get_value(const struct gpio_desc *desc)`

作用：读取逻辑电平（已考虑 `ACTIVE_LOW`）。

返回值和错误：0 或 1；出错返回负值。

最小示例：`val = gpiod_get_value(gpiod);`

常见误用：与 `gpiod_get_raw_value` 混用，导致有效电平反了。

### `int gpiod_to_irq(const struct gpio_desc *desc)`

作用：把 GPIO 描述符转换为中断号。

返回值和错误：成功返回中断号；失败返回负错误码。

最小示例：`irq = gpiod_to_irq(gpiod);`

常见误用：未检查返回值直接 `request_irq`。

### `int request_threaded_irq(...)`

作用：注册可睡眠的中断处理，适合 SR501 这类需要读电平并唤醒应用的场景。

最小示例：

```c
err = request_threaded_irq(irq, sr501_hardirq, sr501_thread,
			   IRQF_TRIGGER_RISING | IRQF_TRIGGER_FALLING,
			   "sr501", priv);
```

常见误用：两个处理函数都做重活；忘记 `free_irq`。

## 最小可运行实验

实验目录：`Linux/experiments/Day12_SR501实战/`

```text
sr501_drv.c    完整驱动：GPIO + 中断 + 等待队列 + read
sr501.dts      设备树片段
sr501_test.c   阻塞读与 poll 测试
Makefile
README.md      接线、编译、验证与排错
```

核心：

```c
static irqreturn_t sr501_thread(int irq, void *data)
{
	struct sr501_dev *s = data;

	s->value = gpiod_get_value(s->gpiod);
	s->events++;
	wake_up_interruptible(&s->wq);
	return IRQ_HANDLED;
}

static ssize_t sr501_read(struct file *f, char __user *buf,
			  size_t size, loff_t *off)
{
	struct sr501_dev *s = f->private_data;
	int v;

	if (wait_event_interruptible(s->wq, s->events != s->read_events))
		return -ERESTARTSYS;

	s->read_events = s->events;
	v = s->value;
	if (copy_to_user(buf, &v, sizeof(int)))
		return -EFAULT;
	return sizeof(int);
}
```

## 常见错误和陷阱

| 现象 | 原因 | 定位方法 |
| --- | --- | --- |
| 从不触发 | 有效电平/触发边沿错误 | 先改用轮询读电平确认接线 |
| 一直触发 | 输入悬空或灵敏度太高 | 加下拉、调电位器 |
| 偶发多次事件 | 输出抖动 | 增加软件去抖（时间窗） |
| `read` 立即返回 0 | 未实现阻塞条件 | 检查等待队列 |
| 无人移动也触发 | 电源噪声、热源干扰 | 更换电源、调整安装角度 |
| `-ENODEV` | `gpios` 属性名不匹配 | 检查 dts 与 `con_id` |

## 故障排查方法

1. **先验证硬件**：用轮询方式读电平，确认接线与有效电平。
2. **再验证中断**：`cat /proc/interrupts` 看计数是否变化。
3. **再验证唤醒**：`dmesg` 看线程函数是否执行。
4. **最后验证应用**：阻塞读与 poll 分别测试。
5. 无法触发时，回到 Day15 的思路——用内核线程轮询替代中断。

## 练习题

### 基础题

题目：给驱动增加去抖：同一方向的变化在 50ms 内只记录一次。

提示：记录上次事件时间 `jiffies`，比较差值。

验收标准：快速挥手不会产生成串事件。

### 改错题

题目：下面的 probe 有什么问题？

```c
static int sr501_probe(struct platform_device *pdev)
{
	struct gpio_desc *g = devm_gpiod_get(&pdev->dev, "gpio", GPIOD_IN);
	int irq = gpiod_to_irq(g);
	return request_irq(irq, isr, IRQF_TRIGGER_RISING, "sr501", NULL);
}
```

提示：属性名、返回值检查、以及是否需要线程化。

验收标准：能指出三处问题并修正。

### 综合题

题目：实现"无中断"版本：用内核线程每 20ms 读一次电平，变化时唤醒应用。

提示：`kthread_run` + `msleep(20)` + `kthread_should_stop`。

验收标准：在禁用中断的节点上仍能检测人体移动，且 `rmmod` 能正常停止线程。
