## 5. 动手与观察

**无板必做**：对设备先注册、驱动先注册、身份不匹配、依赖未就绪四种场景做纸面推演。每种分别写出“应该出现什么”和“到哪里查证”。

**条件实验**：只在已审查的无硬件访问副本中验证注册顺序；本章 LED 资源值不能直接用于 PC。按 [环境指南](../experiments/驱动入门_环境与验证指南.md) 检查加载对象与恢复方案。

**观察点**：设备对象、驱动对象、绑定状态、`probe()` 的实际返回、解绑后的引用与资源。不要仅凭模块出现在 `lsmod` 就写匹配成功。

## 6. 复盘与故障排查

1. `probe()` 失败时，设备与驱动注册一定都消失吗？
2. `remove()` 与模块退出、文件 `.release` 分别针对哪种生命周期？
3. 单个全局设备指针为何可能使第二个设备覆盖第一个设备状态？

排查顺序：双方是否注册 → 身份/匹配表 → 探测日志/返回值 → 资源依赖 → 用户接口。签名或 API 类型错误先在构建层解决。
