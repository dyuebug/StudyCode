# 每日学习任务与驱动入门导航

**定位**：本目录是 Day 序号与记录文件的索引，**不定义学习路线**。路线以
[`CLAUDE.md`](../CLAUDE.md) §3（阶段划分）与 §12（当前优先级）为准；两者冲突时以 `CLAUDE.md` 为准，
并回来修正本文件。

任务文件命名为 `YYYY-MM-DD_第X天_任务.md`。每日任务包含主题、目标、资料、阅读顺序、源码入口、动手任务、复盘、预计时长和成功标准。

## 日期、顺序与状态

- 按 **Day 序号** 学习，不按当前文件名中的日期排序；已有 Day1 任务/日志与 Day2 的日期不一致，历史文件保持原名。
- Day3～Day14 文件中的 `2026-09-19` 是本批计划编制日期，不是预约执行日期，也不是完成日期。
- **实际执行日期**：Day1 = 2026-09-28，Day2–Day14 = 2026-09-29～2026-10-11（逐日连续）。
  核对方式：`daily_logs/` 中同序号文件名的日期即为实际执行日；本目录的 Day 序号与日志同序号一一对应。
- 实际执行时填写任务中的“实际学习日期”，日志使用真实日期命名，内容同时注明 Day 序号。
- 当前可见的 Day1 日志记录概念学习完成、编译运行未验证；Day2–Day14 的实际验证进度见 [`../README.md`](../README.md) 的「验证状态」列与 [`../tests/qemu-vexpress/RESULT.md`](../tests/qemu-vexpress/RESULT.md)。任务文件本身不代表已验证。
- 任务文件里的复选框**未逐项维护**，不能当作完成度依据；完成度以 `daily_logs/` 的「任务完成情况」与实验产物为准（`CLAUDE.md` §12 P3）。
- 每个 Day 可拆多次完成。没有 Linux/板卡时先做源码分析，但不能将条件实验勾为已验证。

## 每天怎么执行

1. 读上一份实际日志，确认遗留与环境。
2. 打开本 Day 的任务，按链接先讲义、再构建规则、再源码和测试程序。
3. 先完成无板必做，再根据环境决定是否进行条件实验。
4. 填工作簿对应题目及三条自己的结论，不必等聊天逐题批改才能继续。
5. [实际日志](../daily_logs/README.md)在当日出现可核验产物时**自动生成**（`CLAUDE.md` §8.2，
   不必等到说"学习结束"），分别记录理解、构建、软件接口与硬件证据。

任务是计划，不是完成证明。Day7 和 Day14 的验收不过时，优先补前置，不机械地追赶天数。
