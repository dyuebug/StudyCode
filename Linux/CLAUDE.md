> 本文件是 `Linux/` 学习目录的唯一总控配置。它定义学习目标、阶段路线、文件组织、每日流程、质量标准、复盘方式和 Claude 的协作规则。
>
> 常用指令：
>
> - **开始学习**：生成今日学习任务并检查上次遗留问题
> - **学习结束**：生成当日日志、记录问题并安排下一次学习
> - **生成周报**：汇总本周学习结果并制定下周目标
> - **整理笔记**：提取知识点并更新知识库
> - **检查变更**：检查构建、测试、文档和未完成事项
> - **制定路线**：根据目标岗位或当前阶段重新规划学习路径

## 1. 总控原则

### 1.1 事实来源优先级

判断学习状态、项目状态和能力状态时，遵循以下优先级：

1. **实际文件、构建结果和测试结果**：判断代码是否存在、能否构建、是否通过测试。
2. **学习日志**：记录实际学习时间、完成内容、问题和产出。
3. **项目文档**：说明设计意图、限制、运行方法和已知问题。
4. **本文件**：维护路线、规则和汇总，不作为代码完成状态的唯一依据。

### 1.2 状态定义

- `计划中`：只有学习计划，没有开始或没有可验证产出。
- `学习中`：正在学习，已有部分笔记或实验。
- `学习完成`：完成概念学习和基础练习，但不代表工程质量已验证。
- `项目完成`：完成一个可运行项目，并有使用说明和基本测试。
- `工程化中`：正在补充构建、测试、错误处理、资源生命周期、并发安全、性能数据或文档。
- `已验证`：在明确的平台、内核、编译器和运行环境中完成构建、测试或基准测试，并留下记录。
- `暂停`：暂时不推进，必须记录原因和恢复条件。

### 1.3 统一学习原则

- Linux 学习以**可运行实验**为中心，不只阅读概念。
- 每个主题都必须回答：它解决什么问题、如何工作、如何验证、常见故障是什么。
- 代码必须标注平台、编译器、语言标准、内核假设和运行方式。
- 性能数字必须注明“理论估算”或“实测结果”，没有基准数据不得写成普遍结论。
- 学习示例可以简化，但必须明确简化点；工程项目必须处理错误、资源释放、并发安全和可观测性。
- 不把“代码写出来”直接等同于“掌握”；至少经过解释、运行、修改、故障注入和复盘。
- 新增文件前先检查目录、命名和已有文档，避免重复建设。

## 2. Linux 学习总目标

### 2.1 能力目标

建立从用户态到系统和网络底层的完整 Linux 能力：

- 熟练使用 Linux 命令行、Shell、文件系统和权限系统。
- 理解进程、线程、虚拟内存、文件描述符和系统调用。
- 掌握进程间通信、线程同步和并发设计。
- 掌握 TCP/UDP Socket、I/O 多路复用和高并发服务器模型。
- 理解 epoll、Reactor、线程池、协程和异步 I/O 的适用边界。
- 能够使用 GDB、strace、lsof、ss、perf、valgrind、Sanitizer 等工具定位问题。
- 能够使用 C/C++、Make/CMake、Git 和 Shell/Python 完成交付。
- 能够继续进入嵌入式 Linux：交叉编译、启动链、设备树、驱动和系统调试。

### 2.2 作品目标

至少形成以下可复现作品：

1. Linux 系统编程实验集：进程、IPC、线程、同步、文件和信号。
2. TCP/UDP 网络编程实验集：阻塞、非阻塞、select、poll、epoll。
3. 高性能服务器项目：Reactor、线程池、连接生命周期、超时和优雅退出。
4. 协程或异步 I/O 项目：明确生命周期、取消、异常和资源回收。
5. 工程化综合项目：统一构建、自动化测试、日志、性能基准和问题复盘。
6. 后续可选项目：嵌入式 Linux 网关、设备驱动或航空主题实时嵌入式项目。

### 阶段0：Linux 环境与工具

目标：能够独立使用 Linux 开发环境完成编译、运行、调试和脚本化操作。

知识范围：

- Linux 目录结构和文件系统
- Shell 基础、管道、重定向和环境变量
- `grep`、`find`、`xargs`、`awk`、`sed` 的常用场景
- `gcc`、`g++`、`make`、`cmake`
- Git 基础和提交规范
- GDB 基础
- 编译警告和 Sanitizer

验收：

- 能从命令行构建并运行 C/C++ 程序。
- 能用脚本重复执行构建和测试。
- 能用 GDB 设置断点、查看栈和检查变量。
- 能解释编译、链接和运行时错误的区别。

### 阶段1：文件系统、系统调用与进程

知识范围：

- 文件描述符
- `open`、`read`、`write`、`close`
- `stat`、目录操作和权限
- `fork`、`exec`、`wait`
- 进程状态、僵尸进程和孤儿进程
- 信号、管道和重定向
- 环境变量和进程生命周期

验收：

- 实现一个简化 Shell 或命令执行器。
- 能解释父子进程地址空间和文件描述符继承。
- 能处理子进程退出、信号和错误路径。

### 阶段2：IPC、线程和并发

知识范围：

- 匿名管道、命名管道、共享内存、消息队列和 Unix Domain Socket
- `pthread_create`、`pthread_join`、`pthread_detach`
- 互斥锁、读写锁、条件变量和原子操作
- 数据竞争、死锁、活锁和虚假唤醒
- 生产者消费者模型
- 线程池、任务队列和优雅关闭

验收：

- 完成线程安全的生产者消费者程序。
- 完成带有任务队列和关闭协议的线程池。
- 能使用 ThreadSanitizer 或日志定位数据竞争。
- 能解释锁的粒度、锁顺序和资源所有权。

### 阶段3：网络编程

知识范围：

- Socket 生命周期
- TCP 连接、字节流和粘包
- UDP 无连接通信
- 字节序、地址结构和端口
- 阻塞与非阻塞 I/O
- 超时、半关闭、断连和错误处理
- `select`、`poll`、`epoll`

验收：

- 完成 TCP 回显服务器和客户端。
- 完成 UDP 通信示例。
- 完成支持多个客户端的非阻塞服务器。
- 能解释监听 Socket、连接 Socket 和文件描述符的关系。

### 阶段4：高性能服务器模型

知识范围：

- LT 与 ET
- Reactor 模式
- 单 Reactor 单线程
- Reactor 加线程池
- 主从 Reactor
- 连接分配策略
- EPOLLONESHOT
- 连接生命周期和优雅退出

验收：

- 完成 ET 模式服务器，并正确处理 `EAGAIN`。
- 完成 Reactor 抽象和 Handler 分发。
- 完成 Reactor 加线程池版本。
- 对不同模型进行统一压测和结果记录。

### 阶段5：协程和异步编程

知识范围：

- 协程与线程的区别
- `co_await`、`co_yield`、`co_return`
- Promise、Awaitable 和 `coroutine_handle`
- 协程生命周期和销毁
- 协程与 Reactor 的结合
- 任务调度、优先级、公平性和取消
- 超时、异常传播和资源回收

验收：

- 完成 Generator 和 Task 基础实现。
- 完成协程版异步 I/O 示例。
- 能说明协程句柄的所有权和销毁时机。
- 能测试取消、超时、异常和连接断开。

### 阶段6：调试、性能和工程化

知识范围：

- GDB、core dump 和 backtrace
- `strace`、`ltrace`、`lsof`、`ss`
- `perf`、火焰图和系统调用分析
- Valgrind、AddressSanitizer、UndefinedBehaviorSanitizer
- 日志、指标和故障复现
- 单元测试、集成测试、压力测试和长稳测试
- CMake、CI、版本和发布说明

验收：

- 每个综合项目都有构建说明和测试命令。
- 能复现至少一个崩溃、死锁、内存错误或连接异常。
- 有基准测试环境、方法、数据和结论。
- 能区分功能正确性、并发正确性和性能结论。

#### 关键源码阅读顺序

1. Linux 应用：`fileio → pthread 条件变量 → select/poll → UART termios`，先理解文件描述符、阻塞和共享数据。
2. MCU/RTOS：先运行最小任务与外设示例，再局部阅读调度、队列、中断和资源管理实现。
3. Linux 驱动：`hello 字符设备 → platform/Device Tree → 综合按键驱动 → I2C/SPI → Input/Framebuffer`。
4. RTOS 网络扩展：在任务、队列和网络基础完成后，再读 FreeRTOS+TCP 的 IP task 与事件队列。
5. RT-Thread epoll：作为 POSIX 兼容层实现案例，理解 poll waitqueue 与 ready list；不要将它等同于 Linux 内核 epoll 实现。

#### 代码资料使用边界

- `Linux_WEIDS` 是多平台、多来源的教学资料集合，不是单一、可在根目录直接构建的完整 BSP。
- 先以 i.MX6ULL/QEMU 或课程指定环境复现最小驱动链路；明确记录目标内核树、`ARCH`、`CROSS_COMPILE` 和工具链版本。
- 课程示例可能对应 Linux 4.4/4.9 等旧接口。先在其目标环境学习机制，再对照新内核 API；不得将教学样例默认为生产级驱动。
- 对 FreeRTOS-LTS/AWS、测试框架、第三方依赖和归档平台按问题选读，不作为新手的全量阅读任务。详见 `Linux/Linux_WEIDS/Docs/Obsidian学习导航/16_第三方与参考资料边界.md`。
- 硬件相关结论要区分“源码推断”“仿真验证”和“真实板卡验证”；没有示波器、逻辑分析或目标板证据时，不宣称已完成硬件验证。

其他可选方向：

- 嵌入式 Linux 应用开发
- Linux 驱动和设备树
- 高性能网络服务器
- 工业控制和实时通信
- 航空主题实时嵌入式项目

进入任何深入方向前，必须完成至少一个具有真实测试证据的系统编程、网络或板级实验项目。

## 6. 学习材料标准

每个 Linux 学习材料至少包含以下结构：

```markdown
# 主题名称

## 学习目标

## 环境与前置条件

## 核心概念

## 系统调用/接口卡片

## 最小可运行实验

## 编译与运行

## 结果观察

## 常见错误和陷阱

## 故障排查方法

## 练习题

## 验收标准

## 延伸阅读
```

### 6.1 概念优先

使用新系统调用、库函数或工具前，必须先说明：

- 作用
- 适用场景
- 参数和返回值
- 成功和失败条件
- 线程安全或进程安全约束
- 资源所有权
- 与相近接口的区别

### 6.2 接口卡片

每个重要接口使用以下格式：

```markdown
### `接口名称`

作用：

原型或命令：

参数：

返回值和错误：

资源所有权：

线程/进程安全：

最小示例：

常见误用：
```

### 6.3 代码要求

- 关键代码说明“为什么这样做”，不只说明“这行做了什么”。
- 检查所有系统调用和库函数返回值。
- 明确处理 `EINTR`、`EAGAIN`、`EPIPE`、`ECONNRESET` 等常见错误。
- 文件描述符、线程、锁、内存、Socket 和协程句柄必须有明确的创建、使用和释放路径。
- 网络代码必须考虑短写、短读、半关闭、粘包、超时和断连。
- 多线程代码必须说明共享数据、锁保护范围和关闭协议。
- ET 模式必须使用非阻塞 I/O，并循环读取或接受直到 `EAGAIN`。
- 协程代码必须说明句柄生命周期、`final_suspend`、异常传播和取消方式。

### 6.4 练习题要求

- 每个主题至少包含基础题、改错题和综合题。
- 默认只提供题目、提示和验收标准，不直接提供答案。
- 用户明确要求答案或进入验收环节时，才提供参考实现。
- 练习应优先覆盖边界、错误路径、并发和资源释放，而不是只覆盖正常路径。

## 10. 问题分析和调试协议

遇到问题时，Claude 不应直接跳到最终答案，必须引导形成可复用的排查方法：

1. **复现**：记录命令、输入、环境和最小步骤。
2. **分类**：编译错误、链接错误、运行时错误、并发错误、协议错误、性能问题还是环境问题。
3. **观测**：使用日志、GDB、`strace`、`lsof`、`ss`、`perf`、Sanitizer 等工具获取证据。
4. **假设**：列出可能原因，并说明如何验证每一个假设。
5. **最小修改**：一次只验证一个主要假设。
6. **回归**：运行原测试和新增测试，确认没有引入新问题。
7. **沉淀**：将现象、原因、修复和预防措施写入日志或知识库。

重点排查清单：

- 文件描述符是否泄漏、重复关闭或误用。
- `fork` 后是否正确处理锁、缓冲区和文件描述符。
- 线程退出前是否释放资源，线程池是否能够停止。
- 条件变量是否使用 `while` 检查条件，是否处理虚假唤醒。
- Socket 是否处理短读、短写、超时、半关闭和断连。
- ET 模式是否使用非阻塞 I/O 并循环到 `EAGAIN`。
- 是否存在同一连接被多个线程重复处理的竞态。
- 协程句柄是否重复恢复、遗漏销毁或在对象失效后继续使用。
- 性能结论是否有统一环境和可重复数据。

## 11. Claude 教学和协作规范

### 11.1 教学原则

- 先教判断方法，再给结论。
- 先讲原理和边界，再讲 API。
- 先给最小实验，再扩展到工程设计。
- 将正常路径、错误路径、并发路径和资源生命周期放在一起讲。
- 对难点给出“必学”和“选学”分层。
- 不把大量代码当成学习本身；每段代码都要有可观察结果。
- 不默认用户已经掌握硬件、Linux 内核或网络细节。

### 11.2 生成代码时

必须说明：

- 文件用途
- 依赖和平台
- 构建命令
- 运行命令
- 预期结果
- 错误处理
- 资源释放
- 测试方法
- 已知限制

### 11.3 修改已有项目时

1. 先读取相关 README、设计文档、构建文件和测试入口。
2. 先确认问题和验收标准。
3. 优先做最小修改，避免无关重构。
4. 修改后运行相关构建和测试。
5. 汇报变更文件、验证命令、实际结果和未解决风险。

### 11.4 安全和真实性

- 不将学习项目描述为生产系统或安全认证系统。
- 航空主题项目必须与工作代码、数据、参数和接口隔离。
- 不把个人实验结果描述为真实航空器、工业设备或生产服务器结论。
- 不建议展示或复制受保密协议约束的信息。

## 14. Linux 学习的最终验收标准

当满足以下条件时，认为具备较完整的 Linux 系统开发基础：

- 能独立使用 Linux 命令行完成开发、构建、调试和脚本化操作。
- 能解释进程、线程、文件描述符、虚拟内存和系统调用的基本关系。
- 能编写正确处理错误和资源释放的多进程、多线程程序。
- 能完成 TCP/UDP 网络程序，并处理非阻塞 I/O、短读短写、超时和断连。
- 能解释并实现 select/poll/epoll、LT/ET、Reactor 和线程池模型。
- 能说明协程与线程的区别，并正确处理协程生命周期和取消。
- 能使用工具定位至少一类内存、并发、连接或性能问题。
- 至少有一个可构建、可测试、可压测、可解释的 Linux 综合项目。
- 能将 Linux 系统编程方法迁移到嵌入式 Linux、实时嵌入式或高性能服务器场景。

> 最终目标不是记住更多 API，而是能够从问题出发选择 Linux 机制，建立可验证实现，并在故障和约束条件下完成可靠交付。
