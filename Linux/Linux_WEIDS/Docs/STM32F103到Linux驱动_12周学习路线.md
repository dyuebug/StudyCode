# STM32F103 到 Linux 驱动 / BSP：12 周学习路线

**适用资料**：`DShanMCU-F103/`、`rtos_doc_source/`、`01_全系列新Linux系列教程之快速入门视频/`、`02_嵌入式Linux驱动入门直播/`  
**最终方向**：Linux 驱动 / BSP  
**建议投入**：每周 5 天，每天 2～3 小时；每周预留 1 天复盘或补缺。  
**总原则**：先跑通，再解释；先最小闭环，再扩展；每个外设都至少完成一次“HAL 现象 → 查硬件连接 → 看寄存器本质”的对照。

---

## 1. 先明确：这 12 周要建立什么能力

这不是“把所有示例打开一遍”的计划，而是从 MCU 经验逐渐迁移到 Linux 驱动的训练路线。

```text
嵌入式 C
  -> STM32 GPIO / 中断 / 串口 / DMA
  -> I2C / SPI / Timer / PWM
  -> FreeRTOS 的任务、同步与通信
  -> Linux 应用与内核模块
  -> 字符设备、platform、device tree、GPIO / 中断
  -> I2C / SPI 等专题驱动
```

12 周结束时，应能做到：

- 用 Keil、ST-Link、CubeMX 跑通并修改 F103 外设工程；
- 不依赖死记 HAL API，能解释 GPIO、UART、DMA、I2C、SPI 的数据流；
- 能用 FreeRTOS 的队列、互斥锁、任务通知组织小型工程；
- 能说明 MCU 工程、Linux 应用程序、Linux 内核模块三者的不同；
- 能在目标系统或 QEMU 中完成 `编译 -> 加载 .ko -> dmesg 验证 -> 卸载`；
- 能沿着 `设备树 -> driver -> 应用测试程序` 三条线阅读简单 Linux 驱动。

## 2. 固定学习方法：每次学习都按这个闭环

### 2.1 单个例程的阅读顺序

每次打开一个新例程，严格按顺序做，不要先钻进 `main.c` 的细节：

1. **确定现象**：这个工程最终要让 LED、串口、传感器或屏幕表现出什么？
2. **看讲义或源码说明**：先知道它引入了什么新机制。
3. **看工程入口和配置**：MCU 看 `.ioc`、`main.c`、`stm32f1xx_hal_msp.c`；Linux 看 `Makefile`、`*_drv.c`、`*_test.c`、`.dts`。
4. **跑通原工程**：先不修改，确认工具链、下载和硬件连接没有问题。
5. **只做一个最小改动**：改 LED 周期、打印内容、缓冲区大小、传感器数据格式或命令字。
6. **验证改动**：用 LED、串口终端、逻辑分析仪、`dmesg` 等可观察结果证明它实际生效。
7. **写三条笔记**：本例程新增什么机制、数据从哪里来、出错时第一步检查哪里。

### 2.2 每天的 2～3 小时节奏

- 前 20 分钟：复习昨天笔记，并口头回答昨天的复盘题。
- 40 分钟：看讲义、源码目录与关键结构。
- 60～80 分钟：运行工程并完成最小修改。
- 最后 20 分钟：记录现象、命令、报错和结论。

### 2.3 每周必须留下的学习证据

每周至少保留以下内容到 `daily_logs/` 或个人笔记中：

- 本周运行成功的工程路径；
- 一张自己画的流程图或数据流图；
- 一次自己修改后的可验证现象；
- 至少 3 个仍不清楚的问题；
- 周末用自己的话回答“这一周比上一周多了什么机制”。

## 3. 学习前准备（第 0 天，可安排半天）

### 必做事项

1. 安装 Keil MDK、STM32F1 Device Pack、ST-Link 驱动和 STM32CubeMX。
2. 连接 ST-Link：`GND / SWCLK / SWDIO / 3.3V` 对接板卡同名引脚。
3. 解压一个最小工程到无中文、较短路径，例如 `D:\STM32\F103\week01\`。
4. 不要一次解压全部 `.7z` 源码；只解压当前周的 1～3 个工程。
5. 准备串口终端，并确认串口号、波特率、换行方式。

### 先看资料

- `DShanMCU-F103/5_程序源码/02_FreeRTOS程序/04_视频配套的文档/[2-1]_开发板使用.md`

### 硬件限制

底板部分模块复用了引脚：DS18B20 与 DHT11 不能同时接；红外发射与蜂鸣器不能同时接；超声波和 Flash 可同时接但要避免并发访问。接线前以底板原理图为最终依据。

## 4. 常见卡点与固定排查顺序

### MCU 工程编译或下载失败

```text
工程是否已解压到无中文、短路径
-> Keil 是否安装 STM32F1 Device Pack
-> ST-Link 驱动是否识别
-> SWDIO / SWCLK / GND / 3.3V 是否正确连接
-> Keil 下载器是否选择 ST-Link
-> 芯片型号是否与工程一致
```

### LED / 按键 / 传感器现象不对

```text
先看底板原理图确认实际引脚和有效电平
-> 确认相关模块是否存在引脚复用冲突
-> 再检查 CubeMX/HAL 初始化
-> 再检查中断、时钟或总线参数
-> 最后才怀疑业务逻辑
```

### UART 无输出或乱码

```text
串口号
-> TX/RX 是否接反
-> GND 是否共地
-> 波特率和帧格式
-> 程序是否真的下载运行
-> printf 重定向是否正确
-> 是否在中断或任务中进行了不安全输出
```

### FreeRTOS 任务表现异常

```text
任务是否创建成功
-> 调度器是否启动
-> 任务是否一直阻塞或被更高优先级任务占满 CPU
-> 栈是否不足
-> 队列/信号量是否已创建且正确传递
-> ISR 中是否调用了 FromISR 版本 API
```

### Linux 模块无法加载或没有预期行为

```text
内核版本与模块编译版本是否一致
-> dmesg 是否有错误
-> Makefile / Kbuild 是否正确
-> 设备树节点是否生效
-> compatible 是否与 of_match_table 匹配
-> probe 是否被调用
-> 应用是否打开了正确的设备节点
```
