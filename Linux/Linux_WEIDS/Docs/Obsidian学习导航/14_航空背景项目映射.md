## 推荐个人项目：教学级实时计算机地面仿真节点

### 项目边界

- 仅用于个人学习和面试作品展示。
- 不用于真实飞行、飞控或安全认证结论。
- 控制逻辑使用自定义教学模型。
- 所有参数、协议、数据帧、状态名称和测试数据独立设计。

### 第一版：STM32F103 + FreeRTOS

```text
PC 传感器模拟器
-> UART 数据帧
-> DMA / IDLE 或中断接收
-> 帧解析与 CRC
-> 数据有效性检查
-> Queue
-> 周期状态处理任务
-> 健康监控任务
-> UART 状态回传 / LED 指示
```

建议任务：

| 任务 | 职责 | 关键学习点 |
| --- | --- | --- |
| `receive_task` | 接收和解析输入帧 | UART、环形缓冲区、DMA、CRC |
| `state_task` | 状态机与简化控制计算 | 周期调度、数据新鲜度、边界保护 |
| `health_task` | 任务心跳、超时、队列和栈监控 | 看门狗、错误计数、降级逻辑 |
| `telemetry_task` | 输出状态和日志 | Queue、UART、可观测性 |
| `indicator_task` | LED / OLED 状态指示 | 状态可视化、低优先级任务 |

对应资料：[[11_新手入门路径|新手入门路径]]。

### 第二版：Linux 网关或驱动验证节点

```text
Linux 用户态服务
-> 串口 / I2C / SPI / GPIO 设备接口
-> 配置、日志、网络、测试工具
-> Device Tree
-> platform / I2C / SPI 驱动
-> 真实或模拟外设
```

对应资料：[[12_进阶驱动路径|进阶驱动路径]]。

### 第三版：STM32MP157 A7 + M4 分工

```text
A7 Linux
-> 配置、日志、网络、用户态测试
-> RemoteProc 加载 M4 固件
-> RPMsg

M4 FreeRTOS
-> 实时采集 / 控制 / 健康状态
-> UART、I2C、SPI、CAN 等外设
```

对应资料：[[13_精通与BSP路径|精通与 BSP 路径]]。

## 必须留下的面试证据

- [ ] 任务与时序图：周期、优先级、队列和数据依赖。

- [ ] 故障注入报告：丢帧、CRC 错误、数据越界、超时、队列满、任务阻塞。
- [ ] 需求—设计—测试追踪表。
- [ ] 可重复构建和测试的 README。

## 故障注入最小集合

| 故障 | 预期行为 | 验证证据 |
| --- | --- | --- |
| 输入超时 | 标记数据失效，进入降级状态 | 日志、状态输出、恢复时间 |
| CRC 错误 | 丢弃帧并累计错误计数 | 发送错误帧后的日志 |
| 数据越界 | 拒绝或钳制，并记录故障 | 边界测试结果 |
| 队列满 | 记录水位和丢弃/背压策略 | 统计信息 |
| 任务心跳丢失 | 健康任务禁止喂狗或进入恢复流程 | 重启原因和日志 |
| 总线 / 设备 NACK | 有限重试后报告失败 | 错误码和恢复结果 |

## 面试表达边界

推荐表达：

> 我在航空领域从事 C 语言软件开发，积累了实时处理、状态管理、接口联调和需求验证经验。为了补齐板级实时嵌入式能力，我独立完成了一个教学级实时计算机地面仿真节点，使用开发板、FreeRTOS、UART/CAN 类通信、健康监控和故障注入。该项目与工作项目没有代码、数据和接口复用。

不要表达：

- “我做过真实飞控硬件驱动”，除非可公开且确实负责过。
- “该项目满足航空认证或安全标准”。
- 真实项目名称、产品参数、接口、工具截图或源代码细节。
