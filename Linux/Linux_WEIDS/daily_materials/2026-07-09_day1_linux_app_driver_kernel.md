## 第一部分：核心概念

今天只建立一个最重要的分层认知：

```text
用户态应用程序
-> 通过系统调用请求内核服务
-> 内核管理进程、内存、文件系统、驱动
-> 驱动在内核中直接或间接管理硬件
-> 硬件执行真实输入输出
```

在 Linux 系统中，普通应用程序和驱动程序不是同一层东西。

`hello.c` 属于用户态应用程序。它有 `main()` 函数，使用 `printf()` 输出内容，依赖 C 标准库和 Linux 运行环境。它不能像单片机裸机程序那样随便直接访问硬件寄存器。

Linux 驱动程序属于内核态代码。后面你会看到它通常没有 `main()`，而是通过 `module_init()`、`module_exit()` 这类入口交给内核管理。驱动常用 `printk()` 打印内核日志，而不是 `printf()`。

可以先记住这个对比：

| 对比项 | Linux 应用程序 | Linux 驱动程序 |
|---|---|---|
| 所在层次 | 用户态 | 内核态 |
| 常见入口 | `main()` | `module_init()` |
| 常见输出 | `printf()` | `printk()` |
| 编译产物 | 普通可执行文件 | `.ko` 内核模块 |
| 运行方式 | `./hello` | `insmod xxx.ko` |
| 退出方式 | 程序运行结束 | `rmmod xxx` |

## 第二部分：为什么需要它

学习 Linux 驱动之前，必须先区分“应用”和“驱动”。如果这一步不清楚，后面看到 `.c`、`.ko`、`.dts`、`Makefile` 时就会混成一团。

单片机裸机程序通常更接近这种模式：

```text
main()
-> 初始化时钟、GPIO、串口等外设
-> 直接读写寄存器
-> while(1) 循环执行业务逻辑
```

Linux 程序不是这样。Linux 应用运行在操作系统提供的环境里，它默认不能直接控制硬件。应用想访问硬件，一般要通过文件接口、系统调用或设备节点进入内核，再由驱动完成真正的硬件访问。

所以课程先让你看 `hello_app`，不是为了教你 `printf()`，而是为了让你先站在用户态视角看 Linux 程序。只有先知道应用程序长什么样，后面看到驱动时，你才会明显感觉到：驱动不是普通应用。

这就是 Day1 的关键目标：

```text
先分清文件身份，再深入驱动机制。
```

## 第三部分：最小可运行例子

今天的最小例子是 `hello.c`。

源码位置：

```text
02_嵌入式Linux驱动入门直播/01_单片机程序和Linux程序从上层到底层的完整比较/source/01_hello_app/hello.c
```

源码内容：

```c
#include <stdio.h>


/* 执行命令: ./hello weidongshan 
 * argc = 2
 * argv[0] = ./hello
 * argv[1] = weidongshan
 */

int main(int argc, char **argv)
{
	if (argc >= 2)
		printf("Hello, %s!\n", argv[1]);
	else
		printf("Hello, world!\n");
	return 0;
}
```

如果在 Linux 环境中编译运行，典型命令是：

```bash
gcc hello.c -o hello
./hello
./hello weidongshan
```

预期输出类似：

```text
Hello, world!
Hello, weidongshan!
```

这一步只说明一件事：它是一个可以从 shell 启动的普通用户态程序。

## 第四部分：关键代码逐行讲解

### 1. `#include <stdio.h>`

这行表示程序使用 C 标准输入输出库。

`printf()` 就来自这里。普通 Linux 应用程序可以使用标准库函数，但 Linux 内核驱动不能直接按这种方式使用用户态标准库。

### 2. 注释中的执行命令

```c
/* 执行命令: ./hello weidongshan 
 * argc = 2
 * argv[0] = ./hello
 * argv[1] = weidongshan
 */
```

这段注释说明程序从命令行接收参数。

当你执行：

```bash
./hello weidongshan
```

操作系统会把命令行参数传给 `main()`：

- `argc = 2`：表示参数个数是 2。
- `argv[0] = ./hello`：第 0 个参数是程序自身路径。
- `argv[1] = weidongshan`：第 1 个参数是你传入的字符串。

这也是用户态应用程序的典型特征。

### 3. `int main(int argc, char **argv)`

`main()` 是普通 C / Linux 应用程序的入口函数。

程序被 shell 启动后，运行时环境会调用 `main()`。这和 Linux 驱动不同。驱动模块不是由 shell 直接调用 `main()`，而是由内核在加载模块时调用注册好的初始化函数。

### 4. `if (argc >= 2)`

这行判断用户是否传入了额外参数。

如果传了参数，就输出用户传入的名字；如果没传参数，就输出默认的 `Hello, world!`。

### 5. `printf("Hello, %s!\n", argv[1]);`

这行通过标准输出打印字符串。

`printf()` 面向用户态程序，输出通常出现在终端。后面学习驱动时，内核打印会使用 `printk()`，输出通常通过 `dmesg` 查看。

### 6. `return 0;`

返回 0 表示程序正常结束。

这也是普通应用程序的行为。驱动模块不会用这种方式表示模块卸载完成，它有专门的退出函数。

## 第五部分：常见错误和陷阱

### 错误 1：把所有 `.c` 文件都当成同一种程序

错误现象：
看到 `hello.c`、驱动 `.c`、测试程序 `.c` 时，分不清哪个是应用，哪个是驱动。

错误原因：
只看文件后缀，没有看程序入口、使用的 API 和编译产物。

如何定位：
先找入口函数。如果有 `main()`，通常是应用或测试程序；如果有 `module_init()`，通常是内核模块。

正确做法：
读源码先判断文件身份，再看具体逻辑。

记忆方法：
`main()` 看用户态，`module_init()` 看内核态。

### 错误 2：以为 Linux 应用可以像单片机一样直接操作硬件

错误现象：
想在普通应用里直接读写 GPIO 寄存器或硬件地址。

错误原因：
没有理解用户态和内核态的权限隔离。

如何定位：
问自己：这段代码运行在用户态还是内核态？有没有权限访问硬件资源？

正确做法：
应用通过设备文件、系统调用或驱动接口访问硬件。

记忆方法：
应用提请求，驱动管硬件。

### 错误 3：混淆 `printf()` 和 `printk()`

错误现象：
在驱动代码里想直接使用 `printf()`，或者在应用里以为 `printk()` 能正常使用。

错误原因：
没有区分用户态标准库和内核日志接口。

如何定位：
看代码是否包含 `<stdio.h>`，以及代码运行在用户态还是内核态。

正确做法：
应用用 `printf()`，驱动用 `printk()`。

记忆方法：
`printf` 给终端看，`printk` 给内核日志看。

### 错误 4：一开始就死磕驱动 API

错误现象：
还没分清应用、驱动、内核，就开始背 `file_operations`、`copy_to_user` 等 API。

错误原因：
学习顺序太靠后置细节，缺少整体结构。

如何定位：
如果你说不清一个文件属于哪一层，就说明还不该死磕 API。

正确做法：
先建立分层图，再逐步学习驱动接口。

记忆方法：
先看地图，再进森林。

### 错误 5：只看代码，不写复盘

错误现象：
看完 `hello.c` 感觉很简单，但第二天看到驱动又混乱。

错误原因：
没有把“应用程序特征”和“驱动程序特征”整理成自己的判断标准。

如何定位：
问自己能不能用 3 句话解释：为什么 `hello.c` 不是驱动？

正确做法：
每天至少写 3 条笔记：主线、区别、疑问。

记忆方法：
不复盘，就等于只路过。

## 今日最小结论

今天必须记住一句话：

```text
hello.c 是用户态 Linux 应用程序，不是驱动；判断依据是它有 main()，使用 printf()，依赖 C 标准库，并从 shell 直接运行。
```

后面进入驱动时，你要用这个例子做对照：

```text
应用：main() + printf() + ./hello
驱动：module_init() + printk() + insmod/rmmod
```
