 # 高优先级资料清单

 这个文件用于告诉你：如果时间有限，哪些资料最该先看。

 ## 优先级 01：总路线

 - `StudyPlan/01_学习总路线.md`

 用途：

 - 先建立地图
 - 避免一开始陷入细节

 ## 优先级 02：14天计划

 - `StudyPlan/02_14天学习计划.md`

 用途：

 - 按天执行
 - 每天只解决当天目标

 ## 优先级 03：第一个认知入口

 - `01_单片机程序和Linux程序从上层到底层的完整比较/doc_pic/01_单片机程序和Linux程序从上层到底层的完整比较.md`

 必看原因：

 - 这是整套资料的起点
 - 帮你建立 Linux 应用、驱动、内核的整体关系

 ## 优先级 04：第一个应用程序

 - `01_单片机程序和Linux程序从上层到底层的完整比较/source/01_hello_app/hello.c`

 必看原因：

 - 它很简单
 - 能让你先从应用程序视角进入 Linux

 ## 优先级 05：第一个驱动程序

 - `01_单片机程序和Linux程序从上层到底层的完整比较/source/01_hello_drv`
 - `02_彻底分析第1个驱动程序/doc_pic/02_彻底分析第1个驱动程序.md`

 必看原因：

 - 真正开始进入驱动开发
 - 建立最小驱动的整体感觉

 ## 优先级 06：板子上实操

 - `04_板子上的第1个驱动程序_实际操作及编译过程`

 必看原因：

 - 从 PC 练习进入开发板实战
 - 理解交叉编译、部署、测试流程

 ## 优先级 07：驱动模型

 - `05_分离的设计思想与总线设备驱动模型`
 - `06_总线设备驱动模型彻底分析`

 必看原因：

 - 这是从“会看简单驱动”到“理解 Linux 驱动框架”的关键转折点

 ## 优先级 08：设备树与 GPIO

 - `07_设备树入门`
 - `08_设备树示例_Pinctrl和GPIO`
 - `09_Pinctrl和GPIO`

 必看原因：

 - 后面很多驱动都建立在设备树和 GPIO 基础上

 ## 优先级 09：驱动交互机制总结

 - `10_应用程序和驱动程序的更多交互方式`
 - `11_用一个程序总结驱动机制`

 必看原因：

 - 有助于把查询、休眠/唤醒、poll、异步通知串起来

 ## 优先级 10：进入一个总线专题

 推荐先看：

 - `24_I2C设备驱动程序开发1_AT24C02程序框架`

 然后再看：

 - `27_SPI设备驱动开发1_OLED屏幕`
 - `29_Framebuffer驱动程序框架`

 必看原因：

 - 让你对 I2C、SPI、Framebuffer 建立提高阶段的整体认识
