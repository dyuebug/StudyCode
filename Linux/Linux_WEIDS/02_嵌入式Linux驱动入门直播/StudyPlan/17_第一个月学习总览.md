 # 第一个月学习总览

 这份文档是把前面的学习计划再往前拉长一点，帮你看到“第一个月”大概应该学成什么样。

 前 14 天的目标是建立主线。

 后面的 2 周，目标是：

 **从知道学习路径，推进到能稳定阅读代码、能做小改动、能开始选择一个专题深入。**

 ---

 ## 1. 第一个月总目标

 一个月结束时，理想状态不是“全部学完”，而是做到下面这些：

 1. 能说清楚 Linux 应用、驱动、内核、设备文件、硬件的大致关系
 2. 能看懂第一个最小驱动的基本骨架
 3. 能理解 device / driver / bus / 设备树的大致联系
 4. 能看懂一个驱动目录里 `Makefile`、驱动源码、测试程序分别在干什么
 5. 至少完整跟过一条专题路线
 6. 至少做过几次小改动，而不只是纯看资料

 ## 5. 第 4 周：开始动手改小东西

 这一周不要贪大，重点是做小改动。

 例如：

 - 改 `printk` 或 `printf` 输出
 - 改测试程序的输入输出
 - 找到设备树里的 `compatible`
 - 对照两个版本源码，说出差异
 - 给自己写一页“这条专题路线的总结”

 这一周结束时你最少应该做到：

 - 对至少一个例子有“我改过它”的体验

 ---

 ## 6. 第一个月不需要做到什么

 下面这些事情，一个月内做不到也完全正常：

 - 独立从零写完整复杂驱动
 - 记住所有 API
 - 完全吃透所有总线和子系统
 - 看一眼陌生驱动就能立刻理解

 不要用这些不现实目标打击自己。

 ---

 ## 7. 一个月后怎么判断自己有没有进步

 你可以用下面这几个标准判断：

 - 我能不能区分用户态代码和内核态代码？
 - 我能不能先看 `Makefile` 再判断目录产物？
 - 我能不能大致说出 `probe`、设备树、匹配在做什么？
 - 我能不能看懂一个测试程序在怎样调用驱动？
 - 我有没有改过至少一个小例子？

 如果这些大部分都能做到，说明你已经不是“刚接触”，而是在真正进入 Linux 驱动学习状态了。

 ---

 ## 8. 最后建议

 第一个月最重要的不是速度，而是：

 **主线稳定、节奏稳定、笔记稳定、复盘稳定。**

 只要这四个稳定了，你后面深入 I2C、SPI、input、framebuffer 都会越来越顺。
