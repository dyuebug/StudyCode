 # Linux驱动学习总路线

 ## 1. 学习目标

 用 14 天时间建立一条清晰主线，先完成入门，再具备继续深入专题驱动的能力。

 目标不是一次性吃透所有章节，而是做到：

 1. 理解 Linux 应用、驱动、内核之间的关系
 2. 能看懂并跑通第一个驱动程序
 3. 理解字符驱动、总线/设备/驱动模型、设备树的基本思想
 4. 对 GPIO、中断、I2C、SPI、Framebuffer 有整体认知
 5. 能按资料目录继续自主深入

 ## 2. 推荐主线顺序

 ### 第一阶段：建立整体认知

 优先级最高，必须先学。

 - 01_单片机程序和Linux程序从上层到底层的完整比较
 - 02_彻底分析第1个驱动程序
 - 03_驱动辅助信息及地址空间概念
 - 04_板子上的第1个驱动程序_实际操作及编译过程

 这一阶段重点回答：

 - Linux 应用程序和单片机程序有什么区别？
 - 驱动程序在系统中的位置是什么？
 - 一个驱动是怎么编译、加载、测试、卸载的？

 ### 第二阶段：理解驱动框架

 - 05_分离的设计思想与总线设备驱动模型
 - 06_总线设备驱动模型彻底分析

 这一阶段重点理解：

 - device / driver / bus 的关系
 - 为什么 Linux 驱动强调分离思想
 - platform 总线模型的作用

 ### 第三阶段：设备树与板级资源

 - 07_设备树入门
 - 08_设备树示例_Pinctrl和GPIO
 - 09_Pinctrl和GPIO

 这一阶段重点理解：

 - 设备树如何描述硬件
 - compatible 的作用
 - pinctrl 与 gpio 的使用场景

 ### 第四阶段：APP 和驱动的交互

 - 10_应用程序和驱动程序的更多交互方式
 - 11_用一个程序总结驱动机制
 - 12_驱动开发基础答疑

 这一阶段重点理解：

 - 查询
 - 休眠/唤醒
 - poll/select
 - 异步通知
 - ioctl

 ### 第五阶段：实战驱动训练

 推荐顺序：

 - 13~16：SR501
 - 17：SR04
 - 18~20：DHT11
 - 21：DS18B20
 - 22~23：HS0038

 重点不是背代码，而是理解：

 - 数据从哪里来
 - 驱动如何等待事件
 - 为什么会有多种实现方式
 - 出错时如何调试

 ### 第六阶段：专题提高

 - 24~25：I2C + AT24C02
 - 26：I2C 触摸屏
 - 27~28：SPI + OLED
 - 29~30：Framebuffer + OLED 改造

 这一阶段开始进入：

 - I2C 总线驱动
 - SPI 总线驱动
 - 输入/显示类子系统
 - Framebuffer 驱动框架

 ## 3. 每章通用学习方法

 每章都按这个顺序来：

 1. 先看 `doc_pic/*.md` 或 `doc_pic/*.pdf`
 2. 再看 `source/` 下的代码
 3. 优先看 `Makefile`、`*_drv.c`、`*_test.c`、`.dts`
 4. 自己总结这章新增了什么机制

 ## 4. 重要提醒

 - 不要一开始就钻“重要的参考资料”
 - 不要一开始就死磕所有 API
 - 第一遍学习以“贯通主线”为目标
 - 第二遍再做专题深入
 - 第三遍开始动手改代码、仿写代码
