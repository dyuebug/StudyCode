## 学习内容

### 1. 对比两类运行模型

单片机裸机程序通常在启动代码完成基本初始化后直接运行，应用逻辑可以通过芯片寄存器或 HAL 操作外设。Linux 用户态应用则运行在操作系统管理的进程环境中，通常通过库函数和系统调用请求内核服务；设备访问也通常经过设备接口和驱动，而不是任意直接访问硬件。

今天先建立下面这张粗略地图，不需要掌握所有层次细节：

```text
用户态应用（main、C 库）
        ↓ 库函数 / 系统调用
Linux 内核（进程、内存、文件系统、驱动框架）
        ↓ 驱动与硬件接口
外设 / 硬件
```

### 2. 阅读 `hello.c`

找到并解释：

- `#include <stdio.h>`：声明标准输入输出接口。
- `main(int argc, char **argv)`：普通 C 应用的入口。
- `printf()`：向标准输出打印内容。
- `return 0`：向启动它的环境报告正常结束。

尝试回答：如果执行 `./hello Cursor`，`argc`、`argv[0]`、`argv[1]` 分别代表什么？不必假设一定能在当前 Windows 终端直接构建；在可用的 Linux/WSL 环境尝试即可，否则完成源码分析并标记未运行。

### 3. 判断一个源文件的身份

不要只看 `.c` 扩展名。先找入口和运行方式：

| 观察点 | 用户态应用的典型特征 | 内核模块的典型特征 |
| --- | --- | --- |
| 入口 | `main()` | `module_init()` 注册的初始化函数 |
| 常见输出 | `printf()` / 标准输出 | `printk()` / 内核日志 |
| 构建产物 | 可执行程序 | `.ko` 模块 |
| 启动方式 | shell 执行程序 | 内核加载模块 |

此表用于初步判断；真实工程仍要结合 Makefile、头文件、链接目标和运行环境核实。
