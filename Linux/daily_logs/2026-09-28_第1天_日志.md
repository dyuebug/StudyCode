## 2. 学到的核心知识

### 2.1 单片机与 Linux 应用的运行模型

单片机裸机程序或 RTOS 程序通常更接近寄存器和 HAL，可以直接或通过硬件抽象层访问外设。Linux 应用运行在用户态，通常通过 C 库、系统调用、设备文件或其他内核接口请求驱动访问硬件。

```text
单片机程序：应用逻辑 -> 寄存器 / HAL -> 硬件

Linux 应用：应用逻辑 -> C 库 / 系统调用 -> Linux 内核 -> 驱动 -> 硬件
```

### 2.2 `hello.c` 的身份判断

`hello.c` 是用户态应用程序，主要依据包括：

1. 存在 `main()` 函数。
2. 使用 `printf()` 向标准输出打印。
3. 使用 `return 0` 表示普通程序正常结束。
4. 包含 `<stdio.h>`，使用用户态标准输入输出接口。
5. 没有 `module_init()`、`module_exit()`、`printk()` 或驱动注册代码。

其中 `main()` 和 `printf()` 是最直接的判断依据；`return 0` 是辅助证据，不能单独作为程序身份的唯一判断标准。

### 2.3 `argc` 与 `argv`

执行：

```text
./hello Linux
```

得到：

```text
argc = 2
argv[0] = "./hello"
argv[1] = "Linux"
```

`argc` 表示参数数量，类型是整数；`argv` 是字符串指针数组。`argv[0]` 通常是程序自身的名称或路径，不包含多余的尾随空格。

## 4. 遇到的问题与修正

### 问题 1：`argc` 的含义

**现象**：最初把 `argc` 和命令行字符串混在了一起。

**原因**：没有区分“参数个数”和“参数内容”。

**修正**：`argc` 是参数个数；`argv[0]`、`argv[1]` 才是具体字符串。

### 问题 2：代码证据的准确性

**现象**：将“运行在应用层、用户直接感知”作为判断依据。

**修正**：优先使用代码证据：`main()`、`printf()`、`<stdio.h>`、`return 0`，以及缺少 `module_init()` / `module_exit()`。另外，函数名应写作 `printf()`，不是 `prinf()`。
