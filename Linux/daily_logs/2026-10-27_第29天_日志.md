## 学到的知识

1. **`CNDTR` 的两条硬规则**：递减到 0 表示完成；`EN=1` 时不可写，重装前必须关 `EN` **并等它读回 0**
   （硬件是在当前传输结束后才清 `EN`，写完就走会落在窗口里）。mem2mem 下源端被当作"外设端"，
   不置 `PINC` 就是同一个字写 N 次——完成标志照来，数据全错。
2. **标志只能由 `IFCR` 清**，写 `ISR` 无效。"假完成"的形状是：上一次留下的 `TCIF=1` 被读成这一次的完成，
   轮询循环立刻返回。`CNDTR` 能当场戳穿，但它是**边读边变**的量（256 字只要几十微秒），
   不能写进判据——判据要用不随时间变化的量（本次改为只看 `stale && tcif_now`）。
3. **bxCAN 的两段状态**：`MCR.INRQ` 请求 → `MSR.INAK` 确认；不在初始化模式时 `BTR` 与过滤器写入被
   **静默忽略**。过滤器还多一层 `FMR.FINIT`。回环模式（`BTR.LBKM`）不需要收发器，
   是单板把"配置→发送→过滤→接收"走完的唯一办法，也是排错链路上必须先过的一档。
4. **位时序要现算不能背**：`tq = (BRP+1)/PCLK1`，一位 = `1 + TS1 + TS2` 个 tq。本工程 `PCLK1 = 8 MHz`，
   16 tq × 125 ns = 2 µs → 500 kbps，采样点 87.5%。照抄 36 MHz/72 MHz 的参数会差整数倍。
5. **ADC 的码值不是物理量**：`code` 是 12 位比值；换电压要先知道 `Vdda`（用 Vrefint 反推），
   换温度要用出厂 `TS_CAL1/TS_CAL2` 两点校准。典型参数（`V25 = 1.43 V`、`4.3 mV/℃`）只能当量级参考。
6. **故障字怎么读**：`CFSR = 0x00008200` = bit15 `BFARVALID` + bit9 `PRECISERR`（精确总线错误，
   地址可定位）；`HFSR = 0x40000000` = bit30 `FORCED`（BusFault 未使能时升级为 HardFault）；
   `BFAR = 0x40006400` 就是出错的 CAN1 基址。三者合起来能直接下结论"这段地址没映射"。

## 遇到的问题

**现象 1**：`F103_17` 第一版校准判据在 QEMU 上打印 `RSTCAL 清零：ok`、`CAL 清零：ok`，
看起来像校准完成，实际 ADC 完全没响应。

**分析过程**：`ADON` 读回也是 0。未建模外设恒读 0，而判据写的是"等某位被硬件清零"——
位从来没被置起来过，等待立刻成功。**判据本身在制造假信号**，比超时危险得多。

**解决**：把一个判据拆成两段——先 `ADC1->CR2 |= RSTCAL` 后立刻读回"是否置位"，
再 `wait_clear()` 看"是否被清掉"；任一失败就打印"校准流程不可判定"。
`F103_19` 沿用同一思路：先读回 `CCR`，读回 0 就直接说明"未建模"，不再让后面的超时替它背锅。

**现象 2**：`F103_18` 在 QEMU 里"静默挂死"，日志停在半截。

**分析过程**：先在访问前加一行标记 → 确认死在 `CAN1->MCR` 的第一次写；加上
`BusFault_Handler`/`HardFault_Handler` 打印 `CFSR`/`HFSR`/`BFAR` 后，得到
`BFAR = 0x40006400`，正好是 `CAN1_BASE`。结论：该段地址未映射，不是 CAN 逻辑问题。

**现象 3**：`F103_19` 用例 3 的判据最初包含 `CNDTR == BUF_WORDS`。

**分析过程**：mem2mem 在 8 MHz 下 256 字只要几十微秒，`printf` 前几行代码就可能让它递减甚至归零；
真板上这条判据会"有时成立、有时不成立"。

**解决**：判据改为只依赖 `stale && tcif_now`（两者都回答"启动瞬间标志是不是 1"），
`CNDTR` 降级为辅助读数。教训：**判据要用不随时间变化的量**。

**还需验证**：以上三条都是仿真侧结论，真板行为要靠上板重跑补证据。
