## 2. 学到的核心知识

### framebuffer 的最小要求

```text
fb_info
  ├─ var / fix（分辨率、色深、行长）
  ├─ screen_base（显存）
  └─ fbops ── 决定 /dev/fb0 能不能 read/write
```

没有 `fb_ops`，`register_framebuffer` 仍可能成功，但 `/dev/fb0` 的 read/write 没有实现，文档里的 `dd ... of=/dev/fb0` 不可能成功。显存在 CPU 可访问内存时，直接用 `fb_sys_read`/`fb_sys_write` + `sys_fillrect`/`sys_copyarea`/`sys_imageblit`。

### 复盘

14 天的公共骨架只有一条：**设备怎么被发现 → `probe` 拿到什么 → `file_operations` 怎么用实例数据 → 怎么有序释放**。设备树、GPIO、I2C、SPI、FB 都是替换其中的某一层。

## 4. 遇到的问题与修正

### 问题 1：缺 `fb_ops` 导致 `/dev/fb0` 无法读写

**原因**：驱动只填了 `fb_info` 的分辨率与显存，没有 `fbops`。

**修正**：补 `fb_read`/`fb_write`/`fb_fillrect`/`fb_copyarea`/`fb_imageblit`。

### 问题 2：`dma_alloc_wc(NULL, ...)` 会崩溃

**原因**：DMA API 内部会解引用 `dev` 取 DMA 参数。

**修正**：传 `&spi->dev`，并保证 `dma_free_wc` 用同一个设备。

### 问题 3：`modpost: "__spi_register_driver" undefined`

**原因**：内核只开了 `CONFIG_I2C`，没有 SPI；且 `CONFIG_SPI` 是 bool，`--module SPI` 会被忽略。

**修正**：用 `--enable SPI` 重新配置并重建 `zImage`/`vmlinux`，让 `Module.symvers` 出现 SPI 导出符号。

## 5. 今日心得

「文档里写过的操作」不等于「代码支持的操作」：`dd of=/dev/fb0` 能否成功，取决于 `fb_ops` 是否实现。
