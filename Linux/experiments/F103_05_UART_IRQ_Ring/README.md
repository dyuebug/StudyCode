# F103_05：USART1 中断接收与无锁环形缓冲

## 学习目标

1. **轮询的能力边界**：用数字说明实验 04 为什么会丢字节，而不是仅凭直觉。
2. **中断的最小职责**：ISR 只搬数据、不做格式化，为什么把 `printf` 放进 ISR 是错误设计。
3. **SPSC 环形缓冲**：单生产者单消费者为什么可以不关中断；为什么要留一个空位；为什么容量取 2 的幂。
4. **两类丢失**：硬件溢出 `ORE` 与软件缓冲满 `drop` 的成因、观测与区别。

行为：与实验 04 相同的回显，但接收在中断中完成，主循环被 `printf` 阻塞期间数据不会丢。

## 与实验 04 的对照

| 维度 | 实验 04（轮询） | 实验 05（中断 + 环形缓冲） |
| --- | --- | --- |
| 谁发现数据到达 | 主循环每轮查 `RXNE` | `RXNEIE` 触发 IRQ 37 |
| 主循环阻塞 3 ms 时 | 缓冲只有硬件 1 字节，后续字节被覆盖 | 最多 127 B 排队，不丢 |
| 丢失可观测性 | 只能看到 `over` 累加 | `drop`（软件满）与 `ore`（硬件覆盖）分开计数 |
| 代码耦合 | 收、发、打印都在主循环 | ISR 只写缓冲；格式化留在主循环 |
| 额外成本 | 无 | 128 B RAM + 尾部临界区无需关中断 |

## 关键实现点

### 1. 为什么轮询一定会丢：把时间算出来

115200 8N1 每字节 10 bit，传输时间 `10 / 115200 ≈ 86.8 µs`。
实验 04 的心跳行约 40 字符，阻塞发送约 `40 × 86.8 µs ≈ 3.5 ms`；这期间到达约 40 字节，
而硬件接收寄存器只有 1 字节深，后续字节全部触发 `ORE` 被覆盖。

本实验的缓冲容量 127 B 提供了 `127 × 86.8 µs ≈ 11.0 ms` 的排空时间，约为心跳耗时的 3 倍。
这不是「更大就永远安全」——缓冲只是把丢数据的阈值从 3.5 ms 提高到 11 ms，真正的保障是主循环及时排空。

### 2. ISR 只做「搬移」

`USART1_IRQHandler` 的全部工作是：确认事件、读一次 `DR`（同时清 `RXNE` 与 `ORE`）、写缓冲、计数。
不调用 `printf`，理由有三：

- `printf` 是阻塞的，在 115200 下输出 40 字节约 3.5 ms；期间其他中断被延迟，接收缓冲持续增长。
- `printf` 内部使用 newlib 的静态 `FILE` 缓冲区，非可重入；主循环同时打印会破坏其内部状态。
- ISR 越短，中断嵌套与实时性越可控。格式化、协议解析都应放在主循环，或专门的低优先级任务。

### 3. 为什么这个环形缓冲不需要关中断

前提是**单生产者单消费者**：

- `s_head` 只由 ISR 写，`s_tail` 只由 ISR 读；
- `s_tail` 只由主循环写，`s_head` 只由主循环读；
- 两个索引都是 16 位对齐量，Cortex-M3 的 `ldr/str` 是单指令原子访问。

因此不存在「两个写者同时改同一变量」的竞争，无需临界区。若将来加入第二个中断源写同一个缓冲，
这个前提立刻失效，必须用 `__disable_irq()` 或原子操作保护。

`volatile` 是必要条件：没有它，`-Og` 及以上优化可能把 `s_head` 缓存在寄存器里，
主循环就永远看不到 ISR 的推进。但 `volatile` **不提供**跨变量的顺序保证，
本设计靠「每个变量只有一个写者」回避了这个问题。

### 4. 为什么要留一个空位，为什么容量取 2 的幂

若允许 `head == tail` 表示「满」，就无法与「空」区分。经典做法是让 `head` 永远不追上 `tail`：

```c
next = (head + 1) & (SIZE - 1);
if (next == tail) { /* 满 */ }
```

代价是容量减少 1 字节（128 B 实际可用 127 B），换来判断只需一次比较。

取 2 的幂是为了用 `& (SIZE - 1)` 代替 `% SIZE`：Cortex-M3 有硬件除法，但掩码仍是一条 `and`，
且不依赖除法器的结果延迟。若容量的 2 的幂特性被破坏，回绕会静默错位——这是最容易埋下的隐患。

### 5. `drop` 与 `ore` 不是同一件事

| 计数 | 触发点 | 含义 | 典型原因 |
| --- | --- | --- | --- |
| `ore` | 硬件置 `ORE` | 上一字节还没读走，新的已经到达 | ISR 被长时间屏蔽、ISR 本身太慢 |
| `drop` | `rx_ring_put` 发现满 | 软件缓冲没有空间 | 主循环长时间不排空 |

两者都表示数据丢失，但排查方向相反：`ore` 高说明中断侧的延迟不可接受；`drop` 高说明主循环侧的
阻塞时间超过了缓冲能吸收的时长。把它们分开计数，比只报一个「丢了多少」有用得多。

### 6. 主循环要「一次取空」

若每轮只取一个字节再去处理别的，ISR 会持续把缓冲填满，而主循环排空速度取决于循环体耗时。
本实验用 `while (rx_ring_get(&b))` 把当前所有可读数据一次性处理完，再进入心跳判断。
在回显场景下这不影响实时性（每字节 86.8 µs），但结构上保证了「排空优先于其他工作」。

### 7. 优先级：串口低于时基

`SysTick` 保持默认优先级 0，USART1 设为 1（数值越大优先级越低）。这样毫秒计时不会被串口中断打断，
`f103_tick_now_ms()` 的单调性不会因串口流量变化而抖动。反过来若串口优先级更高且 ISR 变得更长，
时间戳就会出现可见的跳变。

### 8. 与课程实现的差异

课程 `0703_uart_circle_buffer` 的 `circle_buf_*` 是通用实现：长度任意（用取模回绕）、满/空返回 −1、
写入失败由调用者判断。本实验改用 2 的幂 + 掩码、把失败计入 `drop`、并补齐 `volatile`。
课程版本在本场景下同样可用；差异在于本实验把「丢失必须可观测」当成硬要求。

## 常见错误

| 现象 | 可能原因 | 排查 |
| --- | --- | --- |
| 中断完全不进 | `RXNEIE` 未置位；队列未使能；`USART1_IRQn` 优先级被设为不可用值 | 读 `0x4001380C` 的 bit5 与 `0xE000E104` 的 bit5 |
| 进入一次后卡死 | ISR 没读 `DR`，`RXNE` 一直有效 | 确认 ISR 内有且仅有一次 `USART1->DR` 读取 |
| `ore` 持续增长 | ISR 太长，或被更高优先级中断长时间屏蔽 | 检查 ISR 是否有 `printf`、阻塞发送、长循环 |
| `drop` 持续增长 | 主循环长时间不排空，或缓冲太小 | 缩短心跳输出；增大 `RX_RING_SIZE`（保持 2 的幂） |
| 数据偶尔错位 | 多个上下文同时改 `head`/`tail`（破坏了 SPSC 前提） | 确认只有 ISR 写 `head`、只有主循环写 `tail` |
| 优化后收不到数据 | 索引缺少 `volatile` | 声明为 `static volatile uint16_t` |
| 回显顺序错乱或字符重复 | 主循环读了索引但在用之前被中断修改 | 先拷贝数据再推进索引；不要暴露内部索引 |
| 心跳三个计数互相矛盾 | 三个 `volatile` 变量不是同一瞬间的快照 | 需要一致快照时在读取处短暂 `__disable_irq()` |

## 已知限制

- 只支持单生产者单消费者；多中断源或 RTOS 多任务场景需要额外同步。
- 无硬件流控，缓冲满时无法反压主机，只能丢弃并计数。
- 容量固定 128 B（可用 127 B），未做动态分配；大流量场景需 DMA。
- 未处理帧错误 `FE`、噪声 `NE`、校验错误 `PE`，这些标志会在读 `DR` 时一并清除而不计数。
- 主循环回显仍是阻塞发送，输出量大于输入时会反过来填满缓冲。
