# F103_19：DMA1 内存到内存搬运（轮询 / 中断 / 假完成）

## 学习目标

1. **DMA 的三要素**：谁触发（`CCR.EN` 或外设请求）、搬多少（`CNDTR`）、搬到哪（`CPAR`/`CMAR`）。
   mem2mem 模式下"外设端"就是内存，所以能否成功只取决于寄存器序列，与外设是否工作无关。
2. **`CNDTR` 的两条硬规则**：递减到 0 表示完成；**`EN=1` 时不可写**，重装前必须关 `EN` 并等它读回 0。
3. **标志只能由 `IFCR` 清**：写 `ISR` 无效。`TCIF` 不清就复用时，上一次留下的 1 会被读成这一次的完成。
4. **"假完成"这一类缺陷的形状**：轮询标志的循环在标志是陈旧的 1 时立刻返回，数据还没搬完，
   代码却继续往下走。`CNDTR` 是唯一能当场戳穿它的证据。
5. **mem2mem 的 `PINC` 陷阱**：源端被当作"外设端"，不置 `PINC` 就是同一个字写 N 次，
   传输出错但"完成标志"一样会来。

## 核心概念

### mem2mem 与"外设请求"两种用法的区别

| 项 | mem2mem（本实验） | 外设请求（USART/ADC/SPI） |
| --- | --- | --- |
| 触发源 | 软件置 `EN` 后硬件自走 | 外设的 DMA 请求信号 |
| `CCR.MEM2MEM` | 1 | 0 |
| `CPAR` 指向 | 源内存 | 外设数据寄存器 |
| `PINC` | **必须置 1**（否则源地址不递增） | 一般清 0（外设寄存器地址固定） |
| 失败原因可分辨性 | 高（无外设参与） | 低（分不清是 DMA 还是外设没工作） |

### 标志与清零

`DMA_ISR` 是只读的；清零只能对 `DMA_IFCR` 写 1（`rc_w1`）。通道 1 的四个标志与对应清除位：

| 传输完成 | 半传输 | 传输错误 | 全局 |
| --- | --- | --- | --- |
| `TCIF1`(bit1) | `HTIF1`(bit2) | `TEIF1`(bit3) | `GIF1`(bit0) |
| `CTCIF1`(bit1) | `CHTIF1`(bit2) | `CTEIF1`(bit3) | `CGIF1`(bit0) |

## 接口卡片

### `dma1_ch1_disable()`

作用：关通道并**等 `EN` 真正读回 0**。

返回值：1 = 已关断，0 = 超时。

为什么不能写完就走：硬件在"当前这次传输结束"后才清 `EN`。立刻重装 `CNDTR` 会被忽略，
表现为"第二次搬了上一次的长度"或"完全没动"。

### `dma1_ch1_start(src, dst, words, extra)`

作用：装 `CPAR/CMAR/CNDTR/CCR`，最后置 `EN`。

`CCR` 固定包含 `MEM2MEM | PINC | MINC | DIR | PSIZE_1 | MSIZE_1`（32 位宽），
`extra` 用于追加 `TCIE` 等。

常见误用：把 `CCR` 的最后 `|= EN` 写成一次性赋值——次序无所谓，但**先写 `TIR` 类外设寄存器
再开 `EN`** 的规则在通用 DMA 上同样成立：`EN` 一置位，地址与长度就锁进去了。

### `DMA1_Channel1_IRQHandler()`

作用：判 `TCIF1` → 清 `CTCIF1` → 计数。

资源所有权：中断里不碰 `printf`，不做任何阻塞动作。计数变量必须是 `volatile`。

## 最小可运行实验

`main()` 依次跑三个用例：

1. **轮询**：启动后先读回 `CCR`/`CNDTR`，再轮询 `TCIF1`（上限 200000 次），最后逐字比对 256 个字。
2. **中断**：清标志、开 `TCIE` 与 NVIC、启动，等中断计数（上限 200000 次）。
3. **假完成对照**：先做一次完整搬运并**故意保留** `TCIF1`，然后不清标志直接重装启动，
   立刻读 `TCIF1` 与 `CNDTR`；之后按正确顺序（关 `EN` → 清标志 → 重装 → 启动）再来一遍。

## 预期现象

真板（**推算，未实测**）：

```text
=== F103_19 DMA1 ch1 内存到内存 ===
用例1 轮询：TCIF1=1 CNDTR=0 用时 0 ms，拷贝 全对
      CCR 读回 0x00004AD1（= EN|DIR|PINC|MINC|PSIZE_1|MSIZE_1|MEM2MEM），CNDTR 读回 ≤256
用例2 中断：TCIF1=1 CNDTR=0 用时 0 ms，拷贝 全对
      中断进入 1 次（应为 1；>1 说明标志没清干净导致重复进中断）
用例3 假完成：复用前 TCIF1=1，启动后立刻读 TCIF1=1 CNDTR=≤256
      如预期：启动瞬间标志就是 1，等 TCIF 的循环会立刻返回，与这一帧是否搬完无关
      清标志后重启：TCIF1=0 CNDTR=256（应为 0 与 256）
```

256 个字在 8 MHz 下只需几十微秒，`0 ms` 是毫秒计数器分辨率的限制，不是"没搬运"。
判断搬运是否真的发生要看 `CNDTR` 归零与逐字比对，不看计时。

QEMU 实测（见下节）全部落在超时分支，这是预期结果而非缺陷。

## 实测记录

**构建实测**（2026-10-27，arm-none-eabi-gcc 14.2.1）：

| 布局 | FLASH | RAM | text/data/bss |
| --- | --- | --- | --- |
| `build`（F103C8T6，64 KB/20 KB） | 6684 B（10.20%） | 4032 B（19.69%） | 6588 / 96 / 3936 |
| `build-qemu`（F100RB，128 KB/8 KB） | 6684 B（5.10%） | 4032 B（49.22%） | 同上 |

零编译告警、零链接告警。RAM 里 2048 B 是本实验的两个 1 KB 缓冲区，1536 B 是链接脚本预留的
512 B 堆 + 1 KB 栈哨兵，其余是 newlib 的 `__sf`/`__sglue` 等。

**QEMU 实测**（`tests/qemu-stm32/logs/neg_f103_19_dma_mem2mem.log`）：

```text
用例1 轮询：TCIF1=0 CNDTR=0 用时 76 ms，拷贝 有错
      首个不一致下标 0：src=0xA5A50000 dst=0x00000000
      CCR 读回 0x00000000（期望含 EN|DIR|PINC|MINC|PSIZE|MSIZE|MEM2MEM），CNDTR 读回 0
      CCR 恒为 0：本机未建模 DMA1，下面两个用例也只能看超时分支
用例2 中断：TCIF1=0 CNDTR=0 用时 2 ms，拷贝 有错
      首个不一致下标 0：src=0xA5A50000 dst=0x00000000
      中断进入 0 次（应为 1；>1 说明标志没清干净导致重复进中断）
用例3 假完成：复用前 TCIF1=0，启动后立刻读 TCIF1=0 CNDTR=0
      本机 TCIF 从未置位，这一条无从对照（未建模）
      清标志后重启：TCIF1=0 CNDTR=0（应为 0 与 256）
```

`CCR` 读回 0 是关键结论：配置根本没进寄存器，所以后面等待 `TCIF` 必然超时。
这条读回自检让"未建模"与"配置写错"在日志里就能分开——两者都会表现为超时，
但前者连 `CCR` 都不认，后者 `CCR` 会读回配置值。

**关于那两行计时（76 ms / 2 ms）**：QEMU 未开 icount，虚拟时钟按内部代价模型推进，
对 MMIO 访问有固定惩罚。所以 76 ms 与 2 ms 的差别反映的是"200000 次 MMIO 读 vs 200000 次 RAM 读"
在 QEMU 的代价模型里差两个数量级，**不是真实硬件时序**，不能引用为性能数据。
三次运行的用例 1 分别打印 76 / 81 / 82 ms，同一份固件、同一个 QEMU，说明这个读数连"可复现"都做不到。

**未验证**：真板上的 `TCIF1`、`CNDTR` 归零、数据比对结果、中断次数、真实搬运耗时。

## 关键实现点

### 1. 为什么先读回 `CCR`

`CCR` 读回 0 与"配置写错"在行为上完全一样：都是 `TCIF` 不来。加一行读回就把两者分开了。
这个习惯来自 `F103_17` 的教训——未建模的外设恒读 0，会让"等待清零"这类判据变成永远通过。

### 2. 为什么关 `EN` 之后还要轮询

`EN` 是"关断请求"，不是"已关断"。手册明确写：该位在当前传输结束后由硬件清除。
只写不查，紧接着写 `CNDTR` 就会落在"硬件已经清 `EN`、但读取时序未定"的窗口里，
表现为偶发的"长度不对"。

### 3. 中断版本为什么要 `NVIC_DisableIRQ`

用例 2 结束后关掉通道中断，避免用例 3 的对照实验被上一个用例残留的 `TCIE` 干扰。
教学代码里保留这一步，是因为"只关 `TCIE` 不关 NVIC"在实践中同样容易漏。

### 4. 计时用 `f103_tick_init_irq()` 而不是轮询模式

轮询模式的 `f103_tick_now_ms()` 恒为 0（见 `f103_tick.h`），`t1 - t0` 永远是 0，
看起来像"搬运瞬完"，其实是没计时。中断模式才有真实毫秒值。

### 5. 用例 3 的判据只有 `TCIF`，不看 `CNDTR`

用例 3 里 `CNDTR` 是**边读边变**的量：mem2mem 在 8 MHz 下 256 字只要几十微秒，
`printf` 前的几行代码就可能让 `CNDTR` 递减甚至归零。把它写进判据会得到一个
"有时成立、有时不成立"的结论。所以判据只用 `stale && tcif_now`——这两者读的是同一个
"启动瞬间标志是否为 1"，与帧是否搬完无关。`CNDTR` 只作为辅助读数打印。

这条经验对通用判据都成立：**判据要用不随时间变化的量**，否则日志会解释不清失败原因。

## 常见错误和陷阱

| 现象 | 可能原因 | 排查 |
| --- | --- | --- |
| `TCIF` 立刻为 1，数据没搬 | 标志没清就复用（本实验用例 3） | 看 `CNDTR` 是否仍为全量；启动前清 `CTCIF` |
| 数据全等于源的第 0 个字 | `PINC` 没置（mem2mem 源端不递增） | 读回 `CCR` 的 bit6 |
| 第二次搬运长度不对 | 没关 `EN` 就改 `CNDTR` | 加"关 `EN` 并等读回 0" |
| 写 `ISR` 清不掉标志 | `ISR` 只读，清零只能写 `IFCR` | 改用 `DMA1->IFCR = DMA_IFCR_CTCIF1` |
| 中断进两次 | 中断里没清标志，或清了 `GIF` 但没清 `TCIF` | 中断里只清自己处理的那一位 |
| 程序卡在 `dma1_ch1_disable()` | 通道未使能时 `EN` 本来就是 0（不会卡）；卡住说明写的是别的通道 | 确认 `DMA1_Channel1` 而不是 `DMA1_Channel2` |

## 故障排查方法

1. **先看 `CCR` 读回值**：0 说明时钟没开（`RCC->AHBENR.DMA1EN`，注意是 AHB 不是 APB）或本机未建模。
2. **再看 `CNDTR`**：启动后立刻读应为全量，完成后应为 0；两种都不是就说明通道根本没跑。
3. **看 `ISR` 的全部四位**：`TEIF1` 置位是地址/宽度配置错误，不是"没搬完"。
4. **清标志后重试一次**：如果第二次成功、第一次失败，问题是标志残留而不是配置。
5. **上真板前不要相信 QEMU 的耗时**。

## 练习题

1. **基础题**：把搬运宽度改成 8 位（`PSIZE=MSIZE=00`），把两个缓冲区改成 `uint8_t[300]`。
   提示：`CNDTR` 计数单位是"传输项"不是字节，且 mem2mem 下源/目的宽度必须一致。
2. **改错题**：下面这段在真板上第二帧数据总是第一帧的残留，为什么？
   ```c
   dma_start(src, dst, 256, 0);
   while (!(DMA1->ISR & DMA_ISR_TCIF1)) { }
   dma_start(src2, dst2, 256, 0);      /* 直接复用 */
   while (!(DMA1->ISR & DMA_ISR_TCIF1)) { }
   ```
3. **综合题**：把用例 2 改成用 `HTIF`（半传输）做"双缓冲"：前半搬完时处理前 128 字，
   后半搬完时处理后 128 字。要求说明为什么不能用 `TCIF` 实现双缓冲。
4. **思考题**：为什么 mem2mem 模式下必须置 `PINC`，而 USART 的 DMA 接收一般要清 `PINC`？
