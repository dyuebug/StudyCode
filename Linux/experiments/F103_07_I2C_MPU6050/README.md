# F103_07：I2C1 主机轮询读写 MPU6050

## 学习目标

1. **总线的电气前提**：为什么 I2C 必须用复用开漏，开漏 + 上拉如何形成"线与"。
2. **三个时钟寄存器**：`CR2.FREQ`、`CCR`、`TRISE` 各自约束什么，为什么 `FREQ` 是参考频率而不是分频值。
3. **单字节读的状态机**：`START → 地址W → ADDR → 寄存器 → 重复START → 地址R → 清ACK → 清ADDR → STOP → RXNE`，
   以及其中**每一步为什么必须在这个位置**——顺序错一步就多收一个字节，或者 STOP 迟到导致总线不释放。
4. **超时与恢复**：轮询必须带超时；NACK/总线错误如何和超时区分；软件复位能救什么、不能救什么。
5. **寄存器级验证方法**：用反汇编确认写入的常量、偏移与顺序，而不是"看代码觉得对"。

行为：上电后通过 USART1 打印 `WHO_AM_I`，唤醒 MPU6050，之后每秒打印一次三轴加速度原始值。

## 硬件

| 项 | 值 |
| --- | --- |
| SCL | **PB6** = I2C1_SCL，复用开漏 |
| SDA | **PB7** = I2C1_SDA，复用开漏 |
| 从机地址 | `0x68`（AD0 接地时的 7 位地址；AD0 接高为 `0x69`） |
| 关键寄存器 | `0x75` WHO_AM_I（读回 `0x68`）、`0x6B` PWR_MGMT_1、`0x3B..0x40` 加速度三轴 |
| 串口 | USART1：PA9 / PA10，115200 8N1 |

**硬件来源必须说清**：开发板原理图中 I2C1 只以网络标号 `PIJ205/206`、`PIJ405/406` 引到
`J2`/`J4` 两个 20-pin 2.54 mm 排针上，**板上没有焊接传感器**。
因此本实验的前提是外接 MPU6050 模块（模块自带上拉电阻）。
如果手头没有模块，程序会在 `WHO_AM_I` 阶段报 `nack`，这本身也是一次有效的错误路径验证。

引脚与地址依据课程 `[08]_I2C/0801_i2c_hal_poll`：`.ioc` 中 `PB6.Signal=I2C1_SCL`、`PB7.Signal=I2C1_SDA`，
`GPIO_MODE_AF_OD`，`ClockSpeed=100000`，`DutyCycle=I2C_DUTYCYCLE_2`，7 位寻址；
`main.c` 中使用 `(0x68 << 1)`、寄存器 `0x75` 与 `0x6B`。

## 关键实现点

### 1. 复用开漏不是可选项

I2C 是双向总线：主机发地址时 SDA 是输出，收到从机 ACK 时同一根线要变输入。
推挽输出会在从机拉低时形成短路（两个 MOS 同时导通）。开漏只有"拉低"和"高阻"两种状态，
高电平由外部上拉电阻提供，多设备挂同一根线时天然实现"线与"：任何一方拉低，整条线就是低。

PB6/PB7 的配置值 `0xF` = `CNF=11`（复用开漏）+ `MODE=11`（50 MHz）。复用（`CNF=1x`）是让外设而不是 `ODR` 控制引脚。

### 2. 三个值的推导

| 寄存器 | 公式 | 本实验 | 作用 |
| --- | --- | --- | --- |
| `CR2.FREQ` | `PCLK1 / 1 MHz` | **8** | 告诉外设 `PCLK1` 多少 MHz，内部用它换算 `t_LOW`、`t_HIGH`、`t_SU:DAT` 等时序 |
| `CCR` | `PCLK1 / (2 × f_SCL)` | **40** | 标准模式下直接就是 SCL 半周期的 `T_PCLK1` 个数 |
| `TRISE` | `t_r(max) / T_PCLK1 + 1` | **9** | 标准模式 `t_r ≤ 1000 ns`，`1000 ns / 125 ns + 1 = 9` |

`FREQ` 写错的危险在于它**不改变 `CCR`**：SCL 频率看起来还对，但数据建立/保持时间已经违反规范，
表现为"大部分时候能读、偶尔 NACK 或读到错值"——比彻底不通更难查。
本实验 `PPRE1 = 1`（复位值），`PCLK1 = HCLK = 8 MHz`；一旦配置 PLL 就必须按 `RCC->CFGR` 重算这三个值，
不能沿用 40/9。

### 3. 单字节读：顺序即正确性

```text
S | 0xD0 | A | reg | A | Sr | 0xD1 | A | data | N | P
```

对应寄存器操作：

| 步 | 操作 | 为什么必须在这里 |
| --- | --- | --- |
| 1 | `CR1 |= START`，等 `SR1.SB` | `SB` 置位表示起始条件已发出，此时总线归主机 |
| 2 | 写 `DR = 地址+W`，等 `SR1.ADDR` | `ADDR` 置位 = 地址已被从机 ACK |
| 3 | 读 SR1、再读 SR2 | **只有这个读序列能清 `ADDR`**；只读 SR1 会一直拉低 SCL（clock stretching），后面全部超时 |
| 4 | 写 `DR = 寄存器地址`，等 `TXE` 再等 `BTF` | `TXE` 只说明 `DR` 空，字节可能还在移位；`BTF` 才表示真正发完 |
| 5 | `CR1 \|= START`，等 `SB` | 重复起始，不发 STOP，总线保持占用 |
| 6 | 写 `DR = 地址+R`，等 `ADDR` | ✓ |
| 7 | `CR1 &= ~ACK` | 先决定"这一字节之后回 NACK"，再让接收开始 |
| 8 | 关中断 → 读 SR1、SR2 清 `ADDR` → `CR1 \|= STOP` → 开中断 | `ADDR` 一清从机立刻发送，STOP 必须赶在本字节结束前落下 |
| 9 | 等 `RXNE`，读 `DR` | 单字节收到 |

第 7、8 步是本实验最容易写错的地方，两个约束叠加在一起：

- **清 ADDR 与置 STOP 之间的窗口必须极短。** 参考手册把"接收 1 字节时清 ACK、清 ADDR、置 STOP"这一组操作称为
  EV6_3 事件。ST 勘误表原文指出：这类事件若没能在当前字节传输结束前处理完，
  可能出现**多收一个字节、重复读到同一数据或丢失数据**。
  勘误表给的 workaround 之一是在清 ADDR 与置 STOP 之间把 SCL 拉低（手动拉伸时钟）；
  ST 自家 HAL 用的是另一种：关中断包住这两步。本实验照 HAL 实现（用 `PRIMASK` 保存原状态，避免无条件开中断）。
  注意这一条与上一条不是重复：ACK 位只在一个应答脉冲窗口内有效，慢了就得多等一个字节；
  STOP 慢了的后果则是整个收尾时序错位。

顺序不能反过来写成"先清 ADDR 再清 ACK"，也不能把 STOP 拖到最后，这两个错误分别对应上表的两条约束。

依据：ST 勘误表 **ES096**（STM32F103x8/B 中密度，与本次使用的 C8 同族）与 **ES0340**（xC/D/E）的 I2C 章节 EV6_3 workaround；
课程树内 ST HAL 的 `HAL_I2C_Master_Receive()`（`[08]_I2C/0801_i2c_hal_poll/Drivers/STM32F1xx_HAL_Driver/Src/stm32f1xx_hal_i2c.c`）
在 `XferSize == 1U` 分支实现的就是同一顺序（`__disable_irq()` 包住清 ADDR 与置 STOP）。

### 4. 超时与三类错误

`i2c1_wait_sr1()` 同时检查目标位、错误标志（`AF` / `BERR` / `ARLO`）与 10 ms 超时：

| 返回 | 含义 | 典型原因 |
| --- | --- | --- |
| `I2C_OK` | 条件成立 | — |
| `I2C_ERR_NACK` | 从机未应答 | 地址错误、模块未接、模块未供电 |
| `I2C_ERR_TIMEOUT` | 位一直不出现 | 引脚接反、无上拉、`PE` 未置位、总线被钳死 |

没有超时的轮询在裸机上等于挂死，且看门狗也救不了（若不喂狗则整机复位，问题被掩盖）。
10 ms 的依据：100 kHz 下单字节读约 300 µs，留 30 倍余量足够覆盖 clock stretching。

`i2c1_recover()` 先尝试 `STOP` 再 `SWRST` 重新初始化。它救不了的情况是**从机把 SDA 钳在低电平**
（典型场景：主机在从机发送中途复位）。此时总线物理上无法产生 STOP，标准做法是手动把 SCL 打 9 个时钟
让从机把剩余位吐完，再发 STOP——本实验不实现，作为练习。

### 5. 为什么不用突发读

读 6 个加速度寄存器时，本实验用了 6 次独立的单字节读。突发读要处理"倒数第二个字节后仍回 ACK、
最后一个字节前回 NACK"，控制流分支更多，属于另一个知识点。代价是 6 倍的总线时间（约 1.8 ms/s），
在本实验的 1 Hz 采样率下完全可以忽略。突发读留作练习。

### 6. 与课程 HAL 实现的差异

课程的 `HAL_I2C_Mem_Read()` 把上述 9 步全部封装进库函数，调用者看不到 `ADDR` 何时清、`ACK` 何时关。
本实验把每一步展开，代价是代码更长，收益是任何一步出错都能定位到具体寄存器。
另外课程用 `HAL_I2C_Init()` 按 `I2C_DUTYCYCLE_2` 计算 `CCR`，本实验直接给公式，便于核对数值。

## 常见错误

| 现象 | 可能原因 | 排查 |
| --- | --- | --- |
| 立即返回 `nack` | 模块未接、地址错（AD0 接高为 `0x69`）、模块未供电 | 用万用表量模块 VCC；确认 AD0 电平 |
| 一直 `timeout`，`SR2.BUSY` 恒为 1 | SDA/SCL 接反、上拉缺失、从机把 SDA 钳低 | 量两根线空闲时是否都为高；断电后单独量上拉 |
| 读回恒 `0x00` 或 `0xFF` | 无上拉 / 引脚未配成复用开漏（仍是普通输入） | 检查 CRL 的 `0xFF000000`；量空闲电平 |
| 读到的总是下一个寄存器 | 单字节读时先清 `ADDR` 后清 `ACK` | 按第 3 节第 7、8 步纠正顺序 |
| 偶发多收一个字节、重复读到同一数据或丢数据 | 清 `ADDR` 与置 `STOP` 之间被打断（EV6_3 处理晚了） | 用关中断包住这三条寄存器操作 |
| 偶发 NACK、偶发错值 | `FREQ`/`CCR`/`TRISE` 与真实 `PCLK1` 不符 | 改了时钟树就重算三者 |
| 卡在 `SB` 等不到 | `PE` 未置位，或总线被其他主机占用 | 确认 `CR1` 第 0 位为 1 |
| 上电第一次就 `nack`，重试后正常 | 模块上电复位未完成 | 初始化后加 10~100 ms 延时 |
| 烧写后程序不跑 | 与前几个实验相同：检查复位向量与时钟初始化顺序 | — |

## 已知限制

- 仅在 100 kHz 标准模式；未实现快速模式（`CCR.FS=1`、`DUTY` 位、`TRISE` 需重算）。
- 单主机，未处理多主机仲裁（`ARLO` 只当作错误上报，不重试）。
- 6 次单字节读而非突发读；采样率 1 Hz，未评估高采样率下的总线占用。
- 未接入 MPU6050 的 INT 引脚，未做数据就绪中断。
- 全部行为未在真实板卡上验证；原理图推断的"外接模块"结论也未实测。
