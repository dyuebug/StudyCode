# F103_03：外部中断读按键（EXTI14 + NVIC）

## 学习目标

同一个按键、同一个 LED，把「怎么发现按下」从轮询换成中断，重点不在功能，而在线路：

1. **AFIO 的角色**：为什么配 EXTI 还必须开 `AFIOEN`，`EXTICR` 如何把某条 EXTI 线接到具体端口。
2. **EXTI 的四个寄存器**：`IMR`（屏蔽）、`FTSR`/`RTSR`（边沿选择）、`PR`（挂起标志，写 1 清除）。
3. **NVIC**：中断使能与优先级，以及「一个向量对应多条 EXTI 线」时的入口判断。
4. **中断与主循环的分工**：ISR 只记录事件，点灯留给主循环；共享变量为什么必须 `volatile`，临界区为什么只有三条指令。

## 与实验 02 的对照

| 维度 | 实验 02（轮询） | 实验 03（中断） |
| --- | --- | --- |
| 发现按下 | 主循环每 1 ms 采样 `IDR` | CPU 被 EXTI 唤醒进入 ISR |
| 消抖位置 | 状态机计数，在主循环 | 时间戳窗口，在 ISR |
| CPU 占用 | 恒定采样开销 | 空闲时不采样 |

## 关键实现点

### 1. 漏开 `AFIOEN` 是最常见的「中断不进」

`EXTICR` 位于 AFIO，而 AFIO 在 APB2 上，必须 `RCC->APB2ENR |= RCC_APB2ENR_AFIOEN`。
只开了 GPIOB 时钟时，`EXTICR` 写入被静默忽略，引脚变化不会传到 EXTI——现象是「代码看着对、中断从不触发」。

### 2. `PR` 必须写 1 清除

`EXTI->PR` 的挂起位是「写 1 清除」，写 0 无效。ISR 里不清或清错方向，退出中断后挂起位仍然有效，会立刻重新进入，
表现为程序卡死在中段。这与很多「写 0 清除」的标志位寄存器语义相反，是需要记住的差异。

### 3. 共享向量要先判断来源

`EXTI15_10_IRQn` 一个向量覆盖 EXTI10~15 六条线。进入 ISR 后先检查 `PR` 中是不是自己那条线，
否则同组其他线的中断会被误当成按键处理。

### 4. 抖动在边沿上也会放大

轮询时抖动表现为「读数跳动」，中断时抖动表现为「ISR 被连续触发多次」。
这里用「距上次采纳是否满 20 ms」过滤，`now - last_ms` 用无符号减法，天然处理计数器回绕；
代价是必须在 ISR 里读一次毫秒计数（`f103_tick_now_ms()` 只读一个 `volatile` 变量）。

### 5. 为什么不在 ISR 里点灯

`led_toggle()` 需要读 `ODR` 再写 `BSRR`，是读-改-写；若其他上下文也写该引脚，就要加临界区。
更根本的是 ISR 应尽量短：本例用事件计数把工作推回主循环，主循环再用三条指令的临界区安全取走。
这也解释了为什么 `s_key_events` 必须是 `volatile`：否则主循环可能把它缓存在寄存器里，永远看不到中断的修改。

### 6. 与课程实现的差异

课程 `0601_key_isr` 用 `GPIO_MODE_IT_RISING_FALLING`（双边沿），在 `HAL_GPIO_EXTI_Callback` 里
读 `IDR` 分辨按下/松开，并直接写 LED。本实验只开下降沿、按时间窗口去抖、点灯延迟到主循环。
两种都可用，差异在于「抖动过滤放在哪一层」以及「ISR 承担多少工作」。

## 常见错误

| 现象 | 可能原因 | 排查 |
| --- | --- | --- |
| 中断完全不进 | 未开 `AFIOEN`；`EXTICR` 未选对端口；`IMR` 位未置 | 用调试器读 `0x40010000+0x14` 与 `0x40010400` |
| 一进中断就卡死 | `PR` 未清或写 0 清除 | 检查 ISR 里的 `EXTI->PR = EXTI_PR_PR14` |
| 按一次翻多次 | 未做时间窗过滤 | 确认 20 ms 阈值生效，`f103_tick_now_ms()` 在递增 |
| 松手时也触发 | `RTSR` 也被使能 | 确认 `EXTI->RTSR` 的 bit14 为 0 |
| 优先级配置无效 | 优先级分组与抢占/子优先级理解错误 | 本例只用 4 位抢占，`2 << 4` 写入 IPR |
| 编译报 `SysTick_Handler` 重复定义 | 实验自行定义了同名函数 | `f103_tick` 已占用该向量，需合并或改用轮询模式 |

## 已知限制

- 只用了 EXTI 的边沿触发，未涉及软件触发（`SWIER`）与事件模式（`EMR`）。
- 去抖依赖 SysTick 已启动；若在其他实验里先于中断初始化调用 `f103_tick_now_ms()`，返回值恒为 0。
- 未处理按键长按与连发（auto-repeat），也尚未在低功耗场景下验证唤醒行为。
