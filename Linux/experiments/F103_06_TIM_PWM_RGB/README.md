# F103_06：TIM2 三通道 PWM 与 RGB 呼吸灯

## 学习目标

1. **时基与分辨率**：`PSC` / `ARR` / `CNT` 三者如何同时决定 PWM 频率和占空比级数，为什么这两个指标互相牵制。
2. **输出比较转 PWM**：`CCMR` 选模式、`CCER` 使能输出与选极性，`CCR` 才是占空比。
3. **引脚复用与 JTAG 释放**：PA15、PB3 复位后属于 JTAG，不释放就没有波形——一个只有看波形才能发现的坑。
4. **预装载**：`OCxPE` / `ARPE` 为什么能让占空比在更新事件时整体生效，避免半周期改写造成毛刺。

行为：板载 RGB 灯以约 10.2 s 的周期做白色呼吸（256 级亮度、20 ms 一步，上下各一轮）。

## 硬件

| 项 | 值 |
| --- | --- |
| 颜色 | R = TIM2_CH3 = **PA2**；G = TIM2_CH1 = **PA15**；B = TIM2_CH2 = **PB3** |
| 接法 | 共阳极接 3.3 V，引脚拉低点亮 → 输出极性 `CCxP = 1` |
| 板卡 | DShanMCU-103 |

通道映射与极性依据课程 `[10]_定时器/1003_pwm_color_led`：
`driver_color_led.c` 中 `COLOR_LED_R = TIM_CHANNEL_3`、`COLOR_LED_G = TIM_CHANNEL_1`、`COLOR_LED_B = TIM_CHANNEL_2`，
三个通道的 `OCPolarity` 均为 `TIM_OCPOLARITY_LOW`；`0501_led.ioc` 给出 `PA15 = S_TIM2_CH1_ETR`、`PA2 = S_TIM2_CH3`、`PB3 = S_TIM2_CH2`。

白色呼吸同时点亮三个通道，因此也是自检：**若呼吸时偏色，说明某个通道没有输出**（最常见的是 JTAG 未释放）。

| `CCMR2` | `movs #0x68` → `+0x1C` | OC3M = 110 + 预装载 ✓ |
| `CCER` | `movw #0x333` → `+0x20` | 三通道 CCxE + CCxP 全置位 ✓ |
| `CR1 = ARPE` → `EGR = UG` → `CR1 \|= CEN` | `0x80`、`0x1`、`0x81` 写入 `+0x00`/`+0x14`/`+0x00` | 预装载 → 装载影子寄存器 → 启动 ✓ |

## 关键实现点

### 1. 频率与分辨率是同一枚硬币

计数时钟 `f_cnt = TIM2CLK / (PSC + 1)`，PWM 周期 `T = (ARR + 1) / f_cnt`：

| 项目 | 本实验 | 说明 |
| --- | --- | --- |
| TIM2CLK | 8 MHz | 未开 PLL，PPRE1 = 1 |
| 计数频率 | 8 MHz / 18 ≈ 444 kHz | `PSC = 17` |
| PWM 频率 | 444 kHz / 2000 ≈ **222 Hz** | `ARR = 1999` |
| 占空比级数 | **2000 级**（≈ 11 bit） | 上限就是 `ARR + 1` |

想让频率更高，就得减小 `ARR`，占空比级数随之下降；想更细腻，就加大 `ARR`，频率下降。
222 Hz 远高于人眼闪烁融合频率（通常 60~90 Hz），所以看不到闪；11 bit 分辨率足以让呼吸平滑。

课程工程开启了 PLL（72 MHz），APB1 = 36 MHz，按「APB1 分频不为 1 时定时器时钟 ×2」的规则，
TIM2CLK = 72 MHz，同样的 `PSC=17 / ARR=1999` 得到 2 kHz。本实验未配 PLL，所以是 222 Hz —— 参数相同、时钟不同。

### 2. PWM1 模式 + 反极性 = 共阳 LED

| 配置 | 含义 |
| --- | --- |
| `OCxM = 110`（PWM1） | `CNT < CCR` 时参考信号有效 |
| `CCxP = 0`（高有效） | 参考信号有效 → 引脚输出高 |
| `CCxP = 1`（低有效） | 参考信号有效 → 引脚输出低 |

共阳 LED 的阳极接 3.3 V，阴极接引脚：引脚低 → 有电流 → 点亮。因此取 `CCxP = 1`，
此时 **CCR 越大，低电平占比越大，灯越亮**。若误用 `CCxP = 0`，呼吸会反向：数值增大反而变暗。

### 3. PA15 / PB3：不写 `SWJ_CFG` 就永远没有波形

Cortex-M3 复位后，JTAG 占用 PA13（SWDIO）、PA14（SWCLK）、PA15（JTDI）、PB3（JTDO）、PB4（JNTRST）。
AFIO_MAPR 的 `SWJ_CFG[2:0]` 决定这组引脚归谁：

| `SWJ_CFG` | 效果 | 释放的引脚 |
| --- | --- | --- |
| `000` | 全功能 JTAG + SWD（复位值） | 无 |
| `001` | 去掉 JNTRST | PB4 |
| **`010`** | **关 JTAG、留 SWD** | **PA15、PB3、PB4** |
| `100` | 全部关闭 | PA13、PA14、PA15、PB3、PB4 |

本实验用 `010`：三个 LED 引脚全部释放，同时保留 SWD，烧写与调试不受影响。
用 `100` 会连调试口一起关掉，之后只能靠 `BOOT0` 或擦除全片才能重新连上——不要在调试阶段这么做。

这一步没有任何编译期或运行期报错，唯一的现象是「PA15 和 PB3 上的 PWM 不存在」，灯只亮红色。
排查方法：把示波器/逻辑分析仪接到引脚，若一直是高阻/固定电平，先查 `MAPR`。

### 4. 预装载：为什么要两套寄存器

`CCR` 有影子寄存器。`OCxPE = 1` 时，写 `CCR` 只更新预装载寄存器，真正生效发生在下一个更新事件（UEV）。
好处是：若在计数到一半时直接改写 `CCR`，可能出现「本周期变短/变长」的毛刺；预装载保证每个周期都是完整的。

`ARPE = 1` 对 `ARR` 起同样作用。本实验在启动前写 `EGR = UG`，手工产生一次更新事件，
把 `PSC`（`PSC` 本身也有影子寄存器，但只在 UEV 装载）与 `ARR` 立即生效，并把计数器清零。

注意：`UG` 也会把预装载的 `CCR`（此时为 0）装入影子寄存器，所以上电第一刻灯是灭的，符合预期。

### 5. 为什么用硬件 PWM 而不是软件翻转

软件 PWM 需要在定时中断里翻转 GPIO，占空比精度取决于中断响应抖动，且高分辨率时中断频率会高到不可接受
（2000 级 @ 222 Hz 意味着每秒 44.4 万次中断）。硬件 PWM 由比较器直接控制引脚，CPU 只需在改变亮度时写一次 `CCR`。

### 6. 呼吸曲线是线性的，不是视觉线性的

本实验按 `0..255` 线性扫描占空比。人眼对亮度的感知近似幂函数（约 2.2 次方），
所以线性扫描在低亮度段看起来「跳变」，在高亮度段又「变化不明显」。
改善方法是查 gamma 表：`ccr = pow(level / 255, 2.2) * ARR`。本实验不做，保持代码聚焦在定时器配置上。

### 7. 与课程实现的差异

课程 `ColorLED_SetColor()` 每次调用都重新执行 `HAL_TIM_PWM_ConfigChannel()`，相当于重写模式、极性与 `CCR`。
本实验只在初始化时配置一次 `CCMR`/`CCER`，运行期只写 `CCR1/2/3`，更接近实际产品代码，
也更能说明「哪些寄存器是配置、哪个寄存器是数据」。

## 常见错误

| 现象 | 可能原因 | 排查 |
| --- | --- | --- |
| 只有红色，G/B 不亮 | `SWJ_CFG` 未改，PA15/PB3 仍归 JTAG | 读 `0x40010004` 的 bit[26:24] 应为 010 |
| 三个通道都不亮 | TIM2 时钟未开、`CEN` 未置位、通道配成通用输出 | 量 PA2 是否有方波；反汇编确认写了 `0x4002101C` |
| 呼吸方向相反（数值大反而暗） | 极性配成高有效 | 确认 `CCER` 写入 `0x333` |
| 亮度完全不变 | `CCR` 写到了错误的通道，或 `CCxE` 未置位 | 对照 R/G/B 与 CH3/CH1/CH2 的映射 |
| 频率不是 222 Hz | PSC 未通过 `UG` 装载；或 APB1/定时器 ×2 规则被忽略 | 先量频率再算 `TIM2CLK` |
| 亮度调节时有可见抖动 | 未开 `OCxPE`，在半周期改写 `CCR` | 置 `CCMRx` 的 `OCxPE` |
| 烧写后再也连不上 | `SWJ_CFG` 误写成 `100` | 用 `BOOT0` 进系统存储器，或连接时按住复位 |

## 已知限制

- 未配置 PLL，全部运行在 8 MHz HSI；开启 PLL 后必须重新计算 `PSC`/`ARR`。
- 只做白色呼吸，未使用 HSV/色轮；亮度变化是线性的，未做 gamma 校正。
- `CCR` 由 CPU 逐个写入，三个通道之间存在微秒级不同步（肉眼不可见，摄影或高速测量可见）。
- 未使用 DMA 更新 `CCR`（课程未覆盖），复杂灯效时可考虑。
