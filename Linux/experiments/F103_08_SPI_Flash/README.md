# F103_08：SPI1 主机读写外部 SPI NOR Flash（W25Q 系列）

## 学习目标

1. **全双工移位寄存器**：SPI 没有"读"和"写"两种操作，只有一次交换；读数据就是发哑字节换数据。
2. **模式 0 的物理含义**：`CPOL` 决定空闲电平、`CPHA` 决定采样边沿，W25Q 支持模式 0 和模式 3。
3. **NSS 的三种用法**：硬件 NSS、软件 NSS + 普通 GPIO 片选、以及为什么 `SSI` 必须置 1。
4. **片选收尾**：为什么拉高 CS 之前要等 `BSY` 清零，而不是只等 `TXE`。
5. **Flash 指令协议**：`WREN → 命令+24 位地址 → 轮询 WIP` 的三段式，以及擦除 45 ms 级延时为什么不能靠 `delay()`。
6. **超时意识**：没有芯片时轮询状态位会永远为忙，裸机死循环；本实验给每条等待都加超时。

行为：上电读 JEDEC ID 并打印厂商/容量；若读到有效 ID，则擦除扇区 0、写入一句自检字符串、回读比对并打印 PASS/FAIL；
之后每 3 s 重读一次 ID，便于插拔模块时观察。

## 硬件

| 项 | 值 |
| --- | --- |
| SCK | **PA5** = SPI1_SCK，复用推挽 |
| MISO | **PA6** = SPI1_MISO，浮空输入 |
| MOSI | **PA7** = SPI1_MOSI，复用推挽 |
| CS | **PB9** = 普通 GPIO 推挽，空闲为高 |
| 模块 | 外接 W25Qxx（典型 W25Q64，8 MB），3.3 V 供电，**不可接 5 V** |

引脚分配依据课程 `[09]_SPI/0901_spi_flash`：`.ioc` 中 `PA5=SPI1_SCK`、`PA6=SPI1_MISO`、`PA7=SPI1_MOSI`，
`PB9=GPIO_Output`；驱动里 `SPIFlash_Select()` 把 **PB9** 拉低。

**硬件来源必须说清**：底板原理图中这四根信号线引到一个 4 信号排针（旁边标注 `PA5/PA6/PA7/PB9` 与 `3.3 V`），
`PA7` 侧写的是 `DI/SPI1_MOSI`、`PA6` 侧写的是 `DO/SPI1_MISO`——这是**模块视角**的命名（模块的 DI 接主机的 MOSI）。
板上没有焊接存储芯片，必须外接模块。排针的具体针序请以板子丝印为准，本实验未在实物上核对。

顺带说明：底板上的 OLED 占的是 I2C1（PB6/PB7），与 SPI1 不冲突。

## 预期现象

接 W25Q64 模块（下列数值**按数据手册推算，不是实测截图**）：

```text
[F103_08] SPI1 master, mode 0, 8-bit, SCLK = 2000000 Hz, CR1 = 0x034C
JEDEC ID = EF 40 17
厂商 Winbond，容量码 0x17 → 8192 KB

--- 自检：擦除 → 写入 → 回读（会清空 4 KB 扇区 0）---
扇区擦除 : ok         (45 ms)
页编程 55 B: ok         (1 ms)
回读内容 : F103 SPI flash self-test: erase + program + read back.
原始字节 : 46 31 30 33 20 53 50 49 20 66 6C 61 73 68 20 73
结果     : PASS

[3000 ms] ID = EF 40 17
```

`EF 40 17` 是 W25Q64 的 JEDEC ID（Winbond / 类型 0x40 / 容量 2^0x17 = 8 MB）；实际耗时随芯片型号与批号变化。

不接模块：

```text
JEDEC ID = FF FF FF
全 0xFF：MISO 没有驱动，通常是没有接模块（浮空输入被读成高）
[3000 ms] ID = FF FF FF
```

浮空输入的读数不确定，也可能不是 `FF`；本实验只把它当作"没有有效从机"的提示，不做严格判断。

**寄存器写入核对**（反汇编，非推测）：

| 意图 | 生成指令 | 结论 |
| --- | --- | --- |
| 开 GPIOA/GPIOB/SPI1 时钟 | `orr #0x1000` / `orr #12`，写 `0x40021018` | SPI1EN + IOPAEN + IOPBEN ✓ |
| PA5/PA6/PA7 引脚模式 | `ubfx #0,#20` → `orr #0xB4000000` → `orr #0x00B00000` | 合成 `0xB4B00000` = PA7 `B` / PA6 `4` / PA5 `B` ✓ |
| PB9 推挽输出 | `bic #0xF0` / `orr #0x30` 到 `0x40010C04` | CRH bit[7:4] = 0x3 ✓ |
| CS 空闲为高 | `mov #0x200` → `str` 到 `0x40010C10` | BSRR 的 BS9 ✓ |
| CS 拉低 | `mov #0x02000000` → `str` 到 `0x40010C10` | BSRR 的 BR9 ✓ |
| `SPI1->CR1` | `mov #0x30C` → `+0x00`，随后 `orr #0x40` | MSTR+SSM+SSI+BR=/4，最后置 SPE ✓ |
| 字节交换 | `wait 0x2` → `str DR(+0x0C)` → `wait 0x1` → `ldr DR` | TXE 后写、RXNE 后读 ✓ |
| CS 前提 | `ldr SR(+0x08)` → `tst #0x80` | BSY 清零后才拉高 CS ✓ |
| JEDEC ID | `movs #0x9F`，循环 3 次（`cmp #2; bls`） | 读 3 字节 ✓ |
| 扇区擦除 | 先 `flash_write_enable`，再 `movs #0x20` + 24 位地址 | WREN → 0x20 ✓ |
| 读数据 | `movs #3` + 24 位地址 + 循环发 `0xFF` | 0x03 ✓ |

**一个被反汇编抓到的真实错误**：初版把 CRL 常量写成 `0xBF400000`，拆成半字节是 `B/F/4/0`，
即 PA6 被配成复用推挽、PA5 被配成浮空输入——SCK 与 MISO 正好互换。这类错误编译零告警、代码"看起来对"，
只有对着反汇编核半字节才会暴露；已改为 `0xB4B00000` 并在代码注释里留下这个反例。

**未验证**：实际波形（SCLK 频率、模式 0 的采样边沿）、JEDEC ID、擦除/编程耗时、数据正确性。
这些都需要接上模块后实测，README 不把它们当作既有结果。

## 关键实现点

### 1. 读数据就是"发哑字节"

SPI 是一对移位寄存器首尾相接的环形结构：主机移出一位，同时移入一位。因此：

- 写一个字节 → 必然收到一个字节（可能是垃圾）；
- 想收 N 个字节 → 必须移出 N 个字节，`0xFF` 只是习惯用的"什么都没说"的值。

`spi_xfer()` 就是这一条的具体化：先等 `TXE` 保证发送缓冲空，写 `DR`；再等 `RXNE` 保证接收完成，读 `DR`。
只写不读会让 `RXNE` 残留，下一次读到的就是上一次的数据——这是 SPI 代码最常见的错位来源。

### 2. 模式 0 与 `CPOL` / `CPHA`

| 位 | 值 | 含义 |
| --- | --- | --- |
| `CPOL = 0` | 空闲低电平 | SCLK 在两次传输之间保持低 |
| `CPHA = 0` | 第一个边沿采样 | 上升沿采样、下降沿移出（数据在低电平期间稳定） |

W25Q 系列支持模式 0 和模式 3。选哪一个都能工作，但**必须与从机一致**；不一致的典型现象是"读到的 ID 整体错位若干位"，
而不是完全读不到——比接线错误更难判断。

### 3. `SSM` 与 `SSI`：不接硬件 NSS 时的必填项

本实验只用三根信号线 + 一个普通 GPIO 做片选，硬件 NSS 引脚（PA4）空着。这时必须：

```c
SPI1->CR1 = SPI_CR1_MSTR | SPI_CR1_SSM | SPI_CR1_SSI | SPI_CR1_BR_0;
```

`SSM = 1` 表示"NSS 由软件管理，忽略 NSS 引脚"；`SSI = 1` 把内部 NSS 强制为高。
**如果 `SSI = 0`，主机模式会进入 `MODF`（模式错误）并自动清 `SPE`，SPI 直接停摆**，
现象是没有任何波形、`SR` 里 `MODF` 置位。这是只接三根线时第一个要检查的地方。

### 4. 拉高 CS 之前必须等 `BSY`

`TXE = 1` 只说明发送缓冲已经空，最后一位可能还在移位寄存器里。此时立刻拉高 CS，从机看到片选结束就会丢弃这一位，
表现为**读回的最后一个字节高位随机错**——偶发、难复现。

正确顺序是：发完最后一个字节 → 等 `TXE` → 等 `BSY = 0` → 拉高 CS。`flash_deselect()` 做的就是这件事，
并且把之前的错误码原样带出，避免"收尾成功"覆盖掉"传输失败"。

### 5. `WREN → 命令 → 轮询 WIP`

所有会改变 Flash 内容的操作（页编程、扇区擦除）都必须先发 `0x06`（Write Enable），且**发完之后 CS 必须先拉高**，
再发真正的命令——`WREN` 与后续命令必须是两个独立的片选周期。芯片内部把 `WREN` 记在状态寄存器的 `WEL` 位上。

擦除/编程期间芯片忙，会忽略新指令，只能读状态寄存器等 `WIP`（bit0）清零（耗时为 W25Q64 数据手册典型值，本实验未实测）：

| 操作 | 典型耗时 | 本实验超时 |
| --- | --- | --- |
| 页编程 256 B | 0.7 ms | 100 ms |
| 4 KB 扇区擦除 | 45 ms | 1000 ms |
| 整片擦除 | 数十秒 | 未实现 |

用固定 `delay(50)` 代替 WIP 轮询在多数情况下"能跑"，但换一颗芯片或电池供电时就会偶发写失败；
轮询才是协议要求。

### 6. 页编程的 256 B 回卷

页编程一次最多写 256 B，且**不能跨页**。若从 `addr & 0xFF = 250` 开始写 10 个字节，芯片会在页内回卷，
把前 4 个字节覆盖到页首。软件必须自己按页拆分。

本实验在 `flash_page_program()` 里直接拒绝跨页写入（返回 `ERR_PAGE`），而不是悄悄写错；自检数据从地址 0 开始、长度 57 B，
不会触发。真正的驱动需要循环拆页，留作练习。

### 7. 课程驱动的三个问题

课程的 `driver_spi_flash.c` 可以跑通，但有三处不适合直接照抄：

| 位置 | 问题 | 本实验的做法 |
| --- | --- | --- |
| `SPIFlash_WaitReady()` | `while (SPIFlash_ReadStatus() & 1 == 1);` 无超时；且 `==` 优先级高于 `&`，表达式实际是 `status & (1==1)`，**碰巧**结果正确 | 轮询 + 超时，条件写成 `(sr & WIP) == 0` 显式退出 |
| `SPIFlash_ReadID()` | `0x9F` 只读 2 字节（丢了容量码） | 读满 3 字节：厂商、类型、容量 |
| `SPIFlash_Write()` | 不检查跨页，也不限制长度 | 显式拒绝 `len > 256` 与跨页 |

另外，未接模块时 MISO 浮空、读回全 `0xFF`，`WIP` 恒为 1——没有超时的实现会直接挂死。这是本实验给每条等待都加超时的直接原因。

### 8. 时钟：同样的分频，不同的 SCLK

| 工程 | PCLK2 | BR = /4 | SCLK |
| --- | --- | --- | --- |
| 课程（开 PLL） | 72 MHz | 001 | 18 MHz |
| 本实验（HSI 直出） | 8 MHz | 001 | **2 MHz** |

W25Q64 标称可到 104 MHz，但杜邦线 + 排针的走线质量会引入反射与串扰；模块接在排针上时，
建议从 2 MHz 起步、确认能读 ID 后再提速，出现偶发错数据就先降频。

## 常见错误

| 现象 | 可能原因 | 排查 |
| --- | --- | --- |
| 读回全 `0xFF` | 模块未接、CS 未拉低、MISO 接成 MOSI | 量 CS 是否在传输期间为低；核对 PA6/PA7 |
| 读回全 `0x00` | MISO 被拉低（对地短路）或模块未供电 | 量模块 VCC 是否 3.3 V |
| ID 是 `FF 40 17` 之类"前一位错" | 模式不匹配（CPOL/CPHA）或 CS 提前拉高 | 改模式 3 试；确认 `BSY` 等待 |
| 没有任何波形 | `SSI = 0` 触发 `MODF`、`SPE` 被清 | 读 `SR.MODF`；确认 `CR1` 的 `MSTR/SSM/SSI/SPE` |
| 擦除后写不进去 | 漏发 `WREN`，或 `WREN` 与命令共用了同一个片选周期 | 检查两次 CS 之间是否都拉高 |
| 偶发写入失败、等待超时 | 用固定延时替代 WIP 轮询 | 改成轮询 `SR.WIP` |
| 读 8 MB 边界附近数据错 | 地址超过 24 位，或被截断 | 确认地址按 3 字节发送 |
| 串口输出里 ID 能读但数据全乱 | MISO 与 MOSI 互换（初版反汇编抓到的就是这个） | 核对 `CRL` 半字节：PA7=B、PA6=4、PA5=B |

## 已知限制

- 只支持 3 字节地址（≤16 MB）；W25Q256 等 32 位地址器件需要 4 字节地址模式。
- 只实现页编程/扇区擦除/读/ID/状态寄存器；未做块擦除、整片擦除、写保护、OTP、UID。
- 未处理页编程的自动拆页，超过一页直接报错。
- 所有传输为忙等轮询，未用中断或 DMA。
- 未在真实硬件上验证；排针针序、模块型号与实测耗时均为待确认项。
