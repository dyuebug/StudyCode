# F103_17：ADC1 轮询采样（内部温度传感器 + Vrefint）

## 学习目标

1. **ADC 的时钟链必须先算清**：`ADCCLK = PCLK2 / ADCPRE`，不能超过 14 MHz；采样时间决定单次转换耗时，
   两者共同决定"一次采样要多久"。
2. **转换的完整顺序**：开时钟 → 上电（`ADON`）→ 复位校准（`RSTCAL`）→ 校准（`CAL`）→
   内部通道供电（`TSVREFE`）→ 选通道（`SQR3`）→ 软件触发（`SWSTART`）→ 等 `EOC` → 读 `DR`。
3. **内部通道为什么值得先做**：温度传感器（ch16）与 Vrefint（ch17）在芯片内部，
   **不需要外接任何器件**，"能不能采到数"只取决于寄存器序列，不取决于手上有没有传感器。
4. **码值不等于物理量**：`code` 是 12 位比值，要换成电压需要知道 `Vdda`，要换成温度需要出厂标定值。
   典型参数算出来的绝对温度误差可达数摄氏度。
5. **判据的假阳性**：未建模的外设恒读 0，"等待某位被硬件清零"的循环会**立刻成功**。
   所以校准判据必须分两段：先看"写进去的位读不读得回"，再看"硬件有没有清掉"。

## 核心概念

### 时钟与采样时间

```text
PCLK2 = 8 MHz，ADCPRE = 00 → ADCCLK = 4 MHz，t_ADC = 250 ns
采样时间 SMP = 111 → 239.5 个 ADCCLK 周期
总转换时间 = (239.5 + 12.5) / 4 MHz ≈ 63 µs
```

温度传感器要求最小采样时间 17.1 µs，239.5 周期（≈59.9 µs 采样）留了足够余量。
采样时间太短时读数会明显偏低——内部通道的源阻抗比外部电路高，这一档不能省。

### 通道号与寄存器分布

| 通道 | 用途 | 采样时间寄存器 | 位置 |
| --- | --- | --- | --- |
| 0～9 | `PA0`～`PA7`、`PB0`、`PB1` | `SMPR2` | 每通道 3 bit |
| 10～17 | 其余外部 + 内部 | `SMPR1` | ch16 在 bit[20:18]，ch17 在 bit[23:21] |
| 16 | 内部温度传感器 | `SMPR1.SMP16` | 需 `CR2.TSVREFE = 1` 供电 |
| 17 | 内部参考电压 `Vrefint` | `SMPR1.SMP17` | 同上 |

### 出厂标定值

| 值 | 地址 | 用途 |
| --- | --- | --- |
| `TS_CAL1` | `0x1FFFF7B8` | 30 ℃、`Vdda = 3.3 V` 下的温度通道码值 |
| `VREFINT_CAL` | `0x1FFFF7BA` | 同样条件下的 `Vrefint` 码值 |
| `TS_CAL2` | `0x1FFFF7C2` | 110 ℃ 下的码值（与 `TS_CAL1` 一起给出斜率） |

读到 `0x0000` / `0xFFFF` 说明地址或器件型号对不上。本实验把它们打印出来但**不做两点校准**：
只用典型参数，因此温度只能当量级参考。

## 接口卡片

### `wait_clear(reg, mask)`

作用：轮询直到某位被硬件清零，上限 200000 次；返回 1 表示等到。

为什么需要上限：通道没接、时钟没开、或者跑在未建模的仿真器上时，该位永远不会被清。
没有上限就是挂死，日志停在半截也看不出原因。

**它单独使用时不可靠**：未建模设备恒读 0，"等清零"立刻返回 1。详见「关键实现点 1」。

### `adc_calibrate()`

作用：`RSTCAL` 复位校准 + `CAL` 启动校准，两步都做**两段判断**。

输出：

```text
RSTCAL：写入后读回 置位|仍为 0，清零 ok|超时
CAL   ：写入后读回 置位|仍为 0，清零 ok|超时
校准流程不可判定：...（仅当任一位置不起来时打印）
```

资源所有权：只写 `ADC1->CR2`，不碰 NVIC。

### `adc_convert(ch, &code)`

作用：`SQR3 = ch` → `CR2.SWSTART` → 等 `SR.EOC` → 读 `DR & 0xFFF`。

返回：1 = 转换完成，0 = 超时（`*code` 置 0）。

常见误用：读 `DR` 之前手工清 `EOC`。F1 上**读 `DR` 本身就清 `EOC`**，多写一次反而容易在
"读 DR 与清 EOC 之间又完成一次转换"的情况下丢掉新数据。

## 最小可运行实验

```text
=== F103_17 ADC1 轮询采样 ===
ADON 读回：置位
RSTCAL：写入后读回 置位，清零 ok
CAL   ：写入后读回 置位，清零 ok
温度通道 ch16：ok code=17xx
参考通道 ch17：ok code=15xx
估算 Vdda ≈ 3xxx mV（用 1.20 V 典型值反推，未做单板校准）
估算温度 ≈ xx.x ℃（典型参数，误差可达数摄氏度）
出厂标定：TS_CAL1=... TS_CAL2=... VREFINT_CAL=...
```

上面的 `code` 与电压是**推算区间**，不是实测值：真板上 ch17 的码值由实际 `Vdda` 决定，
ch16 的码值由芯片温度决定。本仓库**没有真板读数**。

**QEMU 实测**（`tests/qemu-stm32/logs/neg_f103_17_adc_polling.log`）：

```text
=== F103_17 ADC1 轮询采样 ===
ADON 读回：仍为 0（ADC 没上电，或本机未建模）
RSTCAL：写入后读回 仍为 0（该位没有状态），清零 ok
CAL   ：写入后读回 仍为 0（该位没有状态），清零 ok
校准流程不可判定：CR2 的可写状态位读不回，后面的 code 不能当校准后的读数
温度通道 ch16：超时（EOC 未置位） code=0
参考通道 ch17：超时（EOC 未置位） code=0
Vrefint 无有效读数：本机无法反推 Vdda，也就无法把码值换成电压
```

三条结论：

1. `ADON`、`RSTCAL`、`CAL` 三个可写位**读回全是 0**，说明 ADC1 的寄存器没有状态 → 未建模。
2. 校准的两段判据正确地把这一情形判成"不可判定"，而不是打印"校准完成"。
3. 两路采样走超时分支，`code` 保留 0，程序没有挂死。

同一现象在探针里也独立出现过（`tests/qemu-stm32/logs/probe.log`）：
`[14] ADC1：ADON 读回 清零，SWSTART 后 EOC 未置位，SR=0x00000000 DR=0`。

**未验证**：真板上的 `ADON`/`EOC` 时序、两路 `code` 的绝对值、`Vdda` 反推精度、温度绝对误差、
出厂标定值是否可读。本文档不把这些写成既有结果。

## 关键实现点

### 1. 一次假阳性，以及它为什么值得记下来

第一版校准判据只写"等 `RSTCAL` 被清零"，在 QEMU 上打印 `RSTCAL 清零：ok`、`CAL 清零：ok`，
看起来像校准完成了。实际是 ADC 未建模，这两个位**从来没有被置起来过**，恒读 0 让"等清零"秒过。

修法是把一个判据拆成两段：

```c
ADC1->CR2 |= ADC_CR2_RSTCAL;
const uint32_t set  = (ADC1->CR2 & ADC_CR2_RSTCAL) ? 1U : 0U;   /* 先看写没写进去 */
const uint32_t done = wait_clear(&ADC1->CR2, ADC_CR2_RSTCAL);   /* 再看硬件清没清 */
```

推广：**任何"等硬件把某位清掉"的判据，都必须先验证该位能被置起来**。
只读 0 的外设会让这类判据 100% 假通过，比"超时"危险得多——超时至少会让人去查。

### 2. `SWSTART` 是"写 1 触发"的自清位

不要试图在之后手工清 `SWSTART`。F1 上也存在"两次写 `ADON=1` 启动转换"的用法（第二次写启动），
本实现统一用 `SWSTART`，语义更清楚；这条顺序**需要真板再核一遍**（见文件头注释）。

### 3. `TSVREFE` 不置，内部通道读到的就是 0

温度传感器与 `Vrefint` 共用一个使能位 `CR2.TSVREFE`。忘了它，两路都会返回 0 而不是报错——
又是一个"看起来正常"的失败。

### 4. 顺序：先校准，再采

不自校准直接采样，读数会带固定偏移。校准必须在 ADC 上电后、开始转换前完成，
并且校准期间不应有转换在进行。

### 5. 用典型参数算温度是"能跑通"，不是"测得准"

```c
T = 25 + (V25 - Vsense) / Avg_Slope      /* V25 = 1.43 V, Slope = 4.3 mV/℃ 典型值 */
Vdda = Vrefint_typ * 4095 / code_vref    /* 1.20 V 典型值，实际离散 ±3% */
```

两个误差源叠加：`Vdda` 估算误差直接按比例传进 `Vsense`，`V25`/`Slope` 的器件离散再叠一层。
要拿到可信绝对温度，必须用 `TS_CAL1`/`TS_CAL2` 做两点校准（本实验只打印这两个值，没有使用）。

## 常见错误和陷阱

| 现象 | 可能原因 | 排查 |
| --- | --- | --- |
| 两路都读到 0 | `TSVREFE` 没置；或采样时间太短（内部通道源阻抗高） | 读回 `CR2`、`SMPR1` |
| `EOC` 永不置位 | `ADC1EN` 没开；`ADON` 没置；`SWSTART` 写错寄存器 | 先读回 `CR2`，再看 `SR` |
| 校准"总是一次成功" | 未建模 / 外设没上电，等待清零类判据假通过 | 加"写入后读回"那一段 |
| 读数整体偏大或偏小 | 采样时间不足；`Vdda` 不是 3.3 V | 提高 `SMP` 档位；用 `Vrefint` 反推 |
| 温度值明显不合理 | 用典型参数当标定值；`Vdda` 估算偏差 | 改用出厂 `TS_CAL1/TS_CAL2` |
| `SQR3` 写了但通道不对 | 序列长度 `SQR1.L` 不是 0，`SQ1` 不是唯一项 | 读回 `SQR1` |
| 转换结果停在旧值 | 读了 `DR` 之后没重新触发 | 每次转换都要重新写 `SWSTART` |

## 故障排查方法

1. **看 `ADON` 读回**：0 说明时钟没开或外设未响应，后面的步骤都不用看。
2. **看校准两段的输出**：只看到"清零 ok"而"读回 0"，就是未建模/未上电，不是校准成功。
3. **看 `SR` 与 `DR` 的原始值**：`SR=0` 且 `DR=0` 说明一次转换都没发生；`EOC=1` 但 `DR=0`
   说明通道选错或内部通道没供电。
4. **用 `Vrefint` 自检**：`Vrefint` 的码值应当在 `1200 mV / Vdda × 4095` 附近。
   偏离很多先怀疑 `Vdda` 与采样时间，而不是怀疑公式。
5. **QEMU 上不要期待数值**：ADC1 未建模，只能验证"超时分支是否按要求收敛"。

## 练习题

1. **基础题**：改成一个 3 通道序列（ch16、ch17、ch0），用扫描模式（`CR1.SCAN`）一次触发采完三个，
   再从 `DR` 依次读出。提示：`SQR1.L = 2`、`SQR3` 里按顺序放三个通道、`EOC` 在最后一个才置位。
2. **改错题**：下面的校准为什么在真板上也可能"通过"，但读数仍然偏移？
   ```c
   ADC1->CR2 |= ADC_CR2_ADON;
   ADC1->CR2 |= ADC_CR2_CAL;
   while (ADC1->CR2 & ADC_CR2_CAL) { }
   ```
   提示：少了哪一步？`RSTCAL` 与 `CAL` 的先后关系是什么？
3. **综合题**：用 `TS_CAL1`/`TS_CAL2` 做两点校准，替换掉典型参数，并说明为什么还需要 `Vdda`
   等于标定条件（3.3 V）这个前提；若 `Vdda` 不是 3.3 V，应该怎么修正。
4. **思考题**：为什么"等硬件清零"的判据在仿真器上会假通过，而"等硬件置位"的判据不会？
   这个差别对编写自检代码有什么启示？

## 已知限制

- **QEMU 无法验证功能**：`stm32vldiscovery` 未建模 ADC1，`ADON`/`RSTCAL`/`CAL` 读回全 0，
  `EOC` 不置位。当前证据等级为"构建级 + 超时分支行为"。
- 只用轮询方式，未涉及中断、扫描、注入通道、模拟看门狗、DMA。
- 未做两点校准，温度与电压只按典型参数推算。
- 未测过采样时间不足时的读数偏差，也没有源阻抗相关的实验数据。
- 时钟取自复位值（8 MHz）；配置 PLL 到 72 MHz 后 `ADCPRE` 必须重算，本实验未覆盖。
