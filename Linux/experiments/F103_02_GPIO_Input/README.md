# F103_02：按键读入与消抖

## 学习目标

1. **输入路径**：`CRH` 的 `CNF`/`MODE` 如何把引脚配成输入，以及为什么输入模式下还要关心 `ODR`。
2. **读取方式**：`IDR` 与 `ODR` 的区别——读引脚电平和读自己上次写出的值不是一回事。
3. **消抖**：机械按键在毫秒级反复通断，为什么「读一次就翻转」不可用。
4. **边沿检测**：把电平变成一个事件，为后面的外部中断（EXTI）实验建立同一套心智模型。

行为：每次按下按键，LED 翻转一次；松开不动作，长按也只翻转一次。

## 硬件

| 项 | 值 |
| --- | --- |
| LED | PC13，低电平点亮 |
| 按键 | PB14，板上外部上拉到 3.3 V，按下接地 |
| 电平 | 松开 = 高（1），按下 = 低（0） |

PB14 的外部上拉是推断而非实测：课程 `0506_key_led_cubemx` 与 `0507_key_led_manual` 对 PB14 均配置
`GPIO_NOPULL`（浮空输入），且逻辑为「按下点亮」，说明板上已有上拉、按键接地。
若换用没有外部上拉的板子，必须把 `key_init()` 改成上拉输入（`CNF=10`，并把 `ODR` 的 bit14 置 1），
否则引脚浮空，读数随机。

## 关键实现点

### 1. STM32F1 的输入上下拉由 ODR 选择

这是 F1 与 F4/G4 的差异点，也是最容易照抄错的地方：

| 模式 | `CNF[1:0]` | `MODE[1:0]` | 上拉/下拉由谁决定 |
| --- | --- | --- | --- |
| 模拟输入 | `00` | `00` | — |
| 浮空输入 | `01` | `00` | — |
| 上拉/下拉输入 | `10` | `00` | **`ODR` 对应位：1 = 上拉，0 = 下拉** |
| 通用推挽输出 | `00` | `10`/`11` | — |

因此在输入模式下写 `ODR` 不一定会破坏什么，它可能就是配置的一部分。读外部电平必须用 `IDR`。

### 2. 为什么消抖不能靠 `delay`

抖动窗口约 5~20 ms。若采用「检测到跳变 → `delay(20)` → 再读一次」的写法，主循环在这 20 ms 内完全阻塞。
本实验只控制一个 LED 时看不出问题，一旦主循环还有串口收包、显示刷新，就会丢数据。
这里把消抖做成**每毫秒采样一次的状态机**：主循环保持固定节拍，消抖只是状态机里的计数，不改变节拍。

### 3. 为什么要边沿检测而不是电平镜像

课程示例 `0507` 直接 `WritePin(LED, ReadPin(KEY))`，那是「按住才亮」。
本实验记录 `stable` 变量保存上一次已确认的电平，只在「稳定电平由高变低」时产生一次事件，
因此按住不动不会反复翻转。这个 `stable` 与 EXTI 的边沿触发是同一个语义，后面对照中断版本时可以直接比较。

### 4. 采样周期与抖动窗口的关系

`f103_tick_wait_1ms()` 返回「至少跨过一个 1 ms 边界」，所以 `same_ms` 计数的实际精度是 1 ms 量级，
不是严格相位对齐。消抖时间取 20 ms 远大于该误差，因此不需要更精确的时基。

## 常见错误

| 现象 | 可能原因 | 排查 |
| --- | --- | --- |
| 按下 LED 无反应 | `CRH` 没配成输入，或漏开 GPIOB 时钟 | 反汇编确认写了 `0x40010C04`；确认 `IOPBEN` |
| 读数始终为 1 | 按键未接地或外部上拉路径断开 | 万用表量 PB14 按下时是否为 0 V |
| 读数随机跳变 | 引脚浮空（板子没有外部上拉） | 改上拉输入：`CNF=10` 且 `ODR14=1` |
| 按一次翻两次 | 未消抖 | 确认 `key_poll_pressed_event()` 每 1 ms 调用一次，且阈值 ≥ 5 ms |
| 长按持续翻转 | 用了电平判断而非边沿判断 | 检查是否在 `stable == 0` 时每轮都返回 1 |
| 松开时也翻转 | 抬键时的机械回弹被当成新的按下边沿 | 只在 `stable` 变为 0 时产生事件 |

## 已知限制

- 单按键、单事件源；不支持组合键与长短按区分。
- 消抖为阻塞式主循环节拍，未使用定时器中断，主循环有其他长耗时任务时会拉长采样间隔。
- 未做按下时的低功耗处理（WFI），也不涉及唤醒源配置。
