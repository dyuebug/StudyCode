# F103_18：bxCAN 回环自测（初始化 / 过滤 / 收发）

## 学习目标

1. **bxCAN 的两段状态**：`MCR.INRQ` 请求 → `MSR.INAK` 确认。没进初始化模式时，`BTR` 与过滤器寄存器的写入会被硬件忽略，
   而且**不会报错**——这是"配置写完了但完全不生效"的典型来源。
2. **位时序的算术**：`tq = (BRP+1) / PCLK1`，一位 = `SYNC(1) + TS1 + TS2` 个 `tq`。8 MHz 下要 500 kbps，
   就是 16 个 `tq`（2 µs），`BTR = 0x401C0000`。
3. **回环模式的价值**：`BTR.LBKM=1` 时帧在芯片内部直接进接收 FIFO，不需要收发器、不需要第二块板、
   不需要 120 Ω 终端。单板就能把"配置 → 发送 → 过滤 → 接收"整条链路走完。
4. **过滤器只能在 `FMR.FINIT=1` 时改**，而且是"组"为单位：位宽模式（32 位 / 两个 16 位）、
   掩码 or 列表、挂 FIFO0/1、最后 `FA1R` 激活。
5. **收完必须释放**：`RF0R.RFOM0` 释放输出邮箱，不释放则下一帧永远进不来（`FMP0` 不再增长）。
6. **判断本机能不能验证**：QEMU 的 `stm32vldiscovery` **没有 CAN 模型，0x40006400 这一段根本没映射**，
   第一次访问就 `BusFault → HardFault`。所以本实验在仿真里只能提供故障解码与"代码确实编进去了"的证据。

## 环境与前置条件

| 项 | 值 |
| --- | --- |
| 芯片 | STM32F103C8T6（Cortex-M3 r1p1，含 bxCAN） |
| 系统时钟 | HSI 8 MHz；`PCLK1 = HCLK = 8 MHz`（`RCC_CFGR.PPRE1 = 000`，不分频） |
| 外接模块 | **不需要**（回环模式）。真板上想接真实总线则需 CAN 收发器（TJA1050 等）+ 120 Ω 终端 |
| 引脚 | PA11 = `CAN_RX`（浮空输入），PA12 = `CAN_TX`（复用推挽 50 MHz） |
| 工具链 | `arm-none-eabi-gcc 14.2.1` + CMake + Ninja |
| 串口 | USART1，PA9/PA10，115200 8N1 |
| 公共代码 | `f103_tick`（中断模式）、`f103_uart` |

> **注意 `PCLK1` 与 `PCLK2` 都是 8 MHz**（未配 PLL）。照抄"72 MHz 系统、APB1 = 36 MHz"的例程会把
> 波特率算错 4.5 倍。位时序必须按当前 `RCC_CFGR` 现算，不能记数字。

## 核心概念

### 位时序与 500 kbps 的推导

```text
PCLK1 = 8 MHz
BRP = 0        → tq = (0+1) / 8 MHz = 125 ns
TS1 = 12       → 段 1 = 13 tq
TS2 = 1        → 段 2 = 2 tq
一位 = 1 + 13 + 2 = 16 tq = 2 µs → 500 kbps
采样点 = (1 + 13) / 16 ≈ 87.5%（CAN 推荐 75%～87.5%）
SJW = 0        → 1 tq
BTR = LBKM(bit30) | TS1(bit16=12) | TS2(bit20=1) | BRP(bit0=0) = 0x401C0000
```

### 初始化与过滤器寄存器只在这一段可写

| 寄存器 | 何时可写 |
| --- | --- |
| `MCR`、`BTR` | `MCR.INRQ=1` 且 `MSR.INAK=1` 时 |
| `FM1R`/`FS1R`/`FFA1R`/`FA1R`/`sFilterRegister[n]` | `FMR.FINIT=1` 时（且需在初始化模式下） |
| `sTxMailBox[n].TIR` | 正常/回环模式，`TXRQ` 写 1 触发发送 |

### 过滤器组的三种选择

| 位 | 含义 | 本实验取值 |
| --- | --- | --- |
| `FM1R.FBM0` | 0 = 一个 32 位；1 = 两个 16 位 | 0（32 位） |
| `FS1R.FSC0` | 0 = 掩码模式；1 = 标识符列表 | 0（掩码） |
| `FFA1R.FFA0` | 0 = FIFO0；1 = FIFO1 | 0（FIFO0） |
| `FA1R.FACT0` | 激活该组 | 1 |

掩码全 0 = 全部通过。调试阶段先全通、把"链路是否通"与"过滤是否正确"分开验证，
是排查 CAN 问题的基本顺序。

## 接口卡片

### `fault_report(name)`

作用：在 `BusFault_Handler` / `HardFault_Handler` 里打印 `CFSR`/`HFSR`/`BFAR` 后停机。

为什么需要：默认 Handler 是死循环，日志会停在半截且没有任何原因。有了它，
"开始访问 `0x40006400`…"后面紧跟一行故障解码，本机能力边界就变成可读证据。

局限：只取证不恢复。恢复要改栈上的返回地址，超出本实验范围，也没有必要——
未映射外设上复位重试只会再挂一次。

### `can_filter_all_pass()`

作用：配置滤波器组 0 为 32 位掩码、全通、挂 FIFO0 并激活。

顺序：`FMR |= FINIT` → 位宽/模式/分配 → 写 `FR1`/`FR2` → `FA1R |= FACT0` → `FMR &= ~FINIT`。

常见误用：忘了 `FINIT`，写入被静默忽略，表现为"发出去的帧收不到"。

### `wait_set(reg, mask)` / `wait_clear(reg, mask)`

作用：带 20000/100000 次上限的轮询。返回 1 表示等到。

为什么必须有上限：外设未建模或时钟没开时状态位永远不来，没有上限就是挂死。

## 最小可运行实验

`main()` 的七个步骤对应日志里的七行：

```text
[1] GPIOA 时钟与 CAN1 时钟已开，PA11=浮空输入 PA12=复用推挽
[2] 写 CAN1->MCR.INRQ（第一次访问 0x40006400）…
    等待 INAK 置位：ok，MSR=0x...
[3] BTR 写 0x401C0000，读回 0x401C0000
[4] 过滤器组 0：32 位掩码模式，掩码=0（全通），挂 FIFO0，已激活
[5] 退出初始化：INAK 已清零，MSR=0x...
[6] 发送：RQCP0 完成，TXOK0=1，用时 0 ms
[7] 接收：FIFO0 待处理 有报文，RF0R=0x...
    收到 ID=0x123 DLC=8，数据与发送完全一致： 11 22 33 44 55 66 77 88
```

第 2 步的 `INAK` 超时分支会打印"未进入初始化模式，后面的配置都会被硬件忽略，此处停止"并停住——
这是唯一正确的处理：继续往下配置只会得到一堆"看起来成功"的假象。

| 寄存器 | 值 | 含义 |
| --- | --- | --- |

## 关键实现点

### 1. 先配 GPIO 再碰 CAN

`PA12` 必须是复用推挽（`CRH` bit[19:16] = `0xB`），否则 CAN 外设拿不到引脚控制权，
表现为"发送标志正常、引脚上没波形"。`PA11` 作为输入用浮空即可（内部上拉会让空闲电平判断偏离隐性位）。

本实验用 `GPIOA->CRH = (CRH & ~0x000FF000) | 0x000B4000` 一次性改两个引脚，
保留 `CRH` 其余位的复位值 `0x4`（浮空输入）。

### 2. `TIR` 必须最后写

`TXRQ` 一置位硬件立即开始发送。先写 `TDLR`/`TDHR`/`TDTR`、最后写 `TIR`，是把"数据已就绪"
与"请求发送"合成一次写操作的唯一办法。反过来写就会发出 DLC=0 或数据为残留的帧。

### 3. `TSR` 是 `rc_w1`，`ISR` 类寄存器是只读

`CAN1->TSR = CAN_TSR_RQCP0` 是"写 1 清除"。整寄存器赋值会把其他通道的完成标志一并清掉——
本实验只用邮箱 0，所以两种写法等价；多邮箱场景必须只写自己那一位。

### 4. 收完要 `RFOM0`

`RF0R.FMP0` 是"待处理帧数"。读完报文后置 `RFOM0` 释放输出邮箱，否则 `FMP0` 停在 1，
下一帧进不来，表现为"只收到第一帧"。

### 5. 为什么回环而不是正常模式

正常模式没有收发器时，`CAN_TX` 悬空，控制器收不到自己的 ACK，帧会一直重发
（`MCR.NART=0` 默认），`RQCP0` 要等到错误计数器爆掉才来。这会被误读成"发送失败是代码问题"。
回环模式不需要任何外部电路，是排错链路上必须先用的一档。

## 常见错误和陷阱

| 现象 | 可能原因 | 排查 |
| --- | --- | --- |
| `INAK` 一直不来 | `RCC_APB1ENR.CAN1EN` 没开（CAN 在 APB1，不是 APB2） | 读回 `APB1ENR` |
| `BTR` 读回不等于写入值 | 不在初始化模式（`INAK=0`） | 先 `INRQ` 再等 `INAK` |
| 收发都成功但 `FMP0` 不涨 | 过滤器没激活（`FA1R`）或 `FINIT` 没清 | 读回 `FMR`/`FA1R` |
| 帧发不出去、`TSR` 无变化 | `PA12` 不是复用推挽；或 `TIR` 先于数据写 | 量 PA12 波形、检查写入顺序 |
| 只收到第一帧 | 没置 `RFOM0` | 读 `RF0R.FMP0` 是否停在 1 |
| 波特率差整数倍 | 照抄 36 MHz/72 MHz 的 `BRP` | 按当前 `PCLK1` 重算 `tq` |
| 采样点偏晚导致偶发错误 | 只改了 `TS1` 没改 `TS2`，总和不是 16 `tq` | 复算 `1+TS1+TS2` |

## 故障排查方法

1. **先确认时钟域**：CAN 在 APB1，`APB1ENR.CAN1EN`；GPIOA 在 APB2。开错总线是第一步最常见的失误。
2. **看 `MSR`**：`INAK`、`ERRI`、`SLAK`（睡眠）、`WKU`，一眼能分出"没进初始化"和"总线错误"。
3. **看 `ESR`**：`TEC`/`REC` 错误计数器。回环模式下它们应该保持 0；涨说明位时序或过滤器有配置问题。
4. **回环先通，再接总线**：回环验证的是控制器 + 过滤器 + 邮箱；真实总线验证的是收发器 + 终端 + 对端。
   混在一起排查会同时怀疑三个变量。
5. **QEMU 上不要期待 CAN 结果**：`0x40006400` 未映射，第一次访问必然 HardFault，这是环境事实。

## 练习题

1. **基础题**：把位时序改成 250 kbps（`PCLK1 = 8 MHz`），写出 `BTR` 的十六进制值，并说明采样点比例。
   提示：保持 16 个 `tq`，只改 `BRP`。
2. **改错题**：下面这段为什么在真板上过滤器不生效？
   ```c
   CAN1->MCR |= CAN_MCR_INRQ;
   /* 立刻写，不等 INAK */
   CAN1->FMR |= CAN_FMR_FINIT;
   CAN1->sFilterRegister[0].FR1 = 0x24600000U;
   CAN1->sFilterRegister[0].FR2 = 0x7FF00000U;
   CAN1->FMR &= ~CAN_FMR_FINIT;
   ```
3. **综合题**：把过滤器改成"只接收 ID `0x123` 和 `0x456`、其余丢弃"，要求用一组 32 位掩码实现，
   并写出 `FR1`/`FR2`。提示：32 位掩码模式下一个组只能放一个 ID，两个 ID 要么用两个组，
   要么用 16 位列表模式——请说明你选哪种以及原因。
4. **思考题**：为什么 `MCR.NART`（禁止自动重传）在调试阶段应该置 1，在产品里通常是 0？

## 已知限制

- **QEMU 无法运行本实验**：`stm32vldiscovery` 没有 CAN 模型且 `0x40006400` 未映射，第一次访问即
  `BusFault → HardFault`。当前证据等级为"构建级 + 寄存器路径核对"，不含任何功能结论。
- 只用了一组 32 位全通过滤器，没有验证掩码/列表匹配、16 位模式、FIFO1 分配。
- 未涉及中断收发（`IER`）、错误中断（`ERRI`）、总线关闭（bus-off）恢复、`SILM` 静默模式。
- 未做位时序的实测：采样点与传播段需要示波器与总线长度才能验证，回环模式验证不了电气特性。
- 未验证与真实收发器配合时的 ACK、仲裁与错误帧行为。
