# 进程与服务管理（systemd）

> 学习目标：把论坛应用从“手动运行脚本”改造成由 systemd 托管的后台服务。
> 建议时长：45 分钟。

---

## 1. 为什么不直接 `python app.py`

| 方式 | 退出登录后 | 崩溃后 | 开机自启 | 日志 |
|---|---|---|---|---|
| 手动运行 | 进程结束 | 不会恢复 | 不会 | 输出到终端 |
| systemd | 继续运行 | 可自动重启 | 可配置 | journald 统一收集 |

生产环境使用 Gunicorn 作为 WSGI 服务器，Flask 自带的开发服务器不适合对外提供服务。

## 2. 文件布局

```
/opt/study-forum/                 # 代码
/opt/study-forum/.venv/           # 虚拟环境
/var/lib/study-forum/forum.db     # 数据
/etc/study-forum/forum.env        # 环境变量（权限 600）
/etc/systemd/system/study-forum.service
```

环境变量文件示例：

```bash
SECRET_KEY=请替换为随机值
DATABASE=/var/lib/study-forum/forum.db
PER_PAGE=10
```

生成随机密钥：

```bash
python3 -c "import secrets; print(secrets.token_urlsafe(48))"
```

## 3. 服务单元

完整文件见 `../systemd/forum.service`，核心字段：

```ini
[Service]
User=forum
Group=forum
WorkingDirectory=/opt/study-forum
EnvironmentFile=/etc/study-forum/forum.env
ExecStart=/opt/study-forum/.venv/bin/gunicorn \
    --bind 127.0.0.1:8000 \
    --workers 1 \
    --threads 4 \
    --access-logfile - \
    --error-logfile - \
    "forum_project:create_app()"
Restart=on-failure
RestartSec=5
```

**为什么 SQLite 只开 1 个 worker**：多个进程并发写入时更容易触发 `database is locked`。使用 1 个进程 + 4 个线程，在单机规模下更稳定。迁移到 PostgreSQL 后可增加 worker 数。

## 4. 常用操作

```bash
sudo systemctl daemon-reload          # 修改 unit 文件后必须执行
sudo systemctl start study-forum
sudo systemctl status study-forum
sudo systemctl restart study-forum
sudo systemctl enable study-forum     # 开机自启
sudo systemctl disable study-forum
```

查看日志：

```bash
journalctl -u study-forum -n 100 --no-pager
journalctl -u study-forum -f
```

## 5. 排错顺序

1. `systemctl status` 是否显示 `failed`，错误码是什么。
2. `journalctl -u study-forum -n 50` 看 Python 异常栈。
3. 手动以 `forum` 用户执行 `ExecStart` 中的命令，复现问题。
4. 检查 `EnvironmentFile` 权限与变量名。
5. 检查数据目录属主：`ls -ld /var/lib/study-forum`。

**常见错误**

| 错误 | 原因 |
|---|---|
| `status=203/EXEC` | `ExecStart` 路径不存在或不可执行 |
| `status=200/CHDIR` | `WorkingDirectory` 不存在 |
| `Permission denied: forum.db` | 数据目录属主不是 `forum` |
| `ModuleNotFoundError: forum_project` | `WorkingDirectory` 不在仓库根目录，或虚拟环境路径错误 |

## 6. 练习

1. 为本机（或 WSL）创建 `study-forum.service`，用 `systemctl status` 确认 `active (running)`。
2. 故意把 `DATABASE` 指向无写权限的目录，记录报错并用 `journalctl` 定位。
3. 修改 `PER_PAGE` 环境变量，重启后验证分页大小变化。
4. 解释 `Restart=on-failure` 与 `Restart=always` 的区别，并说明本项目应选哪个。
