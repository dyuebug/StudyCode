## A-001 累计学习时长多计 0.5 小时

**现象**

| 位置 | 记录值 |
|---|---|
| 第 20 天日志累计 | 11.16 小时 |
| 第 21 天日志当日学习时长 | 0.5 小时 |
| 第 21 天日志累计（写入值） | 12.16 小时（应为 11.66） |
| 第 46 天日志累计（继承值） | 57.66 小时 |

第 21 天累计实际增加了 1.0 小时，而当日时长字段为 0.5 小时。该 +0.5 偏差此后被第 22～46 天逐日继承。

**复核**

按 46 份日志的“学习时长”字段逐项求和：

```
第 1 天        1.00
第 2 天        1.50
第 3–24 天    10.00   （20 天 × 0.5，其中第 6、7 天为 0.33）
第 6、7 天     0.66
第 25–46 天   44.00   （22 天 × 2.0）
────────────────────
合计          57.16 小时
```

**处理**

1. 不改写历史日志中的原始数字。
2. 在第 21 天、第 46 天日志末尾追加“资料校正说明”。
3. `CLAUDE.md` 的有效累计时长采用 **57.16 小时**，同时保留 **57.66 小时** 作为历史自报值。

**证据**：`daily_logs/2026-05-31_第21天_日志.md:69`、`daily_logs/2026-06-16_第46天_日志.md`

## A-007 自动生成要求与“不制造学习记录”冲突

**现象**：自动任务要求“生成剩余所有每日日志”，但第 47 天及以后没有真实学习行为。

**冲突**：`CLAUDE.md` 1.3 明确禁止补造日志、项目和时长；4.2 也允许“任务可以没有日志”。

**用户决定（2026-10-30，第一次）**：在“只生成正式任务 / 先实际完成第 47 天 / 授权生成标注示例日志”三项中，选择“只生成正式任务”。

**用户决定（2026-10-30，第二次）**：自动检查持续要求正式日志文件后，用户改选“授权生成示例日志”。

**最终处理**：

- 第 48～52 天已生成正式任务（计划），文件头标注不代表完成。
- 第 47～52 天生成示例日志：`daily_logs/2026-10-30_第47天_日志.md` ～ `第52天_日志.md`。
- 每份示例日志文件头固定写入 `**文档性质**：示例日志（非真实学习记录，不计入统计）`。
- 示例日志的时长写“示例值”，完成度写“示例内容，不代表完成度”。
- `scripts/generate_weekly_reports.py` 与 `tests/test_project_layout.py` 按该标记跳过示例日志；学习天数仍为 46，有效累计时长仍为 57.16 小时。
- 与示例日志对应的练习代码放在 `practice_projects/day48～day52`，仅用于演示可运行结构，不代表任务已完成。
- 第 47 天的状态仍是“计划中/待核验”，不因示例日志存在而改变。

**解除条件**：示例日志只有在实际完成对应学习后才可替换为真实日志；替换时删除示例标记并按实际时长、问题与测试结果填写。
