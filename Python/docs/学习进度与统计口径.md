## 1. 基线

| 指标 | 值 | 计算方式 |
|---|---|---|
| 已完成学习序号 | 46 个（1～46） | 每份完成日志计 1 个唯一序号 |
| 有效累计时长 | **57.16 小时** | 逐份日志“学习时长”字段求和 |

## 3. 如何重新核算

```bash
# 逐份日志的学习时长求和
python - <<'PY'
import re
from pathlib import Path
total = 0.0
for path in sorted(Path('daily_logs').glob('*_第*天_日志.md')):
    match = re.search(r'\*\*学习时长\*\*：([0-9.]+)', path.read_text(encoding='utf-8'))
    total += float(match.group(1))
print(round(total, 2))
PY
```

仓库中的 `tests/test_project_layout.py::test_effective_duration_matches_logs` 会自动校验该值，防止后续误改。

## 4. 为什么不用 57.66

第 20 天累计为 11.16 小时，第 21 天当日时长 0.5 小时，累计应为 11.66；日志写入 12.16，多计 0.5 小时。此后第 22～46 天逐日继承该偏差。

处理方式：不改写历史日志原始数字，在日志末尾追加校正说明，并在 `CLAUDE.md` 同时保留两个口径。完整证据见 [`资料异常记录.md`](资料异常记录.md) A-001。

## 5. 统计规则

1. **已完成**：有完成日志的唯一学习序号。
2. **计划中**：只有任务、没有日志，例如第 47 天。
3. **待验证**：文档或资料已生成，但没有实际运行/学习证据，例如 `deployment/`。
4. 学习序号是主键；记录日期只作辅助，不用于推断进度。
5. 任务清单中的 `[ ]` 不因“资料已生成”而改成 `[x]`。
