### 任务1：准备练习容器（15 分钟）

```bash
docker run --rm -it --name linux-practice ubuntu:24.04 bash
```

容器内安装基础工具：

```bash
apt-get update
apt-get install -y procps iproute2 curl less
```

**完成标准**：`ps aux`、`ss -lntp`、`curl --version` 均可执行。

**注意**：容器退出后内容丢失；需要保留时用 `docker commit` 或挂载目录，本任务不要求保留。

### 任务2：文件与目录操作（30 分钟）

在容器内完成：

```bash
mkdir -p /srv/app/{static,data,logs}
touch /srv/app/data/forum.db
cp /etc/hostname /srv/app/logs/boot.log
mv /srv/app/logs/boot.log /srv/app/logs/start.log
find /srv/app -type f
grep -r "localhost" /etc/hosts
```

**学习内容**：

1. 绝对路径与相对路径。
2. `mkdir -p` 的幂等性。
3. `find` 与 `grep -r` 的分工：按文件属性 vs 按内容。
4. `>` 覆盖与 `>>` 追加的区别。

**完成标准**：能解释每条命令执行后目录发生了什么变化。

### 任务3：权限与属主（30 分钟）

```bash
useradd --system --create-home appuser
chown -R appuser:appuser /srv/app
chmod 750 /srv/app/data
chmod 640 /srv/app/data/forum.db
ls -ld /srv/app /srv/app/data
ls -l /srv/app/data/forum.db
```

然后故意制造故障：

```bash
chmod 000 /srv/app/data/forum.db
su -s /bin/bash appuser -c "cat /srv/app/data/forum.db"
```

**完成标准**：

- 能读懂 `drwxr-x---` 的每一位。
- 能解释为什么应用以 `appuser` 运行时仍可能读不到文件。
- 修复权限后命令成功：

```bash
chmod 640 /srv/app/data/forum.db
```

### 任务4：进程、端口与日志（30 分钟）

启动一个临时服务：

```bash
python3 -m http.server 8080 --directory /srv/app/static &
ps aux | grep http.server
ss -lntp | grep 8080
curl -I http://127.0.0.1:8080
```

模拟日志排查：

```bash
python3 -m http.server 8081 --directory /nonexistent > /srv/app/logs/error.log 2>&1 &
sleep 1
cat /srv/app/logs/error.log
```

结束进程：

```bash
kill %1
jobs
```

**学习内容**：

1. `ps aux` 各列含义。
2. `ss -lntp` 中 `-l`、`-n`、`-t`、`-p` 的作用。
3. `kill` 默认发送 `SIGTERM`；进程不退出时才考虑 `SIGKILL`。
4. 容器内没有 systemd，`journalctl` 不可用；宿主机日志由 systemd 管理。

**完成标准**：能写出“端口被占用”的完整定位步骤。
