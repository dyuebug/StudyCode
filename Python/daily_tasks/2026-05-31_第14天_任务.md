## 💡 温馨提示

1. **调试是一种思维方式**
   - 不是简单的"试错"
   - 需要系统的方法和思路
   - 需要耐心和细心

2. **print 调试的技巧**
   - 在关键位置打印变量值
   - 打印变量类型和长度
   - 使用分隔线区分不同的调试信息
   - 调试完成后记得删除 print 语句

3. **logging 的优势**
   - 可以控制日志级别（开发时 DEBUG，生产时 INFO）
   - 可以输出到文件，方便后续分析
   - 可以添加时间戳和其他上下文信息
   - 不需要手动删除，只需调整日志级别

4. **常见 bug 排查思路**
   - 语法错误：看错误信息，检查拼写和语法
   - 逻辑错误：打印中间结果，验证每一步
   - 运行时错误：检查输入数据，处理边界情况
   - 性能问题：找出瓶颈，优化算法或数据结构

5. **调试的黄金法则**
   - 先重现问题（能稳定重现才能调试）
   - 缩小问题范围（二分法定位）
   - 理解问题原因（不要盲目修改）
   - 验证修复效果（确保问题真正解决）
