📚 JavaScript 事件处理详解

📖 核心概念

是什么？

事件处理是 JavaScript 与用户交互的核心机制。用户的每个操作（点击、输入、滚动等）都会触发事件，我们可以监听这些事件并做出响应。

为什么需要？

  • 响应用户操作（点击按钮、提交表单）
  • 动态交互（实时验证、拖拽、动画）
  • 构建现代 Web 应用的基础

核心特点：

  • 事件冒泡：事件从子元素向父元素传播
  • 事件委托：利用冒泡，在父元素统一处理
  • 事件对象：包含事件详细信息

🎯 第一部分：事件监听基础

1.1 addEventListener() 方法 ⭐⭐⭐⭐⭐

语法：
element.addEventListener(event, handler)

参数：
- event：事件类型（字符串），如 'click'、'input'
- handler：事件处理函数

常用事件类型：
- click：鼠标点击
- input：输入框内容改变
- submit：表单提交
- change：选择框改变
- keydown/keyup：键盘按下/释放

🎯 第三部分：事件冒泡

3.1 什么是事件冒泡？⭐⭐⭐⭐⭐

事件冒泡：事件从触发元素向上传播到父元素，一层层"冒泡"

事件流三个阶段：
1. 捕获阶段：从根元素向下到目标元素
2. 目标阶段：到达目标元素
3. 冒泡阶段：从目标元素向上到根元素 ⭐ 我们主要用这个

为什么叫"冒泡"？
就像水中的气泡，从底部向上冒

🎯 第四部分：事件委托（Event Delegation）⭐⭐⭐⭐⭐

4.1 什么是事件委托？

事件委托：不在子元素上监听，而是在父元素上监听，利用事件冒泡统一处理

为什么需要？
- 动态元素问题：后添加的元素，直接绑定的事件无效
- 性能优化：100个按钮，只需1个监听器
- 代码简洁：统一管理

原理：
1. 在父元素上监听
2. 事件冒泡到父元素
3. 判断 event.target 是否是目标元素
4. 是的话执行相应逻辑

4.4 事件委托最佳实践

留言板删除按钮示例：
// 在留言列表容器上监听
messageList.addEventListener('click', (event) => {
    // 判断：点击的是删除按钮吗？
    if (event.target.classList.contains('delete-btn')) {
        // 获取留言 id
        const id = event.target.dataset.id

        // 确认删除
        if (confirm('确定要删除这条留言吗？')) {
            // 发送 DELETE 请求
            deleteMessage(id)
        }
    }
})
关键点：
- 在父容器上监听（messageList）
- 判断 target 的 class（.delete-btn）
- 从 data-id 获取留言 id
- 执行删除逻辑

📝 总结

核心知识点回顾

  • addEventListener()：添加事件监听，参数（事件类型、处理函数）
  • event.target：触发事件的元素（实际点击的）
  • event.currentTarget：绑定事件的元素（监听器所在）
  • preventDefault()：阻止默认行为（如链接跳转、表单提交）
  • stopPropagation()：阻止事件冒泡
  • 事件冒泡：事件从子元素向父元素传播
  • 事件委托：在父元素监听，利用冒泡统一处理（解决动态元素问题）

事件委托使用场景

  • ✅ 动态添加的元素（留言板的删除按钮）
  • ✅ 大量相同元素（100个按钮）
  • ✅ 统一管理（代码简洁）

记忆口诀

事件冒泡：子→父→祖（向上冒）
事件委托：父监听，子触发，判断target
动态元素：直接绑定×，事件委托✅
