## 📖 学到的知识点

### 一、闭包

- **核心概念**：闭包是函数与其词法环境的组合。内层函数引用了外层函数的局部变量，外层函数返回后，这些变量仍被引用，因此不会释放。
- **判断依据**：看变量在**定义位置**的作用域链，而不是调用位置。只要内层函数仍然可达，被引用的外层变量就仍然可达。
- **私有状态**：

  ```javascript
  function createCounter() {
      let count = 0;
      return {
          increment: () => ++count,
          value: () => count,
      };
  }
  const counter = createCounter();
  counter.increment();
  counter.value(); // 1，count 无法从外部直接修改
  ```

- **循环陷阱**：`var` 只有一个函数级绑定，所有回调共享同一个变量，异步执行时读到的都是循环结束后的值。

  ```javascript
  for (var i = 0; i < 3; i++) setTimeout(() => console.log(i)); // 3 3 3
  for (let i = 0; i < 3; i++) setTimeout(() => console.log(i)); // 0 1 2
  ```

  `let` 在每次迭代创建新的绑定；ES5 时代用 IIFE 把当前值作为参数复制进新作用域。
- **内存影响**：闭包延长变量生命周期，不是内存泄漏本身；泄漏发生在长期存活的引用（事件监听、定时器、缓存）不再需要却没有解除时。

### 二、原型链

- **三个概念**：
  - `Fn.prototype`：函数才有的属性，作为 `new Fn()` 实例的原型。
  - `Object.getPrototypeOf(obj)`：读取对象的内部 `[[Prototype]]`，`obj.__proto__` 是它的历史访问器。
  - `constructor`：默认指向创建该原型的函数，可以被覆盖，不能作为类型判断依据。
- **查找过程**：读取属性时先查自身，再沿 `[[Prototype]]` 逐级向上，直到 `null`；写入属性默认只在自身创建，不会修改原型。
- **继承**：`class Child extends Parent` 的本质仍是原型链，方法定义在 `Child.prototype` 上，且不可枚举。
- **`instanceof`**：沿左侧对象的原型链查找右侧函数的 `prototype`，因此跨 iframe 或修改原型后可能失效。
- **无原型对象**：`Object.create(null)` 不继承 `Object.prototype`，适合做纯字典，避免 `toString` 等键冲突。

### 三、`this` 绑定

- **四条规则**：
  1. 默认绑定：严格模式下为 `undefined`，非严格模式下为全局对象。
  2. 隐式绑定：`obj.method()` 中 `this` 是 `obj`；把方法赋值给变量后调用会丢失绑定。
  3. 显式绑定：`fn.call(obj, ...)`、`fn.apply(obj, [...])`、`fn.bind(obj)`。
  4. `new` 绑定：`this` 指向新创建的对象。
- **优先级**：`new` > `bind` > `call/apply` > 隐式 > 默认。`bind` 产生的函数不能被再次 `bind` 改变 `this`。
- **箭头函数**：没有自己的 `this`，捕获定义时外层作用域的 `this`；`call/apply/bind` 无法改变它，也不能作为构造函数。
- **常见误用**：把对象方法直接作为回调传入（如 `setTimeout(obj.method, 0)`），丢失隐式绑定；解决方式是箭头函数包装或 `bind`。

### 四、ES6 模块

- **运行条件**：`<script type="module">` 只在 HTTP(S) 下工作，`file://` 会因 CORS 被拒绝；模块默认严格模式、自动延迟执行、顶层 `this` 为 `undefined`。
- **导出形式**：
  - 命名导出：一个文件可多个，导入名必须匹配，可用 `as` 重命名。
  - 默认导出：一个文件最多一个，导入时可任意命名。
  - 混合导出合法，但默认导出与命名导出应职责清晰。
- **实时绑定**：导入得到的是导出变量的只读视图，导出方重新赋值后导入方能看到新值；不能直接给导入的绑定赋值。
- **与 CommonJS 的差异**：ESM 是静态结构，可在编译期确定依赖，支持 tree-shaking；CommonJS 的 `require` 在运行时执行，导出是值的快照。
- **动态导入**：`import()` 返回 Promise，用于按需加载，不参与静态依赖图。

## ⚠️ 遇到的问题与解决

**问题1**：直接双击打开 `04_es6_modules_详解/index.html`，控制台报跨源错误，模块未加载。

- 现象：页面结构正常，但 `main.js` 的导入全部失败。
- 报错信息：`Access to script at 'file:///...' from origin 'null' has been blocked by CORS policy`。
- 定位过程：确认 `<script type="module">` 已正确书写；把地址栏协议从 `file://` 换成 `http://` 后恢复。
- 原因：模块加载受同源策略约束，`file://` 的源被视为 `null`。
- 解决：在材料目录启动静态服务器：

  ```bash
  python_basics/.venv/Scripts/python.exe -m http.server 8080 \
      --directory web_basics/javascript_advanced/04_es6_modules_详解
  ```

  浏览器访问 `http://127.0.0.1:8080`。
- 可复用的经验：**模块问题先看协议和 Network 面板**，不要先怀疑语法。

**问题2**：`for (var i = ...)` 配合 `setTimeout` 输出三个相同的值。

- 现象：期望 `0 1 2`，实际 `3 3 3`。
- 原因：`var` 是函数作用域，三个回调捕获同一个 `i`；定时器执行时循环已结束。
- 解决：改用 `let` 获得每次迭代的独立绑定；需要兼容旧环境时用 IIFE 传参复制当前值。
- 可复用的经验：**闭包捕获的是绑定，不是值**。
