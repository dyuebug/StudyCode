## 📖 学到的知识点

### 一、数据持久化核心概念
1. **什么是持久化**：把内存数据保存到磁盘，程序重启后数据不丢失
2. **内存 vs 磁盘**：内存快但易失，磁盘慢但持久
3. **持久化方式对比**：JSON 文件（简单、够用）、pickle（Python 专用）、数据库（大数据）
4. **应用价值**：用户数据、配置、日志等重要数据必须持久化

### 二、JSON 文件读写 ⭐⭐⭐⭐⭐
1. **json.dump()**：保存 Python 数据到 JSON 文件
   - 参数：obj（数据）、f（文件对象）、indent（缩进）、ensure_ascii（中文）
2. **json.load()**：从 JSON 文件加载数据到 Python
   - 返回：Python 对象（字典、列表）
3. **类型转换**：JSON object → dict、array → list、string → str、number → int/float
4. **对比**：dump/load（文件）vs dumps/loads（字符串）

### 三、中文处理三件套 ⭐⭐⭐⭐⭐
1. **encoding='utf-8'**：文件操作支持中文
2. **ensure_ascii=False**：保留中文可读（不转义成 \uXXXX）
3. **indent=2**：格式化输出，方便调试

### 四、持久化模式：启动加载 + 操作保存
1. **启动时**：load_messages() 从文件加载到内存
2. **操作时**：修改内存 + save_messages() 立即保存
3. **关闭时**：数据已保存，下次启动可恢复
4. **核心思想**：内存操作快，文件保证持久

### 五、异常处理
1. **FileNotFoundError**：文件不存在（首次运行）→ 返回空列表
2. **json.JSONDecodeError**：JSON 格式错误（文件损坏）→ 创建新文件
3. **try-except 必备**：加载数据必须处理文件不存在

### 六、全局变量修改
1. **global 关键字**：函数内修改全局变量必须声明
2. **只读不需要**：只读全局变量不需要 global
3. **赋值创建局部**：函数内赋值默认创建局部变量

### 七、留言板持久化改造
1. **新增函数**：load_messages()、save_messages()
2. **启动流程**：app 启动前调用 load_messages()
3. **next_id 计算**：从现有留言中获取最大 id + 1（避免冲突）
4. **实时保存**：POST 接口添加留言后立即调用 save_messages()

## ❓ 遇到的问题与解决

**问题1**：emoji 字符编码错误
- 现象：Windows 控制台 GBK 编码无法显示 emoji（⚠️ ✅ ❌ 💾）
- 原因：`UnicodeEncodeError: 'gbk' codec can't encode character`
- 解决：把 emoji 改成普通文字标记（[INFO]、[OK]、[ERROR]、[SAVE]）
- 经验：生产环境的日志输出避免使用 emoji，用纯文本更稳定

JSON 文件操作的三件套（encoding='utf-8' + ensure_ascii=False + indent=2）很重要，缺一不可：不加 encoding 可能中文乱码，不加 ensure_ascii 中文变成 \uXXXX 难读，不加 indent 所有内容挤在一行难调试。异常处理也很关键，第一次运行时文件不存在必须用 try-except 处理，否则程序崩溃。

遇到的 emoji 编码问题是个小插曲，说明 Windows 控制台对 Unicode 支持有限。生产环境的代码应该避免这类问题，用纯文本标记更稳定。现在留言板项目已经是一个真正实用的应用了：前后端分离 + 数据持久化，可以作为其他项目的基础模板！
