## 📖 学到的知识点

### 一、RESTful API 设计原则 ⭐⭐⭐⭐⭐
1. **核心思想**：URL = 资源（名词），HTTP 方法 = 操作（动词）
2. **设计对比**：
   - ❌ 传统：/api/deleteMessage/1（URL 含动词）
   - ✅ RESTful：DELETE /api/messages/1（方法表示操作）
3. **优点**：统一、直观、易理解、跨语言通用

### 二、HTTP 四种方法（CRUD）
1. **GET - 查询**：只读，不修改数据，可缓存
2. **POST - 创建**：创建新资源，非幂等
3. **PUT - 更新**：更新资源，幂等（多次结果相同）
4. **DELETE - 删除**：删除资源，幂等

### 三、URL 设计规范
1. **使用名词**：/api/messages（不要 /api/getMessages）
2. **使用复数**：/api/messages（不要 /api/message）
3. **用方法表示操作**：DELETE /api/messages/1（不要 /api/messages/delete/1）
4. **层级关系**：/api/users/123/posts（用户123的文章）
5. **过滤参数**：/api/messages?limit=10（查询参数）

### 四、HTTP 状态码
1. **2xx 成功**：200 OK、201 Created、204 No Content
2. **4xx 客户端错误**：400 Bad Request、404 Not Found、401/403 权限
3. **5xx 服务器错误**：500 Internal Server Error
4. **使用原则**：返回正确的状态码，前端才能准确处理

### 五、Flask 路径参数 ⭐⭐⭐⭐⭐
1. **基本语法**：`<参数名>` 或 `<类型:参数名>`
2. **类型转换**：`<int:id>` 自动转换为整数
3. **错误处理**：格式错误（abc）Flask 自动返回 404
4. **推荐用法**：指定类型（`<int:id>`）更安全

### 六、删除接口实现
1. **路由定义**：`@app.route('/api/messages/<int:id>', methods=['DELETE'])`
2. **删除逻辑**：
   - 遍历列表查找对应 id
   - 找到：删除（pop）+ 保存（save_messages）+ 返回 200
   - 未找到：返回 404 错误
3. **持久化**：删除后立即 save_messages()
4. **状态码**：成功 200、未找到 404

### 七、前端 DELETE 请求（理论）
1. **fetch 语法**：`fetch(url, {method: 'DELETE'})`
2. **确认提示**：`if (!confirm('确定删除吗？')) return`
3. **删除后刷新**：`loadMessages()` 重新加载列表
4. **错误处理**：检查 response.ok 和 response.status

## 💭 今日心得

今天学习了 RESTful API 设计规范，理解了一个重要思想：URL 代表资源（名词），HTTP 方法代表操作（动词）。这种设计统一、直观，比传统的 /getXXX、/deleteXXX 清晰太多。

成功为留言板添加了删除功能，实现了完整的 CRUD 操作（创建、查询、删除）。关键点是 Flask 的路径参数 `<int:id>`，它自动把 URL 中的 id 转换为整数，并且格式错误时自动返回 404，非常方便。删除逻辑也很清晰：遍历列表查找 → 找到就删除并保存 → 未找到返回 404。

测试结果完美：删除 id=2 成功，列表正确更新；删除不存在的 id=999 返回自定义404错误；删除格式错误的 abc，Flask 自动返回404。数据持久化也验证成功，删除操作立即保存到文件。

RESTful API 的状态码使用也很重要：200表示成功，404表示资源不存在，400表示请求错误。前端可以根据状态码做出正确的反应。现在留言板已经有了完整的后端 API：GET 获取、POST 创建、DELETE 删除，符合 RESTful 规范，接口清晰易用。

虽然前端删除按钮没有实际实现，但后端接口已经完全可用，前端只需要发送 `fetch(url, {method: 'DELETE'})` 即可。理解了原理和规范，比单纯写代码更重要。
