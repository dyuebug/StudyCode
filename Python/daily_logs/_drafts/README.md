# 逐日日志底稿（_drafts）

## 这些文件是什么

- `第47天_日志底稿.md` ～ `第51天_日志底稿.md`：学习结束后用来填写日志的**空白底稿**。
- 只有标题、字段名和任务项；没有学习时长、完成度、心得或结论。
- **不是完成记录**，不计入“已完成学习天数”“累计时长”等统计。

## 为什么不直接生成完成日志

`CLAUDE.md` 1.3 明确禁止：

- 把任务清单当成完成日志；
- 推断学习日期；
- 补造日志、项目或学习时长；
- 在没有用户确认时填写“遇到的问题”“学习心得”或完成度。

因此这里只提供可填写的骨架。真实日志必须在学习结束后生成。

## 与示例日志的区别

- `daily_logs/2026-10-30_第47天_日志.md` ～ `第51天_日志.md` 是**示例日志**，用于演示格式与知识点写法，文件头明确标注“不计入统计”。
- 本目录的底稿是**空白骨架**，没有任何示例结论。
- 要开始学习时，以底稿为起点填写真实数据，并**替换**同序号的示例日志文件；替换时删除 `**文档性质**：示例日志（非真实学习记录，不计入统计）` 这一行，否则统计脚本会继续跳过它。

## 如何把底稿变成正式日志

1. 完成当天学习，确认实际开始和结束时间。
2. 复制底稿到 `daily_logs/YYYY-MM-DD_第X天_日志.md`。
3. 文件名日期改为**真实记录日期**；正文“记录日期”保持一致。
4. 逐项勾选实际完成的任务；未完成的保留 `[ ]` 并写明原因。
5. 填写实际时长、完成度、知识点、问题、测试输出。
6. 运行 `python scripts/generate_weekly_reports.py` 重新生成周报。

## 规则

- 底稿中的 `[ ]` 不得提前改为 `[x]`。
- 完成度 = 已勾选任务数 / 总任务数，不预设 100%。
- 没有遇到的问题写“今日未遇到阻塞性问题”，不编造。
- 底稿文件不会被测试或统计脚本识别，因为文件名不以 `_日志.md` 结尾且位于子目录。
