## 📖 学到的知识点

### 命令行工具开发
1. **命令行工具的概念**：通过命令行与用户交互的程序，不需要图形界面，轻量高效。
2. **应用场景**：自动化任务、开发工具、系统管理、数据处理、个人工具。
3. **常见示例**：git、pip、npm、docker等都是命令行工具。

### argparse 模块基础
1. **argparse 的作用**：Python标准库中的命令行参数解析模块，自动生成帮助信息。
2. **基本步骤**：创建解析器 → 添加参数 → 解析参数 → 使用参数。
3. **参数类型**：位置参数（必需）、可选参数（--开头）、type参数（类型验证）、action参数（布尔标志）。
4. **子命令**：使用subparsers创建子命令（如git add、git commit）。

### 项目结构设计
1. **为什么需要好的项目结构**：易于理解、易于维护、易于扩展、易于测试。
2. **推荐的项目结构**：main.py（主程序）、models.py（数据模型）、utils.py（工具函数）、config.py（配置）、data/（数据文件）、logs/（日志文件）。
3. **设计原则**：单一职责、高内聚、低耦合、易于测试。

### 日志记录和错误处理
1. **日志记录的价值**：调试、监控、审计、分析。
2. **logging 模块使用**：basicConfig配置、日志级别（DEBUG、INFO、WARNING、ERROR、CRITICAL）、日志格式化。
3. **错误处理最佳实践**：预期错误要处理、提供友好的错误提示、记录错误日志。

### 代码组织最佳实践
1. **函数职责单一**：每个函数只做一件事，函数名清晰表达功能，函数长度不超过50行。
2. **类的设计原则**：单一职责原则、封装数据和行为、提供清晰的接口。
3. **代码复用**：提取公共代码为函数、避免重复代码、使用继承和组合。
4. **命名规范**：变量名（user_name）、函数名（get_user）、类名（UserManager）、常量（MAX_SIZE）。
5. **注释和文档**：复杂逻辑要注释、函数要有文档字符串、注释要说明"为什么"。

### 常见错误和陷阱
1. **忘记处理用户输入错误**：用户输入总是不可信的，使用type参数验证，添加范围检查。
2. **数据文件路径硬编码**：使用相对路径，使用os.path.join()拼接路径，确保目录存在。
3. **所有代码写在一个文件里**：按功能模块拆分文件，单个文件不超过300行，遵循单一职责原则。
4. **没有使用日志，只用print**：使用logging模块，配置日志级别和格式，同时输出到文件和控制台。
5. **没有提供帮助信息**：使用description参数说明程序功能，使用help参数说明每个参数，使用epilog参数提供使用示例。
6. **JSON文件编码问题**：使用encoding='utf-8'指定编码，使用ensure_ascii=False保留中文，使用indent=2格式化输出。
7. **没有验证数据完整性**：读取数据后要验证结构，检查必需字段是否存在，处理数据损坏的情况。

### 综合项目实战：待办事项管理工具（TODO CLI）
1. **项目功能**：添加任务（add）、查看任务（list）、完成任务（done）、删除任务（delete）、数据持久化（JSON）。
2. **技术栈**：面向对象设计（Task类、TodoManager类）、文件操作（JSON读写）、异常处理、日志记录、命令行参数解析。
