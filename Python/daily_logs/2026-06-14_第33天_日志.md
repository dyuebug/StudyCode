## 📖 学到的知识点

### 一、前后端分离核心概念
1. **前后端分离**：前端管界面，后端管数据，通过 API 传递数据（JSON 格式）
2. **API 是桥梁**：约定好的"接口"，前端通过 URL 访问，后端返回数据
3. **数据流向**：前端表单 → fetch → Flask → 保存 → 返回 JSON → 前端渲染
4. **与模板对比**：传统 Jinja2 后端生成 HTML，分离模式后端只返回数据

### 二、Flask 返回 JSON 数据
1. **jsonify() 函数**：把 Python 字典/列表转成 JSON 响应，自动设置 Content-Type
2. **request.get_json()**：获取前端 POST 的 JSON 数据，返回 Python 字典
3. **路由方法**：`methods=['GET', 'POST']` 指定接口接受的请求方法
4. **数据验证**：用 `.get('key', default)` 安全获取字段，避免 KeyError

### 三、CORS 跨域问题 ⭐⭐⭐⭐⭐
1. **什么是跨域**：浏览器同源策略，协议/域名/端口任一不同算跨域
2. **为什么限制**：安全考虑，防止恶意网站偷偷调用你的 API
3. **跨域错误**：`blocked by CORS policy`（浏览器拦截）
4. **解决方案**：`pip install flask-cors` + `CORS(app)` 一行搞定

### 四、fetch 调用后端 API
1. **GET 请求**：`fetch(url)` → `await response.json()` 获取数据
2. **POST 请求三要素**：
   - method: 'POST'
   - headers: {'Content-Type': 'application/json'}
   - body: JSON.stringify(数据)
3. **数据转换**：发送用 JSON.stringify()，接收用 response.json()
4. **错误处理**：检查 response.ok，用 try/catch 捕获异常

### 五、留言板项目实战
1. **后端架构**：全局列表存储留言，两个 API（GET 获取、POST 提交）
2. **前端逻辑**：页面加载自动获取留言，提交后重新加载列表（实时刷新）
3. **完整流转**：表单输入 → fetch POST → Flask 保存 → 返回成功 → fetch GET → DOM 渲染
4. **项目测试**：curl 测试 API 成功（GET 返回列表、POST 添加留言）

## 💭 今日心得

今天完成了一个重要里程碑——第一次打通前后端！终于理解了前后端分离的真正含义：前端负责展示和交互，后端负责数据和逻辑，通过 API（JSON）传递数据。这种模式比传统的模板渲染更灵活，前端可以用 fetch 实时获取数据，无需刷新整个页面。

最大的收获是理解了完整的数据流转：用户在前端提交 → fetch POST 发送 JSON → Flask 用 request.get_json() 接收 → 保存到列表 → 用 jsonify() 返回成功 → 前端再 fetch GET 获取最新列表 → 用 DOM 渲染显示。每一步都能追踪到，清晰可控。

CORS 跨域是个关键点，必须在后端加 CORS(app) 才能让前端跨域调用。留言板项目虽然简单，但五脏俱全：GET 获取数据、POST 提交数据、前端实时刷新、错误处理，涵盖了前后端交互的核心要素。现在终于能做出真正"活"的 Web 应用了，不是静态页面，而是能与服务器交互的动态应用！
