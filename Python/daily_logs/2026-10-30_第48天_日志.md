## 📖 学到的知识点

### 一、应用工厂

- **为什么用工厂**：`create_app()` 每次调用返回独立实例，测试可以并发创建多个应用，不会共享模块级全局状态。
- **配置覆盖顺序**：`Flask(__name__)` 内置默认值 → `config.from_mapping(...)` 项目默认值 → `test_config` 覆盖。`test_config` 必须放在最后，否则会被默认值覆盖。
- **测试隔离**：测试传入临时数据库路径，`init_app()` 在应用上下文中执行建表脚本，因此不会写入开发用的 `forum.db`。
- **目录创建**：`Path(config["DATABASE"]).parent.mkdir(parents=True, exist_ok=True)` 保证数据目录存在；`parents=True` 创建多级目录，`exist_ok=True` 避免并发或重复创建时报错。
- **初始化顺序**：建目录 → 注册数据库钩子并建表 → 注册请求钩子 → 注册路由 → 注册错误处理。数据库必须先于钩子，因为 `before_request` 会调用 `get_db()`。

### 二、请求生命周期

- **执行顺序**：
  1. 创建应用上下文与请求上下文。
  2. `before_request` 按注册顺序执行：`load_logged_in_user` → `protect_form_posts`。
  3. 视图函数。
  4. `after_request`（本项目未注册）。
  5. `teardown_request` → `teardown_appcontext`，`close_db` 在此关闭连接。
- **`g` 与 `session`**：
  - `g` 是单次应用上下文内的临时对象，请求结束即销毁，不序列化，适合放数据库连接和当前用户。
  - `session` 是签名后写入 Cookie 的字典，跨请求保留，客户端可见（可读不可篡改），不能放敏感数据。
- **连接复用**：`get_db()` 先查 `g.db`，同一请求内多次调用复用同一连接；`close_db` 用 `g.pop("db", None)`，确保重复调用安全。
- **外键**：SQLite 默认关闭外键约束，必须在每个连接上执行 `PRAGMA foreign_keys = ON`，否则删除父记录不会触发约束。

### 三、CSRF 与认证

- **token 生成**：`csrf_token()` 从 `session` 读取，不存在时用 `secrets.token_urlsafe(24)` 生成并写回；模板通过 `context_processor` 注入。
- **校验时机**：`protect_form_posts` 在 `before_request` 阶段拦截所有非 `/api/` 的 POST，用 `secrets.compare_digest` 做常量时间比较，失败返回 400。
- **为什么 API 例外**：`/api/posts` 只提供只读 GET，不接收表单状态变更；一旦增加写接口，必须单独设计 token 或改用其他认证方式。
- **登录后保留 token**：登录成功后若清空整个 session，浏览器已渲染页面中的 token 会失效，下一次提交表单立即 400。正确做法是 `session.clear()` 后重新生成或保留 `_csrf_token`。
- **开放重定向防护**：`next` 参数只允许站内相对路径，拒绝 `//evil.com`、`http://...` 等绝对地址。

### 四、测试客户端

- `application.test_client()` 不经过真实网络，直接走 WSGI 调用，仍会执行全部钩子，因此适合验证重定向、状态码和 session 行为。
- `client.get("/", follow_redirects=False)` 可断言 302 与 `Location`；`follow_redirects=True` 用于验证最终页面内容。
- 测试使用 `tmp_path` 生成独立数据库，每个用例互不影响；需要预置数据时在应用上下文中调用 `init_db()` 或直接执行 SQL。

## ⚠️ 遇到的问题与解决

**问题1**：新增的未登录重定向测试拿到 200 而不是 302。

- 现象：`assert response.status_code == 302` 失败，实际为 200。
- 定位过程：打印 `response.request.path`，发现测试请求的是 `/`，而首页本身允许匿名访问。
- 原因：受保护的是发帖等写操作，不是首页。
- 解决：把请求改为 `client.post("/posts", data={...})`，未登录时由 `login_required` 重定向到登录页。
- 可复用的经验：**先确认被保护的路由，再写断言**；状态码不符合预期时先打印实际请求路径。

**问题2**：测试之间出现数据串扰，前一个用例创建的帖子出现在后一个用例中。

- 原因：多个用例共用了同一个数据库文件路径。
- 解决：fixture 中用 `tmp_path / "test.db"` 为每个用例创建独立路径，并在 `create_app({"TESTING": True, "DATABASE": ...})` 中覆盖。
- 可复用的经验：**测试隔离靠资源隔离，不靠执行顺序**。
