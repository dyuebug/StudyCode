## 📖 学到的知识点

### 一、反向代理

- `proxy_pass http://127.0.0.1:8000;` 把匹配的请求转发给上游；后端只监听回环地址，公网无法直连。
- `proxy_set_header Host $host;` 保留原始域名，后端生成绝对 URL 时不会变成 `127.0.0.1:8000`。
- `X-Real-IP` 与 `X-Forwarded-For` 传递客户端地址；`X-Forwarded-Proto` 传递原始协议。
- 后端若要正确识别协议和客户端地址，需要 `ProxyFix` 之类的中间件显式信任这些头；否则 Flask 看到的仍是 `http` 和代理地址。
- `proxy_connect_timeout` 控制连接上游的超时；`proxy_read_timeout` 控制等待响应的超时，二者含义不同。

### 二、静态资源

- `alias /opt/study-forum/forum_project/static/;` 会把 `location /static/` 后面的部分拼到该目录。
- `alias` 末尾的 `/` 必须保留：`/static/app.css` → `/opt/.../static/app.css`；缺少斜杠会拼成 `staticapp.css`。
- `root` 是拼接完整 URI，`alias` 是替换 location 前缀；两者语义不同，混用是 404 的常见原因。
- `expires 7d` 让 Nginx 返回 `Cache-Control: max-age=604800`；`access_log off` 减少静态请求日志量。

### 三、HTTPS 与跳转

- 80 端口保留 `/.well-known/acme-challenge/` 供证书签发验证，其余请求 `return 301 https://$host$request_uri`。
- `$request_uri` 包含原始路径和查询串，跳转后不会丢参数。
- TLS 只启用 1.2 和 1.3；`ssl_session_cache` 减少重复握手开销。
- 安全响应头加 `always`，确保 4xx/5xx 响应也带 `nosniff`、`DENY` 等头。

### 四、限流

- `limit_req_zone $binary_remote_addr zone=forum_limit:10m rate=10r/s;` 必须放在 `http` 上下文，不能写在 `server` 内。
- `$binary_remote_addr` 比 `$remote_addr` 更省内存；`10m` 是共享内存区大小。
- `burst=20 nodelay` 允许瞬时突发 20 个请求，超出速率的请求立即返回 503，而不是排队等待。
- 限流按 IP 维度生效；经过 CDN 或反向代理时，需要结合 `real_ip` 模块获取真实客户端地址。

### 五、错误码定位

- `502 Bad Gateway`：Nginx 连不上上游，通常是后端未启动或端口不符。
- `504 Gateway Timeout`：连上了但上游超时。
- `404`：Nginx 找到了 server 但没有匹配的静态文件或 location。
- `503`：可能是限流拒绝，也可能是上游主动返回；需要结合 `error.log` 区分。

## ⚠️ 遇到的问题与解决

**问题1**：配置 `alias /srv/static;` 后访问 `/static/app.css` 返回 404。

- 现象：文件确实存在，`nginx -t` 也通过。
- 定位过程：`nginx -T` 查看实际配置；打开 `error.log` 看到请求被映射为 `/srv/staticapp.css`。
- 原因：`alias` 路径末尾缺少 `/`，前缀替换后直接拼接文件名。
- 解决：改为 `alias /srv/static/;`。
- 可复用的经验：**静态 404 先看 `error.log` 里的实际文件路径**，比反复改配置更快。

**问题2**：后端停机后请求返回 502，但限流测试想验证 503，两者混在一起。

- 原因：后端不可用时所有未被限流的请求都是 502，只有被限流拒绝的才是 503。
- 解决：先确认后端正常，再单独压测限流；或直接根据状态码分布判断，503 只可能来自 Nginx 限流。
- 可复用的经验：**错误码要结合上游状态解释，不能只看单个响应**。
