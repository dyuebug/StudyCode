📚 核心概念

什么是异步编程？

异步编程是一种编程范式，允许程序在等待耗时操作（如网络请求、文件读取）完成时，继续执行其他代码，而不是阻塞等待。

为什么需要异步编程？

JavaScript的特点：

  • 单线程：JavaScript只有一个执行线程
  • 非阻塞：不能让耗时操作阻塞整个程序
  • 事件驱动：通过事件循环处理异步操作

实际场景：

  • 网络请求（fetch、Ajax）
  • 文件操作（读写文件）
  • 定时器（setTimeout、setInterval）
  • 用户交互（点击、输入）
  • 数据库操作

同步 vs 异步

同步执行（阻塞）

任务1 ━━━━━━━━▶ 完成
                   ↓
              任务2 ━━━━━━━━▶ 完成
                               ↓
                          任务3 ━━━━━━━━▶ 完成

❌ 每个任务必须等待前一个任务完成

异步执行（非阻塞）

任务1 ━━━━━━━━▶ 完成
任务2 ━━━━━━━━━━━━━━━━▶ 完成（耗时长）
任务3 ━━━━━━━━▶ 完成

✅ 任务2在后台执行，不阻塞任务3

2️⃣ 事件循环（Event Loop）⭐⭐⭐⭐⭐

【核心机制】

什么是事件循环？

事件循环是JavaScript实现异步的核心机制。它不断检查执行栈是否为空，如果为空就从任务队列中取出任务执行。

执行流程：

  1. 执行栈（Call Stack）：同步代码在这里执行
  2. Web APIs：浏览器提供的异步API（setTimeout、fetch等）
  3. 任务队列（Task Queue）：异步任务完成后回调函数进入队列
  4. 事件循环：栈空时，从队列取任务到栈执行

事件循环示意图

┌─────────────────────────────────────────────┐
│   执行栈（Call Stack）                       │
│   ┌─────────────────────────────────┐      │
│   │ 同步代码在这里执行                │      │
│   └─────────────────────────────────┘      │
└─────────────────────────────────────────────┘
                    ↓
┌─────────────────────────────────────────────┐
│   Web APIs（浏览器提供）                     │
│   setTimeout / fetch / DOM events           │
└─────────────────────────────────────────────┘
                    ↓
┌─────────────────────────────────────────────┐
│   任务队列（Task Queue）                     │
│   [回调1] [回调2] [回调3] ...               │
└─────────────────────────────────────────────┘
                    ↑
              事件循环不断检查

3️⃣ 宏任务 vs 微任务 ⭐⭐⭐⭐

【概念卡片】

宏任务（MacroTask）：

  • setTimeout / setInterval
  • setImmediate（Node.js）
  • I/O操作
  • UI渲染

微任务（MicroTask）：

  • Promise.then / catch / finally
  • async/await
  • MutationObserver
  • process.nextTick（Node.js）

执行顺序：

  1. 执行同步代码
  2. 执行所有微任务
  3. 执行一个宏任务
  4. 回到步骤2（循环）

4️⃣ 回调函数基础 ⭐⭐⭐⭐

【概念卡片】

什么是回调函数？

回调函数是作为参数传递给另一个函数的函数，在异步操作完成后被调用。

语法：

function doSomethingAsync(callback) {
    setTimeout(() => {
        const result = '异步操作完成';
        callback(result);  // 调用回调函数
    }, 1000);
}

5️⃣ 回调地狱（Callback Hell）⭐⭐⭐⭐⭐

【问题说明】

⚠️ 回调地狱的问题：

  • 嵌套层级深：代码横向增长，难以阅读
  • 难以维护：修改逻辑困难
  • 错误处理困难：每层都要处理错误
  • 代码复用困难：逻辑耦合严重

示例：回调地狱演示

💡 解决方案：

  • Promise：链式调用，扁平化代码
  • async/await：同步写法，异步执行
